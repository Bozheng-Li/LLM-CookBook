# Judge 评审协议

每轮评审由**全新上下文**的评审智能体执行（互不知晓彼此与其他轮次的存在），各自扮演独立身份，只对自己负责的维度给出结论。

## 轮次设计（全部维度，每轮全新身份）

| 轮 | 身份 | 职责焦点 |
|---|---|---|
| R1 | 资深技术编辑（前 O'Reilly 主编） | 文字质量：语法、用词、句式、AI 腔、翻译一致性 |
| R2 | 技术事实核查员（研究员） | 精确度：论文引用、数字、代码正确性、概念准确性 |
| R3 | 书籍装帧设计师 | 图文样式与图示设置：图表清晰度、编号、布局、留白 |
| R4 | 前端/UX 设计师 | 界面美观与阅读观感：主题、排版、导航、响应式 |
| R5 | 语言质量审校（中文母语编辑） | 语言准确率与语言风格：术语统一、标点、中英混排规范 |

## 输出格式（每个 judge 必须遵守）

对每个检查对象输出：
```
[严重度 P0/P1/P2/P3] 位置(章节/图/节) | 问题描述 | 修改建议
```
最后给出本轮总结论：PASS / PASS WITH FIXES / FAIL。

## 修复循环

评审意见 → 修复（编辑或派发修复 agent）→ 复审（新的 judge 实例，同维度）→ 直至 PASS。
