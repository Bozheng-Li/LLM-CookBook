# RAG 与幻觉

检索增强生成把回答建立在检索到的证据上。但证据在手并不等于回答正确——把知识库里的内容原样搬进 prompt，模型依然可能编造。

幻觉需要分来源看。一是检索失败：检索器没找到相关片段，模型拿不到证据，只能靠先验知识硬答。二是上下文丢失：找到的证据太长，被模型自己的截断策略砍掉，或超窗被裁剪。三是合成失败：证据齐全，但模型在拼接时编造了证据里没有的细节。

有一个测量口径容易混淆：忠实度（faithfulness）和准确性（accuracy）。回答里每个细节都能在证据中找到，叫忠实；回答与真实世界事实一致，叫准确。RAG 系统能控制的只有前者——证据本身错，忠实回答也会错。评测时必须分开报。

缓解手段按来源对号入座：检索失败靠查询改写、多路召回；上下文丢失靠更好的切分、检索后重排、压缩再输入；合成失败靠提示约束"只依据证据回答"、让模型标注不支持的断言、加一个引用校验器事后检查。

一个值得警惕的现象：知识库里的陈旧信息。模型会把过时的内容当成事实自信地复述，而且引用机制会让错误看起来更可信。对时效敏感的问题，检索之外还要给证据打上时间戳。
