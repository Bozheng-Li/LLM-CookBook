# 从零搭一个可评测的 RAG

零依赖，只用 Python 标准库，CPU 几秒跑完。**重点不是"能跑通"，而是"能量化"**：
换切分策略、换检索器，指标会怎么动。没有评测集的 RAG 调优等于盲调。

```bash
cd examples/rag-practice
python eval.py            # 3 种切分 × 3 种检索器的对照表
python test_rag.py        # 21 项自检
python -m pytest          # 或者用 pytest 跑
```

单独问一个问题：

```bash
python -c "from rag import build_index, answer; _, r = build_index(); print(answer('QLoRA 用了哪几个技巧', r).render())"
```

## 文件

| 文件 | 内容 |
| --- | --- |
| `chunk.py` | 三种切分：定长带重叠、按句、按段。每个块都带回原文的字符偏移 |
| `retrieve.py` | BM25、字符 bigram 词袋向量、RRF 混合 |
| `rag.py` | 建索引 + 抽取式回答（每句话都可溯源） |
| `eval.py` | Recall@k / MRR / nDCG@k 三个指标 + 完整对照表 |
| `data/kb/*.md` | 6 篇中文知识库文档 |
| `data/qa.json` | 22 条评测问题，标注了正确文档和问题类型 |

回答部分刻意用**抽取式**而非生成式：答案里每个字都来自某个原文句子，
忠实度恒等于 1。这样评测时的变量只有检索质量，不会和模型幻觉纠缠在一起。
需要接真实模型时，把 `answer()` 换掉即可，检索层和评测层不用动。

## 跑出来的三个结论

**1. 切分策略的影响比换检索器大。**

实测（k=5，22 条问题）：

```
     切分    块数       检索器   Recall@k      MRR   nDCG@k
    fixed    13      BM25      0.955    0.902    0.915
 sentence    12      BM25      0.955    0.909    0.921
paragraph    35        向量      0.955    0.932    0.938
```

Recall@5 三种切分全都是 0.955，动不了——但 MRR 从 0.902 爬到 0.932。
**召回率看不出差别的地方，排序质量看得出。** 只盯着 Recall 调参会漏掉这一半的收益。
`paragraph` 把 6 篇文档切成 35 块，粒度更细，命中块和问题的语义更集中，
所以正确答案更容易排到第一位。代价是块数接近三倍，索引和上下文成本都涨。

**2. 同义改写是真实的天花板，混合检索也补不上。**

按问题类型拆开看：

```
字面重叠（16 条）  BM25 1.000  向量 1.000  混合RRF 1.000
同义改写（6 条）  BM25 0.833  向量 0.833  混合RRF 0.833
```

字面重叠的问题三种检索器全对。改写过的问题全都掉到 0.833，**而且三条路完全一样**。
原因是本例的"向量"是字符 bigram 词袋——它和 BM25 共享同一套词面信号，
只是加权方式不同。两条同源的路做 RRF，融合不出新信息。
`test_paraphrase_queries_are_actually_harder` 把这个差距钉成了断言。

这正是需要真实 embedding 模型的地方。想验证：把 `DenseRetriever` 换成
调用 embedding API，重跑 `eval.py`，看同义改写那一行能不能过 0.833。
指标是现成的，换掉一个类就能对比。

**3. 词面检索无法校准拒答阈值。**

一个反直觉的负面结论。给一个和知识库毫无关系的问题："紫色的大象在星期四会做什么梦"，
检索器**依然会返回结果**，因为中文 bigram 里"什么""会做"这类功能词在任何语料里都有。

RRF 分数看不出区别（无关问题 0.0328，真实问题 0.0328），因为 RRF 只用排名、
丢掉了分数大小——这既是它不需要归一化的原因，也是它无法表达"都不相关"的原因。

退回到稠密路的原始余弦分数，分布是这样的：

```
真实问题首位分数：min 0.103  median 0.226
无关问题首位分数：0.107 / 0.000 / 0.163 / 0.000
```

**两个分布重叠**：无关问题能到 0.163，真实问题能低到 0.103。不存在既不误杀
又不漏放的阈值。所以 `answer()` 的 `min_score` 默认是 0（关闭），
文档里也不给"推荐值"——给了就是假精确。要做可用的拒答，前提是换语义编码器，
不是调这个数。

`test_lexical_retriever_cannot_calibrate_abstention` 断言了 `noise_max >= real_min`。
哪天换成真 embedding 让两个分布分开了，这条测试会失败并提示更新——
**用失败来通知进展，比注释里写一句"以后再改"可靠。**

## 两个实现细节

**块偏移必须能切回原文。** 早期版本用 `"".join(sentences)` 拼块，
但 `split_sentences` 会 strip 掉句间空白，拼出来的字符串和 `text[start:start+len]`
对不上，引用高亮就会错位。现在直接从原文切片。
`test_chunk_offsets_point_back_to_source` 覆盖全部三种策略。

**BM25 的 IDF 要防负数。** 教科书上的 `log((N-df+0.5)/(df+0.5))` 在词项出现在
超过一半文档时会变成负数，于是"命中一个常见词"反而扣分，排序颠倒。
这里用 `log(1 + (N-df+0.5)/(df+0.5))`，把外层加一挪进 log 里保证恒正。
知识库只有 6 篇、中文 bigram 又高频，`df > N/2` 是常态而非边缘情况，
`test_bm25_idf_is_never_negative` 钉住它。

## 练习

1. 把 `DenseRetriever` 换成真实 embedding，看同义改写那一行能不能超过 0.833
2. 给 `data/qa.json` 加 10 条你自己领域的问题，重跑看结论是否还成立
3. 加一个 rerank 阶段：先取 top-20 再精排到 top-5，量化 MRR 的变化
4. 实现 `test_lexical_retriever_cannot_calibrate_abstention` 失败的那一天——
   换掉编码器，让拒答真正可用
