免奖励模型对齐

RLHF 里最脆弱的零件是奖励模型——它会被钻空子、会过拟合，训练它还要额外一组标注数据和一轮训练。DPO 及其变体（IPO、KTO、SimPO）问了一个尖锐的问题：既然最终目标只是让策略满足人类偏好，为什么不直接用偏好数据训练策略，跳过中间那个「打分裁判」？这一跳，砍掉了四模型显存里的两个（奖励模型和价值模型），让对齐训练的门槛骤降。这一节从数学消元讲到一步梯度里到底发生了什么，再讲清它会在什么地方翻车。

前置知识 本页假定你已读过 RLHF，理解奖励模型、PPO 目标函数、KL 惩罚的作用；也假定你知道 SFT 是怎么回事，因为 DPO 几乎总是接在 SFT 后面跑。如果 Bradley-Terry 模型和策略梯度的概念还不熟，建议先回看 强化学习基础。
一图看懂

RLHF 是「先学裁判再学选手」——训练一个奖励模型打分，再用 PPO 优化策略去追高分。DPO 的关键洞察是：RLHF 的最优策略有闭式解，可以把奖励函数用策略本身表示出来，代回损失后奖励模型就消掉了。于是偏好数据直接变成策略的梯度信号，一个模型、一次前向、一次反向，对齐完成。用一句大白话说：不用先请一个裁判来给每场比赛打分，直接拿「谁赢了谁输了」的比赛录像去练选手。

先看地图：偏好对齐这条路是怎么走过来的

DPO 不是凭空冒出来的。它站在一条清晰的技术脉络上：每一步都在把「对齐」这件事的工程复杂度往下砍一刀。理解这条脉络，比死记每个方法的公式更有用——因为你会发现每个新方法都在回答「上一个方法的哪个零件太贵、太脆」。

看这条时间线要抓住一个反复出现的模式：每砍掉一个零件，就会丢掉这个零件原本提供的某种保护。砍掉奖励模型，丢掉的是它对标注噪声的平滑作用；砍掉 on-policy 采样，丢掉的是策略偏移时的自动纠错；砍掉参考模型，丢掉的是显式的 KL 锚点。后面每一节讲的失效模式，本质上都是这些「被丢掉的保护」在事后讨债。

DPO 的数学内核：奖励模型的消去法

理解 DPO 不需要新数学，只需要一个代数技巧。我们从 RLHF 的目标出发：在 KL 约束下最大化奖励，等价于求解

$$\max_\pi \; \mathbb{E}_{x \sim D,\, y \sim \pi(\cdot|x)}\!\left[r(x,y)\right] - \beta \, \text{KL}\!\left(\pi(\cdot|x) \,\|\, \pi_{\text{ref}}(\cdot|x)\right)$$

这个 constrained optimization 有闭式最优解——即最优策略 $\pi^*$ 可以用奖励函数 $r$ 显式写出：

$$\pi^*(y|x) = \frac{1}{Z(x)} \, \pi_{\text{ref}}(y|x) \, \exp\!\left(\frac{r(x,y)}{\beta}\right)$$

其中 $Z(x) = \sum_y \pi_{\text{ref}}(y|x) \exp\!\left(r(x,y)/\beta\right)$ 是配分函数，保证 $\pi^*$ 是合法的概率分布。这个式子的物理含义很直白：最优策略 = 参考策略在奖励高的地方加权、在奖励低的地方减权，再归一化。$\beta$ 控制加权的激进程度——$\beta$ 越小，指数项越陡，最优策略越敢于偏离参考模型。

但这个闭式解不能直接拿来用：$Z(x)$ 要对所有可能的回答 $y$ 求和，而回答空间是词表大小的序列长度次方，天文数字，算不出来。历史上大家因此才退回去用 PPO 做迭代优化。

DPO 的关键一步是把这个等式反过来——不去求 $\pi^*$，而是用策略表示奖励：

$$r(x,y) = \beta \log \frac{\pi^*(y|x)}{\pi_{\text{ref}}(y|x)} + \beta \log Z(x)$$

现在把这个奖励表达式代回 Bradley-Terry 偏好模型（「A 优于 B 的概率 = $\sigma(r(A) - r(B))$」）。神奇的事情发生了：$\log Z(x)$ 在 $r(A) - r(B)$ 中被消掉（因为两个回答共享同一个 prompt $x$，那个算不出来的配分函数在做差时正好相互抵消），最终得到：

$$P(A \succ B) = \sigma\!\left(\beta \log \frac{\pi(A|x)}{\pi_{\text{ref}}(A|x)} - \beta \log \frac{\pi(B|x)}{\pi_{\text{ref}}(B|x)}\right)$$

奖励模型消失了。整个表达式只剩下策略模型和参考模型的对数概率比。DPO 的损失函数就是对这个概率取负对数似然：

$$\mathcal{L}_{\text{DPO}} = -\mathbb{E}_{(x, y_w, y_l)}\!\left[\log \sigma\!\left(\beta \log \frac{\pi_\theta(y_w|x)}{\pi_{\text{ref}}(y_w|x)} - \beta \log \frac{\pi_\theta(y_l|x)}{\pi_{\text{ref}}(y_l|x)}\right)\right]$$

其中 $y_w$ 是偏好标注中更好的回答（winner），$y_l$ 是更差的回答（loser）。梯度会推高 $\pi_\theta(y_w|x)$ 相对于参考模型的比例，同时压低 $\pi_\theta(y_l|x)$ 的比例——KL 约束被「内置」进了对数比里，不需要额外维护。

推导步骤做了什么为什么这一步是关键
① 写出 KL 约束下的最优解$\pi^* \propto \pi_{\text{ref}} \exp(r/\beta)$这一步是 RLHF 目标函数的标准结论，不是 DPO 的发明
② 反解出奖励$r = \beta \log(\pi^*/\pi_{\text{ref}}) + \beta \log Z$视角翻转：不再把 $r$ 当输入，而是把它当 $\pi$ 的函数
③ 代入 Bradley-Terry$P(y_w \succ y_l) = \sigma(r_w - r_l)$偏好只关心奖励差值，这给了消元的机会
④ $\log Z(x)$ 抵消两项共享同一个 $x$，做差即消那个算不出来的配分函数被绕过了——整套方法能成立全靠这一步
⑤ 取负对数似然得到 $\mathcal{L}_{\text{DPO}}$目标从「强化学习」退化成「二分类监督学习」
一句话直觉 DPO 把「训练一个裁判再训练选手」变成「直接用比赛录像训练选手」。裁判（奖励模型）不是真的不需要了，而是被数学消去了——它隐含在策略与参考模型的对数比里。论文标题里那句 Your Language Model is Secretly a Reward Model 就是这个意思：任何一个语言模型，配上一个参考模型，本身就定义了一个奖励函数。

把公式拆开看：一次 DPO 更新里到底发生了什么

公式看懂了不等于知道训练时在发生什么。这一节用具体数字走一遍单步更新，你会对后面所有失效模式的成因有更直观的把握。

一个具体的数值例子

设 $\beta = 0.1$。训练刚开始时，策略模型就是 SFT 模型的拷贝，也就是 $\pi_\theta = \pi_{\text{ref}}$。此时两个对数比都精确为 0，它们的差也是 0，于是

$$\mathcal{L}_{\text{DPO}}^{(0)} = -\log \sigma(0) = -\log 0.5 = \log 2 \approx 0.693$$

这是一个非常有用的健全性检查：任何一次正确配置的 DPO 训练，第 0 步的 loss 都应该等于 0.693 左右。如果第一步的 loss 明显偏离这个值，说明参考模型和策略模型的初始化没对上——最常见的原因是参考模型加载错了权重，或者两者的对话模板、特殊 token 处理不一致。

训练若干步之后，假设某个样本上：

量训练前训练后变化解读
$\log \pi_\theta(y_w|x)$-12.0-11.4+0.6好回答的概率被推高
$\log \pi_{\text{ref}}(y_w|x)$-12.0-12.00参考模型冻结，永不变
$\log \pi_\theta(y_l|x)$-13.0-15.4-2.4差回答的概率被大幅压低
$\log \pi_{\text{ref}}(y_l|x)$-13.0-13.00同上

loss0.693$-\log \sigma(0.3) \approx 0.554$-0.139下降，训练在进行

注意这张表里最值得玩味的一行：差回答概率下降的幅度（2.4）远大于好回答概率上升的幅度（0.6）。这不是偶然，而是 DPO 的典型行为——压低差回答比推高好回答「容易」得多，因为概率空间下方有的是空间，往上却要跟其他所有候选回答抢概率质量。这个不对称是后面很多问题的源头。

训练监控必看 实践中最该盯的不是 loss 本身，而是隐式奖励的三个派生量：好回答的隐式奖励、差回答的隐式奖励、以及「好回答隐式奖励大于差回答」的样本占比（即 accuracy）。主流训练框架（如 HuggingFace TRL 的 DPOTrainer）都会记录这几个量，具体指标名称以官方文档为准。健康的训练是：accuracy 稳步上升到 0.7 以上，margin 缓慢增大，而好回答的隐式奖励不要跌得太深。
展开：为什么训练中「好回答」的概率也在下降？

刚上手 DPO 的人几乎都会碰到这个困惑：打开训练日志，发现 chosen 回答的对数概率 $\log \pi_\theta(y_w|x)$ 是负增长的——它在往下走，只是走得比 rejected 慢。这看起来完全违反直觉：我们不是在「奖励」好回答吗？

原因在于 DPO 的损失函数只约束两者之差，完全不约束绝对值。回看目标：

$$\text{margin} = \beta\left[\left(\log \pi_\theta(y_w) - \log \pi_{\text{ref}}(y_w)\right) - \left(\log \pi_\theta(y_l) - \log \pi_{\text{ref}}(y_l)\right)\right]$$

只要这个差在增大，损失就在下降。至于是「$y_w$ 涨 1、$y_l$ 跌 0」还是「$y_w$ 跌 1、$y_l$ 跌 4」，损失函数一视同仁。而优化器会挑阻力最小的那条路——由于语言模型的输出是一个 softmax 分布，同时压低两个具体序列的概率、把概率质量分散给其他海量未被观测的序列，往往比精确抬高某一条序列容易得多。

后果是什么？模型对训练集里出现过的所有回答（包括好的那些）都变得更不自信，概率质量流向了没人监督过的第三方区域。这块区域里可能是别的好回答，也可能是胡言乱语。这就是 DPO 有时会出现「跑分涨了但实际输出变怪」的机理性原因。

缓解手段有几种：一是在 DPO 损失上叠加一个针对 chosen 回答的 SFT 交叉熵项（有些实现叫 DPO+SFT 或加 NLL 正则），把「好回答的绝对概率」也约束住；二是提高 $\beta$，让策略整体不敢跑太远；三是用 SimPO 这类做了长度归一化并引入固定 margin 的变体。

DPO 的工程优势：从四模型到两模型

数学上的优雅直接转化为工程上的简化。对比 RLHF 和 DPO 的训练资源需求：

维度RLHF（PPO）DPO
驻留模型数4（策略 + 参考 + 奖励 + 价值）2（策略 + 参考）
需要训练的模型3（策略 + 奖励 + 价值）1（策略）
需要反传的模型3（含优化器状态与激活）1
采样阶段需要 on-policy rollout（策略生成回答）不需要（直接用离线偏好数据）
训练循环多轮迭代（采样 → 打分 → 更新）单轮（像 SFT 一样跑 epoch）
超参数敏感度高（$\beta$、clip、学习率、GAE 相互耦合）低（主要调 $\beta$ 和学习率）
7B 模型权重显存（BF16 粗算）约 56GB（四份 14GB）约 28GB（两份 14GB）
调试难度高：训崩了要判断是奖励模型的问题还是 PPO 的问题低：只有一条 loss 曲线要看

上表的显存数按 7B 模型 BF16 权重约 14GB 粗算，只统计权重、不含优化器状态和激活值——实际显存要在此基础上乘几倍，具体取决于并行方案与是否开梯度检查点。但「四份 vs 两份」这个比例关系是稳定的，这才是重点。

显存减半只是表面好处。更大的优势是训练流程的简化：DPO 不需要 on-policy 采样——不用在训练循环中反复让策略模型生成回答，不用维护 rollout 的基础设施，不用处理生成与训练的节奏配合。整个训练过程退化成类似 SFT 的监督学习：读一批偏好数据，算 loss，反向传播，下一个 batch。

这也是为什么 DPO 成为 2024 年之后开源社区对齐的事实标准：它把「对齐」从一个需要 RL 工程团队的项目，变成了一个会跑 SFT 就能上手的任务。参考模型甚至可以进一步省掉——如果策略模型用 LoRA 训练，那么「关掉 adapter 的同一个底座」就是参考模型，两个模型共享一份基座权重，显存再省一半。这是 LoRA + DPO 组合在消费级显卡上如此流行的原因。

工程小技巧 参考模型的输出与训练进程完全无关，因此可以提前离线算好并缓存：遍历一遍数据集，把每条 chosen / rejected 的 $\log \pi_{\text{ref}}$ 存成一列，训练时直接读。这样训练循环里只剩策略模型的两次前向，速度接近翻倍，代价是多一个预处理步骤和一点磁盘空间。注意缓存必须与 tokenizer、对话模板、截断长度严格绑定——任何一项变了都要重算，否则会得到一个静默错误的参考基线。

动手：DPO 损失的最小实现

把公式翻译成代码只有十几行。下面这段是可读性优先的实现，帮助你把每个符号和张量操作对应起来：

import torch
import torch.nn.functional as F


def sequence_logprob(logits, labels, loss_mask):
    """把 token 级 logits 汇总成整条回答的对数概率。

    logits:    (batch, seq_len, vocab)  模型输出，已经右移对齐
    labels:    (batch, seq_len)         目标 token id
    loss_mask: (batch, seq_len)         1 表示属于回答部分，0 表示 prompt 或 padding
    返回:      (batch,)                 每条序列的 log p(y|x)
    """
    logp = F.log_softmax(logits, dim=-1)                    # (b, s, v)
    token_logp = torch.gather(
        logp, dim=2, index=labels.unsqueeze(2)
    ).squeeze(2)                                            # (b, s)
    # 只累加回答部分:prompt 的 token 不参与,padding 也不参与
    return (token_logp * loss_mask).sum(dim=-1)             # (b,)


def dpo_loss(policy_chosen_logp, policy_rejected_logp,
             ref_chosen_logp, ref_rejected_logp, beta=0.1):
    """DPO 损失。四个入参都是形状 (batch,) 的整句对数概率。"""
    # 策略相对参考模型的对数比 —— 这就是 DPO 的"隐式奖励"
    chosen_reward = beta * (policy_chosen_logp - ref_chosen_logp)
    rejected_reward = beta * (policy_rejected_logp - ref_rejected_logp)

    margin = chosen_reward - rejected_reward                # (batch,)
    loss = -F.logsigmoid(margin).mean()

    # 训练监控用的三个量:好/差回答的隐式奖励,以及区分准确率
    metrics = {
        "rewards_chosen": chosen_reward.mean().item(),
        "rewards_rejected": rejected_reward.mean().item(),
        "rewards_margin": margin.mean().item(),
        "rewards_accuracy": (margin > 0).float().mean().item(),
    }
    return loss, metrics

两个容易踩的实现细节，值得单独强调：

  • loss_mask 必须只覆盖回答部分。如果你不小心把 prompt 的 token 也算进 $\log \pi(y|x)$，那么 chosen 和 rejected 共享的那段 prompt 概率会同时出现在两边——理论上做差会抵消，但只要两条样本的 prompt 长度或 padding 位置有任何不一致，就会引入难以察觉的偏差。
  • 不要对 token 数取平均。上面用的是 sum 而不是 mean，这是原始 DPO 的定义：整句的对数概率是各 token 对数概率之和。改成 mean 就变成了长度归一化，那已经是 SimPO 的思路了，两者行为差别很大——用错了你会发现模型对回答长度的偏好完全变了。
不必自己造轮子 上面的代码是为了讲清原理。生产训练建议直接用成熟框架（如 HuggingFace TRL 的 DPOTrainer），它已经处理好了参考模型缓存、LoRA 场景下的 adapter 开关、多种损失变体的切换、以及各类监控指标的记录。具体的参数名与支持的变体列表以官方文档为准，本页不复述可能过时的 API 细节。

只有一个旋钮：$\beta$ 怎么调

DPO 相比 PPO 最舒服的一点是超参极少。真正需要你决策的基本只有两个：学习率和 $\beta$。学习率的经验是比 SFT 再小一个量级（SFT 常用 $2\times10^{-5}$ 量级，DPO 常落在 $5\times10^{-7}$ 到 $5\times10^{-6}$ 之间，具体随模型规模和是否用 LoRA 而变）。$\beta$ 则值得单独说清楚。

$\beta$ 在公式里出现在两个地方，含义是统一的：它是 KL 约束的强度。$\beta$ 越大，同样的对数比变化产生的 margin 越大，损失越快饱和，于是策略越早停止偏离参考模型；$\beta$ 越小，模型越敢跑远。

$\beta$ 取值行为典型症状什么时候选它
偏小（约 0.01–0.05）KL 约束松，策略大幅偏离 SFT偏好指标涨得快，但通用能力（如知识问答、代码）明显掉点；输出风格突变偏好数据量大且质量高，且你确实想让风格发生较大改变
常用默认（约 0.1）平衡点，社区最常见的起手值—不知道选什么就从这里开始
偏大（约 0.3–0.5）KL 约束紧，策略贴近 SFT偏好指标几乎不动，accuracy 长期卡在 0.5 附近偏好数据量少或噪声大，主要目的是「微调风格、别搞坏基座」

调 $\beta$ 的正确姿势不是盲试，而是看隐式奖励曲线：如果 chosen 的隐式奖励很快跑到很大的负值（说明策略把好回答的概率也砍了很多），说明约束太松，加大 $\beta$；如果 margin 长期趴在 0 附近不动，说明约束太紧或学习率太小。

一个高频翻车点 DPO 通常只跑 1 个 epoch，最多 2 个。这跟 SFT 的直觉完全相反。原因见下一节的「概率塌缩」：DPO 的损失在训练集上可以无限下降，多跑几轮几乎必然过拟合到偏好数据的表面特征（比如「更长的回答更好」「带 markdown 列表的更好」），而不是真正的质量差异。如果你的 DPO 训到第 3 个 epoch 还在「进步」，请立刻去看人工样例，那多半不是好消息。

DPO 的失效模式：什么情况下会翻车

DPO 不是银弹。它省掉了奖励模型，但也丢掉了奖励模型提供的「缓冲层」，带来三类独特的失效模式。下面这张状态图把一次 DPO 训练可能经历的阶段画了出来——理想情况是停在「有效分离」，现实中很多训练滑进了后面两个状态还浑然不觉。

问题 1：退化与概率塌缩

DPO 的损失在 $\pi_\theta(y_l|x) \to 0$ 时趋于饱和——一旦差回答的概率被压到极低，$\sigma$ 已经接近 1，梯度就消失了，但训练不会停。模型会继续寻找新的方式来拉大 $y_w$ 和 $y_l$ 的概率差距，而如前面深入块所述，最省力的手段是全局降低所有被观测回答的概率，让概率质量流向未被监督的区域。极端情况下，策略退化成只会输出少数几种模式，或者开始产生重复、截断的输出。

RLHF 的 PPO 不会这样，因为 on-policy 采样会持续暴露退化行为——模型生成出奇怪回答时，奖励模型会给低分，负反馈会把它拉回来。DPO 没有这个闭环：它永远只看那几条固定的离线样本，看不到自己现在真实生成的是什么。

问题 2：离线数据的分布偏移

DPO 用的是离线偏好数据——这些回答是某个旧模型（或人类）生成的，不是当前策略 $\pi_\theta$ 生成的。随着训练进行，$\pi_\theta$ 越来越偏离生成这些数据的分布，偏好标签的准确性也在下降。一个在旧模型上标注「更好」的回答，在当前策略的分布下未必仍然更好；更糟的是，当前策略最可能生成的那些回答，在偏好数据里根本没有出现过，DPO 对它们没有任何约束。

这个问题在实践中有一个明确的缓解方案：迭代 DPO / 在线 DPO。做法是把训练切成若干轮，每一轮开始时先用当前策略对一批 prompt 采样出成对回答，再用一个打分器（可以是奖励模型、可以是更强的 LLM 做 judge、也可以是可验证的规则）给出偏好标签，然后跑一轮 DPO；下一轮再重新采样。这相当于把被砍掉的 on-policy 环节部分补了回来，代价是重新引入了采样基础设施和一个打分器——某种意义上是向 RLHF 回退了半步。

问题 3：对数据质量极度敏感

RLHF 的奖励模型起到了「噪声过滤器」的作用——它在大量偏好数据上训练，学到了一个平滑的奖励函数，个别标注错误会被平均掉，而且它对训练集里没见过的回答也能给出一个泛化的分数。DPO 没有这个中间层，每一条偏好标注都直接变成梯度。标注噪声会一比一地传导到策略上。

更隐蔽的是系统性偏置而非随机噪声。人类标注者（以及 LLM judge）普遍存在几种可预测的偏好：更长的回答、带格式排版的回答、语气更自信的回答。如果你的偏好数据没有控制这些混淆变量，DPO 会非常高效地学会「把回答写长、加列表、语气笃定」，因为这是提升 margin 最省力的路径——而这跟真正的回答质量只有微弱关联。这就是为什么很多 DPO 之后的模型「看起来更专业了但实际没更对」。

常见误区 「DPO 就是 RLHF 的简化版，效果差不多」——不对。DPO 在数据质量高、分布偏移小的场景下可以媲美 RLHF，但在数据噪声大或需要持续探索的场景下，RLHF 的 on-policy 闭环仍然有不可替代的优势。生产环境中，很多团队采用 DPO 做快速迭代、RLHF（或迭代 DPO）做最终对齐的混合策略。把 DPO 当成「省事版 PPO」是错的，它是一个有不同偏差-方差取舍的另一种方法。

DPO 的变体家族：各补一块短板

DPO 的三个失效模式催生了一系列变体。它们共享「免奖励模型」的核心思路，但在损失函数的设计上各有取舍。下面这张思维导图先给全景，再逐个展开。

IPO：用正则化对抗过拟合

IPO（Identity Preference Optimization）针对的是 DPO 的概率塌缩问题。它的观察是：DPO 的损失在偏好数据上可以无限下降（因为 $\sigma$ 函数在输入极大时趋于 1，$\log \sigma$ 趋于 0），这鼓励模型无限拉大好回答和差回答的概率比，最终导致过拟合。特别是当某个 prompt 的偏好标注是「确定性」的（同一对回答总是同一个赢），DPO 的最优解会把 margin 推向无穷大——KL 约束在这种情况下实际上失效了。

IPO 的做法是加一个恒等正则项，把损失改为：

$$\mathcal{L}_{\text{IPO}} = \left(\log \frac{\pi_\theta(y_w|x)}{\pi_{\text{ref}}(y_w|x)} - \log \frac{\pi_\theta(y_l|x)}{\pi_{\text{ref}}(y_l|x)} - \frac{1}{2\beta}\right)^2$$

这是一个回归损失而不是分类损失——它不追求「越大越好」，而是把对数概率差推向一个固定目标 $\frac{1}{2\beta}$。到了目标就停，超过了还会被拉回来。这从结构上阻止了概率比的无限放大，代价是收敛更保守、在数据充足时上限可能不如 DPO。

KTO：从成对偏好到单点标签

DPO 和 IPO 都需要成对偏好数据——同一问题下必须同时有好回答和差回答。这种数据的采集成本高：标注者需要看两个回答再比较，而且两个回答必须来自同一个 prompt。现实中大量已有的数据是单点标签——「这个回答好」或「这个回答差」，比如用户点赞 / 点踩、客服系统的满意度评分、人工审核的通过 / 打回记录。

KTO（Kahneman-Tversky Optimization）的突破在于：它借鉴行为经济学中的前景理论（prospect theory），用单点标签就能训练。损失函数为：

$$\mathcal{L}_{\text{KTO}} = \mathbb{E}_{y_w}\!\left[\log \sigma\!\left(\beta \log \frac{\pi_\theta(y_w|x)}{\pi_{\text{ref}}(y_w|x)} - z_{\text{ref}}\right)\right] + \lambda \, \mathbb{E}_{y_l}\!\left[\log \sigma\!\left(z_{\text{ref}} - \beta \log \frac{\pi_\theta(y_l|x)}{\pi_{\text{ref}}(y_l|x)}\right)\right]$$

其中 $z_{\text{ref}}$ 是参考模型在数据集上的对数概率比的移动平均，起到基线作用——它替代了「成对比较」中另一条回答扮演的角色。好回答推高概率比，差回答压低概率比，但不需要它们成对出现。前景理论的部分体现在两侧可以用不同的权重 $\lambda$：人对「损失」的敏感度高于「收益」，因此在数据不平衡时（比如点踩远少于点赞）可以调这个权重做补偿。

一句话直觉 KTO 用的逻辑是「这个回答好就多生成类似的，差就少生成」——不需要同时看好坏两个版本来比较，只看一个就知道该往哪个方向调。就像你在餐厅吃饭不需要同时吃两盘菜才知道哪盘好吃，一盘好吃你就记住了。它的最大实用价值是让线上日志直接变成训练数据：点赞点踩本来就在数据库里躺着，不需要再花钱做成对标注。

SimPO：扔掉参考模型

SimPO（Simple Preference Optimization）进一步砍掉了参考模型 $\pi_{\text{ref}}$。DPO 系列的所有方法都依赖参考模型来计算 KL——你需要一个冻结的 SFT 模型驻留在显存里，或者至少缓存一遍它的输出。SimPO 的观察是：如果对策略的 log 概率做长度归一化，就可以用一个固定的阈值替代参考模型的比例：

$$\mathcal{L}_{\text{SimPO}} = -\mathbb{E}\!\left[\log \sigma\!\left(\frac{\beta}{|y_w|} \log \pi_\theta(y_w|x) - \frac{\beta}{|y_l|} \log \pi_\theta(y_l|x) - \gamma\right)\right]$$

其中 $|y|$ 是回答的 token 长度，$\gamma$ 是目标裕度（margin）。SimPO 有两个实际好处：

  • 省掉参考模型的显存与前向开销，训练更简单更快。
  • 长度归一化消除了长度偏置。DPO 里，一条回答的对数概率是所有 token 对数概率之和，token 越多这个和就越负——长回答天然「概率更低」。这个纯粹由长度导致的差异会混进 margin 里，让 DPO 的行为对长度敏感。SimPO 除以长度后，比较的是「平均每个 token 的对数概率」，长短回答处在同一量纲上。

代价是：没有了参考模型这个锚点，防止策略跑偏的责任全压在 $\gamma$ 和学习率上，训练的稳定性对超参更敏感。此外「长度归一化」本身也是一种取舍——有些任务里回答长确实意味着信息量大，一刀切归一化会抹掉这个真实信号。

偏好数据从哪来：四种来源与各自的坑

前面反复强调「DPO 对数据质量极度敏感」，那么这些数据具体怎么造？实践中主要有四条路，成本和质量差异巨大。

来源怎么做成本主要风险
人工成对标注同一 prompt 生成两条回答，请标注员选一条高标注员间一致性低；长度 / 格式偏置；规模上不去
AI 反馈（RLAIF）用更强的模型当 judge 给出偏好低继承 judge 的偏见；位置偏置（judge 倾向选第一个）；能力上限受 judge 限制
线上用户信号点赞点踩、重新生成按钮、会话是否继续极低（本来就有）是单点标签不是成对，需用 KTO；信号极稀疏且有幸存者偏差
拒绝采样构对同一 prompt 采 N 条，用验证器 / 奖励模型选出最好和最差配成一对中（算力换标注）依赖打分器质量；N 太小则 chosen 与 rejected 差异不明显

无论哪条路，有三条数据卫生规则值得写进流程：

  • 控制长度混淆。统计一下你的数据集里 chosen 平均长度是不是显著大于 rejected。如果是，DPO 学到的多半是「写长点」。可以做长度分层配平，或至少在评测时把长度作为协变量报出来。
  • 过滤「没有区分度」的对。如果 chosen 和 rejected 质量其实差不多（标注员是随机选的），这条数据不但没用，还会往梯度里注入纯噪声。可以用打分器的分差做阈值过滤，或看标注员的一致性。
  • chosen 必须落在策略的分布内。如果 chosen 是人类精心写的、模型根本写不出来的回答，DPO 试图去抬高一个它几乎不可能生成的序列的概率，效率极低且容易引发前面说的塌缩。这也是为什么「用当前模型自己采样出来的回答做偏好对」通常比「用人类写的黄金答案做 chosen」效果更好——这条经验很反直觉，但在实践中相当稳固。

实践选择：什么时候用 DPO 系，什么时候回到 RLHF

理解了各方法的优劣，选择策略可以归结为一棵决策树：

  • 默认从 DPO 起步：资源消耗低、超参少、效果在大多数场景下够用。开源社区的大量对齐实践都基于 DPO。
  • 数据是单点标签 → KTO：如果你有的是点赞 / 点踩日志而不是成对比较，KTO 是唯一直接可用的选项。
  • 过拟合严重 → IPO：偏好数据量小、训练轮次多时，DPO 容易塌缩，换 IPO。
  • 显存极度紧张 → SimPO 或 LoRA + DPO：前者去掉参考模型，后者让参考模型和策略共享基座权重。
  • 需要持续探索和 on-policy 修正 → 迭代 DPO 或回到 RLHF：如果你的场景中奖励环境会变化（比如用户偏好漂移），或者需要策略主动探索新的回答模式，离线数据无法覆盖这些。

实际生产中，一个常见的混合策略是：先用 DPO 快速迭代验证数据质量，确认偏好信号有效后再投入迭代 DPO 或 RLHF 做精细对齐。这比上来就跑 PPO 的试错成本低得多——毕竟如果你的偏好数据本身就有问题，用什么算法都救不回来，而 DPO 能用最低的成本把这个事实暴露出来。

怎么知道 DPO 训好了：评估的三层

DPO 训练的最大陷阱是自动指标与真实质量脱钩。前面的状态图已经指出，进入「损失饱和」区之后 loss 和 accuracy 还在改善，但模型已经在退化。因此评估必须分三层来看，缺一层都会误判。

层级看什么能发现什么发现不了什么
① 训练内指标loss、margin、accuracy、chosen / rejected 隐式奖励训练是否在跑、是否已饱和、是否配置错误（看第 0 步是否为 0.693）真实生成质量；一切没在训练集里出现的行为
② 通用能力回归知识 / 推理 / 代码等标准基准跑一遍，与 SFT 模型对比对齐税——为了对齐掉了多少基础能力回答风格是否讨喜；是否出现重复退化
③ 生成侧人工 / judge 评测固定一批 held-out prompt，实际生成后做成对比较塌缩、重复、长度膨胀、风格突变成本高，不能每步都做；judge 自身有偏置

一个务实的做法是：训练时每隔固定步数存一个 checkpoint，训完后把这几个 checkpoint 一起做第 ② ③ 层评估，选最好的那个，而不是无脑用最后一步。因为 DPO 的最优 checkpoint 经常不在训练末尾——它在「有效分离」到「损失饱和」的那个转折点附近，而这个点用训练内指标是看不出来的。

展开：DPO 的梯度直觉，以及它为什么会「学不动」

DPO 损失对 $\theta$ 的梯度可以整理成一个很有解释力的形式：

$$\nabla_\theta \mathcal{L}_{\text{DPO}} = -\beta \, \mathbb{E}\!\left[\underbrace{\sigma(\hat{r}_l - \hat{r}_w)}_{\text{权重}} \cdot \left(\nabla_\theta \log \pi_\theta(y_w|x) - \nabla_\theta \log \pi_\theta(y_l|x)\right)\right]$$

其中 $\hat{r} = \beta \log(\pi_\theta / \pi_{\text{ref}})$ 是隐式奖励。这个形式说明两件事：

第一，梯度方向永远是「抬 chosen、压 rejected」，方向是固定的，变化的只有步长。

第二，权重项 $\sigma(\hat{r}_l - \hat{r}_w)$ 是一个自动的样本加权器。当模型把这个样本判错了（差回答的隐式奖励反而更高），括号内为正，$\sigma$ 接近 1，权重大，这条样本被重点学习；当模型已经能很好区分好坏时，括号内是大负数，$\sigma \to 0$，梯度自动衰减。这是一种内建的 curriculum：难样本权重大，已经会的样本自动淡出。

好处很明显：不需要手工设计课程，模型自动聚焦在还没学会的地方。但坏处同样明显：一旦模型对训练数据「记住」了，梯度就消失了，泛化能力不再提升——它没有任何机制去改善那些训练集里没出现的输入上的行为。这就是 DPO 容易在少量数据上过拟合、且「多训几轮也不会更好只会更坏」的梯度层面原因。

对比 PPO 的梯度：PPO 的优势函数 $A$ 是 on-policy 计算的，策略变了 $A$ 就跟着变，梯度不会因为「记住训练数据」而消失，模型始终在自己当前的分布上接受评判。这是 on-policy 方法在探索性上的结构性优势，也解释了为什么迭代 DPO（每轮重新采样）能部分找回这个性质。

要点速查

  • 本质：利用 RLHF 最优策略的闭式解，把奖励函数用策略自身表示，代回 Bradley-Terry 模型后配分函数 $Z(x)$ 相消、奖励模型被消去——偏好数据直接变成策略梯度。
  • 核心公式：$\mathcal{L}_{\text{DPO}} = -\mathbb{E}\!\left[\log \sigma\!\left(\beta \log \frac{\pi(y_w)}{\pi_{\text{ref}}(y_w)} - \beta \log \frac{\pi(y_l)}{\pi_{\text{ref}}(y_l)}\right)\right]$，KL 约束内建在对数比中。
  • 健全性检查：训练第 0 步的 loss 应为 $\log 2 \approx 0.693$。不是这个值说明参考模型或模板配错了。
  • 工程优势：四模型 → 两模型；离线训练不需要 rollout；超参基本只有 $\beta$ 和学习率；LoRA 场景下参考模型可与策略共享基座。
  • $\beta$ 的含义：KL 约束强度。默认从 0.1 起手；掉通用能力就调大，指标不动就调小或检查数据。
  • 只训 1 个 epoch：DPO 损失可以无限下降，多训必过拟合。最优 checkpoint 常在中途而非末尾。
  • 三大失效模式：概率塌缩（只约束差值不约束绝对值，好回答概率也被压低）、离线分布偏移（数据不是当前策略生成的）、数据噪声与偏置敏感（无奖励模型做缓冲，会高效学会「写长写花」）。
  • 变体分工：IPO 换平方损失防塌缩、KTO 用单点标签、SimPO 去参考模型 + 长度归一化、迭代 DPO 补回 on-policy 采样。
  • 数据卫生三条：控制长度混淆、过滤无区分度的对、让 chosen 落在策略自己的分布内。
  • 评估三层：训练内指标（看配置对不对）、通用能力回归（看对齐税）、生成侧评测（看塌缩与风格）。缺一层就会误判。

面试高频问题

Q1：DPO 为什么可以不训练显式奖励模型？

标准回答：在带 KL 约束的偏好优化中，最优策略可以写成参考策略与奖励函数的关系。把这个关系代回 Bradley-Terry 偏好模型后，奖励函数被策略与参考策略的 log-probability ratio 替代，于是可以直接用 chosen/rejected 数据训练策略。

Q2：DPO 的 beta 参数控制什么？

标准回答：beta 控制偏好优化相对参考模型的尺度，也可理解为 KL 约束强度的相关温度参数。beta 太大，策略容易激进、概率塌缩；beta 太小，更新保守，偏好信号不明显。

追问：为什么初始化时 DPO loss 常接近 0.693？

如果策略模型初始等于参考模型，那么 chosen 和 rejected 的 log-ratio 都接近 0，margin 接近 0，损失约为 $-\log\sigma(0)=\log 2\approx0.693$。这是非常实用的实现健全性检查。

Q3：DPO 常见的训练失效模式是什么？

标准回答：包括 chosen 概率也下降、chosen/rejected margin 极端化、长度偏置、离线数据分布偏移和过拟合偏好格式。评估时不能只看训练 loss，还要看胜率、KL、长度、拒答率和通用能力回归。

常见误区：DPO 省掉奖励模型不等于没有奖励偏差；偏差仍可能藏在偏好数据、参考模型和采样分布里。

方法横向对比：从离线偏好到可验证奖励

前面的变体家族按“各自解决什么短板”来讲，这里给出一张可直接用于面试和方案评审的选型表。要特别区分两类问题：DPO/IPO/KTO/ORPO/SimPO 主要学习人类或模型给出的偏好；GRPO 主要利用可计算的奖励（规则验证器、单元测试、数学答案检查器或奖励模型）做在线/半在线探索。GRPO 不是“DPO 的又一个损失函数”，而是另一条需要 rollout 的强化学习训练路线。

一个常见误解是“GRPO 不需要 reward model，所以和 DPO 一样免奖励”。准确说法是：GRPO 不一定需要学习型奖励模型，但必须有奖励来源；在可验证任务中这个来源通常是程序验证器。没有 verifier、RM 或其他可计算反馈时，GRPO 没有优势函数可用，应该优先选择离线偏好方法。

偏好数据卫生：先证明信号可靠，再调损失

偏好数据的第一步不是训练，而是审计。建议按 prompt 分组切分 train/validation，避免同一 prompt 的近重复回答泄漏；同时统计 chosen/rejected 的长度、来源模型、语言、领域和标注者一致性。对每条样本记录一个可复现的 pair_id，便于回溯错误标签。

审计项建议统计危险信号处理动作
长度混淆$\Delta L=\mathrm{len}(chosen)-\mathrm{len}(rejected)$ 的均值、分位数，以及长度分桶后的 chosen 胜率chosen 显著更长；胜率随 $\Delta L$ 单调上升长度分层配平、同长度重采样；评测同时报告平均长度
标签噪声多标注者一致率、judge 交换顺序一致率、重复样本冲突率同一 pair 反复标注结果冲突；换位置后胜负翻转剔除低置信样本；对 judge 做位置随机化和双向评审
区分度两答案的 reward/judge 分差与人工“明显优于”比例chosen 与 rejected 几乎相同或均不可用设最小分差阈值；增加 hard negative 而不是重复 easy pair
来源偏差按生成模型、领域、语言、模板分组统计模型只在某个来源或模板上提升分层采样、去重、留出跨来源验证集
分布覆盖prompt 长度、任务类型、拒答/安全样本占比训练集窄，线上 prompt 不在覆盖范围混入 on-policy 样本；对关键领域单独设回归集

长度偏置尤其容易被忽视。原始 DPO 使用序列 log-probability 的求和，长度越长数值通常越负；但如果标注者又偏好更长、更完整的回答，优化器会同时面对“长回答的概率惩罚”和“标签要求更长”两个相反信号，最终可能通过模板化填充来取巧。不要只看全局平均长度，应画出 $\Delta L$ 与 margin、win rate 的散点或分桶曲线；若控制长度后胜率明显回落，说明模型学到的是长度代理而非质量。

面试回答模板：把“会背公式”讲成“会做决策”

Q4：为什么说 DPO 不是无损的 RLHF？

标准回答：DPO 不是把 RLHF 完整等价地搬到监督学习里，而是在 Bradley-Terry 偏好模型、KL 参考策略、离线数据和策略最优解等假设下，得到一个可优化的替代目标。它省掉了显式 reward/value model 与 on-policy rollout，因此降低了工程成本，但也失去了奖励模型的平滑、在线探索和对当前策略分布的反馈。离线标签噪声、长度偏置和分布偏移会直接进入梯度；所以 DPO 是不同 bias-variance 与探索-稳定性取舍的方法，不是“零损失压缩版 PPO”。

Q5：如何选择 DPO、IPO、KTO、ORPO、SimPO 和 GRPO？

标准回答：先看反馈形态和是否可验证：有成对偏好且数据质量尚可，先用 DPO；数据少或 DPO margin 无限制增大，用 IPO；只有点赞/点踩单点标签，用 KTO；希望 SFT 与偏好单阶段完成且不维护 reference，可试 ORPO；显存受限或长度偏置突出，用 SimPO；有数学/代码 verifier、需要当前策略持续探索时用 GRPO。最后用 held-out win rate、KL、长度和通用能力回归共同选 checkpoint，而不是只看训练 loss。

Q6：DPO 训练 loss 下降但效果变差，你怎么排查？

标准回答：我会按顺序检查第 0 步 loss 是否约为 0.693、reference/cache 与 tokenizer/template/mask 是否一致；再比较 train/valid margin 和 win rate，确认是否过拟合或数据泄漏；随后看 chosen/rejected 的绝对 reward、KL、长度分布和拒答率，识别概率塌缩或长度代理。处理上优先早停、降低学习率/epoch、提高 $\beta$、加 NLL 正则并清理噪声 pair，最后用独立 prompt 做人工和自动评测。

发展脉络

DPO 将 RLHF 的偏好优化改写为 reference policy 上的分类式目标，随后出现 IPO、KTO、ORPO 等降低 reference 或偏好数据要求的方法。

机制抓手

核心 logit=beta*((log pi(y+)-log ref(y+))-(log pi(y-)-log ref(y-)))；只对 response token 求和，prompt token 不应进入偏好差。

工程权衡

beta、长度归一化、偏好噪声和 reference 漂移会改变梯度；margin 过大时 sigmoid 饱和，过拟合数据偏好。

前沿观察

在线偏好、拒绝采样和 verifier preference 正在与 SFT/RLVR 合流，离线 DPO 仍需检查分布外行为。
