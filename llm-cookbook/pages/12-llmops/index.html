工程化与运维

把 demo 变成能长期运行的线上系统:看得见、改得动、算得清、拦得住。这一层的失败模式通用 APM 全都发现不了。

本篇共 5 个知识点进阶 5。左侧可按难度筛选。
01 可观测性与全链路追踪 端到端 trace 记录输入、渲染后 prompt、模型与版本、token 数、延迟、每次工具调用与检索、最终输出;质量分 / p95 延迟 / 错误与拒答率 / 每请求成本是四个能提前预告事故的生产信号。与离线评估的分工一句话:离线比模型,线上比昨天 进阶 02 Prompt 版本管理与评估门禁 改一次 prompt 就是一次发布:prompt registry 把提示、变量与模型 pin 当作一个版本化单元,golden set 配 LLM-as-Judge 做回归,canary 5% 流量与影子模式先行,失败即阻断;供应商静默换模型版本同样按 canary 对待 进阶 03 推理成本工程 按工作流 / 租户 / 用户 / 发布版本四维归因;系统提示、对话历史、RAG 上下文、重排、重试与 fallback 路由共同推高账单,只按模型报价算必然算不准;语义缓存与前缀缓存的真实收益。与 serving-cost 的分工一句话:效率篇讲怎么让它快,运维篇讲怎么让它不烧钱 进阶 04 RAG 生产运维 三条 RAG 里负责「让它跑三个月不烂掉」的一条。陈旧 embedding(源文档更新而向量库没刷,模型自信地答旧信息)、检索噪声、上下文溢出三类失效各需不同监控信号;chunk 策略版本化,以及 embedding 模型迁移时的静默掉点与向量库治理 进阶 05 护栏与输出校验 入口拦提示注入,出口过 PII、毒性与越权内容,并强制输出 schema;校验失败必须 fail closed,而不是把脏数据放进下游状态。这是安全四方里的运行时组件侧:线上那道可插拔的闸门。训练侧见 safety-alignment,执行侧见 agent-safety,攻方与测评侧见 safety-redteam 进阶
