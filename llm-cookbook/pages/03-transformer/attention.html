注意力机制

为什么一句话里的每个词都要「回头看」别的词？注意力就是让模型学会：预测当前位置时，该给上下文里每个词分配多少关注。它是整个 Transformer 时代的第一块基石。这一节从 RNN 的痛点讲到 QKV 的直觉，从缩放点积公式讲到两条优化路线，配上完整代码和逐图讲解。

一图看懂

注意力做的事只有一句话：用一个查询（Query）去匹配所有的键（Key），按匹配度加权汇总对应的值（Value）。就像你带着问题去图书馆——先看每本书的标签（Key）跟你的问题（Query）有多相关，再按相关度决定从每本书（Value）里抄多少内容。

为什么需要注意力：RNN 的两个硬伤

在 Transformer 之前，处理序列靠的是 RNN/LSTM：一个词一个词按顺序读，把「记忆」压缩进一个固定大小的隐状态里向后传。这带来两个硬伤：

  • 长依赖丢失：句子开头的信息传到结尾时，往往已经被稀释甚至遗忘。
  • 无法并行：第 t 步必须等第 t-1 步算完，训练慢，吃不满 GPU。

注意力换了个思路：不再顺序传递记忆，而是让每个位置直接「看到」序列里所有其他位置。任意两个词之间的距离都是 1 跳，长依赖不再衰减；而且所有位置可以一次性并行计算。

一句话直觉 RNN 是「传话游戏」，信息越传越糊；注意力是「开全体大会」，每个词都能直接跟所有词对话。前者信息会衰减，后者不会——但后者每个人都要跟所有人说话，所以人数一多就爆炸（$O(n^2)$ 复杂度）。

QKV：同一个词的三重身份

注意力把每个输入词向量通过三个不同的线性变换，投影成三个角色。这是理解注意力的关键——同一个词，同时扮演三种身份：

Query 查询

当前词「想问的问题」。拿它去和所有词的 Key 匹配，决定该关注谁。

Key 键

每个词对外展示的「标签/索引」，用来被 Query 检索、打相关度分。

Value 值

每个词真正携带的「内容」。按注意力权重加权求和，得到输出。

用一个例子体会：在句子 "The animal didn't cross the street because it was too tired" 中，当模型处理 it 时，it 的 Query 会和 animal、street 等词的 Key 打分，发现和 animal 最相关，于是主要从 animal 的 Value 里取信息——模型由此「理解」了 it 指代 animal。

缩放点积注意力：四步公式

把上面的直觉写成公式，就是 Transformer 采用的缩放点积注意力（Scaled Dot-Product Attention）：

$$\text{Attention}(Q, K, V) = \text{softmax}\!\left(\frac{QK^\top}{\sqrt{d_k}}\right)V$$
步骤运算含义形状
① 打分$QK^\top$每个 Query 和每个 Key 做点积，得到相关度分数矩阵$(n, d) \times (d, n) \to (n, n)$
② 缩放$\div \sqrt{d_k}$除以维度的平方根，防止点积过大导致 Softmax 梯度消失$(n, n)$
③ 归一$\text{softmax}$把每一行分数变成和为 1 的权重分布$(n, n)$
④ 加权$\times V$用权重对所有 Value 加权求和，得到融合上下文的新表示$(n, n) \times (n, d) \to (n, d)$
展开：为什么要除以 √dₖ？

假设 Query 和 Key 的每个分量都是均值 0、方差 1 的独立随机变量，那么它们的点积 $q \cdot k = \sum_{i=1}^{d_k} q_i k_i$ 的方差会是 $d_k$。

当 $d_k$ 较大（比如 64、128），点积的数值范围会变得很大。Softmax 在输入值很大时会变得极度「尖锐」——几乎把全部权重压给一个位置，其余位置权重趋近 0，导致梯度趋近于 0，训练无法进行。

除以 $\sqrt{d_k}$ 正好把方差重新拉回到 1 量级，让 Softmax 保持在梯度健康的区间。这就是「缩放」二字的由来。

展开：最小代码实现（PyTorch 风格） 
import torch
import torch.nn.functional as F

def scaled_dot_product_attention(Q, K, V, mask=None):
    """
    Q, K, V: 形状 (batch, seq_len, d_k)
    返回:    (batch, seq_len, d_k)
    """
    d_k = Q.size(-1)

    # ① 打分 + ② 缩放
    scores = Q @ K.transpose(-2, -1) / (d_k ** 0.5)   # (batch, seq, seq)

    # 因果掩码:让每个位置只能看到自己和之前的词
    if mask is not None:
        scores = scores.masked_fill(mask == 0, float('-inf'))

    # ③ 归一化为权重
    weights = F.softmax(scores, dim=-1)               # (batch, seq, seq)

    # ④ 对 Value 加权求和
    output = weights @ V                               # (batch, seq, d_k)
    return output, weights

整个注意力的核心逻辑，就是这几行矩阵运算。真正的复杂度来自多头拆分、位置编码和高效实现（如 FlashAttention），但数学骨架不变。

除以 √d_k 的数值算例：点积的方差是怎么涨起来的

前面说了「不缩放会导致 Softmax 梯度消失」，但这句话到底意味着什么？与其停留在定性描述，不如把数字代进去算一遍。

假设训练初期 Query 和 Key 的每个分量都近似服从均值 0、方差 1 的分布（这是随机初始化后的常见情况），那么两个向量的点积 $q \cdot k = \sum_{i=1}^{d_k} q_i k_i$ 是 $d_k$ 个独立乘积之和。每个乘积的期望是 0，而两个方差为 1 的独立变量相乘，乘积的方差仍约 1，于是整个点积的方差是 $d_k$，标准差是 $\sqrt{d_k}$。也就是说，点积的典型大小会随维度一起涨：$d_k = 64$ 时标准差已经到 8，$d_k = 128$ 时约 11.3。

为了看清这个「涨」带来的后果，构造一个小例子。设 $d_k = 4$，某一行 Query 与四个 Key 算出的原始分数如下：

步骤分数 1分数 2分数 3分数 4
原始点积（未缩放）3.51.0-0.5-2.0
除以 $\sqrt{4} = 2$ 之后1.750.5-0.25-1.0

先看未缩放这行。对分数 $[3.5, 1.0, -0.5, -2.0]$ 做 Softmax，指数分别是 $e^{3.5} \approx 33.1$、$e^{1.0} \approx 2.72$、$e^{-0.5} \approx 0.61$、$e^{-2.0} \approx 0.135$，四项之和约 36.6，归一化后权重是 0.905、0.074、0.017、0.004——第一个位置拿走了 90.5% 的注意力，其余三个位置加起来不到 10%。

再看缩放后这行。对分数 $[1.75, 0.5, -0.25, -1.0]$ 做 Softmax，指数分别是 $e^{1.75} \approx 5.75$、$e^{0.5} \approx 1.65$、$e^{-0.25} \approx 0.78$、$e^{-1.0} \approx 0.37$，四项之和约 8.55，权重变成 0.673、0.193、0.091、0.043。同样是这组数据，缩放后第二个位置从 7.4% 涨到了 19.3%。

缩放改变的到底是什么 缩放并没有改变排名——3.5 依然最大。它改变的是分布的形状：把「几乎全部押注一个位置」变成「几个位置都有机会」。权重太尖的后果是大多数位置的梯度接近 0，模型学不到东西；而且 $d_k$ 越大，原始点积越尖，所以必须用 $\sqrt{d_k}$ 把方差拉回 1 的量级。$\sqrt{d_k}$ 不是拍脑袋定的缩放因子，而是方差推导给出的精确答案——方差是 $d_k$，标准差是 $\sqrt{d_k}$，除以标准差就是把分布重新归一化到单位尺度。

换一个角度记住这个结论：注意力分数的量级决定 Softmax 的「锐利程度」，而 Softmax 的锐利程度决定梯度的健康程度。缩放因子 $\sqrt{d_k}$ 保证的是，无论模型把注意力头维度设成 64 还是 128，初始阶段注意力分布的形状都大致一致——这让 $d_k$ 这个超参对训练稳定性的影响被削掉了。这也是为什么你几乎会在每一个 Transformer 实现里看到这一行，却很少有人注意到它。

Softmax 温度：注意力分布的锐化旋钮

Softmax 的输入前面还可以挂一个旋钮——温度 $T$。带温度的 Softmax 写作 $\text{softmax}(x_i / T)$：$T < 1$ 时分数被放大，分布更「锐」；$T > 1$ 时分数被压缩，分布更「平」；$T = 1$ 就是标准情形。虽然训练时几乎总是用 $T=1$，但理解这个旋钮，能帮你把「注意力分布的形状」这件事彻底想明白。

用数字说话。设某一行有三个位置的原始分数 $[2.0, 1.0, 0.0]$，依次代入不同温度：

温度 $T$除以 $T$ 后的分数位置 1 权重位置 2 权重位置 3 权重
$0.5$$[4.0, 2.0, 0.0]$0.8670.1170.016
$1.0$$[2.0, 1.0, 0.0]$0.6650.2450.090
$2.0$$[1.0, 0.5, 0.0]$0.5070.3070.186
$5.0$$[0.4, 0.2, 0.0]$0.4020.3290.269

看第一行：$T = 0.5$ 时第一名拿到 86.7%，几乎一票定音；到 $T = 5$ 时只剩 40.2%，三个位置都「有得聊」。温度越低，注意力越像非此即彼的硬选择；温度越高，越像雨露均沾的软加权。极限情况：$T \to 0$ 时 Softmax 退化成取最大值，$T \to \infty$ 时退化成均匀分布。温度变化直接对应前一小节说的「锐利程度」——它给了我们一个旋钮，可以在同一组分数上任意调整分布形状。

温度在哪里真的有用？至少三个地方。其一，知识蒸馏：让学生模型学教师模型的输出概率时，通常把温度调高（如 $T = 2$ 到 $4$），让教师输出的第二名、第三名也给出足够信号，学生才能学到类间的细粒度差异。其二，调试注意力：如果怀疑某层注意力出现病态的尖峰（几乎所有权重压在一个位置），可以临时调高温度观察分布是否回到合理范围，用来排查数值或训练问题。其三，长上下文扩展：YaRN 等 RoPE 扩展方法会引入一个注意力缩放因子（本质就是调整有效温度），补偿插值后注意力分布变平的趋势——这一点在长上下文技术里会再次遇到。

别混淆：注意力温度 ≠ 采样温度 生成时说的「temperature sampling」作用在词表上的 logits，决定采样时概率分布的尖锐程度；本节说的温度作用在注意力分数上，决定每个位置拿到的权重。两者都叫 temperature，但一个在注意力 Softmax 里、一个在采样器里，是完全不同的两处旋钮，不要混为一谈。

掩码注意力：解码时怎么做到「不偷看未来」

自回归模型在预测第 $t$ 个位置时，只能依赖它左边（包括自己）的词，绝不能看到右边的未来词——否则训练和推理就「作弊」了：模型永远有标准答案可抄，学不到真正的生成能力。把这条纪律写进注意力，就是一张因果掩码（causal mask）。

实现上只有一步：在 Softmax 之前，把未来位置对应的分数填成 $-\infty$。因为 $e^{-\infty} = 0$，这些位置在 Softmax 之后权重恰好是 0，等于「假装它们不存在」。以 4 个 token 的序列为例，掩码矩阵是严格的下三角：

（行 = 当前位置，列 = 可看位置）词 1词 2词 3词 4
词 1可见掩掉掩掉掩掉
词 2可见可见掩掉掩掉
词 3可见可见可见掩掉
词 4可见可见可见可见

训练时整条序列并行前向，一张下三角掩码一次性作用在所有行上——这正是前面最小实现里 scores.masked_fill(mask == 0, float('-inf')) 那一行做的事。几个实现细节值得记住：

  • 为什么用 $-\infty$ 而不是直接置 0：把分数设成 0 意味着「相关度为 0」，但 Softmax 之后这些位置仍会分到权重（因为 $e^0 = 1$），信息照样泄漏。只有 $-\infty$ 才能让 Softmax 输出严格为 0。
  • 别让整行都被掩掉：因果掩码保证每行至少对角线可见，Softmax 的分母恒大于 0。如果某个位置连自己都不能看，分子分母同时趋 0，会得到 NaN。
  • 掩码填在缩放之后、Softmax 之前：顺序是打分 → 除以 $\sqrt{d_k}$ → 填 $-\infty$ → Softmax。$-\infty$ 在指数函数下是 0，顺序上其实怎么放都对，但统一在 Softmax 前处理最清晰。

推理 Decode 阶段则是另一副面孔：每生成一个新 token，只需拿它一个 Query 去和缓存里的历史 K/V 打分，未来词根本还没生成，不需要掩码——这恰恰是 KV Cache 能成立的先决条件。换句话说，掩码是训练期的纪律，缓存是推理期的红利，它们描述的是同一个「只看左边」的约束：训练时用掩码保证不偷看，推理时用缓存保证不重算。

自注意力 vs 交叉注意力

根据 Q、K、V 来自哪里，注意力分成两种常见形态：

类型Q 来源K / V 来源典型场景
自注意力 Self-Attention当前序列同一序列让序列内部各词互相理解（GPT/BERT 主力）
交叉注意力 Cross-Attention解码器序列编码器序列翻译时让目标语言「看」源语言（Encoder-Decoder）

O(n²) 代价：注意力的阿喀琉斯之踵

标准注意力要计算 $n \times n$ 的分数矩阵——这意味着序列长度翻倍，计算量和显存都翻四倍。这就是长上下文的最大瓶颈：

复杂度提醒 标准注意力要计算 $n \times n$ 的分数矩阵，时间和显存都是 序列长度的平方 $O(n^2)$。这正是长上下文的最大瓶颈，催生了后续 GQA、MLA、稀疏注意力、KV Cache 等一系列优化。

两条优化路线：改算法 vs 改实现

知道了 $O(n^2)$ 这个瓶颈，后续所有优化都能归到两条互相正交的路线上。很多人把它们混为一谈，但它们解决的根本不是同一个问题：

路线解决的问题做法输出是否改变
注意力变体
MQA / GQA / MLA / 稀疏注意力		 算什么 改变算法本身：共享 K/V、低秩压缩、只算部分位置 会变 —— 是近似，用可接受的精度损失换效率
FlashAttention

一句话记住 变体是换一种算法，FlashAttention 是换一种搬数据的方式。前者有精度取舍，后者没有——所以后者已经成为几乎所有主流框架的默认后端，而前者需要在模型设计阶段就做决策。两者可以叠加使用。

注意力在 Transformer 中的位置

注意力不是孤立存在的——它是 Transformer 层的核心组件之一，和 FFN、残差连接、层归一化配合工作：

注意力和 FFN 的分工很清晰：注意力让词与词互相理解（跨位置信息交换），FFN 让每个词的表示更丰富（逐位置非线性变换）。只靠注意力没有 FFN，模型缺乏非线性能力；只靠 FFN 没有注意力，词与词之间无法交流。这就是为什么 Transformer 层总是「注意力 + FFN」成对出现。

注意力的失败模式：尖峰、坍塌与「不可解释」

注意力机制并不总是「优雅地」工作。知道它有哪些典型故障，对排查训练问题和读懂注意力可视化都很有帮助。至少三种失败模式值得记住：

  • 注意力尖峰（attentional spike）：某一行的权重几乎全部压在一个位置——比如一个特殊的开头 token（BOS 或分隔符）常年拿走一半以上的权重。2023 年的研究发现，这几乎是所有自回归模型的普遍现象，被称为「注意力汇聚」（attention sink）：模型发现在开头位置存一个「安全缓存」，把用不上的信息都堆进去。它本身不一定是坏事，但如果尖峰严重到挤占了真正相关的信息，就要警惕。
  • 注意力坍塌（attention collapse）：训练不稳时，多个头可能收敛到几乎相同的注意力分布——头与头之间不再有分工，多头的「多视角」红利消失。常见诱因是学习率过大、初始化不当或归一化设置不对。缓解手段包括更稳的初始化、层丢弃（layer drop）以及把学习率调小。
  • 可视化 ≠ 解释：很多人把注意力热力图当作「模型在思考什么」的证据，这个直觉要打折。权重高可能只是统计惯性的结果（比如总是看相邻词），并不代表模型在因果上依赖这个词。要真正回答「模型为什么这么预测」，需要干预实验（把某个词的表示改掉、看预测变不变），而不是盯着权重看。

把这三种失败模式放在一起看，能得出一个务实的结论：注意力分布是模型训练出来的统计产物，而不是人为设计的解释工具。理解它有助于调试，但别把它神化。这也是为什么现代研究更多关注注意力「在哪一层、以什么模式被使用」，而不是单张热力图。

一个相关的工程细节是，「注意力汇聚」还与 KV Cache 压缩、流式生成有关：既然开头 token 吸收了那么多注意力，粗暴地删掉它会对后续生成造成不成比例的影响，所以在做流式 KV 淘汰时要格外小心保留开头位置——这也是 KV Cache 优化里的一个已知陷阱。

作为小结，给初学者一个务实的检查清单：训练时如果发现 loss 震荡剧烈或注意力权重异常集中，先看是不是学习率过大、再看归一化和初始化；阅读别人画的热力图时，先确认画的是哪个头、哪一层、哪个 token 的行为，再下结论；复现模型时，注意注意力实现里缩放、掩码、多头拼接的顺序有没有一致。注意力机制本身很简单，复杂的往往是对它的使用和解读——把这三个失败模式记在心里，能帮你少走很多弯路。

要点速查

  • 本质：Query 检索 Key，按相关度对 Value 加权求和。让每个位置直接「看到」所有其他位置。
  • 为什么取代 RNN：任意距离 1 跳直连（解决长依赖）+ 完全并行（吃满算力）。RNN 是传话游戏，注意力是全体大会。
  • QKV：同一个词通过三个权重矩阵投影成三个角色——Query（我想问什么）、Key（我的标签）、Value（我的内容）。三个矩阵是学习的。
  • 公式：$\text{softmax}(QK^\top / \sqrt{d_k})\,V$，四步——打分、缩放、归一、加权。
  • 缩放：除 $\sqrt{d_k}$ 是为了稳住 Softmax 的梯度——点积方差随 $d_k$ 增长，不缩放会导致梯度消失。
  • 自注意力 vs 交叉注意力：Q/K/V 来自同一序列（自注意力）还是不同序列（交叉注意力）。
  • 代价：$O(n^2)$ 复杂度，长序列开销大。序列从 512 到 32768，计算量增 4096 倍。
  • 两条优化路线：注意力变体（改算法，输出会变）vs FlashAttention（改实现，输出不变）。可叠加。
  • 在 Transformer 中的角色：注意力负责跨位置信息交换，FFN 负责逐位置非线性变换。两者成对出现。

面试高频问题

Q1：为什么 Attention 要除以 $\sqrt{d_k}$？

标准回答：如果 Query 和 Key 的各维度方差约为 1，点积的方差会随维度 $d_k$ 增长。分数过大后，Softmax 会变得极尖锐，几乎只保留一个位置，其他位置的梯度接近 0。除以 $\sqrt{d_k}$ 可以把分数尺度拉回稳定范围。

追问：为什么不能只说“防止数值溢出”？

数值溢出只是表面现象，真正重要的是梯度和优化尺度。即使实现使用了数值稳定的 Softmax，大幅分数仍会让概率分布饱和，导致学习信号集中在极少数位置。面试中最好同时说出“方差随 $d_k$ 增长”和“Softmax 梯度变小”两个因果环节。

Q2：为什么说 Attention 能替代 RNN？它是不是所有方面都更好？

标准回答：训练时 Attention 可以让所有位置并行计算，任意两个 token 之间只需一跳信息交互，缓解长依赖和串行计算问题。但它要构造 $n\times n$ 的关系矩阵，时间和显存复杂度是 $O(n^2)$；序列很长时，RNN 的线性扫描反而可能更省资源。

常见误区：不要把“并行”说成“推理也能完全并行”。Decoder-only 的生成仍然受因果约束，通常是逐 token Decode；并行优势主要体现在训练和 Prefill。

Q3：因果 Mask 应该放在哪里？把未来位置填 0 可以吗？

标准回答：Mask 应在 Softmax 之前作用于注意力分数，把未来位置填成负无穷或该 dtype 的最小值，再做 Softmax。不能填 0，因为 0 仍会产生非零概率。

scores = scores.masked_fill(future_mask, torch.finfo(scores.dtype).min)
weights = torch.softmax(scores, dim=-1)

面试追问：Softmax 通常沿最后一维做，因为最后一维对应当前 Query 对所有 Key 的候选位置；沿错维度会破坏“每行权重和为 1”的语义。

Q4：注意力权重能不能直接当作模型的可解释性？

标准回答：不能直接等同。注意力权重描述的是信息汇聚时的加权关系，但不一定是输出对某个 token 的因果依赖。要验证解释，需要做遮挡、激活干预或输入替换等实验，再观察预测是否改变。

追问：为什么一个高权重 token 可能并不重要？

不同头、不同层的表示会经过残差、FFN 和后续层继续变换；某个位置虽然被读取很多，但它的 Value 可能被后续线性组合抵消。反过来，低权重位置也可能通过其他路径影响结果。因此热力图适合做调试线索，不适合单独作为因果证明。

Q5：请手推一次 Attention 的 shape、复杂度和显存账本

先统一符号：批大小为 $B$，序列长度为 $S$，当前 Query 长度为 $T_q$，Key/Value 长度为 $T_k$，模型宽度为 $d_{model}$，Query 头数为 $H$，每头维度为 $d_h=d_{model}/H$，KV 头数为 $H_{kv}$。这套符号与 Transformer 原论文 的多头拆分一致。

张量/账本Prefill（一次喂入 $S$ 个 token）Decode（每次生成 1 个 token）面试要点

手推顺序：先写 $Q:(B,H,T_q,d_h)$、$K^T:(B,H,d_h,T_k)$，所以 $QK^T:(B,H,T_q,T_k)$；再乘 $V:(B,H,T_k,d_h)$，输出回到 $(B,H,T_q,d_h)$，最后 transpose+concat 回 $(B,T_q,d_{model})$。训练时 $T_q=T_k=S$，Decode 时 $T_q=1$、$T_k=S_{cache}+1$。反向传播通常是同阶甚至更高的计算量，且要保存中间激活；推理若启用 KV Cache，则不重复计算旧 token 的 K/V。

一句话账本 Prefill 是“宽而平方”：一次算完整 $S\times S$；Decode 是“窄而线性”：每个新 Query 扫过历史 KV。FlashAttention 主要省显存读写和峰值，不会把精确注意力的理论算术复杂度从 $O(S^2)$ 变成线性；KV Cache 则主要省重复的 K/V 投影计算和带宽。

Q6：causal mask、数值稳定 Softmax 和 attention dropout 怎么追问？

因果 mask：在 Softmax 前将未来位置加上 $-\infty$（或该 dtype 的最小有限值），使其概率为 0；填 0 只表示“分数为 0”，仍会产生非零概率。对角线必须可见，否则整行全被 mask 会产生 NaN。PyTorch 的参考实现和参数语义见 scaled_dot_product_attention 文档。

数值稳定：对每一行 logits $z$ 先减最大值 $m=\max_i z_i$，再计算 $p_i=\exp(z_i-m)/\sum_j\exp(z_j-m)$。减去同一个常数不改变 Softmax 结果，却避免 $\exp(z)$ 溢出；实现时还要确认 mask、dtype 和 Softmax 维度一致。可对照 PyTorch Softmax 文档。

Dropout：attention dropout 应作用在 Softmax 后的权重上（不是 Q/K/V 上），训练态随机丢弃部分边并做 inverted scaling $\tilde A=mask\odot A/(1-p)$；评估/推理态必须关闭。使用 PyTorch SDPA 时，dropout_p 不会自动读取模块是否在 eval，调用方应显式传 $0.0$，这是官方文档特别提醒的坑。

scores = (Q @ K.transpose(-2, -1)) * (d_h ** -0.5)
scores = scores.masked_fill(~causal_mask, torch.finfo(scores.dtype).min)
weights = torch.softmax(scores, dim=-1)       # 行方向归一化
weights = torch.dropout(weights, p=dropout_p, train=is_training)
out = weights @ V
追问：为什么 dropout 不能放到 mask 之前随便做？

mask 的语义是“不可达边”，应在归一化前把它们从候选集合中移除；dropout 的语义是训练时随机稀疏化已归一化的概率边。两者混用可能让被禁止的位置重新获得概率，或改变行归一化语义。工程实现以 PyTorch 官方伪代码 为准。

Q7：MHA、MQA、GQA、MLA 怎么选？

先看 KV 头数：MHA 每个 Query 头拥有独立 K/V；MQA 的所有 Query 头共享一组 K/V；GQA 将 Query 头分成 $G$ 组、每组共享一组 K/V；MLA 则把 KV 状态压到低维 latent，再在需要时恢复/解耦位置表示。原始定义分别见 MQA、GQA 和 DeepSeek-V2 MLA。

方案$H_{kv}$ / Cache 规模优点代价与选型追问
MHA$H$，基线 100%每个头有独立 K/V，表达能力和兼容性最直接KV Cache、Decode 带宽最大；适合质量优先或已有模型兼容
MQA$1$，约 $1/H$极省 Cache，Decode 读带宽低共享 K/V 可能损失质量；需评估长上下文和任务退化
GQA$G$，约 $G/H$在质量与 Cache/带宽之间折中，可由 MHA checkpoint 分组转换多一个分组超参；$H$ 必须能被 $G$ 整除
MLAlatent 维度决定，非简单按头复制进一步压缩 KV，兼顾高效推理与位置编码设计实现与 checkpoint 结构更复杂，需配套训练；不能把它当作“免费 MQA”

选型模板：先问瓶颈是显存容量、Decode 带宽还是训练吞吐；若只想降低推理 Cache，优先 GQA/MQA；若接受更大架构改造并追求更高压缩比，再看 MLA；若瓶颈是 HBM 读写而不是算法输出，叠加 FlashAttention。注意力变体的实现与更多边界见 attention-variants，KV 账本见 kv-cache。

Q8：RoPE 为什么有效，长上下文外推为什么会坏？

核心回答：RoPE 将每个二维子空间中的 $q,k$ 按位置角度旋转，再做点积；旋转后 $q_m^T k_n$ 依赖相对位移 $m-n$，因此把位置信息直接注入注意力分数，而不额外增加可学习位置表。原始推导见 RoFormer: Enhanced Transformer with Rotary Position Embedding。

外推追问：模型只在长度 $L_{train}$ 的位置频率上训练，推到远大于 $L_{train}$ 时，旋转相位分布和训练分布不匹配，可能导致注意力错位、困惑度升高。常见办法是位置插值或频率缩放（如 YaRN、LongRoPE），但会改变有效分辨率，通常需要校准/微调；不要笼统地说“把 max_position_embeddings 改大就行”。可查 YaRN、LongRoPE 以及本站的长上下文技术。

  • 频率/基底问题：检查 RoPE base、缩放因子、训练与推理的 position_ids 是否一致。
  • 长度问题：区分“模型支持的最大长度”“训练过的长度”和“评测长度”，三者不是同一个数字。
  • 系统问题：RoPE 改善的是位置表示，不会消除 $O(S^2)$；仍要结合 KV Cache、GQA 或 FlashAttention。

Q9：FlashAttention 和稀疏/近似注意力的边界是什么？

一句话：FlashAttention 是“数学不变、IO 重排”：通过 tiling、片上 SRAM 和 online softmax，不把完整 $S\times S$ 分数/概率矩阵写回 HBM，仍计算精确的全注意力；论文明确将其定义为 IO-aware exact attention，见 FlashAttention。它降低的是显存峰值与内存访问，不改变全连接注意力的 $O(S^2)$ 算术依赖。

边界：稀疏、局部、低秩或线性注意力改变了要计算的边集合/核函数，因此可能降低理论复杂度，但输出不再等于标准全注意力，存在质量、长程依赖或任务分布取舍。BigBird 的稀疏模式可作为代表性对照，见 Big Bird。面试时不要说“FlashAttention 是稀疏注意力”，也不要说“用了 FlashAttention 就把 $O(n^2)$ 变成 $O(n)$”。

发展脉络

Bahdanau 注意力解决固定长度向量瓶颈，Transformer 改成全并行 scaled dot-product attention；FlashAttention 又把瓶颈从 FLOP 转向 HBM IO。

机制抓手

对 X 做 Q=XWq、K=XWk、V=XWv，计算 softmax(QK^T/sqrt(d))V；因果 mask 后第 i 行只能读 j<=i，朴素实现保存 O(n^2) 分数矩阵。

工程权衡

head_dim、GQA/MQA、mask 形状和 dtype 会决定 kernel 是否融合；长上下文中减少 KV 头数常比盲目降精度更直接。

前沿观察

FlashAttention-2/3、滑窗和稀疏注意力分别从调度、Tensor Core 与稀疏模式降低 IO，必须按长度和硬件复测。
