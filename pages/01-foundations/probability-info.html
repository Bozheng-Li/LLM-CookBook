入门

概率与信息论

语言模型本质上不输出文字，而是输出「下一个词的概率分布」。熵、交叉熵、KL 散度和困惑度，就是用来衡量这种概率分布「有多确定」「有多准」「和真实差多远」的四把尺子。不懂这套尺子，就看不懂训练 loss 为什么长那样，也说不清 temperature 到底在调什么、为什么两个模型的 PPL 不能直接比。这一节全部用能手算的小数字把它们坐实。

一图看懂

一句话串起来：熵量「真实分布本身有多不确定」，交叉熵量「用我的预测分布去编码真实分布要付多少代价」，KL 散度量「我的预测和真实差多远」，困惑度是交叉熵的指数化，直觉是「模型相当于在多少个候选里纠结」。四者之间只有一条恒等式：交叉熵 = 熵 + KL 散度。

概率分布：模型如何表达「不确定」

大模型每生成一个 token 前，其实是在词表上给每个候选 token 打了一个分数（logits），经 softmax 归一成一组和为 1 的概率。这组数就是模型对「下一个词」的概率分布。

为什么是概率而不是确定的答案？因为自然语言天生有不确定性——「今天天气真好，我们去____吧」，填「公园」「爬山」「看电影」都合理。模型没法也没必要给出唯一答案，合理的做法是给不同可能性分配不同概率。所谓训练，就是让这组概率尽量逼近真实数据的分布。

softmax：从打分到概率，手算一遍

softmax 的定义是 $q_i = \dfrac{e^{z_i}}{\sum_j e^{z_j}}$。取一个只有三个候选的玩具词表，模型输出 logits 为 $z = (2.0,\, 1.0,\, 0.1)$：

候选logit $z_i$$e^{z_i}$概率 $q_i$
token A$2.0$$7.389$$0.659$
token B$1.0$$2.718$$0.242$
token C$0.1$$1.105$$0.099$
合计$11.213$$1.000$

这里有个值得记住的性质：softmax 只关心 logits 之间的差，不关心绝对值。给所有 logit 同时加 100，结果一模一样（分子分母同乘 $e^{100}$ 约掉）。框架实现里正是利用这一点，先减去最大值再取指数，避免 $e^{z}$ 溢出——这就是「数值稳定版 softmax」。

温度：同一组 logits 能有几副面孔

解码时的 temperature 参数 $T$，做的事就是在 softmax 前把 logits 除以 $T$：$q_i \propto e^{z_i / T}$。还用上面那组 logits：

链式法则：一整句话的概率怎么来

语言模型建模的是一整个句子的概率 $P(x_1, x_2, \dots, x_n)$。这个联合概率没法直接建模（组合数爆炸），但概率的链式法则给了一条出路：

$$P(x_1, \dots, x_n) = \prod_{t=1}^{n} P(x_t \mid x_{<t})$$

把「一句话的概率」拆成「每一步给定前文、预测下一个词的条件概率」的连乘。这一个等式就是自回归语言模型的全部合法性来源——它说明「一个个往下预测 token」不是权宜之计，而是在精确地建模整句话的联合分布。

一句话直觉 概率分布是模型对世界的「打分表」，softmax 是把任意打分变成合法打分表的标准手续，temperature 是这张表的「锐化/柔化」旋钮。训练就是让这张表越来越接近真实世界那张。

熵：不确定性到底有多大

熵是信息论的奠基概念，由香农（Shannon）在 1948 年提出，用来度量一个分布「本身有多不确定」。对一个离散分布 $p$，熵的定义是：

$$H(p) = -\sum_{i} p_i \log p_i$$

这个公式为什么长这样？关键在于 $\log p_i$。一个事件越罕见（$p_i$ 越小），它一旦发生带来的「信息量」$-\log p_i$ 就越大——这是信息论的核心假设：罕见即意外，意外即信息。熵就是所有事件的「意外程度」按其发生概率加权平均，可以理解为「在这个分布下，平均每发生一次要用多少比特来记录」。

四个分布，四个熵值

都取 4 个候选，用 $\log_2$ 算（单位 bits）：

分布熵（bits）解读
$(1, 0, 0, 0)$ 完全确定$0$结果早已知道，一个比特都不用传
$(0.97, 0.01, 0.01, 0.01)$ 极端偏斜$\approx 0.242$几乎总是同一个结果，偶尔有意外
$(0.7, 0.1, 0.1, 0.1)$ 有偏好$\approx 1.357$有主流选项，但不确定性明显
$(0.25, 0.25, 0.25, 0.25)$ 完全均匀$\log_2 4 = 2$最大值，最摸不着头脑

规律很清楚：越接近均匀，熵越大；越集中在少数几个选项，熵越小。$N$ 个候选的熵上界是 $\log N$，这是熵的一个硬边界。

为什么偏偏是对数

很多人第一次看到熵的公式都会问：衡量「意外程度」的函数那么多，为什么非得是 $-\log p$？答案是对数几乎是唯一同时满足下面三条朴素要求的函数：

  • 越罕见越意外：$p$ 越小，$-\log p$ 越大，且概率为 1 的必然事件信息量恰好为 0。
  • 独立事件的信息量可以相加：两个独立事件同时发生的概率是 $p_1 p_2$，而 $-\log(p_1p_2) = -\log p_1 - \log p_2$。这条「乘法变加法」的性质是对数独有的，也正是它让「一句话的信息量 = 每个词的信息量之和」成立。
  • 连续变化：概率微小变化时信息量也微小变化，不会跳变，这样才能求导、才能拿来当 loss。

第二条尤其关键。回头看上一小节的链式法则：整句话的概率是各步条件概率的连乘，取对数后就变成了各步 loss 的连加。「一句话的总 loss = 每个 token 的 loss 之和」这件在代码里天经地义的事，根子就在对数的这条性质上。

「概率越小，信息量越大」「信息量可以相加」——这两条听起来像课本教条，但它们有一条非常具体的工程化身：算术编码（arithmetic coding）。下面这张论文原图来自 DeepMind 2023 年的《Language Modeling Is Compression》，画的正是「一个概率模型如何把字符串 'AIXI' 变成二进制代码」：

新手读这张图，只需要看懂一个动作：把区间 $[0,1)$ 当作一根刻度尺，每来一个字符，就按它的概率把当前子区间再切一刀，指针所在位置最后转成二进制码。蓝色是模型给每个字符的概率，绿色是切完之后分配到的码段。核心规律就一条：出现概率越大的字符，分到的区间越宽、最终码长越短；整段字符串越「被模型猜中」，总码长就越短。

这和图上的 $- \log p$ 是同一件事：一段文本所需的平均码长，正好等于它的平均信息量（即交叉熵）；交叉熵越小，压缩率越高。这篇论文用「语言模型能不能当压缩器用」把这条等式做到了极致——它证明了在无损压缩比赛里，一个训练好的 70B 语言模型能赢过 gzip 这类通用压缩器。反过来想：「会压缩」和「会预测下一个 token」是同一件事的两面。这也是为什么「压缩即智能」会被当作一个大模型研究纲领——你现在理解的熵，就是这件事的计量单位。

单位坑：nats 还是 bits $\log$ 取自然对数 $\ln$ 时单位是 nats，取 $\log_2$ 时是 bits。换算关系 $1 \text{ nat} = 1/\ln 2 \approx 1.4427 \text{ bits}$。深度学习框架（PyTorch 的 cross_entropy）默认用自然对数，输出是 nats；而信息论教材和很多评测报告用 bits。看到一个「交叉熵 2.0」先问清单位，否则困惑度会算差一大截：$e^{2.0} \approx 7.39$，而 $2^{2.0} = 4$。

语言为什么难预测？因为它的熵远高于 0——同一个上下文，下一个词往往有好几种合理选择。这也是为什么语言建模能成为一个有意义的任务：如果熵是 0，意味着语言可被完美预测，模型也就没存在的必要了。反过来，如果熵等于 $\log(\text{词表大小})$，说明语言完全随机、无规律可学，模型同样没意义。语言的熵不高不低，正好落在「有规律但不确定」的甜区，这是整个领域成立的前提。

新手最容易搞错 「熵小」不等于「模型好」。熵 $H(p)$ 衡量的是真实数据分布本身的不确定性，它是数据固有属性，与模型无关；模型能改变的是交叉熵 $H(p,q)$，而且无论模型多强，交叉熵都降不到数据熵以下——因为 $H(p,q) = H(p) + D_{\mathrm{KL}}(p\|q) \ge H(p)$。所以看到「这个数据集熵很低」就下结论说「模型很准」，是把两把不同的尺子混用了。正确的说法是：模型好不好，看交叉熵逼近数据熵的距离（KL 那一段），而不是看交叉熵的绝对值。同一个模型在中文小说和英文代码上的交叉熵差很多，不是因为模型偏心，而是两种数据的固有熵本就不同。

交叉熵：编码代价，也是训练 loss 的真身

现在模型给出预测分布 $q$，真实数据的分布是 $p$。我们想知道：用 $q$ 去「编码」真实事件 $p$，平均要付多大代价？这就是交叉熵：

$$H(p, q) = -\sum_{i} p_i \log q_i$$

注意它的结构：权重用的是真实概率 $p_i$（因为事件确实按真实分布发生），但「意外程度」用的是模型的预测 $-\log q_i$。如果模型对真实发生的事件给的概率高（$q_i$ 大），$-\log q_i$ 就小，代价就低；反之模型把概率压错了地方，代价就暴涨。

训练里的交叉熵，其实只剩一项

训练数据给的是一个确定的「正确 token」，所以真实分布 $p$ 是 one-hot：正确那一项为 1，其余全 0。代入上式，求和里除了正确项以外全被 0 乘没了：

$$H(p, q) = -\log q_{\text{正确 token}}$$

还用前面那组 softmax 结果 $q = (0.659, 0.242, 0.099)$：

真实答案模型给它的概率loss = $-\ln q$（nats）评价
token A$0.659$$0.417$预测对了，loss 小
token B$0.242$$1.419$没押中主流选项，loss 明显变大
token C$0.099$$2.313$押错得很离谱，loss 是第一行的 5.5 倍

把这个关系画成完整曲线，就能看清交叉熵的性格：

横轴是模型给正确答案的概率，纵轴是对应的交叉熵 loss（nats）。曲线在右侧几乎贴地、在左侧陡然拉起——模型「对得差不多」时几乎没有惩罚，「错得离谱」时惩罚趋于无穷。这正是我们想要的性格：优先把灾难性错误改掉。

常见误区 交叉熵 loss 是 $-\log q_{\text{正确 token}}$，看起来只惩罚「正确那一个 token 的预测概率」，并不直接管其他错误 token。但因为 softmax 的分母是全词表求和，抬高正确项必然连带压低其他项——梯度会同时作用在所有 logits 上。这个「间接」的机制很容易被忽略，也是下面深入块里那条漂亮梯度公式的来源。
工程细节：标签平滑 把 one-hot 的 1 改成 $1-\varepsilon$、把 0 改成 $\varepsilon/(V-1)$，就是标签平滑（label smoothing）。它让真实分布不再是绝对确定，从而阻止模型把正确 token 的 logit 推到无穷大，缓解过度自信。代价是模型输出的概率不再是良好校准的置信度。大模型预训练现在多数不开标签平滑，但在分类微调和一些机器翻译任务里仍常见，具体以各家训练配置为准。

KL 散度：两个分布差多远

交叉熵里其实混了两个东西：一部分是真实分布本身的熵 $H(p)$（无法改变），另一部分是模型预测偏离真实多出来的「额外代价」。把这部分单独拎出来，就是 KL 散度（Kullback-Leibler divergence）：

$$D_{\mathrm{KL}}(p \| q) = \sum_{i} p_i \log \frac{p_i}{q_i} = H(p, q) - H(p)$$

它度量「用 $q$ 近似 $p$」额外付出的代价。最重要的性质有三条：

  • 非负：$D_{\mathrm{KL}}(p \| q) \geq 0$，当且仅当 $p=q$ 时为 0。这就是吉布斯不等式。
  • 不对称：$D_{\mathrm{KL}}(p \| q) \neq D_{\mathrm{KL}}(q \| p)$。它不是真正意义上的「距离」，而是「方向性散度」。
  • 恒等关系：$H(p,q) = H(p) + D_{\mathrm{KL}}(p \| q)$。这就是概览图里那条线的数学来源。

用两个数字把「不对称」坐实

取 $p = (0.5,\, 0.5)$（一枚公平硬币），$q = (0.9,\, 0.1)$（模型以为它严重偏向正面）。用自然对数算：

$$D_{\mathrm{KL}}(p \| q) = 0.5\ln\frac{0.5}{0.9} + 0.5\ln\frac{0.5}{0.1} \approx -0.294 + 0.805 = \mathbf{0.511}\ \text{nats}$$ $$D_{\mathrm{KL}}(q \| p) = 0.9\ln\frac{0.9}{0.5} + 0.1\ln\frac{0.1}{0.5} \approx 0.529 - 0.161 = \mathbf{0.368}\ \text{nats}$$

同样两个分布，换个方向差了近 40%。为什么？因为 KL 的加权系数是第一个参数的概率。$D_{\mathrm{KL}}(p\|q)$ 在 $p$ 有质量而 $q$ 接近 0 的地方会被 $\log(p/q)$ 拉爆——它不允许模型漏掉真实分布覆盖到的区域；反过来 $D_{\mathrm{KL}}(q\|p)$ 只在 $q$ 有质量的地方计较，模型可以只盯住一个峰、忽略其余。

方向俗称行为典型用途
$D_{\mathrm{KL}}(p \| q)$前向 KL / mode-covering逼模型覆盖真实分布的所有峰，宁可摊平也不漏最大似然训练、知识蒸馏 里让学生对齐教师全分布
$D_{\mathrm{KL}}(q \| p)$反向 KL / mode-seeking允许模型只锁定一个主峰，产出更聚焦变分推断；部分对齐方法里做「别漂太远」的正则

因为训练时 $H(p)$ 是固定的（真实数据不变），所以最小化交叉熵等价于最小化 KL 散度，都等于「让模型预测分布尽量逼近真实分布」。这是交叉熵 loss 在数学上站得住脚的根本原因。

KL 散度在大模型里还有个高频用途：RLHF 和 强化学习 里，为了防止微调后的策略跑得太远，常常加一个 KL 惩罚项，让新策略不要偏离参考策略太多。这个「不要漂太远」的约束，背后就是 $D_{\mathrm{KL}}$。同样的思路也出现在 DPO 的目标函数推导里。

困惑度：把 loss 换成人能读的单位

交叉熵的单位是 nats 或 bits，数值不太直观。把它指数化就得到困惑度：

$$\mathrm{PPL} = \exp\!\left(H(p, q)\right) = \exp\!\left(-\frac{1}{N}\sum_{t=1}^{N} \log q(x_t \mid x_{<t})\right)$$

困惑度的直觉是：模型相当于在多少个等概率候选之间犹豫。PPL=1 表示完全确定，PPL=100 表示模型每次像在 100 个候选里随机猜。数值越低越好。对照表：

平均交叉熵（nats）困惑度 $e^{H}$直觉
$0.5$$\approx 1.65$几乎已经确定下一个词
$1.0$$\approx 2.72$在两三个候选里挑
$2.0$$\approx 7.39$在七八个候选里挑
$3.0$$\approx 20.1$相当不确定
$5.0$$\approx 148$模型基本在瞎猜
$\ln V$（$V$ = 词表大小）$= V$纯随机的理论上界

最后一行是个有用的坐标：一个词表 $V = 32000$ 的模型，如果 PPL 接近 32000，说明它完全没学到东西。真实训练里 loss 曲线从 $\ln 32000 \approx 10.4$ 附近起步一路下降，就是这个道理——训练刚开始时模型的输出确实是均匀分布。

三条使用纪律

  • 不能跨分词器比。困惑度是「每 token」的量。同一段文本，分词器 A 切成 100 个 token、分词器 B 切成 130 个 token，每 token 的平均难度就不同，PPL 天然不可比。要跨模型比，得换成与分词无关的指标，比如 bits per byte（BPB） 或 bits per character。
  • 不能跨语料比。在维基百科上测的 PPL 和在代码库上测的 PPL 不是一回事，代码的重复模式多、PPL 天然更低。
  • 它不等于生成质量。PPL 低的模型也可能生成无聊或重复的内容；PPL 衡量的是「建模准不准」，不是「说话好不好」。评估生成质量要看 评估基准 和人工评测。

第三条值得多说一句，因为它是很多误判的源头。一个把「的」「了」「是」这类高频虚词预测得极准的模型，PPL 可以压得很低，但它未必真的理解内容——大量的 loss 权重被虚词吃掉了。反过来，一个经过强指令微调、习惯输出结构化长回答的模型，在纯文本语料上测 PPL 甚至可能比它的基座还高，因为它的输出分布已经被对齐目标改造过了。把 PPL 当成「模型好不好」的唯一指标，是评估环节最常见的方法论错误之一；它更合适的定位是「同一模型在训练过程中的进度条」。

一句话记牢 交叉熵是 loss 的真身，KL 是交叉熵减掉真实熵剩下的「差距」，困惑度是给交叉熵换了个更直觉的皮肤。三者是同一个东西的三种说法，优化任一个等于优化全部。

解码熵temperature、top-p 本质都在调输出分布的熵

动手：手算与框架结果对一遍

下面这段代码把本节所有数字都验证一遍。建议实际跑一次，看手算和框架是否吻合：

import torch
import torch.nn.functional as F

# ---- 1. softmax：手算的 0.659 / 0.242 / 0.099 ----
logits = torch.tensor([2.0, 1.0, 0.1])
q = F.softmax(logits, dim=-1)
print(q)                                  # tensor([0.6590, 0.2424, 0.0986])

# ---- 2. 温度：T=0.5 更尖锐，T=2 更平坦 ----
for T in [0.5, 1.0, 2.0]:
    print(T, F.softmax(logits / T, dim=-1))

# ---- 3. 熵（bits）：手算 1.22 ----
ent_bits = -(q * torch.log2(q)).sum()
print(ent_bits)                           # tensor(1.2217)

# ---- 4. 交叉熵 loss：真实答案是第 0 个 token ----
target = torch.tensor([0])
loss = F.cross_entropy(logits.unsqueeze(0), target)
print(loss)                               # tensor(0.4170)  == -ln(0.6590)
print(-torch.log(q[0]))                   # 完全一致

# ---- 5. 困惑度 ----
print(torch.exp(loss))                    # tensor(1.5174)

# ---- 6. KL 的不对称性：手算 0.511 vs 0.368 ----
p = torch.tensor([0.5, 0.5])
r = torch.tensor([0.9, 0.1])
kl_pr = (p * (p / r).log()).sum()
kl_rp = (r * (r / p).log()).sum()
print(kl_pr, kl_rp)                       # tensor(0.5108) tensor(0.3681)
最高频的实现坑 F.cross_entropy 内部已经包含了 log_softmax，它要的输入是原始 logits，不是概率。先 softmax 再 cross_entropy 等于算了两次 softmax，模型照样能训但收敛异常慢，而且不会报任何错。同理，F.kl_div 的第一个参数要求传对数概率（log_softmax 的输出），第二个参数传概率——参数约定不对称，是另一个高频翻车点，用之前务必查一次官方文档。
展开：为什么 softmax + 交叉熵的梯度这么漂亮

把交叉熵对 logits 求导，结果简洁得令人意外：

$$\frac{\partial L}{\partial z_i} = q_i - y_i$$

其中 $q_i$ 是 softmax 输出的概率，$y_i$ 是 one-hot 标签。也就是说，梯度就是「模型的预测」减去「真实答案」，没有任何多余的项。

这带来三个重要后果：

  • 不会梯度饱和。对正确 token，梯度是 $q_{\text{正确}} - 1$；模型越错（$q$ 越接近 0），梯度绝对值越接近 1，仍然强劲。对比之下，如果用 MSE 配 sigmoid，预测越错梯度反而越接近 0，训练会卡死——这就是分类任务不用 MSE 的根本原因。
  • 数值上极其稳定。框架把 softmax 和 NLL 融合成一个算子（cross_entropy），中间不显式生成 $q$，避免了 $\log 0$ 和指数溢出。这也是为什么不要自己拆开写。
  • 梯度自动作用于全词表。对错误 token $j$，梯度是 $q_j - 0 = q_j$，正数，会把它的 logit 往下压。押得越高的错误答案被压得越狠。

推导本身不难：$\frac{\partial q_i}{\partial z_j} = q_i(\delta_{ij} - q_j)$，代入 $L = -\sum_k y_k \log q_k$ 并利用 $\sum_k y_k = 1$ 化简即得。感兴趣可以在纸上推一遍，二十分钟就能走通，是理解 反向传播 的绝佳练习。

展开：三个自测小题（含答案）

题 1：某模型在测试集上平均交叉熵为 2.3 nats，它的困惑度是多少？如果换算成 bits 该报多少？

答：PPL $= e^{2.3} \approx 9.97$，约等于 10，说明模型平均在十来个候选里犹豫。换算成 bits 是 $2.3 \times 1.4427 \approx 3.32$ bits，注意 $2^{3.32} \approx 9.97$ 结果一致——换单位只换指数的底，PPL 不变。

题 2：把 temperature 从 1.0 调到 0.7，输出分布的熵变大还是变小？生成结果会更保守还是更发散？

答：变小、更保守。$T<1$ 相当于把 logits 放大，差距被拉开，分布更尖锐，高概率 token 更容易被采到。极限 $T \to 0$ 就是贪心解码，熵为 0。

题 3：训练刚启动时，一个词表 5 万的模型 loss 大约是多少才算「正常的随机初始化」？

答：约 $\ln 50000 \approx 10.8$ nats。如果开局 loss 远低于这个值，八成是数据泄漏或标签对齐错了（比如输入和标签没错位）；如果远高于这个值，多半是初始化或数值精度出了问题。这是一条非常实用的开局体检指标。

要点速查

  • softmax：$q_i = e^{z_i}/\sum_j e^{z_j}$，只关心 logits 的差不关心绝对值；temperature 除在指数上，调的是输出分布的熵。
  • 链式法则：$P(x_1..x_n)=\prod_t P(x_t\mid x_{<t})$，这是自回归语言模型的合法性来源；实现上一定取对数把连乘变连加。
  • 熵 $H(p)$：$-\sum p_i \log p_i$，衡量分布自身的不确定性，均匀分布取最大值 $\log N$，确定分布为 0。
  • 交叉熵 $H(p,q)$：$-\sum p_i \log q_i$。标签是 one-hot 时退化为 $-\log q_{\text{正确}}$，这就是训练 loss。
  • KL 散度：$H(p,q) - H(p)$，非负、不对称（$p=(0.5,0.5)$ 对 $q=(0.9,0.1)$ 是 0.511 vs 0.368 nats）。前向 KL 覆盖所有峰，反向 KL 锁定单峰。
  • 困惑度：$\exp(H)$，直觉是「相当于在几个等概率候选里犹豫」。$\ln V$ 对应的 PPL 就是词表大小，是随机初始化时的开局值。
  • 关键梯度：softmax + 交叉熵对 logits 的梯度就是 $q - y$，不饱和、数值稳定，这是它取代 MSE 做分类的根本原因。
  • 常见坑：nats 与 bits 混用、跨分词器/跨语料比 PPL、把 PPL 当生成质量、对 softmax 结果再过一次 cross_entropy、F.kl_div 的两个参数一个要 log 一个不要。
