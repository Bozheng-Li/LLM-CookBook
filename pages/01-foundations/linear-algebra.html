入门

线性代数基础

大模型里几乎不存在标量，一切运算都是高维数组之间的批量变换。向量、矩阵、张量是这套运算的基本容器，矩阵乘法是它们之间唯一的「语言」。这一节不追求数学上的完备，只把读论文、看代码、排 shape 错误真正会用到的那部分几何直觉讲透——讲完你应该能看着 [2, 5, 4096] 这样一串数字，脑子里立刻浮现出「两句话、每句五个词、每个词一个 4096 维向量」的画面。

一图看懂

线性代数研究的就是一件事：把空间里的点变换到另一个位置。向量是「坐标」，矩阵是「变换的说明书」，矩阵乘法是「按说明书执行变换」。张量只是把这套逻辑推广到更高维的容器——大模型里一批 token 的嵌入，本质就是一个三维张量。整本 Cookbook 后面所有公式，都是在这三个概念上搭起来的。

向量：从一列数字到空间中的一个点

向量最朴素的定义是「一列有序的数字」。但这样看丢掉了它最有用的性质。换一种视角：一个 $n$ 维向量 $v = (v_1, v_2, \dots, v_n)$ 代表 $n$ 维空间里的一个点，也代表从原点指向该点的一个箭头。两个视角合在一起，才是向量的完整面貌。

为什么要强调「空间里的点」？因为大模型的几乎所有信息都活在向量空间里：一个 token 的嵌入是一个几百到几千维的向量，一张图片经过视觉编码器后也被压成一组向量。这些向量不是孤立的数字，而是空间里某个位置——位置之间的距离和方向，就对应着语义上的相似与差异。这正是 词嵌入 那一节「语义相近即距离相近」这句话的几何来源。

两个基本运算，都有明确的几何意义

用一个能心算的例子。设 $u = (1, 2)$、$v = (3, -1)$：

运算算式结果几何含义
加法$u + v$$(4, 1)$先沿 $u$ 走，再沿 $v$ 走，落点就是合成位移的终点
数乘$2 \cdot u$$(2, 4)$方向不变，箭头长度拉伸 2 倍
负数乘$-1 \cdot u$$(-1, -2)$长度不变，方向掉头 180 度
线性组合$2u - v$$(-1, 5)$先各自缩放再相加，能张成一个平面

由加法和数乘能线性组合出的一切向量集合，构成一个「空间」。线性代数关心的是：这些组合能张成多大空间、哪些向量彼此独立、变换后空间被压扁了没有。这三个问题分别对应后面要讲的张成、线性无关、秩。

范数：向量「有多长」的三种量法

「长度」在高维里不止一种定义。大模型工程里最常见的三种：

范数定义$u=(3,-4)$ 的取值在大模型里用在哪
$L_1$ 范数$\sum_i |u_i|$$3 + 4 = 7$稀疏化正则；量化里衡量误差绝对量
$L_2$ 范数$\sqrt{\sum_i u_i^2}$$\sqrt{9+16} = 5$最常用。梯度裁剪按全局 $L_2$ 范数裁；权重衰减压的也是它
$L_\infty$ 范数$\max_i |u_i|$$4$量化里定 scale（看最大绝对值）；异常值检测

后面 优化算法基础 里的「梯度裁剪按全局范数裁到 1.0」，指的就是把所有参数的梯度拼成一个超长向量，算它的 $L_2$ 范数，如果超过 1.0 就整体等比缩小。理解范数是长度，这句话就不再抽象。

一句话直觉 向量加法是「走两步」，数乘是「步幅放大缩小」，范数是「一共走了多远」。大模型训练本质上就是在向量空间里反复做这几件事，把信息搬来搬去。

这四个词经常被混着用，其实它们是同一个东西在不同维数下的名字。用一张关系图先分清：

把「维数」和「维度大小」分清很重要，这是初学者第一个坑：ndim 是「有几个轴」，shape 里每个数是「这个轴上有多少个元素」。一个 shape 为 [2, 5, 4096] 的张量，ndim=3，读作「2 个样本、每个 5 个 token、每个 token 4096 维」。有人说「这是一个 4096 维的张量」，是把两个概念说混了。

点积：相似度的几何本质

点积（内积）是向量之间最重要的二元运算。代数定义很简单：

$$u \cdot v = \sum_{i=1}^{n} u_i v_i = u_1 v_1 + u_2 v_2 + \dots + u_n v_n$$

但只看这串求和会错过它的几何含义。等价的几何定义是：

$$u \cdot v = \|u\|\,\|v\|\cos\theta$$

其中 $\theta$ 是两向量夹角。这个式子把「一串相乘求和」和「夹角」挂上了钩，意义极其重大：

夹角$\cos\theta$点积含义检索场景里对应什么
同向（$0°$）$1$最大正值方向一致，最「相似」查询命中语义几乎相同的文档
锐角（$60°$）$0.5$正值部分相关相关但不完全对题的候选
垂直（$90°$）$0$$0$正交，互不相关完全无关的文档
反向（$180°$）$-1$最大负值方向相反，语义对立实践中少见，多数嵌入模型输出集中在正半空间

手算一遍，把公式坐实

设 $u = (1, 2, 2)$，$v = (2, 0, 1)$：

  • 点积：$u \cdot v = 1 \times 2 + 2 \times 0 + 2 \times 1 = 4$。
  • 模长：$\|u\| = \sqrt{1 + 4 + 4} = 3$，$\|v\| = \sqrt{4 + 0 + 1} = \sqrt{5} \approx 2.236$。
  • 余弦相似度：$\cos\theta = \dfrac{4}{3 \times 2.236} \approx 0.596$，对应夹角约 $53.4°$。

再看一个对照：把 $u$ 整体放大十倍变成 $u' = (10, 20, 20)$。这时点积变成 $40$，翻了十倍；但余弦相似度仍是 $0.596$，一点没变。这个对照就是「点积会被长度污染、余弦不会」最直接的证据。

$$\cos\theta = \frac{u \cdot v}{\|u\|\,\|v\|}$$
相似度度量公式受向量长度影响典型用法
点积 Dot$u \cdot v$是注意力 打分；向量库里若嵌入已归一化则等价于余弦
余弦 Cosine$\dfrac{u\cdot v}{\|u\|\|v\|}$否RAG 语义检索的默认度量，只看方向
欧氏距离 L2$\|u - v\|$是聚类、近邻搜索；对归一化向量与余弦单调等价

在大模型里，点积几乎无处不在：注意力 里 Query 和 Key 做点积来衡量「该关注谁」；RAG 里两个句向量做点积或余弦相似度来判断语义是否接近。可以说，点积就是「相似度」这件事的几何化定义。

常见误区 点积大不等于「相似」。只有在向量被归一化或量级相当时，点积大小才反映方向接近程度。否则一个长向量跟谁点积都偏大，会误导判断。工程上的通用做法是：入库前把所有嵌入做 $L_2$ 归一化，之后点积和余弦就完全等价，还省掉了在线除法。

维度一高，点积就会「爆」——$\sqrt{d_k}$ 缩放的来历

这里插一段推导，它是本页里离 Transformer 最近的一处，也是很多人第一次读注意力公式时最想不通的地方：为什么 $QK^\top$ 算完之后要除以 $\sqrt{d_k}$，而不是除以 $d_k$ 或者干脆不除？答案完全来自点积的统计性质，不需要任何深度学习知识。

设 $q$ 和 $k$ 是两个 $d_k$ 维向量，它们各分量相互独立、均值为 0、方差为 1（这大致就是训练初期经过归一化后的实际情况）。那么点积 $q \cdot k = \sum_{i=1}^{d_k} q_i k_i$ 是 $d_k$ 个独立随机变量之和。每一项的均值是 $E[q_i k_i] = E[q_i]E[k_i] = 0$，方差是 $\mathrm{Var}(q_i k_i) = E[q_i^2]E[k_i^2] = 1$。独立变量之和的方差可以直接相加，于是：

$$E[q\cdot k] = 0, \qquad \mathrm{Var}(q\cdot k) = d_k, \qquad \text{标准差} = \sqrt{d_k}$$

关键就在最后一项：点积的典型量级随维度按 $\sqrt{d_k}$ 增长，而不是按 $d_k$。代入真实数字感受一下：$d_k = 64$ 时标准差是 8，$d_k = 128$ 时是 11.3。也就是说注意力分数会自然散布在 $\pm 20$ 甚至更宽的区间里。这个量级送进 softmax 会发生什么？$e^{20}$ 与 $e^{-20}$ 相差约 $10^{17}$ 倍——softmax 输出几乎必然退化成一个 one-hot：某一个位置权重接近 1，其余全部接近 0。而 softmax 在饱和区的梯度趋近于 0，这一层就学不动了。

所以除以 $\sqrt{d_k}$ 恰好把标准差拉回 1，让分数落在 softmax 敏感的区间里。之所以不是除以 $d_k$，是因为那样会「除过头」：标准差变成 $1/\sqrt{d_k}$，$d_k=64$ 时只有 0.125，所有分数挤在 0 附近，softmax 输出趋于均匀分布——注意力就退化成了简单平均，同样学不到东西。一个是过度尖锐，一个是过度平坦，$\sqrt{d_k}$ 正好卡在中间。这段推导会在 注意力机制 里被直接复用。

矩阵：变换的代数表示

一个矩阵 $A$ 不仅仅是一张数字表，它代表一个线性变换：把输入向量 $x$ 映射成输出向量 $Ax$。理解一个矩阵，关键是搞清它对空间做了什么——拉伸、旋转、投影、剪切、压扁。

用矩阵的列来看最直观：$A$ 的第 $j$ 列 $a_j$，就是「把基向量 $e_j$ 变成了什么」。任何一个输入向量 $x = \sum_j x_j e_j$，经过变换后就是 $Ax = \sum_j x_j a_j$——把输入坐标当成权重，对矩阵的列向量做线性组合。

这个「列视角」有个非常重要的推论：$Ax$ 这个操作，可以理解为用 $x$ 对 $A$ 的列做「检索」——$x$ 的第 $j$ 个分量越大，第 $j$ 列被取的权重就越高。这正是注意力机制「用权重对 Value 加权」的几何根源。

四个能心算的 2×2 变换

把抽象的「变换」落到具体矩阵上，看它们分别对单位正方形做了什么：

矩阵对 $(1,0)$ 的作用对 $(0,1)$ 的作用行列式几何效果
$\begin{pmatrix}2&0\\0&3\end{pmatrix}$$(2,0)$$(0,3)$$6$横向拉 2 倍、纵向拉 3 倍，面积变 6 倍
$\begin{pmatrix}0&-1\\1&0\end{pmatrix}$$(0,1)$$(-1,0)$$1$逆时针旋转 90 度，面积不变
$\begin{pmatrix}1&1\\0&1\end{pmatrix}$$(1,0)$$(1,1)$$1$剪切（把正方形推成平行四边形），面积不变
$\begin{pmatrix}1&0\\0&0\end{pmatrix}$$(1,0)$$(0,0)$$0$投影到 x 轴，二维被压成一维，信息不可逆地丢了

最后一行值得盯久一点：行列式为 0 意味着变换把空间压扁了，多个不同的输入会落到同一个输出点上——信息丢失、变换不可逆。深度学习里「表示坍缩」「秩塌陷」这些说法，讲的都是这件事。

线性变换有几个关键不变量，决定了一个矩阵「是什么样子的变换」：

秩 Rank

变换后空间的维数。秩越小，空间被压得越扁。满秩意味着信息无损。LoRA 的全部立论就在「权重更新量往往是低秩的」。

行列式 Det

变换对体积的缩放倍数。为零意味着把空间压扁到低维，可逆性丧失。

特征值 Eigenvalue

变换在特定方向上只拉伸不旋转，这些方向是特征向量，拉伸倍数是特征值。反复作用时，最大特征值决定是爆炸还是衰减。

矩阵乘法：变换的复合，也是算力的大头

两个矩阵 $A$ 和 $B$ 相乘得到 $AB$，几何含义是「先做 $B$ 变换，再做 $A$ 变换」的复合变换。这正是矩阵乘法顺序不可交换的根源。

用具体数字证明 $AB \neq BA$

取上面表里的旋转 $R=\begin{pmatrix}0&-1\\1&0\end{pmatrix}$ 和缩放 $S=\begin{pmatrix}2&0\\0&1\end{pmatrix}$：

$$RS = \begin{pmatrix}0&-1\\2&0\end{pmatrix},\qquad SR = \begin{pmatrix}0&-2\\1&0\end{pmatrix}$$

两者完全不同。直觉上也很清楚：先把图形横向拉长再旋转，和先旋转再横向拉长，得到的形状当然不一样——后者拉长的是已经转过去的方向。这就是为什么把两个 Linear 层串联时，顺序不能随意调换。

三种互补视角

从计算角度看，$C = AB$ 中 $C_{ij}$ 是 $A$ 的第 $i$ 行与 $B$ 的第 $j$ 列的点积。但这个「行乘列」的口诀只是机械规则，真正该记住的是三个视角：

视角怎么看 $AB$对应直觉什么时候最好用
元素视角$C_{ij} = \sum_k A_{ik}B_{kj}$第 $i$ 行点乘第 $j$ 列手算小矩阵、验证结果
列视角$AB$ 的第 $j$ 列 $= A \cdot (B\text{ 的第 } j \text{ 列})$$A$ 把 $B$ 的每一列搬到新位置理解「一层线性变换作用于一批向量」
行视角$AB$ 的第 $i$ 行 $=$ $B$ 各行的加权组合权重来自 $A$ 的第 $i$ 行理解注意力「权重矩阵 × V」在做加权求和
新手最容易搞错 AB 能乘，BA 未必能乘，而且就算能乘结果也几乎必不相同。判定能不能乘只有一个口诀：A 的列数必须等于 B 的行数，即 [m, k] @ [k, n] = [m, n]，中间的 k 是「对齐维度」。PyTorch 里一句 x @ W 报 mat1 and mat2 shapes cannot be multiplied，九成九是这里没对齐——先别改代码，把两个 shape 右对齐写下来看中间那一位。另一个高频错觉是把 [k, n] @ [m, k] 当成「矩阵乘法可交换」来写，结果维度对不上才意识到顺序反了。记住：矩阵乘法读作「先做右边那个变换，再做左边那个」，顺序就是语义，永远不要随便调换。

它到底吃掉多少算力

一次 $(m \times k) \times (k \times n)$ 的矩阵乘法，需要约 $2mnk$ 次浮点运算（每个输出元素做 $k$ 次乘法加 $k$ 次加法）。这个「乘 2」的口诀在算训练预算时天天要用。

举个大模型里的真实规模：一个 $d_{\text{model}} = 4096$ 的 Linear 层，处理长度 2048 的序列，等价于 $(2048 \times 4096) \times (4096 \times 4096)$：

$$2 \times 2048 \times 4096 \times 4096 \approx 6.87 \times 10^{10} \text{ FLOPs} \approx 68.7 \text{ GFLOPs}$$

而一个 Transformer 层里这样的大矩阵乘法有好几个（QKV 投影、输出投影、FFN 的升降维），再乘上几十层、再乘上千亿 token——这就是为什么预训练要成千上万张 GPU。想把这本账算明白，去看 FLOP、显存核算与性能剖析。

框架里矩阵乘法叫 matmul 或 linear，GPU 上由 cuBLAS 这类库高效实现，并会被编译成专门的 Tensor Core 指令。矩阵乘法是大模型里唯一被硬件专门优化的运算——这也解释了为什么架构设计总倾向于「把计算塞进大矩阵乘法里」，而不是用一堆零碎的逐元素操作。

为什么线性层后面必须加激活函数 两个线性变换 $A$、$B$ 的复合 $AB$ 仍是线性变换，再多层叠在一起也等价于一个矩阵。没有非线性激活，一百层深网络就塌缩成一层，参数量白白浪费。这正是激活函数必须存在的根本原因，见 神经网络基础。

张量：大模型的数据容器与常见 shape 坑

张量是向量和矩阵的自然推广。框架（PyTorch / TensorFlow）里几乎所有数据都是张量，用一个 shape 描述各维大小。

张量典型 shape含义
token 嵌入[batch, seq_len, d_model]一批句子，每句若干 token，每个 token 一个向量
多头拆分后的 Q/K/V[batch, heads, seq_len, d_head]把 d_model 切成 heads × d_head，每头独立算注意力
注意力权重[batch, heads, seq_len, seq_len]每头一张 $n \times n$ 的关注分布，这就是显存杀手
Linear 层权重[out_features, in_features]注意 PyTorch 是「输出在前」，与数学写法 $Wx$ 一致
输出 logits[batch, seq_len, vocab_size]每个位置在整个词表上的打分，词表几万到几十万

广播：形状不同也能相加的规则

张量运算的精髓在于「按维度对齐」。广播（broadcasting）的规则只有两条，从最后一维开始往前比对：两维相等，或其中一维是 1（会被自动复制展开），否则报错。

A 的 shapeB 的 shape能否广播结果 shape / 原因
[2, 5, 4][4]可以[2, 5, 4]，B 被复制到每个位置——加 bias 就是这么干的
[2, 5, 4][5, 1]可以[2, 5, 4]，最后一维 1 被展开成 4
[2, 5, 4][2, 5]不可以末维 4 与 5 既不相等也没有 1，报 shape mismatch
[8, 1, 6][1, 7, 1]可以[8, 7, 6]，两边各自展开各自的 1 维

第三行是最典型的 bug 现场：本想给每个 token 加一个标量权重，结果忘了 unsqueeze(-1)。记住排查口诀——报 shape 错误时，先把两个 shape 右对齐写下来，一列一列看。

另一个高频坑：transpose 之后不能直接 view transpose / permute 只改变对维度的解释方式，底层内存顺序没动，得到的张量不再连续。这时直接调 view 会报 view size is not compatible with input tensor's size and stride。解决办法是先 .contiguous() 再 view，或者直接用 reshape（它会在必要时自动复制）。多头注意力里「拆头—转置—合并」那几行，几乎每个手写 Transformer 的人都在这里栽过一次。

低秩：LoRA 背后就是这一个概念

秩这个概念在教科书里往往讲得很抽象，但它在大模型里有一个极其具体、极其重要的落点：LoRA。

先把秩的直觉说清：一个 $d \times d$ 的矩阵，如果它的列向量里只有 $r$ 个是「真正独立」的、其余都能由这 $r$ 个线性组合出来，那它的秩就是 $r$。秩为 $r$ 的矩阵可以被分解成两个瘦长矩阵的乘积：

$$\underbrace{\Delta W}_{d \times d} = \underbrace{B}_{d \times r} \cdot \underbrace{A}_{r \times d}, \qquad r \ll d$$

LoRA 的假设是：微调时权重的变化量 $\Delta W$ 内在维度很低，所以不必训练整个 $d \times d$，只训练瘦长的 $B$ 和 $A$ 就够。参数量差多少？取 $d = 4096$：

  • 全量微调一个方阵：$4096 \times 4096 = 16\,777\,216$ 个参数，约 1678 万。
  • LoRA 取 $r = 8$：$2 \times 4096 \times 8 = 65\,536$ 个参数，约 6.5 万。
  • 比值：$\dfrac{2 \times 4096 \times 8}{4096 \times 4096} = \dfrac{8}{2048} \approx 0.39\%$。

纵轴：LoRA 可训练参数量占该方阵全量参数的百分比。可以看到即使 $r=64$ 也只有约 3.1%——这就是 PEFT 能在单卡上微调大模型的算术根源。

「把 $\Delta W$ 拆成 $BA$ 两个瘦长矩阵」到底长什么样？不用脑补，直接看提出它的那篇论文的原图。LoRA 论文的 Figure 1 画的就是这个重参数化（reparametrization）设计，它是理解整篇论文的钥匙：

新手读这张图，抓三个要点就够了。① 中间的权重矩阵 W 上标着一个「冻结」（frozen）：它原本是在海量数据上预训练好的，微调期间一个参数都不动。② 两侧新插入的 A、B 才是唯一被训练的部分：A 负责把 $d$ 维输入压缩到低秩的 $r$ 维（$r \ll d$），B 再把它升回 $d$ 维，两段连起来恰好是 $d \times r$ 乘 $r \times d$ 的瘦长分解。③ 最终生效的权重是 $W + \alpha BA$：推理时并没有多出一层网络，只是把学到的低秩增量「叠回」原权重，因此零额外推理延迟。

这张图的价值在于把抽象的「低秩」变成了看得见的物理结构：微调并不是把几十亿参数全部重新调一遍，而是在每个权重矩阵旁「并联」一对小板子，用数据把这小板子磨到合适——小板子磨好了，接进主电路就能复现绝大多数微调效果。这也顺带解释了为什么 LoRA 常配合 $r=8$、$r=16$ 这种小秩：秩代表旁路板的宽度，越窄越省，但窄过头就装不下需要学习的领域知识，效果会掉。更多训练细节与坑见 LoRA 微调 一节。

秩是怎么被「量」出来的：奇异值

上面说「有 $r$ 个列向量真正独立」，这句话在实际矩阵上很难直接判断——真实数据里几乎没有严格线性相关的列，浮点噪声就足以让秩看起来是满的。工程上真正用的工具是奇异值分解（SVD）：任何一个 $m \times n$ 的矩阵都能唯一地写成

$$M = U \Sigma V^\top, \qquad \Sigma = \mathrm{diag}(\sigma_1 \ge \sigma_2 \ge \dots \ge \sigma_{\min(m,n)} \ge 0)$$

其中 $U$ 和 $V$ 的列都是单位正交向量，$\Sigma$ 只在对角线上有值，这些值 $\sigma_i$ 叫奇异值，按从大到小排列。几何解释很漂亮：任何线性变换都可以拆成「先旋转（$V^\top$）→ 沿各坐标轴按 $\sigma_i$ 拉伸（$\Sigma$）→ 再旋转（$U$）」这三步。奇异值就是这个变换在各个主方向上的拉伸倍数，而秩就等于非零奇异值的个数。

更有用的是，奇异值给了我们一把连续的尺子来衡量「有多低秩」。如果一个矩阵的奇异值是 $(50,\,30,\,20,\,0.3,\,0.1,\,0.02,\dots)$，那么严格意义上它可能是满秩的，但前三个奇异值已经占了绝大部分能量——把后面的全置零，得到的秩 3 矩阵和原矩阵几乎没有差别。这就是低秩近似，而 Eckart–Young 定理保证了一件事：在所有秩不超过 $r$ 的矩阵里，截断 SVD（只保留前 $r$ 个奇异值）给出的近似误差最小。换句话说，SVD 不只是一种可行的分解，它是最优的那一种。

这把尺子在大模型里到处可见：判断某个权重矩阵值不值得做低秩压缩，就看它的奇异值衰减得快不快；LoRA 之所以敢用 $r=8$ 这么小的秩，依据正是「微调带来的权重变化量 $\Delta W$ 的奇异值谱衰减极快」这一经验观察。反过来，如果一个矩阵的奇异值几乎一样大（谱是平的），那它就是「真·满秩」，任何低秩压缩都会造成实质性信息损失——这时候该换的是量化而不是分解。

一句话直觉 低秩就是「这个变换其实没那么复杂，用两块小板子就能拼出来」。你在 MLA 的低秩 KV 压缩、量化 的误差分解里会一次次遇到同一个思路。

这些概念分别落在大模型的哪一环

学基础最容易失去动力的地方，是不知道学了有什么用。把上面所有概念和它们的实际落点连起来：

动手：十行代码把上面全过一遍

光看不练很难形成肌肉记忆。下面这段代码把点积、归一化、矩阵乘法、广播、形状变换全串了一遍，建议逐行跑一次并盯住每一步的 shape：

import torch

# ---- 1. 向量与点积 ----
u = torch.tensor([1.0, 2.0, 2.0])
v = torch.tensor([2.0, 0.0, 1.0])
print(u @ v)                       # 4.0，手算也是 4
print(u.norm())                    # 3.0，L2 范数
print(torch.nn.functional.cosine_similarity(u, v, dim=0))   # 约 0.5963

# ---- 2. 放大十倍：点积变了，余弦没变 ----
u_big = u * 10
print(u_big @ v)                   # 40.0，翻十倍
print(torch.nn.functional.cosine_similarity(u_big, v, dim=0))  # 仍是约 0.5963

# ---- 3. 一批 token 过一个 Linear 层 ----
x = torch.randn(2, 5, 8)           # [batch=2, seq=5, d_model=8]
W = torch.randn(8, 8)              # [in, out]，注意这里按数学写法用 x @ W
out = x @ W                        # [2, 5, 8]，前两维自动广播

# ---- 4. 广播加 bias ----
b = torch.randn(8)                 # [8]
out = out + b                      # b 被广播到每个 batch 每个位置

# ---- 5. 多头拆分：把 8 维切成 2 头 × 4 维 ----
h = out.view(2, 5, 2, 4).transpose(1, 2)   # [batch, heads, seq, d_head]
print(h.shape)                     # torch.Size([2, 2, 5, 4])
print(h.is_contiguous())           # False！transpose 后内存不连续

# ---- 6. 合并回来：必须先 contiguous 或直接用 reshape ----
merged = h.transpose(1, 2).reshape(2, 5, 8)
print(merged.shape)                # torch.Size([2, 5, 8])

第 5、6 步就是多头注意力里最容易出错的两行。@ 运算符对三维以上张量会自动广播前面的维度、只在最后两维做矩阵乘法——这就是为什么 Transformer 里一句 Q @ K.transpose(-2, -1) 就能并行算出整批所有头的注意力分数。

展开：为什么 PyTorch 的 nn.Linear 权重是 [out, in] 而不是 [in, out]

数学上我们写 $y = Wx$，$x$ 是列向量，所以 $W$ 的形状必须是 $[\text{out}, \text{in}]$。PyTorch 的 nn.Linear(in_features, out_features) 内部存的 weight 就遵循这个数学约定，形状是 [out_features, in_features]。

但深度学习框架里的数据是行主序、样本在第 0 维的，即 x 的形状是 [batch, in]。所以 nn.Linear 实际执行的是 x @ weight.T + bias，转置一下才对得上。

这个小小的不一致坑过很多人：手动加载权重时忘了转置，模型能跑但结果全错，且不会报任何形状错误（因为方阵转置后形状不变）。只要 in_features == out_features，转置错误就是静默的——这类 bug 最难查。稳妥做法是加载完权重后拿一条已知输入跑一遍，对比参考实现的输出。

另外，把权重存成 [out, in] 还有一个工程理由：这样每一行是一个输出神经元的全部输入权重，在内存里连续，做行剪枝、按输出通道量化时访问模式更友好。

展开：三个自测小题（含答案）

题 1：a.shape = [4, 1, 6]，b.shape = [3, 6]，a + b 的结果形状是什么？

答：[4, 3, 6]。右对齐后是 4,1,6 与 _,3,6：末维 6=6 匹配；中间 1 与 3，1 被展开成 3；最前面 b 缺失的维补 1 再展开成 4。

题 2：一个矩阵的行列式为 0，还能求它的逆吗？这在神经网络里意味着什么？

答：不能。行列式为 0 说明变换把空间压扁了，多个输入映射到同一输出，信息不可逆地丢失。在网络里对应「表示坍缩」——某一层输出的所有向量都挤在一个低维子空间里，后面的层再怎么算也补不回丢掉的方向。

题 3：$d_{\text{model}}=8192$、$r=16$ 时，LoRA 在一个方阵上的可训练参数占比是多少？

答：$\dfrac{2 \times 8192 \times 16}{8192 \times 8192} = \dfrac{2 \times 16}{8192} = \dfrac{32}{8192} \approx 0.39\%$。注意占比只取决于 $2r/d$，与 $d$ 的绝对大小无关——模型越大，同样的 $r$ 省得越多。

要点速查

  • 向量：既是数字列表，也是空间里的点/箭头。加法是位移合成，数乘是长度缩放，范数是长度的量法（$L_2$ 最常用）。
  • 点积：$u \cdot v = \|u\|\|v\|\cos\theta$，是相似度的几何定义。归一化后点积即余弦相似度，两者在归一化向量上完全等价。
  • 矩阵：一个线性变换。列 = 各基向量变换后的落点；秩/行列式/特征值刻画变换性质；行列式为 0 = 压扁 = 不可逆。
  • 矩阵乘法：变换的复合，非交换（$RS \neq SR$ 有具体反例）。一次 $(m,k)\times(k,n)$ 约 $2mnk$ FLOPs，是训练算力的绝对大头。能不能乘只看中间维：[m,k]@[k,n]。
  • 张量：高维容器，ndim 是轴数、shape 是每轴大小。广播规则：从末维起，相等或其一为 1。
  • 低秩：$\Delta W = BA$，$r \ll d$。$d=4096,r=8$ 时参数量只占 0.39%，这是 LoRA 的算术根基。
  • 常见坑：未归一化就比点积大小、矩阵乘法顺序搞反、广播维度对不齐、transpose 后直接 view、加载 nn.Linear 权重忘了转置（方阵时静默出错）。
