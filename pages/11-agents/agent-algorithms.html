Agent 算法：规划、工具使用与学习

把 Agent 看成可恢复、可评测的 POMDP 闭环。

一个三步任务

回答“公司营收是否增长”需要搜索财报、用计算器比较数字、带来源回答。工具返回是 observation；失败时应改写查询或说明不确定性，不能凭空补全。

ReAct 与 Plan-and-Execute

短链工具探索用 ReAct 的 Thought-Action-Observation；长任务先列计划再执行；只有有明确测试时才加入 Reflexion。反思必须记录失败原因、修复动作和证据，空泛的“再试一次”没有训练价值。

工具轨迹如何训练

保存目标、tool call、真实结果和最终答案。过滤参数错误与越权轨迹，再用成功/失败对做 DPO。训练集必须包含超时、空结果和权限拒绝，工具结果要先过提示注入检测。

Agentic RL

终局奖励会造成信用分配问题。可用 R=任务成功-工具成本-风险成本，并给可验证里程碑奖励；每种工具单独归一化，防止调用次数成为捷径。MCP 是 Agent 到工具，A2A 是 Agent 到 Agent。

评测练习

对同一任务记录完成率、工具精度、重试次数、token、延迟、越权率和人工接管率。故意让工具失败，检查系统能否恢复且不重复执行有副作用的操作。
