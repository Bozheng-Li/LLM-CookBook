推理时扩展：用额外计算换取可靠答案

把 reasoning model、best-of-n、self-consistency 与 verifier 放进同一个实验框架，观察质量、成本和尾延迟的真实曲线。

1. 三种扩展位置

采样扩展并行生成 n 条轨迹再聚合；搜索扩展把中间状态作为节点，用 beam/MCTS 展开；验证扩展由 PRM/规则/执行器给候选打分。它们分别增加 token、上下文和验证成本，不能只按最终准确率比较。

2. Best-of-n 与 self-consistency

若单次成功率为 p，独立采样的 pass@k 为 1-(1-p)^k；真实轨迹相关时收益更低。多数投票适合有离散答案的任务，开放式回答需要语义聚类或 verifier。记录每次候选的 token 数和失败类型，避免“多采样”掩盖成本爆炸。

3. 搜索与价值估计

树搜索选择 a*=argmax(Q(s,a)+c·P(s,a)√N(s)/(1+N(s,a)))，但语言模型的先验 P、价值 Q 和终止条件都可能偏。搜索深度、分支数和状态压缩应作为实验变量；若状态不可复现，搜索只是昂贵的随机重试。

4. Verifier 的边界

规则验证器适合数学、代码测试和结构化输出，LM judge 适合开放式质量但会受位置、长度和表述影响。独立 verifier、人工抽检和对抗样本应同时存在；验证器与生成器共享错误数据时，reward hacking 很难被发现。

5. 质量—成本—延迟曲线

策略质量变量成本变量适用条件
单次长思考推理 token串行延迟难以并行的任务
best-of-n候选数、聚合器并行 token有可靠 verifier
speculative接受率草稿模型主模型验证便宜

6. 最小实验

用 100 道固定题目，扫描 n∈{1,2,4,8,16}，分别运行 temperature 采样、self-consistency 和 verifier 选择。报告 pass@k、平均/ p95 token、墙钟延迟、美元成本和 verifier 与人工的一致率，并以 bootstrap 给出区间。
