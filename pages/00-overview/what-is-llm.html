入门

什么是大模型

剥掉所有包装，大模型只做一件事：给定前面的文字，猜下一个词。可就是这一件事做到极致之后，长出了写代码、解数学题、当助手的能力。这一页要说清四件事——它究竟是什么、「大」到底大在哪、为什么看起来会思考、以及它做不到什么。

一图看懂

大模型的全部工作可以浓缩成一个循环：把文字切成 token，每个 token 变成向量，几十层网络反复加工，输出下一个 token 的概率分布，采样一个，拼回输入再来一轮。就像手机输入法的联想功能，只是把「联想下一个词」这件事做深了好几个数量级。

它本质上是一个下一个词预测器

「大语言模型」（Large Language Model，LLM）这个名字里，「语言模型」才是本体，「大」只是形容词。语言模型的定义几十年没变过：对「下一个词出现的概率」建模。给定前文 $x_1, \dots, x_{t-1}$，输出下一个位置的条件概率分布 $P(x_t \mid x_1, \dots, x_{t-1})$。

注意这里的输出不是一个词，而是整个词表上的一整条概率分布。主流模型的词表规模通常在数万到十几万量级，所以模型每走一步，实际上是在给十万左右的候选各打一个分。至于最终吐出哪个，由解码策略决定——温度调高就更爱冒险，温度调到 0 就永远选概率最高的那个。

训练目标同样只有一条：遮住下一个 token 让模型猜，猜错就按误差反向调整参数，在海量文本上重复这个过程。没有人告诉它语法规则，没有人标注词性和句法树，这些结构是它为了把下一个词猜得更准而自己长出来的副产品。

一句话直觉 它不是一个查得到答案的数据库，而是一台把海量文本里的规律压缩进权重的续写引擎。你问它问题，它并不「查」，它是在续写一段「有人提问、有人回答」的对话。

同一份概率分布，能采出完全不同的文风

很多人以为「模型答得好不好」全看模型，其实解码这一步的影响大到经常被低估：同一个模型、同一句提示，换一组采样参数就能得到风格截然不同的输出。下面这张表是你最常在 API 里见到的几个旋钮。

参数它在动哪一步调大会怎样典型用途
temperature 温度Softmax 之前把 logits 整体除以它，改变分布的陡峭程度分布变平，低概率词更容易被采中，输出更发散也更容易跑偏创意写作调高；抽取信息、生成 JSON 调到接近 0
top-k只在概率最高的 k 个候选里采样，其余直接丢弃候选池变大，多样性上升，出现离谱词的风险也上升需要稳定输出时配合小 k 使用
top-p 核采样按概率从高到低累加，凑够 p 就截断，候选个数随分布动态变化候选池变大，效果类似 top-k 但更自适应目前最常用的默认策略

这里有一个非常实用的推论：当你发现模型「答得不稳定」时，先去看温度而不是急着换模型。把温度设为 0 之后如果输出就固定了，那问题在采样；如果依然飘，那才是提示或模型本身的问题。各种解码策略的完整机制见 解码策略。

动手看一眼那条概率分布

光说「输出是一条分布」比较抽象，最快的建立直觉的办法是亲眼看一次。下面这段代码用 Hugging Face Transformers 拿到最后一个位置的 logits，转成概率后打印前五名：

from transformers import AutoTokenizer, AutoModelForCausalLM
import torch

name = "Qwen/Qwen2.5-0.5B"        # 换成你本地已有的任意 causal LM 即可
tok = AutoTokenizer.from_pretrained(name)
model = AutoModelForCausalLM.from_pretrained(name)
model.eval()

text = "今天天气"
ids = tok(text, return_tensors="pt").input_ids

with torch.no_grad():
    logits = model(ids).logits        # 形状 (batch, seq_len, vocab_size)

next_logits = logits[0, -1]           # 只取最后一个位置
probs = torch.softmax(next_logits, dim=-1)
top = torch.topk(probs, k=5)

for p, i in zip(top.values, top.indices):
    print(f"{tok.decode(i)!r:>10}  {p.item():.4f}")

你会看到类似「真 / 不错 / 怎么样 / 很」这样一组候选，各自带一个概率。模型每生成一个字，背后都是这么一次全词表打分。把 vocab_size 打印出来，你还能直观感受到词表有多大——这也是为什么最后一层的输出投影矩阵通常是整个模型里最大的单个矩阵之一。

往模型内部看一眼：那张著名的架构图

「几十层网络反复加工」到底长什么样？与其听文字描述，不如直接看 2017 年那篇开创性论文《Attention Is All You Need》里的架构图。它是整个深度学习圈被引用最多的图之一，值得花两分钟逐块读懂——因为当代几乎所有大模型，无论 GPT、Llama 还是 Qwen，骨架都是这张图。

新手读这张图，先抓三块，其余先别管：① 中间的「Multi-Head Attention」（多头注意力）是模型的记忆与关联机制——它决定生成下一个词时该"看"输入里的哪些位置；② 右边的「Masked Multi-Head Attention」（带掩码的多头注意力）保证生成第 t 个词时只能看前 t−1 个词，不能偷看未来——这正是本页开头说的"自回归"；③ 最下面箭头指向的「Input Embedding / Output Embedding」就是把词变成向量、把向量变回词的入口和出口，对应前面说的分词与全词表打分。右侧那个 N× 意味着这一套要叠很多层——层数越多，模型越大，也就越"大模型"。

如果你现在觉得「没全看懂」，完全正常。这张图会在本书的 Transformer 完整架构 里被拆成零件逐个讲透，这里只需要一个整体印象：它是一台"边看边写"的机器——写每个字之前，先回头扫一遍已经有的内容，决定下一个字怎么写。把这张图留在脑子里，后面所有章节都是在给它加细节。

「大」大在哪：三个能拧的旋钮

那么「大」大在哪？三件事同时放大：参数量（网络里可训练的权重个数）、数据量（喂进去的 token 总数）、算力（训练消耗的浮点运算）。三者之间存在可预测的定量关系，这是 Scaling Laws 研究的内容。而放大之所以带来质变，一个直接的原因是：要把下一个词猜得足够准，你不得不真正学会点什么。

旋钮它衡量什么常见量级拧到头会撞上什么
参数量权重的个数，决定模型能记住多少、表达多复杂的函数从端侧的十亿以下，到旗舰模型的数千亿；MoE 架构下还要区分总参数与激活参数显存墙：权重放不进单卡，必须切分并行
数据量预训练消耗的 token 总数当代主流基座普遍在万亿 token 以上高质量语料枯竭，只能靠清洗、去重与合成数据补
算力训练总浮点运算量，约等于参数量与 token 数的乘积再乘一个常数大规模训练以「多少张卡跑多少天」计预算墙与训练稳定性：跑得越久越容易遇到 loss spike

参数量最容易被换算成一个你能立刻感知的数字：显存。权重按什么精度存，就按每个参数几字节来算——FP16 或 BF16 是每参数 2 字节，INT8 是 1 字节，INT4 是 0.5 字节。于是一个 7B 模型的 FP16 权重就是 $7 \times 10^9 \times 2 \approx 14$ GB。

按「参数量 × 每参数字节数」直接换算的纯权重显存。真实部署还要再加 KV Cache、激活值、框架开销，通常要在这个数字上再留出可观余量。量化的原理与代价见 量化、剪枝与模型压缩。

别只看参数量 两个同样标着「7B」的模型，能力可能差出一代。因为参数量只是三个旋钮之一——训练 token 数、数据质量、后训练配方的贡献同样大。近年小参数模型在特定任务上打平甚至超过更大模型，已经是常态。参数量决定的是能力上限，不是实际能力。

为什么它看起来会思考

「预测下一个词」听起来是个很低级的任务，但它其实是一道伪装成填空题的通用任务。想象训练语料里有这样一句：

「这道题：一个水池进水管 3 小时注满，出水管 5 小时放空，两管齐开需要____小时。答案是 7.5。」

要把这个空填对，模型没有捷径可走——它必须在内部真的完成那次算术。同理，要续写一段代码的下半部分，它得理解上半部分的变量作用域；要续写一篇论证文的结论，它得跟上前面的逻辑链。损失函数只惩罚预测错误，但为了少犯错，模型被迫在内部构建出可复用的推理结构。这是「压缩即理解」这个说法的来源。

不过，你今天在对话框里用到的那个「助手」，和刚训完的模型不是一回事。中间隔着两到三个阶段：

阶段做什么数据规模的量级差异产出什么
预训练在海量无标注文本上做下一个词预测万亿 token 级基座模型：知识和语言能力都有了，但只会「续写」，你问它问题它可能给你再编三个类似的问题
监督微调 SFT用「指令-回答」样本对示范怎么应答通常在万到百万条量级，比预训练小好几个数量级会听话了：知道被问就该答，而不是接着往下写
偏好对齐 / 强化学习用人类偏好或可验证的奖励信号打磨偏好对数量级与 SFT 相近，但需要在线采样答得有用、诚实、无害；长思维链推理能力也主要在这一步被训出来

三个阶段分别对应本书的 预训练目标、SFT 监督微调 和 RLHF。记住这条分界很有用：很多人抱怨「模型不听指令」，其实是在拿基座模型当助手用。另一个直接推论是——后两个阶段的数据量比预训练小好几个数量级，却几乎决定了你对这个模型的全部主观印象。这也是为什么同一个开源基座，被不同团队微调后气质能差得像两个产品。

别过度拟人化 「看起来会思考」和「在思考」是两回事。模型没有跨对话的连续自我、没有目标、没有信念状态；每次请求它都从同一份冻结的权重出发，你上一次说的话如果不放进上下文，它就完全不知道。把它当成「一个能力很强但完全失忆的临时工」，比当成「一个人」更有助于用好它。

涌现能力：真现象，但别当神话

涌现能力（Emergent Abilities）指的是这样一类观察：某些能力在小模型上的表现几乎等于随机猜，但当规模越过某个点后，表现突然大幅跃升。多步算术、按自然语言指令完成没见过的任务，都曾被当作典型例子。这个说法在 2022 年前后广为流传，也塑造了「继续把模型做大就会有惊喜」的行业预期。

但后续研究给出了一个相当有力的反驳：涌现在很大程度上可能是评测指标不连续造成的假象。逻辑是这样的——如果你用「五位数加法完全算对才得分」这种全或无的指标，那么即使模型的底层能力（比如对正确答案的对数概率）是随规模平滑上升的，它在跨过「每一位都对」的阈值前得分都会趋近于零，跨过之后陡然拉升，曲线看上去就像突变。换成连续指标重新画一遍，同样的数据往往会变成一条平滑曲线。

视角主张对工程的含义
涌现是真实的相变规模越过阈值后出现质变，不可从小模型外推只能靠实际把模型做大来试，小规模实验没有预测力
涌现是指标假象底层能力平滑增长，离散指标制造了断崖换连续指标就能在小规模上提前看到趋势，可以外推

两种视角目前都还没被完全证伪，但对使用者来说，更稳妥的姿势是采纳第二种视角的方法论：不要指望换个更大的模型就自动解锁你要的能力，而是先为你的任务设计一个有区分度的连续指标，在小模型上量出趋势，再决定要不要为规模买单。

落到实操上，「连续指标」可以简单到这个程度：不要只统计「答案完全正确的比例」，而是同时记录格式合法率、关键字段命中率、正确答案的排名这类会随能力平滑变化的量。这几个数字在小模型上就会动，能提前几周告诉你「这条路走得通」还是「换多大都不行」。相关的评测设计问题见 评估方法论。

能力边界：四类它真的做不到的事

知道边界在哪，比知道它能做什么更重要——因为踩坑几乎全都发生在边界上。下面四类问题不是「模型还不够好」，而是由它的工作方式直接决定的结构性限制。

还有一条容易被忽略：它对自己的解释不可靠。你问「你刚才为什么这么答」，它给出的是一段听起来合理的事后叙述，未必对应内部真实的计算过程。模型写出来的思维链和它实际据以得出答案的路径是否一致，是一个仍在研究中的开放问题，见 机制可解释性基础。

展开：为什么「数一数 strawberry 里有几个 r」这么难？

这个经典案例正好把两条边界串在一起。首先，模型看到的不是字母序列，而是分词器切出来的 token——一个英文单词可能只是一两个 token，单词内部的字母构成对模型是不透明的，就像你隔着毛玻璃数窗外的树叶。

其次，即使它「知道」拼写，计数也是一个需要精确迭代状态的操作，而 Transformer 的一次前向传播里没有可循环的计数寄存器，只能靠注意力层数硬堆出有限步的近似。

所以这类任务的正确解法从来不是「换个更强的模型」，而是换个执行体——让它写一行 s.count('r') 交给解释器跑。分词的具体机制见 词元化 Tokenization。

同一个原理还解释了一批看起来毫不相关的失败：让它把一句话倒着写、统计一段文字有多少个字、判断两个长数字哪个大、给一首诗做藏头。凡是需要按字符精确操作的任务，都在分词这一层就已经输了。遇到这类需求，第一反应应该是「这该交给代码」，而不是「换个提示词再试试」。

澄清三个最常见的误解

误解一：它在联网查资料

默认情况下不会。它的回答全部来自权重里压缩的统计规律。只有当产品显式接入了检索或浏览工具时，才会真的去取外部信息——而那已经是一个系统，不只是一个模型了。

误解二：参数越多一定越强

参数量只是三个变量之一。数据质量、训练 token 数、后训练配方的影响同样大。近年来小参数量模型在特定任务上打平甚至超过更大模型，已经是常态。

误解三：它会记住我说的话

模型权重不会因为你和它聊天而改变。你感觉到的「记忆」，是产品层把历史对话重新塞回上下文，或者外挂了一套记忆系统。关掉那层，它就是完全的失忆状态。

展开：那它到底「记住」了多少训练数据？

一个常见的追问是：既然它把海量文本压进了权重，是不是等于存了一份互联网的副本？答案是不是，但也不能说完全没存。

先看数量级。把参数量和训练 token 数放在一起比就会发现，参数远远少于它见过的 token。这意味着模型物理上不可能逐字记住语料——它必须做有损压缩，保留可复用的规律、丢掉具体的措辞。这也是为什么它能流畅谈论一个话题，却给不出准确的出处。

但「有损」不等于「零记忆」。在训练语料里高频重复出现的内容——常见诗句、开源协议正文、被大量转载的代码片段——确实可能被逐字复现。这既是训练数据版权争议的技术根源，也是隐私保护与模型安全里「训练数据提取攻击」这一类研究的前提。

对使用者来说，实用的结论只有一条：它给出的任何具体引用、链接、条款编号，都应当默认为待核实。要它给准确出处，就得把出处放进上下文里，也就是走 RAG 那条路。

新手最容易搞错 很多人第一次读架构图会问：「编码器和解码器是不是两个不同的模型？」对绝大多数生成式大模型（GPT、Llama、Qwen）来说，只用右边解码器那半套，左边编码器整个省略——因为聊天不是"整段翻译"，而是"顺着写下去"。左右都用的是机器翻译时代的 Seq2Seq 模型；到了 GPT 时代，大家发现"光有解码器也能学会一切"，于是左边退出了历史舞台。看到论文里的架构图别慌：你平时用的模型，只涉及它的右半部分。
展开：为什么光靠"猜下一个词"能学会语法、事实甚至推理？

这是每个新手都会问的问题。答案是三个层次的递进：

第一层：预测本身就需要理解。要让「今天天气真____」的空格填得准，模型必须知道"天气"和"好/不错/晴"这些词经常一起出现——这已经是词汇搭配层面的统计知识。要让「他昨天把书放在____上，今天却找不到了」填对"桌子"，模型必须理解"放在…上"和"找不到"之间的物理场景——这逼着它建立一点世界模型。

第二层：任务多样到没有捷径。训练语料里什么都有：数学题、代码、论文、小说、对话。同一个"猜下一个词"的目标，在数学题上逼它学会算术，在代码上逼它学会语法与逻辑，在小说上逼它学会叙事结构。模型无法为每个任务准备专用模块，只能长出通用的内部表示——这是"涌现"的底层来源。

第三层：规模让规律无处可藏。数万亿 token 里，"如果 A 那么 B"的因果关系、"A 是 B 的父亲，B 是 C 的母亲，那么 C 是 A 的____"这类逻辑链，出现的次数足够多。参数越多，模型越有能力把这些规律"刻"进权重而非死记硬背。注意最后一句话的关键：它学的是规律，不是例句——这也解释了为什么它能回答没见过的问题，却记不住精确的出处。

用一句话收束：「猜下一个词」是目标，「学会世界」是副产品，规模是把副产品做大的放大器。更严格的机制讨论见 机制可解释性基础。

要点速查

  • 本质：对 $P(x_t \mid x_{<t})$ 建模的自回归续写引擎，每步输出全词表概率分布，采一个，拼回去，再来一轮。
  • 解码同样重要：温度、top-p、重复惩罚会显著改变输出风格。输出不稳定时先查温度，再怀疑模型。
  • 「大」的三个旋钮：参数量、数据量、算力，三者关系由 Scaling Laws 刻画；参数量可直接换算显存，FP16 每参数 2 字节。
  • 基座 ≠ 助手：预训练给知识，SFT 给听话，偏好对齐给有用与安全。后两步数据量小几个数量级，却决定了你的主观印象。
  • 涌现：确有观察，但很可能被离散评测指标放大。工程上应改用连续指标提前量趋势。
  • 四条硬边界：精确计算、事实幻觉、知识截止、无状态记忆——都要靠系统而不是靠模型本身解决。
  • 自我解释不可信：它对「我为什么这么答」的回答是事后叙述，不是内省报告。
  • 心智模型：一个能力极强、但完全失忆、且不会主动承认自己不知道的临时工。

发展脉络

语言模型从统计计数、神经概率模型演进到自回归 Transformer；指令微调、偏好对齐和工具层改变的是交互行为，不应与基座训练混为一谈。

机制抓手

一次生成依次经过分词、embedding、逐层前向、logits、采样和 KV Cache 更新；模型权重、输入上下文与外部工具是三种不同的信息来源。

工程权衡

更大模型提高模式覆盖，却不会自动获得实时事实、精确计算和持久记忆；这些能力通常需要检索、代码执行与状态系统。

前沿观察

推理模型、多模态模型与 Agent 把测试时计算和环境反馈纳入系统，但“会生成解释”仍不等价于解释忠实。
