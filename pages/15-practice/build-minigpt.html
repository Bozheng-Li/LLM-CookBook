实战：从零实现 miniGPT

两百行 PyTorch 代码，搭出一个可训练的 decoder-only Transformer，并在真实文本上跑通完整的「数据加载 → 前向 → 反向 → 采样生成」闭环。读完这一页，你就拆掉了大模型的第一层神秘感——它不再是黑盒，而是你能逐行追踪的计算图。

一图看懂

miniGPT 的全部就是三件事：把文本切成 token 序列，用因果自注意力逐个预测下一个 token，用交叉熵梯度更新权重。没有魔法，只有矩阵乘法。

为什么从零实现

你可以直接用 Hugging Face 的 AutoModelForCausalLM，一行代码加载预训练模型。但那样你永远不会理解：为什么位置编码很重要？为什么需要因果掩码？残差连接到底在残差什么？

从零实现的价值不在于造一个能用的模型——nanoGPT 训练出来的小模型能力远不如任何开源模型。价值在于：当你遇到训练发散、梯度爆炸、loss 不下降的时候，你知道该去哪里找问题。这份经验是从 API 调用者到算法工程师的分水岭。

一个具体的例子：当你的训练 loss 在 200 步时突然变成 nan，有实现经验的人会立刻去查梯度裁剪和初始化方差，而不是盲目调小学习率。这种「知道去哪找问题」的直觉，只能从亲手写过前向和反向的人身上长出来。再比如推理时显存爆了，你会自然想到是激活值还是权重占大头，从而决定用梯度检查点还是量化——这些判断都建立在对计算图的真实理解上，而不是对 API 的模糊印象。

还有一个隐性的收获：从零实现会让你对「抽象泄漏」习以为常。用 transformers 时，model(config) 一行就建好了网络，出问题时你面对的是「框架行为」，解释空间很大；自己写时，出问题的每一层都是你能直接打印、直接断言的张量。这种「能直接摸到底层」的掌控感，会让你在调大模型时更敢于做假设、验证假设，而不是靠玄学试参数。

本页的实现灵感来自 Karpathy 的 nanoGPT，但进一步精简到约 200 行，确保每一行都能在单卡 GPU（甚至 CPU）上跑通。

第一步：模型定义（约 100 行）

整个 miniGPT 模型由四个组件组成：多头因果注意力、前馈网络、Transformer Block（组合前两者 + 残差 + LayerNorm）、完整 GPT（embedding + N 个 block + 输出头）。

import torch
import torch.nn as nn
import torch.nn.functional as F
from dataclasses import dataclass

@dataclass
class GPTConfig:
    vocab_size: int = 256       # 字符级词表，ASCII 0-255
    block_size: int = 128       # 上下文窗口长度
    n_layer: int = 4            # Transformer 层数
    n_head: int = 4             # 注意力头数
    d_model: int = 128          # 模型维度
    dropout: float = 0.1

class CausalSelfAttention(nn.Module):
    """多头因果自注意力：每个位置只能看到自己和之前的 token"""

    def __init__(self, config: GPTConfig):
        super().__init__()
        assert config.d_model % config.n_head == 0
        # QKV 合并到一个线性层，减少 kernel launch 开销
        self.qkv = nn.Linear(config.d_model, 3 * config.d_model, bias=False)
        self.proj = nn.Linear(config.d_model, config.d_model, bias=False)
        self.n_head = config.n_head
        self.d_head = config.d_model // config.n_head
        self.dropout = config.dropout
        # 因果掩码：上三角为 -inf，softmax 后变成 0
        mask = torch.tril(torch.ones(config.block_size, config.block_size))
        self.register_buffer("mask", mask.view(1, 1, config.block_size, config.block_size))

    def forward(self, x):
        B, T, C = x.shape                     # batch, seq_len, d_model
        qkv = self.qkv(x)                      # (B, T, 3C)
        q, k, v = qkv.split(C, dim=-1)         # 各 (B, T, C)
        # 重排为 (B, n_head, T, d_head)
        q = q.view(B, T, self.n_head, self.d_head).transpose(1, 2)
        k = k.view(B, T, self.n_head, self.d_head).transpose(1, 2)
        v = v.view(B, T, self.n_head, self.d_head).transpose(1, 2)
        # 注意力分数：(B, n_head, T, T)
        att = (q @ k.transpose(-2, -1)) / (self.d_head ** 0.5)
        att = att.masked_fill(self.mask[:, :, :T, :T] == 0, float('-inf'))
        att = F.softmax(att, dim=-1)
        att = F.dropout(att, p=self.dropout, training=self.training)
        # 加权求和：(B, n_head, T, d_head) → (B, T, C)
        out = (att @ v).transpose(1, 2).contiguous().view(B, T, C)
        return self.proj(out)

class FeedForward(nn.Module):
    """前馈网络：两层线性 + GELU 激活，中间层扩展 4 倍"""

    def __init__(self, config: GPTConfig):
        super().__init__()
        self.fc1 = nn.Linear(config.d_model, 4 * config.d_model, bias=False)
        self.fc2 = nn.Linear(4 * config.d_model, config.d_model, bias=False)
        self.dropout = config.dropout

    def forward(self, x):
        return self.fc2(F.dropout(F.gelu(self.fc1(x), approximate='tanh'),
                                   p=self.dropout, training=self.training))

class Block(nn.Module):
    """一个 Transformer Block：Pre-Norm + 注意力 + 残差 + Pre-Norm + FFN + 残差"""

    def __init__(self, config: GPTConfig):
        super().__init__()
        self.ln1 = nn.LayerNorm(config.d_model)
        self.attn = CausalSelfAttention(config)
        self.ln2 = nn.LayerNorm(config.d_model)
        self.ffn = FeedForward(config)

    def forward(self, x):
        # Pre-Norm：先归一化再进子层，残差连接跨子层
        x = x + self.attn(self.ln1(x))
        x = x + self.ffn(self.ln2(x))
        return x

class GPT(nn.Module):
    """完整的 decoder-only GPT"""

    def __init__(self, config: GPTConfig):
        super().__init__()
        self.config = config
        self.tok_emb = nn.Embedding(config.vocab_size, config.d_model)
        self.pos_emb = nn.Embedding(config.block_size, config.d_model)
        self.blocks = nn.ModuleList([Block(config) for _ in range(config.n_layer)])
        self.ln_f = nn.LayerNorm(config.d_model)
        # 权重共享：输出层和 token embedding 用同一个矩阵
        self.lm_head = nn.Linear(config.d_model, config.vocab_size, bias=False)
        self.lm_head.weight = self.tok_emb.weight  # weight tying
        # 初始化
        self.apply(self._init_weights)

    def _init_weights(self, module):
        if isinstance(module, nn.Linear):
            torch.nn.init.normal_(module.weight, mean=0.0, std=0.02)
        elif isinstance(module, nn.Embedding):
            torch.nn.init.normal_(module.weight, mean=0.0, std=0.02)

    def forward(self, idx, targets=None):
        B, T = idx.shape
        pos = torch.arange(T, device=idx.device).unsqueeze(0)  # (1, T)
        x = self.tok_emb(idx) + self.pos_emb(pos)               # (B, T, d_model)
        for block in self.blocks:
            x = block(x)
        x = self.ln_f(x)
        logits = self.lm_head(x)                                 # (B, T, vocab_size)
        loss = None
        if targets is not None:
            loss = F.cross_entropy(
                logits.view(-1, logits.size(-1)),
                targets.view(-1),
                ignore_index=-1
            )
        return logits, loss
Weight Tying lm_head 和 tok_emb 共享同一个权重矩阵——这不是为了省参数，而是因为「从 token id 到向量」和「从向量到 token 概率」本就是同一个语义空间的正反映射。共享权重让训练更稳定，是 GPT-2 以来的标准做法。

第二步：数据准备（约 30 行）

用字符级分词——每个 ASCII 字符就是一个 token。词表大小只有 256，让小模型也能学到有意义的模式。

class CharDataset:
    """字符级数据集：把文本转成 token id 序列"""

    def __init__(self, text: str, block_size: int):
        chars = sorted(set(text))
        self.stoi = {ch: i for i, ch in enumerate(chars)}
        self.itos = {i: ch for i, ch in enumerate(chars)}
        self.vocab_size = len(chars)
        self.data = torch.tensor([self.stoi[ch] for ch in text], dtype=torch.long)
        self.block_size = block_size

    def __len__(self):
        return len(self.data) - self.block_size

    def __getitem__(self, idx):
        # x 是 block_size 个 token，y 是 x 右移一位
        x = self.data[idx : idx + self.block_size]
        y = self.data[idx + 1 : idx + self.block_size + 1]
        return x, y

# 加载数据
with open("input.txt", "r", encoding="utf-8") as f:
    text = f.read()

config = GPTConfig(vocab_size=len(set(text)), block_size=128)
dataset = CharDataset(text, config.block_size)
print(f"词表大小: {dataset.vocab_size}, 语料长度: {len(dataset.data)} tokens")

这里有一个关键设计：目标 y 是输入 x 右移一位。位置 $t$ 的输入预测位置 $t+1$ 的 token，这就是「下一个 token 预测」任务。因果掩码保证了位置 $t$ 只能看到 $0$ 到 $t$，不会偷看未来。

为什么用字符级而不是词级？因为词表是「学」出来的，需要从语料统计；字符级分词词表固定为 256 个 ASCII 码，零训练成本、零未知词。代价前面说过：序列变长。一个额外的好处是：字符级模型的输出层直接对应可见字符，你可以肉眼检验它学到的拼写模式，调试非常直观。如果你之后想换成 BPE，只要替换 CharDataset 里的分词逻辑，训练循环和模型代码一行都不用改——这就是「数据加载与模型解耦」的体现。另外注意 __getitem__ 返回的 x 和 y 都带 block_size 长度，DataLoader 会把它们自动堆成 batch，所以 __len__ 返回的是「可切的窗口数」，而不是样本数——这个细节写错会导致取不到数据而报空 batch。

第三步：训练循环（约 40 行）

from torch.utils.data import DataLoader

def train(model, dataset, config, epochs=10, lr=3e-4, batch_size=64, device="cuda"):
    model = model.to(device)
    optimizer = torch.optim.AdamW(model.parameters(), lr=lr, weight_decay=0.1)
    # 余弦退火学习率
    scheduler = torch.optim.lr_scheduler.CosineAnnealingLR(optimizer, T_max=epochs * len(dataset) // batch_size)
    loader = DataLoader(dataset, batch_size=batch_size, shuffle=True, num_workers=4)

    model.train()
    step = 0
    for epoch in range(epochs):
        for x, y in loader:
            x, y = x.to(device), y.to(device)
            logits, loss = model(x, targets=y)
            optimizer.zero_grad()
            loss.backward()
            # 梯度裁剪：防止梯度爆炸
            torch.nn.utils.clip_grad_norm_(model.parameters(), 1.0)
            optimizer.step()
            scheduler.step()
            step += 1
            if step % 200 == 0:
                print(f"epoch {epoch} step {step} loss {loss.item():.4f} lr {scheduler.get_last_lr()[0]:.2e}")
    return model

# 开始训练
model = GPT(config)
if torch.cuda.is_available():
    device = "cuda"
elif hasattr(torch.backends, 'mps') and torch.backends.mps.is_available():
    device = "mps"
else:
    device = "cpu"
    print("警告：未检测到 GPU，训练会很慢。建议减少 epochs 或使用 Colab。")

model = train(model, dataset, config, epochs=10, device=device)

训练循环里值得注意的参数是 weight_decay=0.1：AdamW 的权重衰减与动量更新是解耦的，它不直接惩罚梯度的方向，而是把权重本身往零收缩一点。对没有 bias 和 norm 参数的矩阵权重，0.1 是常见的起点；对小玩具模型，它主要起「防过拟合」的作用——语料只有约 1MB，训练到后期 loss 很容易贴着训练集走，weight decay 能稍微缓解。另一个容易被忽视的是 scheduler.step() 的位置：它必须和 optimizer.step() 一一对应，每个 batch 更新一次，而不是每个 epoch 更新一次，否则余弦退火的相位会和实际步数错位，退火效果全废。最后，num_workers=4 让数据加载在四个子进程并行，避免 GPU 等数据——对玩具模型影响不大，但这是写真实训练脚本时的默认姿势。

训练发散怎么办 如果你看到 loss 变成 nan，按顺序排查：① 学习率太大（降到 1e-4 试试）；② 没做梯度裁剪（上面的 clip_grad_norm_ 不能省）；③ 初始化方差太大（检查 _init_weights 的 std 是否为 0.02）；④ 数据里有空 batch（检查 __len__ 是否返回 0）。

正常训练时你会看到 loss 从初始的约 2.5 一路下降。这里的直觉是：256 词表下随机猜测的负对数似然约为 ln(256)≈5.5，模型只要学会「下一个字符大概率还是字母、空格和标点」就能迅速压到 2.5 以下；再往后它才开始学单词边界、拼写和语法。在莎士比亚这类小语料上，最终训练 loss 通常稳定到约 1.0–1.5。

判断「收敛」不要只看最后一个数字，要看验证集 loss 的曲线：如果训练 loss 还在降、验证 loss 却开始回升，说明过拟合了，该停。玩具模型数据量小，往往几十分钟就能看到明显的语言模式涌现——这也是从零实现的乐趣之一：你能亲眼看着「智能」一点点长出来，而不是下载一个黑盒权重。等 loss 不再明显下降（连续几百步平台期），就可以停了，继续训也只是过拟合。

第四步：采样生成（约 20 行）

@torch.no_grad()
def generate(model, dataset, prompt: str, max_new_tokens: int = 200, temperature: float = 0.8, top_k: int = 40):
    model.eval()
    ids = [dataset.stoi[ch] for ch in prompt]
    idx = torch.tensor([ids], dtype=torch.long, device=next(model.parameters()).device)

    for _ in range(max_new_tokens):
        # 裁剪到 block_size 以内
        idx_cond = idx[:, -config.block_size:]
        logits, _ = model(idx_cond)
        logits = logits[:, -1, :] / temperature  # 只取最后一个位置
        # Top-K 采样：只从概率最高的 K 个 token 中采样
        if top_k is not None:
            v, _ = torch.topk(logits, top_k)
            logits[logits < v[:, [-1]]] = float('-inf')
        probs = F.softmax(logits, dim=-1)
        next_id = torch.multinomial(probs, num_samples=1)
        idx = torch.cat([idx, next_id], dim=1)

    return "".join([dataset.itos[i.item()] for i in idx[0]])

# 生成莎士比亚风格的文本
print(generate(model, dataset, prompt="ROMEO:\n", max_new_tokens=300))

训练 10 个 epoch 后（单卡 GPU 约 15 分钟），你会看到模型输出类似这样的文本——不完美，但有明显的单词边界、换行和标点模式，甚至偶尔出现看起来像莎士比亚对白的结构：

ROMEO:
Whave my the he mistaked the pacing
And thou the sould the ghat thes the masterd,
The ford the cound the the wour the be the sould the pacing

这已经是从零开始学到的东西——它学会了英文单词的拼写模式、冒号和换行的格式、甚至对白的大致结构。继续训练（更多 epoch、更大模型、更多数据），输出质量会持续提升。

如果生成结果完全不成样子（连单词边界都没有），先别急着怪模型——检查 prompt 是否在词表内：字符级模型只认识它见过的字符，prompt 里出现语料外的字符会映射到错误的 id。用 dataset.itos 打印一遍词表，确认所有字符都在里面，这是调试生成结果的第一步。

采样策略：Temperature 和 Top-K 到底在调什么

训练完只是上半场，生成时的采样策略决定了输出是「死板复述」还是「灵动创作」。核心是两个旋钮：Temperature 和 Top-K（以及常见的 Top-P）。

Temperature 作用在 softmax 之前：把 logits 除以一个温度 T。T 越大，概率分布越平滑，低概率 token 也有机会被选中，输出更多样；T 越小，分布越尖锐，模型越「自信」、越确定，但也更容易重复。T=1 是原分布，T→0 退化为贪心解码（永远选概率最高的 token）。

Top-K 作用在 softmax 之后：只保留概率最高的 K 个 token，其余置为 0 再重新归一化。K 越小输出越保守，K 越大越发散。Top-P（核采样）则是按累计概率截断，保留累计概率达到 P 的最小 token 集合，能自适应地控制候选数量。实践中常用 Top-P=0.9 或 Top-K=40 二者取一，再配合 Temperature=0.7~0.9。

策略调什么偏小效果偏大效果典型取值
Temperature分布平滑度确定、易重复多样、易跑题0.7–0.9
Top-K候选数量保守、安全发散、随机40
Top-P候选累计概率保守发散0.9

一个常见坑：当 loss 已经很低、模型能力也够，但生成结果「车轱辘话」反复循环，通常是 Temperature 太低或没做重复惩罚（repetition penalty）。把 Temperature 提到 0.9、加上重复惩罚往往就解决。采样本身不更新权重，所以调采样参数零成本——生成质量不理想时，先调它，再回头怀疑模型。

如果想更精确地理解两个旋钮，注意它们的生效位置：温度作用在 logits 上，即「决策前的最后一层」，对任何采样策略都生效；top-k、top-p 作用在 softmax 之后，属于「候选集合的过滤」。两者配合的典型思路是：先用 top-p 或 top-k 把明显不合理的候选滤掉，再用温度调节剩余候选之间的相对概率。调参顺序也有讲究——先固定 top-k=40 或 top-p=0.9，只动温度，找到「不重复也不太随机」的温度区间，再回头微调候选集合大小。一次只动一个旋钮，否则两个因素耦合在一起，出了问题你分不清是谁的锅。

学习率调度：warmup 与余弦退火为什么重要

训练里最容易踩的坑不是模型结构，而是学习率。miniGPT 默认用 AdamW + 余弦退火，并在前 10% 的步数做 warmup。为什么要这么麻烦？

warmup 的意思是：训练一开始不急着用大学习率，而是从接近 0 慢慢升到目标值。原因是初始化后权重仍处于「乱糟糟」的状态，一上来就用大步长容易把刚学到的微小结构冲掉，导致 loss 震荡甚至发散。warmup 让模型先「站稳」再加速，相当于发车前先松离合。

余弦退火则是让学习率随训练推进平滑下降，到末期接近 0。它的直觉是：前期用大步长快速靠近最优解区域，后期用小步长精细收敛、避免在最优点附近来回横跳。比起固定学习率，余弦退火通常能多挤出一点最终精度。上面代码里的 CosineAnnealingLR 配合每步调用 scheduler.step()，就是这套机制。如果嫌麻烦，也可以直接用 transformers 的 get_cosine_schedule_with_warmup，它会一次性把 warmup 和退火都安排好。

拆解一次前向传播：以 5 个 token 为例

代码能跑通，不代表你真的懂了。下面用一组具体数字把前向传播走一遍，把抽象的矩阵乘法落到可验证的数值上。假设 batch size=1、序列长度 T=5、模型维度 d_model=4、注意力头数 n_head=2（每头 d_head=2）、块数 n_layer=1，输入 token 序列是 [4, 1, 7, 2, 5]。

第一步，token embedding 把每个 id 查表成一个 4 维向量，再加上可学习的位置编码，得到输入矩阵 X（5×4）。第二步，QKV 线性层（维度 4→12）把 X 投影成 Q、K、V，各为 5×4，再拆成 2 个头、每头 5×2。第三步，算注意力分数 Q·Kᵀ / √d_head，得到一个 5×5 的分数矩阵；因果掩码把右上三角（未来的位置）填成 −∞，softmax 之后变成 0，于是位置 t 只能看到 0…t。第四步，用 softmax 之后的权重对 V 加权求和，得到每个位置的上下文向量。第五步，FFN 把这个向量从 4 维扩到 16 维再压回 4 维，并加回残差。最后 LM Head 把 4 维向量映射到词表（256 维）logits，取最后一个位置做 softmax，得到下一个 token 的概率分布。

关键观察：因果掩码是这份代码能学会「续写」的根本。如果没有掩码，每个位置都能看到整句话，模型会直接「抄」答案而不是「预测」下一个字——训练 loss 会虚假地很低，但生成时一无是处。这也是为什么前面 CausalSelfAttention 里那一长串 masked_fill 不能省。

把这个例子再往前推一步：如果你把 T=5 改成 T=128（代码里的默认 block_size），前向传播的机制完全不变，只是每个位置的「可见范围」从最多 5 个 token 变成最多 128 个。这就是「上下文窗口」的全部含义——它不是模型内部有什么特殊结构，而是因果掩码的尺寸决定了每个位置最多能回看多远。超过窗口的历史 token 根本进不了注意力计算，所以处理超长文本时要么截断、要么靠位置编码做长度外推（见 位置编码）。顺着这条线索还能想明白：为什么推理时要先把输入裁剪到 block_size 以内（第四步代码里的 idx[:, -config.block_size:]）——超了窗口的位置只能白算。

深入：为什么 Pre-Norm 比 Post-Norm 更不容易发散

残差连接 x = x + Sublayer(Norm(x))（Pre-Norm）把每一层的输出变成「上一层的输出 + 一个小的残差增量」。这意味着梯度在反向传播时有一条「高速公路」可以直接从深层流回浅层，不会被每层的小导数连乘压成 0（梯度消失）或爆成 ∞（梯度爆炸）。

Post-Norm（先子层后归一化，x = Norm(x + Sublayer(x))）的问题在于：归一化作用在残差「相加之后」，深层梯度要经过归一化的缩放才能传回去，训练不稳定，通常需要精细的 warmup 学习率。Pre-Norm 把归一化放在残差「相加之前」，残差路径上没有归一化，梯度回流更顺畅，所以 modern GPT 一律采用 Pre-Norm。

一个直观判断：把网络看成一条河，残差连接是并行的一条直河道。Pre-Norm 让直河道全程畅通；Post-Norm 在直河道上架了水闸（归一化），水（梯度）流得磕磕绊绊。这就是为什么上面的代码里写的是 x = x + self.attn(self.ln1(x))，而不是反过来。

从 miniGPT 到真实模型，差了什么

这个 200 行的 miniGPT 和真实的 GPT/Qwen/DeepSeek 之间，差的是工程量而非架构原理：

  • 规模：真实模型层数 32-80，维度 4096-8192，参数量 7B-671B。架构完全一样，只是大了几个数量级。
  • 分词：BPE/SentencePiece 替代字符级，词表 3-15 万，压缩序列长度。
  • 位置编码：RoPE 替代可学习位置编码，支持长度外推。详见 位置编码。
  • 注意力优化：Flash Attention 替代朴素实现，显存从 $O(n^2)$ 降到 $O(n)$。详见 Flash Attention。
  • 归一化：RMSNorm 替代 LayerNorm，去掉中心化只保留缩放，更快。详见 归一化技术。
  • 激活函数：SwiGLU 替代 GELU，引入门控机制。详见 前馈网络与激活函数。
  • 训练策略：分布式训练（数据/张量/流水线/序列/专家并行）、混合精度、课程学习。
  • 后训练：SFT + RLHF/DPO 对齐，让模型从「续写机器」变成「对话助手」。

其中「后训练」这一条常常被初学者忽略：真实的大模型在预训练之后还要经过 SFT 和偏好对齐，才能回答「怎么退款」这类问题——预训练模型只会续写，它可能在你问题的后面接一段「退款流程」的百科式文字，而不是像客服那样直接回答。miniGPT 停在「预训练」这一站，是因为这一页的主题是理解架构与训练机制；想体验「续写模型 → 对话助手」的完整转变，可以直接接着做 LoRA 微调全流程 里的实战。类似的，缩放定律（scaling law）告诉我们：模型的最终能力主要由「数据量 × 参数量 × 算力」决定，架构细节的影响往往小于数量级的差异——这也是为什么 minGPT 的 200 行代码能成为理解数千亿参数模型的钥匙。

核心收获 跑通 miniGPT 之后，你应该能回答这些问题：因果掩码为什么是上三角？Pre-Norm 为什么比 Post-Norm 稳定？权重共享为什么合理？梯度裁剪为什么必要？——这些问题的答案就是你后续读论文、调参数、排 bug 的直觉地基。

新手最容易搞错 训练 loss 下降不等于模型会生成：如果因果 mask 方向写反，训练时每个位置可能偷看目标 token，loss 会异常漂亮，推理时却完全失效。务必用一个极短序列打印 mask，确认上三角在 softmax 前是负无穷、下三角保持可见。
展开：最小可运行版本、验证步骤与排查清单

先把配置缩到 n_layer=1、n_head=2、d_model=32、block_size=32，用几百行文本跑一个 batch。验证输入输出形状：x 和 y 都应为 [B,T]，logits 应为 [B,T,vocab_size]，loss 应为有限标量。再做一次过拟合单 batch 实验：如果几十到几百步后 loss 不能明显下降，先不要扩大数据或模型。

排查顺序是：词表映射是否双射、y 是否右移一位、mask 是否因果、d_model % n_head == 0 是否成立、学习率和梯度是否有限。CPU 太慢时可减少 block_size 和 batch_size；显存不足时先缩短序列，因为注意力中间矩阵按 T² 增长；若只想理解架构而不训练，可用固定随机权重完成一次前向和形状断言。

要点速查

  • 架构：decoder-only Transformer = token embedding + position embedding + N × (因果自注意力 + FFN) + LM head。200 行足够。
  • 因果掩码：上三角填 -inf，softmax 后变 0，保证位置 t 只看到 0 到 t。
  • Pre-Norm：先 LayerNorm 再进子层，残差跨子层。比 Post-Norm 更稳，是现代 GPT 的标配。
  • Weight Tying：lm_head 和 tok_emb 共享权重，省参数、稳训练、语义一致。
  • 训练发散排查：学习率 → 梯度裁剪 → 初始化 → 数据，按这个顺序查。
  • 采样：Temperature 控制随机性，Top-K 截断长尾。生成质量 = 采样策略 × 模型能力。
  • 从 mini 到 real：架构原理一样，差的是规模、分词、位置编码、注意力优化、归一化、训练策略、后训练对齐。
