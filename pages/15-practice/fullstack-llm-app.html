实战：构建全栈大模型应用

这一章不再实现孤立算法，而是把模型、后端、前端、知识库、引用和测试连成一个可以交付的产品闭环。项目默认无密钥也能运行；接入任意 OpenAI-compatible 服务后，同一套接口即可切到真实模型。

完成标准

  • 能解释浏览器、应用后端、模型服务和知识库之间的数据边界。
  • 能用 SSE 将模型 token 增量传到前端，并正确处理完成、引用和错误事件。
  • 能写入文档、检索证据、把引用与回答分开传输，避免模型伪造来源。
  • 能在不修改前端契约的情况下，将演示检索替换为 Embedding 与 pgvector。
  • 能通过健康检查、API 测试和人工验收确认项目达到最小交付标准。

先修：RAG、结构化输出、可观测性。预计 2–4 小时。

一、先固定系统边界

生产系统不应让浏览器直接持有模型密钥。浏览器只认识你的业务 API；应用后端负责鉴权、模型路由、检索、日志和错误收敛；模型服务只是可替换依赖。这个边界决定了后续能否更换供应商、增加缓存或接入私有模型。

层本项目实现生产替换点必须观测
前端React + TypeScript + Vite登录、会话持久化、文件上传首 token 时间、失败率、取消率
应用 APIFastAPI + Pydantic鉴权、限流、队列、供应商路由状态码、模型耗时、token、成本
检索内存词法重叠Embedding + pgvector / 向量库Recall@k、空召回、索引新鲜度
模型demo 或 OpenAI-compatible云 API、本地 vLLM、模型网关TTFT、TPOT、超时、限流

二、先跑通无密钥闭环

参考项目位于 examples/fullstack-llm/。demo 模式不是一个假的静态页面：文档写入、检索、引用事件、SSE 分片和前端增量渲染全部走真实链路，只有模型 token 使用本地生成器。

cd examples/fullstack-llm/backend
python -m venv .venv
# Windows: .venv\Scripts\activate
pip install -r requirements-dev.txt
uvicorn app.main:app --reload --port 8000

# 新终端
cd examples/fullstack-llm/frontend
npm install
npm run dev
第一验收点访问 http://localhost:5173，左侧状态应显示 demo。写入一段至少 20 字的文档，再询问文档中的关键词；回答下方必须出现可展开引用。

三、把 SSE 当成正式接口契约

不要把模型供应商的原始数据流直接透传给前端。参考项目将其归一化为四类事件；前端只依赖这些稳定事件，后端可以自由更换模型 SDK。

event: citations
data: {"items":[{"id":"...","title":"部署说明","excerpt":"...","score":0.67}]}

event: token
data: {"text":"第一段增量文本"}

event: done
data: {"ok":true}

event: error
data: {"message":"模型服务暂时不可用，请稍后重试。"}

这里有三个容易忽略的工程点：错误事件不能泄露密钥和上游响应体；代理层要关闭缓冲，否则 token 会攒成整段才到浏览器；客户端解析器必须保留不完整的最后一个 SSE block，等下一批字节到达后再解析。

四、让检索证据独立于回答

后端实现把文档切成约 700 字的片段，演示检索使用中英文 token 重叠率排序。这个算法只用于验证数据流，但接口已经固定为 Citation：id、title、excerpt、score。升级到向量检索时只替换 search_documents，无需修改聊天接口和前端。

升级到 Embedding + pgvector

  1. 入库时保存 document_id、版本、chunk 顺序、权限标签和 embedding。
  2. 查询时先执行租户/权限过滤，再做向量或混合检索，最后重排。
  3. 引用对象返回稳定文档 ID 和片段 ID，不把数据库主键直接暴露给用户。
  4. 用带 gold evidence 的问题集测 Recall@k，而不是只看最终回答是否“像对的”。

五、接入真实模型服务

复制 .env.example 为 .env，设置端点、密钥和模型。后端只在服务器进程中读取密钥；前端、日志和 SSE 错误事件都不应出现密钥。

LLM_API_BASE=https://your-provider.example/v1
LLM_API_KEY=replace-me
LLM_MODEL=your-model
ALLOWED_ORIGINS=http://localhost:5173
不要照抄到生产示例为了可读性使用进程内文档存储，没有用户身份、持久化、限流和多租户隔离。它是端到端契约基线，不是生产部署模板。

六、按边界排查失败

现象优先检查不要先做
页面显示后端未连接/api/health、Vite proxy、端口更换模型或 prompt
回答一次性出现代理缓冲、SSE 空行、流式读取增加前端动画
没有引用文档是否入库、query token、top_k让模型自己编引用
有引用但答错引用是否真正支持答案、上下文拼接只增加召回数量
真实模型报错base URL、鉴权头、模型名、超时把上游完整错误返回浏览器

七、验收与扩展练习

cd examples/fullstack-llm/backend
pytest
curl http://localhost:8000/api/health

cd ../frontend
npm run build
  1. 基础：连续提交两次问题，确认第二次请求包含必要历史，但不包含欢迎消息。
  2. 检索：构造一个完全无关的问题，要求系统无引用时明确说证据不足。
  3. 可靠性：把模型端点改成无效地址，确认前端只显示可操作错误，不出现堆栈和密钥。
  4. 生产化：将 search_documents 替换为 pgvector，并用同一组 API 测试保证契约不变。
  5. 观测：为每次请求记录 request ID、检索耗时、TTFT、完成状态和估算 token 成本。
最终验收一个新开发者从干净 checkout 出发，能够在 20 分钟内启动 demo，写入文档、获得带引用的流式回答、运行后端测试和前端构建，并能指出四个生产替换边界。

阅读提示：先逐条复现协议和失败路径，再引入向量库、鉴权、持久化与观测，不要一开始就堆生产组件。

  • 官方文档FastAPI
    StreamingResponse ↗

    Server-sent events ↗

    掌握事件名、data 行、空行分隔和浏览器端连接语义，避免把 SSE 当成普通 JSON 响应。

  • Web 标准MDN
    ReadableStream 消费模式 ↗

    对照前端逐字节读取、缓冲不完整 block 和 AbortController 取消的实现。

  • 开源项目pgvector
    pgvector ↗

    从内存词法检索迁移到向量检索时，重点查看索引、距离度量和过滤条件的组合方式。

    OWASP LLM Top 10 ↗

发展脉络

大模型应用从浏览器直连模型的 demo，演进为前端、业务 API、检索、模型网关、评测和观测分层的可交付系统。

机制抓手

浏览器只依赖业务 SSE 契约；后端负责输入校验、检索引用、模型路由和错误收敛，citation/token/done/error 事件相互独立。

工程权衡

demo 内存检索便于理解链路，却不提供持久化、权限和语义召回；生产替换必须保持 API 契约并补齐限流、超时和审计。
