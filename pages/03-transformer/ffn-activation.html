入门

前馈网络与激活函数

注意力让词与词"看见"彼此，但真正把信息加工、存储、变换的，是每一层里的前馈网络（FFN）。它占了整个 Transformer 参数量的大头——动辄三分之二——却常常被注意力抢走聚光灯。这一节把 FFN 拆开，看它到底在算什么、激活函数怎么从 ReLU 演进到 SwiGLU、真实模型的中间维度是怎么定出来的，以及为什么换一个激活函数就得重算参数预算。

一图看懂

FFN 是每个 token 独立经过的一个"两层 MLP 升维-降维"过程：先把隐藏维度放大（通常 4 倍），过一个非线性激活函数，再缩回原来的维度。注意力负责词之间的信息融合，FFN 负责对每个词的信息做深度加工。一个管"交流"，一个管"思考"。

FFN 在 Transformer 里的角色

每个 Transformer Block 有两个子层：多头注意力和前馈网络。注意力部分让序列里每个位置互相"看"一眼，输出融合了上下文的新表示；FFN 则对每个位置独立做一次非线性变换——不同 token 之间不交互，只各自加工自己的向量。

为什么需要这个独立加工？因为注意力的本质是"加权平均"，它擅长信息路由（把相关的信息聚到一起），但加权平均是线性操作，表达能力有限。FFN 通过升维到更高维的空间、施加非线性、再降回来，让模型能学到复杂的特征变换——这更像传统 MLP 的"特征提取"角色。

一句话直觉 注意力是"开会讨论"，FFN 是"会后自己消化"。开会把信息汇总到每个人手里，但真正把信息吃透、变成自己的判断，还得靠每个人会后独立思考。

标准 FFN 的计算是两层线性变换夹一个激活函数：

$$\text{FFN}(\mathbf{x}) = W_2 \; \sigma(W_1 \mathbf{x} + b_1) + b_2$$

其中 $W_1 \in \mathbb{R}^{d_{ff} \times d}$、$W_2 \in \mathbb{R}^{d \times d_{ff}}$。$d_{ff}$ 是中间隐藏维度，原版 Transformer 取 $d_{ff} = 4d$。$\sigma$ 是激活函数。这个"升 4 倍再降回来"的设计让 FFN 的参数量远超注意力——以 $d=4096$ 为例，标准 FFN 两层权重共 $2 \times 4096 \times 16384 \approx 1.34$ 亿参数，而注意力的四个投影矩阵约 $4 \times 4096 \times 4096 \approx 6710$ 万，FFN 占了这个 Block 参数量的约 67%。

"逐位置"到底是什么意思

这个词在论文里叫 position-wise，初学者最容易误解。它的意思是：同一层里所有 token 共用同一套 $W_1$、$W_2$，但每个 token 各算各的，互不影响。换句话说，如果你把一个长度为 512 的序列打乱顺序再送进 FFN，出来的结果只是顺序被打乱，每个 token 自己的输出值完全不变——这和注意力形成鲜明对比，注意力打乱顺序后每个位置的输出都会变。

从实现角度看，这意味着 FFN 就是一次形状为 $(B\times n, d)\times(d, d_{ff})$ 的普通矩阵乘法，batch 和序列两个维度可以直接压平。这也是为什么 FFN 在 GPU 上极其高效：它是纯粹的大 GEMM，没有注意力那样的 softmax 和数据依赖。

参数量占比 在标准 Transformer 中，FFN 占每层参数量的约 2/3。这意味着当你听到"这个模型 7B 参数"，其中相当大一部分在 FFN 里。也正因如此，FFN 是模型压缩（量化、剪枝、MoE 替换）的重点战场。

激活函数的演进：从 ReLU 到 GELU

FFN 里那个激活函数 $\sigma$ 的选择，看似是个小细节，却直接影响模型的表达能力和训练稳定性。

ReLU

$\max(0, x)$。原版 Transformer 的选择。简单高效，但有"死神经元"问题：负输入梯度为 0，一旦神经元"死"了就不再更新。

GELU

高斯误差线性单元。GPT 系列、BERT 的选择。在 0 附近平滑过渡，没有 ReLU 的硬拐点，训练更稳。

SwiGLU

GLU 家族的变体，带门控机制。LLaMA、Qwen、DeepSeek 等现代大模型的标配。

GELU 的定义是：

$$\text{GELU}(x) = x \cdot \Phi(x), \quad \Phi(x) = \frac{1}{2}\left[1 + \text{erf}\!\left(\frac{x}{\sqrt{2}}\right)\right]$$

其中 $\Phi(x)$ 是标准正态分布的累积分布函数。直觉上，GELU 可以理解为"以 $x$ 的概率保留这个值"——$x$ 越大，越可能被保留；$x$ 很负时几乎被置零。和 ReLU 的"硬截断"不同，GELU 在 0 附近是平滑的，这意味着梯度处处存在，不会出现 ReLU 的死区问题。

实际实现中常用 $\tanh$ 近似来加速计算：

$$\text{GELU}(x) \approx 0.5x\left[1 + \tanh\!\left(\sqrt{2/\pi}\left(x + 0.044715x^3\right)\right)\right]$$

手把手读 GELU 论文原图

上面这些数值是「算好」的结论，而第一手证据长什么样？2016 年 Hendrycks 与 Gimpel 在提出 GELU 的论文里，把 GELU、ReLU、ELU 三条激活函数的曲线画在同一张图里对比。这张图被无数后续论文反复引用，是理解「平滑激活」与「硬截断激活」差异的经典教材，值得逐块读一遍。

读这张图，先看坐标系：横轴是输入 $x$，纵轴是输出 $y$，一条曲线就是一个函数。然后抓三个对比点。第一个，看 $x=0$ 附近：ReLU 在这里有个明显的硬拐点——左侧的曲线紧贴横轴（输出恒为 0），右侧变成一条斜率 1 的斜线。这个拐点意味着它在 0 处「断」了一下，导数不连续。ELU（Exponential Linear Unit，指数线性单元）在负半轴不再是平贴 0，而是缓缓回落、在 $x$ 很负时渐近到 $-1$ 附近，它保留了少量负信号，但拐点处的过渡仍然不是处处光滑的。GELU 则整条曲线圆润平滑，在 0 附近以「概率加权」的方式软化了截断——负的小输入会得到一个很小的负输出，而不是被直接清零。第二个，看负半轴的末段：GELU 与 ELU 都有一条微微下探再回升的弧线（这就是前面说的「非单调小凹陷」），而 ReLU 始终是直线 0。第三个，看 $x$ 较大的正半轴：三条曲线几乎重合，都趋近于直线 $y=x$——这说明激活函数的分歧只发生在 0 附近那一小段，而那恰恰是训练初期大量激活值聚集的区间，所以看似「只差一点」的曲线形状，实际效果差异是实实在在的。

还有一个细节值得注意：GELU 在 0 点既不等于 ReLU 那样直接归零，也没有 ELU 那种硬转折，它是用一个概率去「筛选」信号。这种处处有梯度、又带一点概率意味的性质，让它在 Transformer 这样需要几十上百层稳定回传梯度的结构里，比 ReLU 更不容易出现「死神经元」——这也是 GPT 系列与 BERT 放弃 ReLU 改选 GELU 的直观理由。

新手最容易搞错 把 GELU 说成「ReLU 的平滑版」只说对了一半：两者最大的行为差异在负半轴——ReLU 把一切负输入一刀切为零（梯度也随之消失），而 GELU 允许小幅负输出并保留小梯度。另一个高频误解是「position-wise（逐位置）等于每个 token 有自己的参数」——恰恰相反，同一层所有 token 共用同一套 $W_1$、$W_2$，只是各算各的互不干扰。记住了这一条，读源码时看到 FFN 是一块普通线性层就不会再犯迷糊。
踩坑实录：换了激活函数，参数预算悄悄涨了 50%

一次真实的踩坑过程：某团队想把一个标准 FFN（ReLU、$d_{ff}=4d$）升级成 SwiGLU，直接把激活函数换掉、其余不动，结果模型显存比预期大了一截，卡上装不下。原因其实写在公式里——标准 FFN 是 $2 \times d \times d_{ff}$，SwiGLU 因为多了一个门控矩阵 $W_{gate}$，变成 $3 \times d \times d_{ff}$，参数量比原来多出 50%。

更隐蔽的是第二种情形：有些人记得「SwiGLU 要用 8/3 倍率」，但只把 $d_{ff}$ 从 $4d$ 改到 $8d/3$，忘了它还要再向上对齐到 256 的倍数。以 $d=4096$ 为例，$\frac{8}{3}\times4096 \approx 10923$，直接取整后是 10923，而实际模型用的是 11008（$=43\times256$）。如果只是粗略取整、不按 256 对齐，参数量差异不大但 GEMM 效率会掉，张量并行时也可能分不匀。

排查口诀就一条：凡是动了激活函数，先重新算一遍参数量，再对一遍 $d_{ff}$ 的对齐倍数。用本页后面那段纯 Python 脚本（block_params）把新旧配置各算一次，数字对不上就说明预算记错了。

SwiGLU：门控激活的现代标配

GLU（Gated Linear Unit） 的核心思想是引入一个"门控"分支：不是对所有特征统一施加同一个非线性，而是让网络自己学习"哪些特征该通过、哪些该抑制"。GLU 的通用形式是：

$$\text{GLU}(\mathbf{x}) = (\mathbf{x} W_1 + b_1) \otimes \sigma(\mathbf{x} W_{gate} + b_{gate})$$

其中 $\otimes$ 是逐元素乘法，$\sigma$ 是某个激活函数。SwiGLU 就是把 $\sigma$ 换成 SiLU（也叫 Swish，$\text{SiLU}(x) = x \cdot \sigma_{sigmoid}(x)$），因此得名 Swi-GLU：

$$\text{SwiGLU}(\mathbf{x}) = (\mathbf{x} W_1 + b_1) \otimes \text{SiLU}(\mathbf{x} W_{gate} + b_{gate})$$

结构上，SwiGLU FFN 有三个权重矩阵而非两个：$W_{gate}$ 和 $W_1$ 都把 $d$ 维升到 $d_{ff}$ 维，它们的输出逐元素相乘（门控），再由 $W_2$ 降回 $d$ 维。这意味着同等中间维度下，SwiGLU 的参数量是标准 FFN 的 1.5 倍。

参数量换算 标准 FFN：参数量 $= 2 \times d \times d_{ff}$。
SwiGLU FFN：参数量 $= 3 \times d \times d_{ff}$（多一个 $W_{gate}$）。
为了让 SwiGLU 和标准 FFN 参数量持平，通常把 $d_{ff}$ 从 $4d$ 缩小到约 $\frac{8d}{3} \approx 2.67d$。LLaMA 就是这么做的——用更小的中间维度，但靠门控机制获得更强的表达能力。

为什么 SwiGLU 效果更好？门控机制让网络可以动态选择哪些维度参与计算——不同 token 可以激活不同的特征子集，这比统一施加一个 ReLU/GELU 灵活得多。GLU Variants 那篇论文用同等参数预算做了系统对比，门控变体在多项下游任务上优于普通 FFN。自 LLaMA 之后，Qwen、DeepSeek、Mistral 等几乎所有主流开源模型都采用了 SwiGLU。

为什么 Llama 的 11008 不是整数倍

细心的人会发现一个奇怪的数字：Llama-2-7B 的 $d_{ff}$ 是 11008，而 $\frac{8}{3}\times 4096 \approx 10923$。差的这 85 是怎么来的？

答案是对齐。$11008 = 43 \times 256$，是 256 的整数倍。GPU 上的矩阵乘法在维度对齐到 128 或 256 的倍数时，Tensor Core 的利用率最高；同时张量并行要把 $d_{ff}$ 均分到多张卡上，也要求它能被并行度整除。所以真实工程里的流程是：先按 $8d/3$ 算出理论值，再向上取整到 256 的倍数。这条不起眼的规则解释了几乎所有开源模型里那些"看起来很随机"的中间维度。相关的硬件背景见 GPU 架构。

展开：SwiGLU FFN 的 PyTorch 实现 
import torch
import torch.nn as nn
import torch.nn.functional as F

class SwiGLU_FFN(nn.Module):
    def __init__(self, d, d_ff=None, multiple_of=256):
        super().__init__()
        # 默认中间维度取 8d/3，让参数量与标准 4d FFN 持平
        if d_ff is None:
            d_ff = int(8 * d / 3)
            # 再向上对齐到 multiple_of 的倍数，提升 GEMM 效率
            d_ff = multiple_of * ((d_ff + multiple_of - 1) // multiple_of)
        # 三个矩阵：gate、up、down
        self.w_gate = nn.Linear(d, d_ff, bias=False)
        self.w_up   = nn.Linear(d, d_ff, bias=False)
        self.w_down = nn.Linear(d_ff, d, bias=False)

    def forward(self, x):
        # x: (batch, seq_len, d)
        gate = self.w_gate(x)              # (batch, seq, d_ff)
        up   = self.w_up(x)                # (batch, seq, d_ff)
        # SiLU(gate) * up  —— 门控相乘
        activated = F.silu(gate) * up      # (batch, seq, d_ff)
        return self.w_down(activated)      # (batch, seq, d)

现代实现通常把 w_gate 和 w_up 合并成一个 (d, 2*d_ff) 的大矩阵做一次 GEMM，再 split 成两路，减少一次 kernel 启动开销。另外注意三个 Linear 都设了 bias=False——现代大模型普遍去掉了 FFN 的偏置项，实测影响极小却能省下参数和一次加法。

展开：动手核对参数量与 FFN 占比

下面这段纯 Python 脚本不依赖任何框架，把上文那张对照表复算一遍。改改参数就能算你手上任何一个模型的配置：

def block_params(d, d_ff, gated=True, kv_heads=None, head_dim=None):
    """返回 (注意力参数, FFN 参数, FFN 占比%)"""
    if kv_heads is None:                      # 标准 MHA：四个 d×d 方阵
        attn = 4 * d * d
    else:                                     # GQA：K/V 投影变窄
        d_kv = kv_heads * head_dim
        attn = 2 * d * d + 2 * d * d_kv
    ffn = (3 if gated else 2) * d * d_ff
    return attn, ffn, ffn / (attn + ffn) * 100

configs = {
    "Transformer base": dict(d=512,  d_ff=2048,  gated=False),
    "GPT-2 small":      dict(d=768,  d_ff=3072,  gated=False),
    "Llama-2-7B":       dict(d=4096, d_ff=11008, gated=True),
    "Llama-2-70B":      dict(d=8192, d_ff=28672, gated=True,
                             kv_heads=8, head_dim=128),
}
for name, cfg in configs.items():
    a, f, r = block_params(**cfg)
    print(f"{name:18s} attn={a/1e6:7.1f}M  ffn={f/1e6:7.1f}M  FFN占比={r:.1f}%")

跑一遍你会发现前几行都稳定在 66.7% 上下，而带 GQA 的 70B 跳到 82% 左右。这个脚本最实用的地方是拿去读别人的 config.json：把 hidden_size、intermediate_size、num_key_value_heads 填进去，立刻知道这个模型的参数预算花在哪。

激活函数的族谱与演进线

激活函数看着零散，其实分成界限清晰的三族。理清族谱后，遇到新名字（GEGLU、ReGLU、Squared ReLU 之类）就能立刻归位。

FFN 与 MoE 的天然亲缘

FFN 是 Transformer 里参数最密集的部分，也是稀疏化最自然的切入点。MoE（混合专家）的核心想法就是：把一个大 FFN 拆成多个小 FFN（专家），每个 token 只激活其中 Top-K 个。这样总参数量可以做到极大，但单次计算量只和激活的专家数相关。

这解释了为什么 MoE 替换的总是 FFN 而不是注意力——注意力层的参数相对小（QKV 投影 + 输出投影），稀疏化收益有限；而 FFN 占了 2/3 参数量，是投入产出比最高的替换点。另一个原因是路由的语义合理性：FFN 是逐位置的独立计算，天然可以按 token 分派给不同专家；而注意力要跨位置交互，硬拆成多组会破坏信息流。详见 MoE 混合专家。

FFN 还是模型的"知识仓库"

还有一个值得知道的视角：有研究把 FFN 类比成一个键值记忆（key-value memory）——$W_1$ 的每一行是一个"键"，负责检测输入里是否出现某种模式；$W_2$ 的对应列是"值"，一旦该模式被检测到就往残差流里写入相应内容。中间维度 $d_{ff}$ 就相当于"记忆槽位的数量"。

这个视角能解释不少现象：为什么模型的事实性知识主要存在 FFN 里（模型编辑类工作大多在改 FFN 权重）、为什么把 $d_{ff}$ 调大比把层数加深更能提升知识容量、以及为什么 MoE 扩容如此有效——它本质上就是在扩充记忆槽位的总数，同时保持每次只查其中一小部分。

SwiGLU$\text{SiLU}(xW_{gate}) \otimes xW_1$$3 \times d \times d_{ff}$LLaMA、Qwen、DeepSeek门控，同等参数下效果最优

一个趋势性的观察：激活函数的演进方向是从"固定规则"走向"学习型门控"。ReLU 和 GELU 对所有输入施加同一个变换，而 SwiGLU 让网络自己决定每个维度的通过率。这种"让模型自己学"的思路，和注意力机制"让模型自己学该看哪里"一脉相承。

梯度视角：激活函数如何影响反向传播

激活函数不仅在决定前向输出，更在决定梯度能不能顺利流回浅层。深层网络训练困难，很大一部分是激活函数在反向路径上「截断」或「放大」造成的。上一节看了输出值，这一节看导数——三个激活函数在几个典型输入上的导数如下（GELU 按精确的 erf 定义求导，SiLU 按 $x \cdot \sigma(x)$ 求导）：

输入 $x$ReLU 导数GELU 导数SiLU 导数说明
-20-0.085-0.091深负区：ReLU 已把梯度完全截断
-10-0.0830.072负区：平滑族仍保留小幅梯度
00 或 1（不连续）0.50.5原点：平滑族连续过渡
111.0830.928正区：三者都接近 1
211.0851.091大正区：导数略超 1

读这张表，能看到三个关键现象。第一，ReLU 的负半轴导数恒为 0——一旦输入落进负区，该神经元的梯度就是 0，权重再也不更新。如果初始化不好、大量神经元长期落在负区，模型会出现大面积的「死神经元」，训练进度肉眼可见变慢。GELU 和 SiLU 在负区仍保留小梯度，甚至出现负梯度（相当于把梯度「往回推一点」），给了神经元重新翻身的可能。第二，ReLU 在原点处导数不连续（左 0 右 1），训练中 0 附近震荡时数值上更毛糙；平滑族的导数处处连续。第三，三者在大正区的导数都接近 1——所以激活函数的选择，实际影响的主要是「0 附近那一小段」的梯度行为，而训练初期的激活值恰恰大量聚集在 0 附近。

这也是现代模型宁可多花一点计算（GELU、SiLU 都涉及超越函数）也要换成平滑激活的原因：用一个处处有梯度的函数，换取更稳定的深层训练。几十上百层网络里，每层多保留一点梯度，传导到第一层时差异是指数级的。另外注意 GELU 的 tanh 近似在 $-3$ 到 $3$ 区间与原版误差在 $10^{-3}$ 量级，复现他人权重时两种版本必须保持一致，否则会引入难以察觉的微小差异。

再补充一个容易被忽略的细节：导数只是局部性质，前向输出的「数值范围」同样重要。ReLU 和 GELU 的正输出都随输入线性增长，而 SiLU 在大正输入时输出略小于 $x$（因为 $\sigma(x) < 1$），相当于一层隐式的温和缩放，会让激活值的总体方差略小一点。具体到某个架构该选谁，单靠理论说不死，但从 ReLU 到 GELU 到 SwiGLU 的演进路线已经用实验投票了——平滑、有门控、能自适应，是当前被验证最充分的组合。

逐 token 的特征选择：门控为什么更灵活

SwiGLU 相对 ReLU 的另一个优势，只有把「多个 token」放一起对比才能看清。设中间维度 $d_{ff} = 4$，两个 token 经过升维后的特征向量分别是：

升维后的特征（up 分支）维度 1维度 2维度 3维度 4
token A（示意：「银行」）0.8-1.52.00.3
token B（示意：「苹果」）1.20.9-0.61.8

如果激活是 ReLU，两个 token 面对的是同一个「阈值 0」：维度 2 上，token A 的 -1.5 被清零，token B 的 0.9 被保留。一个维度要么对谁都能开、要么对谁都被关，规则全局统一——模型想让「谁需要这个维度」就得靠别处的权重去绕，灵活性有限。

而 SwiGLU 多了一个 gate 分支，每个 token 的 gate 输出各不相同。假设两个 token 的 gate（已经过 SiLU）分别如下：

gate 输出（SiLU 之后）维度 1维度 2维度 3维度 4
token A 的 gate0.60.10.90.2
token B 的 gate0.30.80.40.7

于是 token A 的实际输出近似为 $[0.48, -0.15, 1.80, 0.06]$（up 特征逐元素乘 gate），token B 为 $[0.36, 0.72, -0.24, 1.26]$。注意维度 2：token A 的 gate 只有 0.1，几乎把这个维度的信号关掉；token B 的 gate 是 0.8，放行大半。同一个维度、两个 token、不同的通过率——门控让「哪个 token 走哪个维度」成为逐 token 的动态决策，而不是全局统一的阈值。这就是「让模型自己决定用什么特征」的微观含义，也是门控 FFN 在同等参数预算下效果更好的机制层面解释。

代价也很直白：多一个 $W_{gate}$ 矩阵，参数多 50%，所以倍率要从 4 降到 8/3 才能打平；同时多一次逐元素乘法。用可控的成本换来自适应能力，这正是 SwiGLU 能成为现代大模型标配的账。

中间维度不是越大越好：容量与成本的账

既然 FFN 是模型的「知识仓库」，那是不是 $d_{ff}$ 越大越好？不是。容量越大，代价也越大，关键是看值不值。

先算成本账。以 $d = 4096$ 为例，SwiGLU 的 FFN 参数是 $3 \times d \times d_{ff}$。$d_{ff}$ 取 $11008$（约 8/3 倍）时约 1.35 亿；取 $4d = 16384$ 时约 2.01 亿，中间维度放大 50%，FFN 参数直接多出 50%。参数变多的代价是全方位的：训练算力上升、激活值显存上升、推理带宽上升，而收益只在「能装下的知识」上。如果数据量不变，多出来的容量往往只能靠过度拟合去填，loss 不降反升。

再看质量账。已有的实验结论大致是：在参数量打平的条件下，SwiGLU 的 8/3 倍能追平甚至超过标准 FFN 的 4 倍——也就是说，门控带来的「动态选择」能力，大约值一个倍率差。再往上加 $d_{ff}$，收益呈边际递减。这也是为什么主流开源模型的 FFN 倍率都集中在 2.6 到 3.5 之间，而不是越拉越大。

那想要更多知识容量怎么办？答案是别在单个 FFN 里加维度，而是把 FFN 拆成多个专家（MoE）：总参数可以做得极大，但每个 token 只激活其中少数专家，单次计算量几乎不变。换句话说，「加宽度」买的是容量，「加专家」买的是容量但不买算力——这就是 MoE 能在同样推理预算下显著提升知识量的原因，详见 MoE 混合专家。选型时记住这条主线：先确定预算，再决定把钱花在深度、宽度还是专家数上。

要点速查

  • 本质：FFN 是对每个 token 独立做的"升维-激活-降维"变换，负责深度特征加工，不涉及 token 间交互。打乱序列顺序不影响每个 token 自己的 FFN 输出。
  • 参数量占比：标准 Transformer 中 FFN 占每层参数的约 2/3；用了 GQA 的模型（如 Llama-2-70B）可升到 80% 以上。
  • 激活函数演进：ReLU → GELU（平滑、训练稳）→ SwiGLU（门控、同等参数下效果最优）。现代大模型几乎全用 SwiGLU。
  • SwiGLU 参数量：三个矩阵（gate + up + down），为持平标准 FFN 参数量，中间维度取 $\frac{8d}{3}$ 而非 $4d$，再向上对齐到 256 的倍数（Llama-2-7B 因此得到 11008）。
  • 非单调性：GELU 最小值约 -0.170，SiLU 约 -0.278，都允许小幅负输出，避免 ReLU 的死区。
  • 与 MoE 的关系：FFN 是逐位置计算且参数占比最大，因此是稀疏化的天然切入点，MoE 拆的永远是 FFN。
  • 知识仓库视角：$W_1$ 的行像"键"、$W_2$ 的列像"值"，$d_{ff}$ 相当于记忆槽位数量——这解释了事实性知识为何主要存于 FFN。
  • 常见坑：换 SwiGLU 忘了调 $d_{ff}$ 导致参数量膨胀 1.5 倍；混淆 GLU 家族的 SiLU/Swish 命名；GELU 的 erf 版与 tanh 近似版混用。

发展脉络

FFN 从 ReLU/GELU 两层 MLP 演进到 GLU、SwiGLU 和稀疏 MoE，逐渐承担大部分参数容量与条件计算。

机制抓手

SwiGLU 计算 silu(XWg)⊙(XWu) 后经 Wd 投影；为保持参数量，门控中间维通常小于传统 4D FFN。

工程权衡

更大中间维提高容量却增加参数、激活和通信；门控激活质量更好，但需要额外投影和融合 kernel。

前沿观察

MoE、低秩 FFN、结构化稀疏和动态深度都在重分配 token 级计算，路由稳定性比名义 FLOP 更重要。
