后训练算法：从示范数据到可验证反馈

SFT、偏好优化与 RLVR 处理的是不同监督信号。先分清信号来源，再选择目标函数和验证方式。

关键边界：SFT 学行为分布，DPO 学相对偏好，RLVR 学可计算的结果奖励；把三者混成“让模型更聪明”会导致错误的实验归因。

1. SFT：只在回答 token 上计算损失

对对话序列使用 m_t=1 标记 assistant token，m_t=0 标记 system/user/padding，目标为 L_SFT=-Σ m_t logπ_θ(y_t|x,y_<t)。应检查 EOS、角色边界和 packing mask。训练集格式正确但 mask 错位，是“loss 正常、对话异常”的常见根因。

2. DPO：把 KL 约束吸收到分类损失

给定偏好对 (x,y_w,y_l)，DPO 使用 L=-logσ(β[(logπθ(yw)-logπref(yw))-(logπθ(yl)-logπref(yl))])。β 越大越强调偏好、也越容易过拟合。监控 chosen/rejected 的 token-normalized log-prob、隐式 reward margin、reference KL 和长度差；只看 loss 会漏掉长度偏置。

3. GRPO/RLVR：组内相对优势

对同一问题采样 G 个答案，验证器给分 r_i，组内优势 A_i=(r_i-mean(r))/ (std(r)+ε)。这省去了 value model，但当整组全对或全错时优势为零；题目难度、采样温度和 verifier 覆盖率直接决定学习信号。奖励应拆为正确性、格式、成本和安全项，并保留原始轨迹供审计。

4. 训练配方与失败模式

5. 可复现实验

固定基座和 token 预算，依次做 SFT→DPO→RLVR；每阶段保留同一套通用、领域、拒答和格式评测。报告 bootstrap 置信区间、KL 漂移、平均输出长度、验证器覆盖率与训练成本。没有独立测试集和 verifier 审计，不应把 RLVR 的提升称作泛化。

发展脉络

后训练经历了 SFT、RLHF、DPO，再到可验证奖励和推理时扩展；关键转变是从模仿答案转向优化可检查的行为和过程。

机制抓手

对比 SFT、偏好损失、PPO/GRPO 和 verifier 时，明确参考策略、KL 约束、奖励粒度、采样分组和拒绝样本处理。

工程权衡

更强的奖励信号可能带来 reward hacking、过度拒答、长度偏置或能力遗忘；必须联合看任务质量、安全和分布外表现。

前沿观察

RLVR、过程奖励、蒸馏和长轨迹训练正在融合，论文中的提升应通过独立 verifier 和可复现实验验证。

实践检查能手算 DPO/GRPO 的一个 batch，解释 loss mask、KL、优势归一化和奖励作弊的诊断指标。

学习目标

能在统一 batch 上手算 SFT、DPO 与组相对策略优化的有效 token、偏好 margin、优势和 KL 约束。

先修关系

先修预训练目标、SFT 和基本强化学习；区分训练信号、策略约束与部署行为。

最小实验

构造 4 条对话、4 对偏好和 2 组各 4 个回答，分别实现最小 SFT、DPO、GRPO/RLVR loss；打印每个样本贡献并改变 beta 或组内奖励尺度。

验收标准

手算与代码 loss 误差小于 1e-6，prompt token 不进入 SFT 回答损失；能解释 beta、奖励方差和全零组对梯度的影响。
