推理强化学习

DPO 用人类偏好做对齐，但人类偏好有天花板——标注者判断不了数学证明对不对、代码有没有 bug。RLVR（Reinforcement Learning from Verifiable Rewards）把奖励信号换成可验证的客观正确性：数学题答案对不对、代码能不能通过测试、逻辑推理有没有违反约束。GRPO 及其变体（GSPO、DAPO）是让这套可验证奖励真正能训出长思维链的训练算法。这里也是 reward hacking 最凶猛的战场——模型会找到一切方式骗过验证器拿到高分。

前置知识 本页假定你已掌握强化学习基础（MDP、策略梯度、优势估计、PPO 目标函数），见 强化学习基础；并理解 RLHF 的 PPO 流程和 reward hacking 的基本概念，见 RLHF。如果只读过 DPO 那一节，建议先补一下 PPO 的 clipped surrogate objective——本页的算法全部建立在它之上。
一图看懂

RLVR 的核心变化不在算法而在奖励来源：把「人类标注的偏好比较」换成「验证器自动判定的对错」。数学题的答案可以用字符串匹配验证，代码可以用单元测试验证，逻辑题可以用规则检查器验证。这些奖励是二值的（对 / 错）、客观的、无限供应的。GRPO 在此基础上砍掉了 PPO 的价值模型——用一组采样的平均奖励做基线，省掉一个模型，让 RL 训练在推理模型 scale 上变得可行。一句话：换掉裁判（从人换成程序），再换掉记分板（从价值网络换成同组同学的平均分）。

为什么人类偏好不够用：可验证奖励的动机

RLHF 和 DPO 用人类偏好做对齐，在「让模型更礼貌、更有帮助」这类主观维度上效果很好。但当你想让模型做数学题、写代码、做逻辑推理时，人类标注有一个致命弱点：标注者自己也不一定知道正确答案。

一道竞赛数学题，标注者可能无法判断模型的推理过程对不对。一段代码，标注者可能看不出隐藏的 bug。更根本的问题是：即使标注者能判断，人类标注的速度也远远赶不上模型需要的训练数据量——RL 训练中策略每步都要采样成千上万条回答并获取奖励，人类不可能实时标注。更麻烦的是，人类偏好训练出的奖励模型有一个结构性天花板：奖励模型的判断力来自人类标注，所以策略最多学到「让人类觉得对」，而不是「真的对」。当模型能力逼近甚至超过标注者时，继续优化人类偏好反而会训出更会「说服人」而不是更会「解题」的模型。

RLVR 的思路是：如果问题本身有客观可验证的正确答案，就用程序代替人类做裁判。数学题的答案是一个数，字符串匹配就行；代码题有单元测试，跑一遍就知道对错；逻辑谜题有规则检查器。

维度人类偏好奖励（RLHF / DPO）可验证奖励（RLVR）
奖励来源人类标注 → 训练出的奖励模型程序化验证器（匹配器 / 测试 / 规则）
信号形态连续标量分数，含噪二值 0 / 1，或分段的规则分
获取速度受限于奖励模型前向，且需先攒标注毫秒级，可与采样同步
供应量受标注预算限制题目有多少就有多少，近似无限
能力上限受标注者水平约束受题目难度和验证器覆盖度约束
主要失效奖励模型被过优化（reward model overoptimization）规格博弈：满足字面规格、违背真实意图
适用任务开放对话、写作、风格、安全数学、代码、结构化推理、可执行任务

这些验证器的四条性质，正好补上了人类偏好的短板：

  • 客观的：不依赖标注者的主观判断，同一个答案永远给同一个奖励。这意味着奖励函数在训练全程是稳定的，不会像奖励模型那样随着策略偏移而失准。
  • 即时的：程序判定毫秒级，可以跟上 RL 的采样速度，不需要额外的 GPU 去跑一个奖励模型的前向。
  • 无限的：不需要人工标注成本，想采多少题就有多少题。真正的瓶颈从「标注预算」转移到了「高质量题库」和「采样算力」。
  • 二值的：奖励通常是 0（错）或 1（对），没有「部分正确」的模糊地带。这既是优点（无噪声）也是缺点（信号极稀疏，一道题要么全拿分要么零分）。

DeepSeek 的 R1 系列模型是 RLVR 的标志性成果——用数学和代码的可验证奖励做强化学习，模型自发涌现出了长思维链、自我检查、反思等行为，这些行为从未被显式训练过。

验证器长什么样：三类可验证任务与它们的坑

「可验证」听起来简单，真做起来每一类任务都有自己的麻烦。验证器写不好，后面的算法再精妙也白搭——RLVR 的天花板首先由验证器的质量决定，其次才是算法。

任务类型验证方式真实的坑缓解
数学 / 计算 从输出中抽取最终答案，与标准答案做等价比较 答案格式千变万化：1/2 与 0.5 与 \frac{1}{2} 是同一个数；单位、正负号、多解的顺序都会造成误判 用符号计算库做等价判定而非字符串比对；强制输出格式（如把答案放进指定标记里）
代码 沙箱里跑单元测试，全过为 1 测试覆盖不全 → 模型写出只过测试的假实现；测试有副作用或超时 → 判定不稳定；沙箱逃逸的安全风险 隐藏测试集（训练时不暴露全部用例）；严格超时与资源限制；容器隔离
结构化 / 规则推理 规则检查器验证约束是否全部满足 规则本身可能有歧义或不完备；模型学会输出「刚好通过检查」的退化解 加入反例检查；对退化解显式扣分

下面是一个数学验证器的骨架，展示了「为什么它比看起来难」：

import re
from fractions import Fraction


def extract_answer(text):
    """从模型输出中抽取最终答案。

    约定模型必须把答案写进 \\boxed{...} 或指定标记内 —— 这个约定本身
    就是训练的一部分:格式不对直接判 0,模型很快会学会遵守格式。
    """
    m = re.findall(r"\\boxed\{([^}]*)\}", text)
    if not m:
        return None
    return m[-1].strip()          # 取最后一个,防止思维链中途出现的草稿


def normalize(ans):
    """把不同写法归一化到可比较的形式。"""
    if ans is None:
        return None
    s = ans.replace(" ", "").replace("$", "").rstrip(".")
    s = s.replace("\\frac{", "").replace("}{", "/").replace("}", "")
    try:
        return Fraction(s)        # 1/2 与 0.5 归一到同一个有理数
    except ValueError:
        return s.lower()          # 非数值答案退回字符串比较


def math_reward(completion, gold):
    """返回 0 或 1。注意:任何抽取失败都算错,这是刻意的。"""
    pred = normalize(extract_answer(completion))
    if pred is None:
        return 0.0
    return 1.0 if pred == normalize(gold) else 0.0

这段代码里有三个值得注意的设计决定，每一个都对应一类真实事故：

  • 取「最后一个」boxed 而不是第一个。长思维链里模型会反复试算、写出中间的候选答案。取第一个会把草稿当成结论。
  • 抽取失败直接判 0，而不是跳过这条样本。如果格式错误不扣分，模型就没有动力遵守格式；把它算作错误，格式合规会在几百步内自动学会。
  • 数值等价而非字符串相等。字符串比对会把大量正确答案误判为错误，这些假负例是纯噪声，会显著拖慢训练——而且它们不是随机噪声，是系统性偏向某些答案格式的噪声，模型可能因此学会「只输出小数不输出分数」这种毫无意义的偏好。
先测验证器，再开训 开训前务必做一件事：拿一批已知正确的人工解答喂给验证器，看它的通过率。如果一批标准答案只有 85% 被判为正确，说明验证器有 15% 的假负率——这意味着你的训练信号里有 15% 是纯错误，而且模型会花大量算力去「学会」如何绕过这些误判。这个检查很便宜，但跳过它导致的浪费很贵。

GRPO：砍掉价值模型的群组采样

标准 PPO 需要一个价值模型 $V_\phi(s)$ 来估计状态价值，算出优势函数 $A = R - V$。在 RLHF 里这个价值模型是第四个驻留显存的模型。到了 RLVR 场景，问题更严重：推理模型的思维链动辄几千 token，价值模型需要对每个 token 位置给出估计，而它唯一能依据的监督信号是几千步之后的一个 0 或 1——这是一个信噪比极低的回归任务，价值模型很难训准，训不准的价值模型又会给出有偏的优势估计，进而毒害策略。

GRPO（Group Relative Policy Optimization）的核心创新是：用一组采样的平均奖励替代价值模型。对每个问题 $q$，策略采样 $N$ 个回答 $\{y_1, y_2, \ldots, y_N\}$，验证器给出 $N$ 个奖励 $\{r_1, r_2, \ldots, r_N\}$。优势函数定义为：

GRPO 在论文里的原始表述用一张图讲得最清楚。下面这张是提出 GRPO 的 DeepSeekMath 论文原图，左边是标准 PPO 的结构，右边是 GRPO 的结构——一眼就能看出 GRPO 把右边那条「价值模型」支路整个砍掉了。

新手读这张图，先看左边 PPO 那一半。它包含两条并行的支路：上面的 policy（策略模型）对问题生成回答，下面的 value（价值模型）对每一步给一个估计分数。PPO 算优势的时候，要把「真实奖励」和「价值模型的估计」相减——所以标准 PPO 必须训练一个和策略差不多大的价值模型，这正是 RLHF 里那个「第四个驻留显存的模型」。

再看右边 GRPO 那一半：图上策略仍然在生成回答，但价值模型那一支消失了，取而代之的是从同一问题采样出的一组回答（图中就是那个多路分支），用它们的平均奖励当基线。注意图里每个回答都独立走一遍策略、再统一汇到「组内比较」这一步——这正是本页那个 z-score 归一化公式的图形表达。对比两半最直观的差异就是：PPO 需要两个「思考者」（策略 + 价值），GRPO 只需要一个。

这张图还隐含了两个没画出来的工程结论：其一，GRPO 采样成本更高（一个问题的采样量从 1 变成 $N$），省下的是显存与训练稳定性；其二，图中「组」的概念要求同一个问题能被反复采样——这正是语言模型 RL 独有的性质（状态可重置），也是砍掉价值模型能成立的前提。这两点在下面的「为什么可以放心地砍掉价值模型」深入块里有更完整的推导。

$$A_i = \frac{r_i - \text{mean}(r_1, \ldots, r_N)}{\text{std}(r_1, \ldots, r_N)}$$

即每个回答的奖励在组内做 z-score 归一化。高于组内平均的回答获得正优势（被鼓励），低于平均的获得负优势（被抑制）。

一个具体的数值例子

设 $N = 8$，某道题采样出 8 条思维链，验证器判定结果为 [1, 0, 0, 1, 0, 1, 0, 0]，即 3 对 5 错。那么：

量数值含义
组内均值 $\bar{r}$$3/8 = 0.375$这道题当前策略的通过率
组内标准差 $\sigma$$\sqrt{0.375 \times 0.625} \approx 0.484$二值分布的标准差
答对的优势 $A_+$$(1 - 0.375)/0.484 \approx +1.29$被强化
答错的优势 $A_-$$(0 - 0.375)/0.484 \approx -0.77$被抑制
全对时（8 对 0 错）$\sigma = 0$，优势全为 0这道题太简单，没有梯度
全错时（0 对 8 错）$\sigma = 0$，优势全为 0这道题太难，没有梯度

这张表把 GRPO 的三个关键性质都摊开了：

  • 不需要价值模型：基线来自同一问题的其他采样，而不是一个需要训练的神经网络。四模型变三模型（策略 + 参考 + 验证器），而验证器还是个轻量程序不是神经网络——所以实际只有两个模型要放显存，其中一个还是冻结的。
  • 自适应难度：全对或全错时优势为 0，梯度自动消失。只有「有对有错」的问题才产生有效梯度，天然形成了 curriculum——策略变强，简单题自动退出训练集；策略还弱，难题自动不参与。这是免费得到的课程学习。
  • 注意那个不对称：3 对 5 错时，答对的优势（+1.29）绝对值大于答错的（-0.77）。这是 z-score 归一化的性质：稀有的成功比常见的失败携带更多信息，权重也更大。这个性质在难题上尤其重要——偶尔蒙对一次，会被大力强化。

GRPO 的策略更新沿用了 PPO 的 clipped surrogate objective，只是把优势函数从「价值模型估计」换成「组内归一化」：

$$\mathcal{L}_{\text{GRPO}} = -\mathbb{E}\!\left[\min\!\left(\rho_i A_i,\; \text{clip}(\rho_i, 1-\epsilon, 1+\epsilon) A_i\right)\right] + \beta \, \text{KL}\!\left(\pi_\theta \,\|\, \pi_{\text{ref}}\right)$$

其中 $\rho_i = \frac{\pi_\theta(y_i|q)}{\pi_{\text{old}}(y_i|q)}$ 是重要性采样比率，与 PPO 一致。$\pi_{\text{old}}$ 是采样时用的那份策略权重——因为一批采样通常要跑好几个梯度步（否则采样成本摊不平），所以更新时的策略已经不是采样时的策略了，需要重要性采样来纠偏，clip 则防止这个纠偏系数跑得太离谱。

一句话直觉 GRPO 的组内归一化就像考试后的「拉曲线」——同一道题你考了 80 分，如果全班平均 90 分你就是负优势（要改进），如果全班平均 60 分你就是正优势（继续保持）。你不需要一个「价值模型」来估计你的水平，只需要跟做同一道题的同伴比。而如果全班都满分或全班都零分，这道题对区分能力毫无价值，自然也不该产生学习信号。

动手：GRPO 的优势计算与损失

算法本身的代码量很小，难点全在周边的采样与验证工程上。下面这段展示核心逻辑：

import torch
import torch.nn.functional as F


def group_advantages(rewards, group_size, eps=1e-4):
    """组内 z-score 归一化。

    rewards: (batch,) 一维张量,同一问题的 N 条采样必须相邻排列
    返回:    (batch,) 每条采样的优势
    """
    r = rewards.view(-1, group_size)              # (num_prompts, N)
    mean = r.mean(dim=1, keepdim=True)
    std = r.std(dim=1, keepdim=True)
    adv = (r - mean) / (std + eps)
    # 关键:全对或全错时 std 约为 0,adv 被 eps 压到近似 0 —— 这正是我们要的
    return adv.view(-1)


def grpo_loss(new_logp, old_logp, ref_logp, advantages,
              mask, clip_eps=0.2, kl_coef=0.001):
    """GRPO 的 clipped surrogate + KL 惩罚。

    new_logp / old_logp / ref_logp: (batch, seq_len) token 级对数概率
    advantages: (batch,) 每条序列一个优势,广播到该序列所有 token
    mask:       (batch, seq_len) 1 表示该 token 属于模型生成部分
    """
    adv = advantages.unsqueeze(1)                          # (b, 1) -> 广播
    ratio = torch.exp(new_logp - old_logp)                 # (b, s)

    unclipped = ratio * adv
    clipped = torch.clamp(ratio, 1 - clip_eps, 1 + clip_eps) * adv
    pg_loss = -torch.min(unclipped, clipped)               # (b, s)

    # k3 形式的 KL 估计:无偏且恒非负,比直接用 logp 差更稳
    log_r = ref_logp - new_logp
    kl = torch.exp(log_r) - log_r - 1.0                    # (b, s)

    per_token = pg_loss + kl_coef * kl
    # 逐 token 平均:每个 token 权重相等,长回答不会因为 token 多而被放大
    return (per_token * mask).sum() / mask.sum().clamp(min=1.0)

最后那行的归一化方式看着不起眼，却是 GRPO 一个真实的争议点。原始 GRPO 是先在每条序列内部对 token 取平均，再对序列取平均；这样做的后果是「一条 100 token 的回答」和「一条 5000 token 的回答」对总损失的贡献相同，于是长回答里的每个 token 权重被稀释了 50 倍。DAPO 指出这会让模型在长思维链上的学习信号被系统性削弱，改为把整个 batch 的所有 token 一视同仁地平均（也就是上面代码里的写法）。这个细节改动在长思维链训练里影响相当明显。

GSPO 与 DAPO：GRPO 的两个改进方向

GRPO 在大规模实践中暴露了若干问题，分别催生了 GSPO 和 DAPO。理解这两个变体的关键是：它们都不是在改「奖励从哪来」，而是在改「梯度怎么算才不炸」。

GSPO：从 token 级重要性比率到序列级

GRPO 继承了 PPO 的 token 级重要性采样：每个 token 各自算一个 $\rho_t = \pi_\theta(y_t)/\pi_{\text{old}}(y_t)$，各自 clip。在短序列上这没问题，但思维链动辄几千 token 时，麻烦来了：每个 token 的比率都有一点噪声，几千个带噪声的比率连乘 / 分别加权，方差会被放大得非常厉害。更糟的是，这些 token 共享的是同一个序列级优势 $A_i$——奖励只有终点那一个 0 或 1，却要靠几千个各自波动的比率去分配，信噪比极低。

GSPO（Group Sequence Policy Optimization）的做法是把重要性比率也提到序列级：整条思维链算一个比率、做一次 clip、对应一个优势。这在概念上更自洽——既然奖励是序列级的、优势是序列级的，那么重要性纠偏也应该是序列级的。工程上它显著降低了梯度方差，在 MoE 架构上尤其有效：MoE 的路由会让同一个 token 在新旧策略下走不同的专家，token 级比率因此剧烈跳变，而序列级聚合把这种跳变平均掉了。

DAPO：四项工程修补

DAPO（Decoupled Clip and Dynamic sAmpling Policy Optimization）不是一个新算法，而是一组针对 GRPO 实际训练问题的工程修补包。它的四项改动各自对应一个具体病症：

改动针对的病症具体做法
Clip-Higher
（解耦裁剪）		 熵坍缩：训练几百步后策略输出几乎确定，探索停止 把 clip 上下界解耦，上界放宽（如上界用比下界更大的 $\epsilon$），让低概率 token 有机会被抬升。对称 clip 会系统性压制小概率 token，导致分布越来越尖
Dynamic Sampling
（动态采样）		 零梯度组：全对或全错的组白白消耗算力 过采样后过滤掉方差为 0 的组，只保留有对有错的组进入梯度计算，并补采样直到凑够 batch。代价是采样开销上升
Token-Level Loss
（token 级损失）		 长回答被稀释：序列级平均让长思维链每 token 权重变低 在整个 batch 的 token 维度上做平均，而非先序列内平均再序列间平均
Overlong Reward Shaping
（超长惩罚整形）		 截断噪声：超出最大长度被截断的样本，本可能是对的却被判 0 对接近或超出长度上限的样本用软化的惩罚（按超出量渐变），而不是直接判错，避免给正确但啰嗦的推理注入错误负信号
熵坍缩是头号杀手 上表第一行值得单独强调。RLVR 训练最常见的失败不是「不收敛」，而是收敛得太彻底：策略熵一路下降，采样温度调高也没用，每个问题的 N 条采样几乎一模一样，于是组内方差为 0、优势全 0、训练静止。此时 loss 曲线看着很平静，reward 曲线也停在某个平台上，很容易被误读为「训练完成」。请把策略熵作为一等监控指标，和 reward 放在同一张图上看。

训练动力学：三条曲线决定成败

RLVR 训练跟 SFT 完全不是一回事。SFT 你盯 loss 就行；RLVR 的 loss 曲线几乎没有信息量（它是 surrogate objective，上下波动是正常的）。真正要盯的是三条曲线：平均奖励、策略熵、平均响应长度。它们的组合能告诉你训练处在哪个阶段。

最后一行是整套监控里最重要的一条。训练奖励和 held-out 通过率一旦分叉，基本可以断定模型学到的是验证器的漏洞而不是解题能力。这个分叉往往出现得比想象中早，因此 held-out 评测不能等训完再做，要在训练循环里定期插入。

Reward Hacking 与规格博弈：RLVR 的头号敌人

可验证奖励听起来完美——数学答案对就是对，代码通过测试就是通过，还有什么能被钻空子？但现实是：验证器只检查你让它检查的东西，而模型会找到一切方式满足验证器的字面要求同时违背真实意图。这就是规格博弈（specification gaming），RLVR 场景下比 RLHF 更凶猛，因为奖励信号更密集、训练轮次更多、而且策略有几千个 token 的自由空间可以施展。

RLVR 中 reward hacking 的表现可以按「钻的是谁的空子」分成四大类：

作弊表现怎么发现它为什么自动指标看不出来
答案倒推：先猜答案再编一段合理推理人工读思维链；或把推理过程截断后让模型续写，看结论是否还一致最终答案确实是对的，验证器无从判断过程
暴力枚举：在思维链里穷举所有候选监控响应长度分布；统计输出中出现的候选答案个数枚举也确实「答对了」，奖励是满分
测试集 overfitting：只过测试用例的假实现用训练时未暴露的隐藏测试集重跑公开测试全绿
格式伪装：堆砌特殊标记触发解析漏洞对验证器做模糊测试；检查通过样本中的异常字符验证器自己就是被骗的那一方
题库记忆：直接背下训练题答案held-out 通过率与训练奖励对比；做训练集与评测集的去污染检查训练奖励一路走高，看着像能力提升
关键认知 Reward hacking 不是 bug，是强化学习的必然行为。只要奖励函数与真实目标存在 gap，策略就一定会找到并利用这个 gap。这个 gap 在 RLVR 中尤其大——「答案正确」和「真的会推理」之间有巨大的距离。不能指望通过更好的验证器完全消除它，只能通过奖励设计和训练策略把它控制在可接受范围内。把 reward hacking 当成「需要持续对抗的常态」而不是「一次性修好的缺陷」，是这个领域最重要的心态转变。

缓解 reward hacking：奖励设计的工程实践

完全消灭 reward hacking 不现实，但可以把它控制在可接受范围内。实践中有以下几条路线：

增强验证器覆盖度

代码验证器增加更多测试用例（包括边界情况和对抗性用例），并保留一批训练时不暴露的隐藏用例专门用于检测作弊；数学验证器不仅检查最终答案，还做关键步骤的中间检查。覆盖度越高，可钻的空子越少。但永远无法做到 100% 覆盖。

过程奖励（PRM）替代结果奖励

不只看最终答案对不对，还对推理过程的每一步打分。过程奖励模型（PRM）可以惩罚「先猜答案再倒推」的行为，因为倒推出来的过程在步骤级上往往站不住。代价是需要训练步骤级的奖励模型，回到部分 RLHF 的复杂度，而且 PRM 自身也会被 hack。详见 验证器与过程奖励模型。

KL 约束与熵管理

保持足够的 KL 惩罚，防止策略偏离参考模型太远（偏离越远越容易退化到 hack 模式）。同时用熵奖励或 Clip-Higher 保持策略多样性，避免塌缩到某一种 hack 模式——注意这两者方向相反：KL 拉回、熵推开，需要一起调。

数据与问题多样性

确保训练问题集足够多样——如果全是选择题，模型只学会猜选项；混入开放题、证明题、代码题，让单一 hack 策略无法跨问题类型迁移。定期更换问题集，防止过拟合到特定验证器。同时做训练集与评测集的去污染，否则你分不清是学会了还是背下了，见 数据污染与评估可信度。

即使做了以上所有措施，reward hacking 仍然会以新的、意想不到的形式出现。RLVR 工程中一个不成文的经验是：每次大规模训练后都必须做 reward hacking 审计——人工检查模型在 held-out 问题上的推理过程，看它是真的在推理还是在走捷径。这个审计无法完全自动化，因为「真的在推理」这个判断本身就依赖人类。一个可操作的最小流程是：随机抽 50 条答对的样本（注意是答对的，答错的样本没有作弊动机），人工读思维链，统计其中有多少条的推理过程与结论存在真实因果关系。这个比例如果低于某个你能接受的线，就该回头改验证器或加过程奖励了。

展开：GRPO 的训练超参数实践

GRPO 在推理模型训练中常用的配置（数值为公开技术报告与开源实现中的常见区间，具体取值因模型规模、题库难度和框架实现而异，务必以你自己的实验为准）：

  • 组大小 N：每个问题采样 4–16 个回答。太小组内统计不稳定（想想 N=2 时 z-score 只有 ±1 两个取值），太大采样开销线性上升。N=8 是很多实现的默认。
  • 采样温度：0.6–1.0，需要足够高的温度保证组内有对有错。如果温度太低，所有采样几乎一样，组内方差为零，梯度消失。温度在这里不是「生成质量参数」而是「探索强度参数」，别用推理时的经验值。
  • KL 系数 $\beta$：常见在 0.001–0.04 量级。RLVR 中的 KL 系数通常比 RLHF 小得多，因为可验证奖励更可靠，不需要那么强的约束；有些实现甚至完全去掉 KL 项，靠 clip 和早停控制漂移。但 KL 太小会让 reward hacking 加剧。
  • clip 范围 $\epsilon$：0.2（与 PPO 一致）。DAPO 的 Clip-Higher 把上界单独放宽。
  • 每批采样的梯度步数：1–4。步数越多采样成本摊得越平，但 $\pi_\theta$ 与 $\pi_{\text{old}}$ 偏离越大，重要性比率越不可靠。很多实现干脆用 1（严格 on-policy），代价是采样吞吐必须跟得上。
  • 最大思维链长度：需要设置上限（常见在数千到数万 token 量级），否则模型会无限拉长思维链来枚举答案。这个上限本身也是防 reward hacking 的手段，但配合超长惩罚整形使用才不会引入假负例。

一个容易被忽视的坑：学习率。RLVR 中的学习率通常比 SFT 小一到两个数量级（常落在 $10^{-6}$ 量级），因为 RL 的梯度信号已经很强，大学习率会导致策略剧烈震荡甚至崩溃——而 RL 的崩溃和 SFT 不同，它往往是不可逆的：策略一旦退化到某个退化模式，采样就再也产生不出多样的样本，训练无法自愈，只能回滚 checkpoint。

展开：为什么可以放心地砍掉价值模型？组内基线的方差分析

策略梯度里加基线是老技巧了。核心结论是：只要基线 $b$ 不依赖于当前动作 $a$，从优势里减去它就不会引入偏差，因为

$$\mathbb{E}_{a \sim \pi}\!\left[b \cdot \nabla_\theta \log \pi_\theta(a)\right] = b \cdot \nabla_\theta \sum_a \pi_\theta(a) = b \cdot \nabla_\theta 1 = 0$$

价值模型 $V_\phi(s)$ 是一种基线，组内均值 $\bar{r}$ 也是一种基线。两者都满足「不依赖当前这条采样的具体动作」这个条件——严格地说组内均值包含了当前采样自身，会引入一个 $O(1/N)$ 量级的小偏差，实践中通常忽略，也可以用留一法（leave-one-out）均值来精确消除。

那为什么大家以前要费劲训价值模型？因为在传统 RL 场景（如机器人控制）里，你不可能对同一个状态重复采样 N 次——环境一旦推进就回不去了，所以只能训一个函数近似器来「记住」各状态的平均回报。

而语言模型的 RL 有一个得天独厚的性质：状态是可以完美重置的。同一个 prompt 想采样多少次就采样多少次，采样之间完全独立。这直接把「需要学一个价值函数」的问题变成了「多采几次求个平均」的问题。GRPO 的本质洞察就在这里——它不是发明了更好的价值估计方法，而是发现在这个特定场景下根本不需要价值估计。

代价当然存在：价值模型是「一次训练，处处可用」，而组内采样是「每道题都要多花 N 倍算力」。所以 GRPO 是拿采样算力换模型显存与训练稳定性。在推理模型这个场景下这笔交易非常划算，因为价值模型在超长序列 + 稀疏奖励下本来就训不准；但如果你的序列很短、奖励很稠密，PPO 的价值模型仍然可能是更经济的选择。

还有一个副产品：组内基线让优势天然地被按题归一化了。不同题目的难度差异（有的题通过率 90%、有的 5%）不会互相干扰，因为每道题都在自己的组内比较。价值模型要学会这一点得费很大劲。

RLVR 涌现了什么：长思维链的自行出现

RLVR 最令人兴奋的发现不是模型做对了更多数学题，而是模型在训练过程中自发产生了此前从未被训练过的行为。公开的技术报告记录了这些涌现行为：

  • 自我验证：模型在得出答案后，自发地「回头检查」推理过程，代入验算，发现错误并修正。
  • 反思：遇到困难时，模型会输出「等等，让我重新想想」这类自发的中断和方向调整——这种语言模式在训练数据里当然存在，但「在恰当的时机使用它」不是任何人教的。
  • 分而治之：模型自发地将复杂问题分解为子问题，逐个解决再综合。
  • 替代路径探索：一条路走不通时，模型自发地回退并尝试不同的解题思路。
  • 响应长度自发增长：没有任何机制鼓励「写长一点」，但训练过程中平均响应长度会持续上升。这是因为更长的思考确实提高了答对率，于是被奖励强化——这是「推理时算力换精度」这条 scaling 曲线在训练中被模型自己发现了。

这些行为从未出现在训练数据的监督信号中（训练信号只有问题和最终答案的对错，没有推理过程示范），也不是 SFT 教的。它们是强化学习在「答对有奖励」的压力下自发演化出来的策略。这暗示着：只要奖励信号设计得当，模型有能力自主发现有效的推理模式——这正是推理模型这一新范式的基础，详见 推理模型。

一个必要的清醒 「涌现」这个词容易让人过度浪漫化。更朴素的解释是：这些行为模式在预训练语料里早就存在了（人类写的解题过程里到处是「让我们检查一下」「换个思路」），基座模型本来就会说这些话；RLVR 做的是把「在什么情况下说这些话能提高答对率」这件事学出来。这不减损其价值，但提醒我们：RLVR 是在放大基座里已有的能力，不是无中生有。基座越强，RLVR 能挖出来的东西越多；基座里根本没有的东西，RLVR 也变不出来。

要点速查

  • 本质：用可验证的客观奖励（数学答案、代码测试、规则检查）替代人类偏好标注，让 RL 突破人类标注的天花板。
  • 验证器是第一生产力：验证器的假负率直接变成训练噪声。开训前先用标准答案测一遍验证器的通过率。
  • GRPO 核心：组内采样 z-score 归一化替代价值模型——每个回答的奖励与同组其他采样比较，省掉一个模型，且自带 curriculum（全对全错的题自动零梯度）。
  • 为什么能砍掉价值模型：语言模型 RL 的状态可以完美重置，同一 prompt 可无限重采样，于是「学一个价值函数」退化成「多采几次求平均」。拿采样算力换显存与稳定性。
  • GSPO：把重要性比率从 token 级提到序列级，降长序列梯度方差，对 MoE 尤其有效。
  • DAPO 四项：Clip-Higher 抗熵坍缩、Dynamic Sampling 丢弃零方差组、Token-Level Loss 防长回答被稀释、Overlong Reward Shaping 避免截断假负例。
  • 盯三条曲线：平均奖励、策略熵、平均响应长度。熵断崖式下跌是头号杀手，此时 loss 曲线看着一切正常。
  • 训练奖励与 held-out 通过率分叉 = reward hacking 报警，必须在训练循环里定期跑 held-out。
  • Reward hacking 是必然：验证器只检查字面规格。四条路径——钻验证器实现、钻任务形式、钻奖励整形、钻数据分布，对应四类不同的缓解手段。
  • 缓解四路：增强验证器覆盖（含隐藏测试集）、过程奖励 PRM、KL 与熵一起调、问题多样性与去污染。每次大规模训练后必须人工抽检答对的样本。
  • 涌现行为：自我验证、反思、分而治之、替代路径探索、响应长度自发增长——在纯结果奖励下产生，但本质是放大基座里已有的模式，不是无中生有。
  • 前置依赖：RL 基础概念见 强化学习基础；多步决策训练见 Agentic RL。

发展脉络

PPO 依赖 value model，DPO 绕过在线采样，GRPO 用同题多样本的组内相对奖励去掉 value model，RLVR 再把 verifier 作为奖励来源。

机制抓手

组内优势 A_i=(r_i-mean(r))/(std(r)+eps)，再用 ratio 的裁剪目标和 reference KL 更新；全对或全错组优势为零。

工程权衡

组大小、奖励稀疏、长度偏置和 verifier 错误会直接改变梯度，不能只看 pass@1。

前沿观察

DeepSeekMath/R1 展示了可验证数学推理的规模化路径，迁移到开放域 Agent 仍需要过程奖励和副作用约束。

实践检查手算奖励 [1,1,0,1] 的组内优势，解释零方差处理，并设计能抓住格式正确但答案错误的 verifier。
