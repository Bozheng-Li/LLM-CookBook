现代大模型算法：从稀疏路由到推理时扩展

本页把近年的架构变化放回同一条约束链：参数容量、每 token 计算、显存流量和可验证的输出质量。每个结论都配有可复算的账，而不是把论文名称当作结论。

阅读结论：没有“最先进”的单一算法。MoE 解决训练容量/计算的错配，GQA/MLA 解决解码缓存，MTP 与 test-time scaling 解决质量/延迟的重新分配；它们的收益只有在带宽、批量和验证器条件下才成立。

1. 稀疏 MoE：容量与激活计算分离

对 token 表示 x，路由器产生 p=softmax(W_rx)，选择 top-k 专家并归一化：y=Σ_{i∈TopK(p)} p_i E_i(x)。总参数约为 E 倍 FFN 参数，但每 token 只激活 k/E。Switch Transformer 用 top-1 简化通信并加入负载损失；top-2 提升容量却增加 all-to-all 和溢出风险。容量因子 c 决定每个专家最多接收 c·T·k/E 个 token，溢出 token 被丢弃或走 shared expert。

工程账：报告 active/total 参数、路由丢弃率、专家负载熵、all-to-all 占比和每步尾延迟。只报总参数会把稀疏模型与 dense 模型错误比较。

# 最小路由诊断
probs = router(x).softmax(-1)
topv, topi = probs.topk(k, dim=-1)
load = torch.bincount(topi.flatten(), minlength=num_experts)

2. GQA 与 MLA：解码时的显存账

MHA 的缓存字节数为 2·L·n_kv·d·bytes；GQA 将 n_kv 从 query heads 降到分组数，理论上按比例节省。MLA 则缓存低维 latent，再按需恢复 K/V，压缩比取决于 latent 维度、RoPE 分支和实现是否发生隐式 materialize。比较方法应固定 batch、序列长度、精度和 kernel，记录 bytes/token、prefill 吞吐与 decode p50/p95。

3. MTP 与推理时扩展

多 token 预测让草稿头一次提出多个候选，主模型并行验证；若平均接受长度为 a、验证成本为 C_v、草稿成本为 C_d，粗略加速为 (1+a)/(1+C_d/C_v)。接受率会随温度、任务熵和 batch 改变，小 batch 或低接受率可能变慢。test-time sampling、best-of-n 和 verifier 也属于同一类“用额外计算换质量”，必须画质量—成本曲线而非只报单点分数。

4. 组合时的边界

机制主要瓶颈收益条件典型退化
MoE训练 FLOP / 通信专家负载均衡、互联充足丢 token、专家塌缩
GQA/MLAKV 显存与带宽长序列、decode 占主导质量下降、实现 materialize
MTP/Speculative串行解码高接受率、验证可并行接受率低于额外开销

5. 可复现实验

用同一 checkpoint 建立三组基线：MHA、GQA、MLA；再分别开关 speculative/MTP。固定生成质量阈值，扫描序列长度 1K/8K/32K、batch 1/8/32，保存显存峰值、tokens/s、p95 延迟和任务准确率。任何“加速”都必须与 PyTorch SDPA 或 FlashAttention 的实际 kernel 对比。
