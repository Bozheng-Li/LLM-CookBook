预训练算法：从一批 token 到可扩展训练

新人沿着一条真实训练步读懂目标函数、数据配方、显存、并行和故障恢复，而不是背框架名称。

1. 一个 training step 做了什么

给定 token 序列，decoder-only 模型在位置 t 预测下一个 token。交叉熵为 -sum log p(next_token | prefix)。前向传播得到 logits，反向传播得到梯度，优化器更新权重。手算二分类 logits [2,1] 的正确类概率约为 0.73，loss 约 0.31；真实模型只是把两个类别换成数万词表，并在每个位置重复。

2. 数据配方比爬更多网页重要

先做语言识别、乱码/广告过滤、近重复去重，再按代码、数学、百科、对话等桶设定配比。Chinchilla 表明固定计算量下模型参数和训练 token 需要共同缩放；模型很大但 token 不够，会得到“参数很多但没学饱”的模型。新人实验：固定模型和步数，比较原始、去重、质量过滤三份数据的验证 loss、重复率和长文本一致性。

3. 优化器与稳定性

AdamW 用一阶矩和二阶矩归一化梯度，再做解耦 weight decay。warmup 避免初始化阶段的大更新；梯度裁剪限制异常 batch 的影响。遇到 loss spike，先保存 batch、检查 NaN、数据异常、通信溢出和学习率，而不是直接重启。

loss = model(batch).loss / grad_accum
loss.backward()
if (step + 1) % grad_accum == 0:
    clip_grad_norm_(model.parameters(), 1.0)
    optimizer.step(); scheduler.step(); optimizer.zero_grad()

4. 并行训练怎么选

数据并行复制模型、切分 batch；张量并行切分矩阵；流水线并行切分层；序列并行切分长序列；MoE 专家并行切分 expert。先估算参数、梯度、优化器状态和激活显存，再看通信带宽，最后组合策略。不要因为“用了四种并行”就假定吞吐更高。

5. 混合精度与 checkpoint

BF16 动态范围接近 FP32，FP8 需要尺度管理。checkpoint 必须保存权重、optimizer、scheduler、随机数状态、数据游标和并行拓扑，否则恢复后会重复数据或产生不可解释的 loss 跳变。

6. 训练完成的证据

至少保留固定验证集 loss、按数据桶 loss、梯度范数、吞吐、MFU、通信占比、恢复测试和污染检查。每次改数据或并行策略都做短跑对照，建立“配置到指标”的实验表。
