大模型评测：从一道题到可信结论

把 benchmark 分数拆成数据、评分器、统计不确定性和线上回归，避免“榜单高分但产品失效”。

1. 先定义被测能力

“模型更强”不是一个可测命题。先写任务契约：输入格式、允许工具、成功条件、失败成本和截止时间。例如代码 Agent 的成功不是文本像不像参考答案，而是补丁能否在隔离环境通过隐藏测试。

2. 指标的计算和误差

准确率是通过样本数除以总样本数；当样本只有 100 道时，1 道题就改变 1 个百分点。应报告置信区间、按难度分桶结果和多次随机种子。LLM-as-Judge 还要测与人工标签的一致性、位置偏差和长度偏差。

3. 数据污染与泄漏

测试题出现在训练语料、提示模板或公开解析中，分数就不再代表泛化。可用 n-gram/hash 检索、时间切分和动态私有题集降低风险；发布 benchmark 时同时发布污染检查脚本和版本号。

4. 评测一个 Agent

同时记录任务完成率、轨迹有效率、工具选择精度、重试次数、token 成本、延迟、越权率和人工接管率。只报最终完成率会掩盖“成功但成本十倍”的策略。每次模型、prompt、工具 schema 变更都跑 golden set 和 canary。
