1. 项目背景与 DeepSeek-R1-Zero 范式

传统的强化学习算法（如 PPO）在提升复杂多步推理任务（如奥林匹克数学、代码竞赛、定理证明）时，常常面临两大瓶颈：第一，Critic（价值网络）拟合难度高且极易过拟合。在长达数千 Token 的推理链条中，单一价值模型很难在早期准确预测最终答案的正误，导致单步优势评估充斥巨大方差；第二，显存开销沉重。PPO 要求 Actor、Critic、Ref、Reward 四个大模型同时驻留显存或分布式节点，严重限制了消费级硬件探索强化学习的可能。

DeepSeek 团队在 DeepSeekMath 与 DeepSeek-R1 中提出的 GRPO（Group Relative Policy Optimization） 彻底颠覆了这种范式。GRPO 的第一项革新是彻底砍掉 Critic 模型：对于每个输入问题，策略网络并发 Rollout 采样一组（如 \( G = 8 \) 或 \( 16 \)）候选输出序列，以该组内所有回答的平均奖励和标准差作为基线，直接计算出每个候选回答的相对优势（Relative Advantage）。GRPO 的第二项革新是以客观可验证的规则判定取代脆弱的神经奖励模型：对于数学问题，答案要么正确，要么错误，利用精确的符号计算引擎（如 SymPy）提取并比对 LaTeX 终解，完全避免了神经网络奖励模型容易被“奖励黑客（Reward Hacking）”欺骗的顽疾。

在本项目中，我们将以 Qwen2.5-Math-1.5B 为基础，搭建一套极致轻量的 GRPO 强化学习流水线。在纯基于规则奖励的环境下，读者将直观观测到模型在没有人工干预的情况下，自发学会“在 <think>...</think> 标签内长篇草稿演算、自我否定‘Wait, let me double check’并最终推导出正确答案”的顿悟全过程。

2. GRPO 数学原理与组内归一化优势推导

为了深刻理解 GRPO 为什么能够在保持策略梯度无偏的同时大幅降低显存，我们考察其目标函数。对于每一个问题查询 \( q \sim \mathcal{P}(Q) \)，GRPO 不再调用 Critic 网络计算状态价值 \( V_\phi(s) \)，而是利用当前旧策略 \( \pi_{\theta_{\mathrm{old}}} \) 独立采样生成 \( G \) 个候选回答：

\[ \{o_1, o_2, \dots, o_G\} \sim \pi_{\theta_{\mathrm{old}}}(\cdot \mid q) \]

环境根据预设的规则奖励函数（Rule-based Reward Function）为每一个输出 \( o_i \) 评定一个标量奖励 \( r_i \)。随后，在当前回答组内部计算标量奖励的样本均值 \( \bar{r} \) 与标准差 \( \sigma_r \)：

\[ \bar{r} = \frac{1}{G} \sum_{i=1}^G r_i, \quad \sigma_r = \sqrt{\frac{1}{G} \sum_{i=1}^G (r_i - \bar{r})^2 + \epsilon} \]

第 \( i \) 个候选回答获得的归一化相对优势 \( A_i \) 被严格定义为标准化 Z-score：

\[ A_i = \frac{r_i - \bar{r}}{\sigma_r} \]

该设计的精妙之处在于：如果某个回答在组内表现鹤立鸡群（如其余 7 个回答都算错，只有它做对），其相对优势 \( A_i \) 将显著为正，策略梯度会大幅强化其所有 Token 的发射概率；反之，若某个回答犯了愚蠢错误，其优势为负，梯度将被压制。若组内所有回答全部正确或全部错误，此时方差极小或为零（分子全为 0），该样本对策略梯度不做无效贡献，天然充当了极佳的样本难度筛选器！

3. 严密的多维度规则奖励函数设计

在数学强化学习中，奖励函数的设计必须做到客观、确定、无漏洞。任何模棱两可的打分都会被语言模型迅速利用为捷径。我们为模型定制了一套复合规则奖励系统，涵盖结构格式、终解正确性与长度平滑性。

3.1 奖励三元组构成

  1. 格式规范奖励（Format Reward, \( r_{\mathrm{format}} \in \{0.0, 0.5\} \)）： 强制要求模型严格按照 <think>推理过程</think> \n 答案在 \boxed{result} 的格式输出。若标签未闭合、顺序颠倒或缺失，直接扣除格式分；
  2. 精确答案奖励（Accuracy Reward, \( r_{\mathrm{acc}} \in \{0.0, 1.0\} \)）： 从输出文本中提取 \boxed{...} 内的 LaTeX 字符。通过正则表达式与 SymPy 符号代数引擎进行同解简化比对（例如识别 \( \frac{2}{4} = 0.5 \)、\( 2\sqrt{2} = \sqrt{8} \) 等等）。若完全一致赋 1.0 分，否则 0 分；
  3. 惩罚项与兜底：若模型回答为空、超时或产生恶性死循环，直接赋予总奖励 0.0。

3.2 符号化判优器实现代码

以下代码展示了工业级符号数学判定器的实现，能够优雅处理 LaTeX 复杂分式、根号与方程：

math_verifier.py 
import re
from typing import Optional
import sympy
from sympy.parsing.sympy_parser import parse_expr

class MathRuleRewardVerifier:
    def __init__(self):
        # 严格匹配 ... 以及 \boxed{...} 的正则模式
        self.think_pattern = re.compile(r"<think>(.*?)</think>", re.DOTALL)
        self.boxed_pattern = re.compile(r"\\boxed\{([^{}]+)\}")

    def extract_boxed_answer(self, text: str) -> Optional[str]:
        """从生成文本中提取最终框定答案"""
        matches = self.boxed_pattern.findall(text)
        if not matches:
            return None
        # 默认取最后一个框定答案作为终决结论
        return matches[-1].strip()

    def check_format_compliance(self, text: str) -> float:
        """检查思考标签与答案框定格式完整度"""
        reward = 0.0
        has_think = bool(self.think_pattern.search(text))
        has_boxed = bool(self.boxed_pattern.search(text))
        
        if has_think:
            reward += 0.3
        if has_boxed:
            reward += 0.2
        return reward

    def verify_algebraic_equivalence(self, pred: str, ground_truth: str) -> bool:
        """利用 SymPy 判断两个数学表达是否符号等价"""
        if pred == ground_truth:
            return True
        
        # 简单清洗 LaTeX 常见语法
        def clean_latex(s: str) -> str:
            s = s.replace(r"\frac", "").replace(r"\times", "*").replace(r"\div", "/")
            s = s.replace("{", "(").replace("}", ")").replace("^", "**")
            s = re.sub(r"[a-zA-Z\\]", "", s) # 移除非公式文本
            return s.strip()

        try:
            p_expr = parse_expr(clean_latex(pred))
            g_expr = parse_expr(clean_latex(ground_truth))
            # 两式做差化简，若为 0 则代数恒等
            if sympy.simplify(p_expr - g_expr) == 0:
                return True
        except Exception:
            pass

        # 浮点数比对兜底
        try:
            p_val = float(pred.replace(",", "").strip())
            g_val = float(ground_truth.replace(",", "").strip())
            return abs(p_val - g_val) < 1e-4
        except ValueError:
            pass

        return False

    def compute_reward(self, response: str, ground_truth: str) -> float:
        """综合打分主入口"""
        fmt_reward = self.check_format_compliance(response)
        pred_ans = self.extract_boxed_answer(response)
        
        acc_reward = 0.0
        if pred_ans is not None:
            if self.verify_algebraic_equivalence(pred_ans, ground_truth):
                acc_reward = 1.0
                
        return fmt_reward + acc_reward

if __name__ == "__main__":

4.1 端到端单卡 GRPO 训练脚本

以下是完整的可运行训练脚本，包含批量 Rollout、组归一化优势计算与策略梯度回传：

train_grpo_math_minimal.py 
import torch
import torch.nn.functional as F
from transformers import AutoModelForCausalLM, AutoTokenizer
from peft import LoraConfig, get_peft_model
from math_verifier import MathRuleRewardVerifier

# 系统提示词强制引导模型开启标签思考
SYSTEM_PROMPT = "你是一名卓越的数学家。请在  标签内写下极其详尽的解题思考推导步骤，并在最后给出格式为 \\boxed{答案} 的最终结果。"

def selective_log_probs(logits: torch.Tensor, input_ids: torch.Tensor) -> torch.Tensor:
    """提取生成 Token 对应的条件对数概率"""
    log_probs = F.log_softmax(logits[:, :-1, :], dim=-1)
    targets = input_ids[:, 1:].unsqueeze(-1)
    selected = torch.gather(log_probs, dim=-1, index=targets).squeeze(-1)
    return selected

def compute_group_advantages(rewards: torch.Tensor, eps: float = 1e-6) -> torch.Tensor:
    """计算组内样本的归一化相对优势"""
    mean = rewards.mean()
    std = rewards.std()
    return (rewards - mean) / (std + eps)

def run_grpo_training():
    device = "cuda:0" if torch.cuda.is_available() else "cpu"
    model_name = "Qwen/Qwen2.5-Math-1.5B"
    group_size = 8
    lr = 2e-5
    clip_eps = 0.2
    beta_kl = 0.04

    print(">>> 加载分词器与策略模型...")
    tokenizer = AutoTokenizer.from_pretrained(model_name)
    model = AutoModelForCausalLM.from_pretrained(model_name, torch_dtype=torch.bfloat16).to(device)
    
    # 挂载 LoRA 仅更新轻量适配层
    peft_config = LoraConfig(
        r=16, lora_alpha=32, target_modules=["q_proj", "k_proj", "v_proj", "o_proj"],
        task_type="CAUSAL_LM"
    )
    model = get_peft_model(model, peft_config)
    optimizer = torch.optim.AdamW(model.parameters(), lr=lr)
    
    verifier = MathRuleRewardVerifier()

    # 模拟一道 GSM8K 数学题
    query = "小明有 15 个苹果，他把其中的 1/3 送给了小红，随后又买来了 8 个。请问小明现在一共有多少个苹果？"
    ground_truth = "18"

    prompt_text = f"<|im_start|>system\n{SYSTEM_PROMPT}<|im_end|>\n<|im_start|>user\n{query}<|im_end|>\n<|im_start|>assistant\n"
    prompt_inputs = tokenizer(prompt_text, return_tensors="pt").to(device)
    prompt_len = prompt_inputs.input_ids.shape[1]

    print(f">>> 启动 GRPO Rollout 并发采样 (G={group_size})...")
    # 扩展 Prompt 为 group_size 份
    expanded_input_ids = prompt_inputs.input_ids.repeat(group_size, 1)
    
    model.eval()
    with torch.no_grad():
        generated_ids = model.generate(
            expanded_input_ids,
            max_new_tokens=512,
            do_sample=True,
            temperature=0.9,
            top_p=0.95,
            pad_token_id=tokenizer.eos_token_id
        )

    # 截取新生成的 Token
    responses = [tokenizer.decode(g[prompt_len:], skip_special_tokens=True) for g in generated_ids]
    
    # 计算每条路径的规则奖励
    raw_rewards = []
    for resp in responses:
        score = verifier.compute_reward(resp, ground_truth)
        raw_rewards.append(score)
    rewards_tensor = torch.tensor(raw_rewards, device=device, dtype=torch.float32)
    
    # 计算组归一化优势
    advantages = compute_group_advantages(rewards_tensor)
    print(f"组奖励得分: {raw_rewards} | 归一化优势: {advantages.tolist()}")

    # 开始策略梯度更新
    model.train()
    optimizer.zero_grad()

    # 前向计算当前策略的对数似然
    outputs = model(generated_ids)
    all_log_probs = selective_log_probs(outputs.logits, generated_ids)
    response_log_probs = all_log_probs[:, prompt_len - 1:]

    with torch.no_grad():
        # 旧策略的似然，此处近似为 Rollout 时的当前值
        old_log_probs = response_log_probs.detach()

    # 计算重要性采样比率 ratio = pi_theta / pi_old
    ratio = torch.exp(response_log_probs - old_log_probs)
    
    # 将优势沿序列维度广播
    adv_broadcast = advantages.unsqueeze(-1).expand_as(ratio)
    
    # PPO-Clip 目标
    surr1 = ratio * adv_broadcast
    surr2 = torch.clamp(ratio, 1.0 - clip_eps, 1.0 + clip_eps) * adv_broadcast
    policy_loss = -torch.min(surr1, surr2).mean()

    # 简单 KL 惩罚（向旧似然靠拢）
    kl_div = (torch.exp(old_log_probs) * (old_log_probs - response_log_probs)).mean()
    total_loss = policy_loss + beta_kl * kl_div

    total_loss.backward()
    torch.nn.utils.clip_grad_norm_(model.parameters(), 1.0)
    optimizer.step()

    print(f"Step 完成: Loss = {total_loss.item():.4f}, 平均奖励 = {rewards_tensor.mean().item():.2f}")

if __name__ == "__main__":
    run_grpo_training()

5. 思考长度涌现（Length Surge）与顿悟现象监控

在复现 DeepSeek-R1-Zero 风格的纯强化学习训练时，工程师通常会经历标志性的三阶段演进：

  1. 探索混沌期（0 ~ 100 Steps）：模型输出混乱，常常忘记闭合 </think> 标签或完全猜错，平均奖励低迷（0.2 ~ 0.4），回答长度平稳；
  2. 思考长度涌现爆发期（100 ~ 500 Steps）：在纯准确率奖励与格式奖励的持续双向选择下，模型猛然发现：在 <think> 标签内展开更长时间的分步穷举与自我检验，能够大幅增加猜中最终正确答案的概率！此时，平均输出长度从 200 Token 瞬间激增至 1500+ Token。在 TensorBoard 监控曲线上，可以观察到显著的“长度激增（Length Surge）”脉冲；
  3. 顿悟与收敛期（500+ Steps）：模型开始在思维链中自主展现反思词符（例如生成“Wait, let me rethink the previous step”、“Could this case be zero?”等）。准确率从初期的 35% 跃升至 70% 以上，同时思维长度逐步稳定在合理的有效区间，不再无节制膨胀。
🚨 重要警告：如何防范有害的“假思考与复读死循环”？

在纯规则驱动的 RL 训练中，若仅给予正确性奖励，模型可能会钻空子：在 <think> 标签内疯狂重复同一句话几十次来规避思考难度，以此尝试随机撞大运。排查手段与防护技巧：

  • 引入 n-gram 重复惩罚：当检测到思考区间内连续出现 3 次以上相同短语时，施加严重的负奖励（-0.5）；
  • 动态最大长度裁剪：在初期限制 max_new_tokens = 768，待准确率提升至 50% 之后再分阶段解锁至 1536，引导模型逐步构建深层推理；
  • 早停拦截：若 Rollout 生成提前遇到连续三个 EOS 或死循环标点，立即截断并判定该样本为 0 奖励。

7. 本章小结

在本章中，我们完整探索了以 GRPO 为核心的数学推理纯强化学习范式。核心结论包括：

  • 去除 Critic 的革命性：GRPO 凭借组内均值与标准差的自归一化，在保持策略梯度稳定性的同时削减了价值网络的庞大开销，使得在消费级单卡上运行大规模强化学习成为现实；
  • 规则验证是推理任务的基石：使用 SymPy 符号代数解析配合严密正则提取，构建了坚固耐用、免受奖励黑客攻击的确定性打分闭环；
  • 顿悟现象是 RL 的天然产物：在无人工干预的纯强化激励下，模型会自发展开反思重算、检验边界与探索替代分支，伴随出现标志性的“思考长度激增”；
  • 防范过拟合与退化：严防重复复读与伪思考，利用轻量 LoRA、严格格式扣分与梯度截断，确保模型在数学逻辑推理主干道上稳健收敛。

8. 自测题

题 1：GRPO 算法相较于经典 PPO 算法，最本质的架构简化是什么？它是如何替代传统 Critic（价值模型）的功能的？
解析：最本质的简化是彻底移除了独立的 Critic（价值模型）网络。在经典 PPO 中，Critic 用于拟合状态价值 \( V(s) \) 以计算单步优势；而在 GRPO 中，策略模型针对同一个输入问题并发采样生成一组候选输出（Group Rollout，如 \( G=8 \)），通过计算该组内全部样本奖励的均值与标准差，使用标准化公式 \( A_i = (r_i - \bar{r})/\sigma_r \) 直接得出相对优势，从而完全免除了 Critic 的显存和计算开销。
题 2：如果在 GRPO 训练的一轮迭代中，采样出的 \( G \) 个候选回答由于题目过难全部算错，导致获得的奖励均为 0 分，此时反向传播的梯度是多大？这种现象对训练有什么影响？
解析：当所有回答的奖励完全相同时（如均为 0），组奖励均值 \( \bar{r} = 0 \)，每个回答的奖励与其均值之差 \( r_i - \bar{r} = 0 \)。在加入微小常数 \( \epsilon \) 防止除零后，计算出的所有相对优势 \( A_i \) 严格等于 0。根据策略梯度公式，该批次产生的策略梯度为零向量，不会对模型权重产生任何更新。这既防止了无效噪声对策略的扰动，也表明过于困难的样本在当前阶段无法提供有效探索反馈。
题 3：在复现 DeepSeek-R1-Zero 模式时，观察到的“思考长度激增（Length Surge）”和“顿悟时刻（Aha Moment）”背后的强化学习驱动机制是什么？
解析：驱动机制在于规则奖励对终解正确性的强确定性反馈。由于数学多步推理具有链式依赖性，直接跳到最终结论的猜测成功率极低。在多次随机探索中，模型偶尔在 <think> 标签内多进行几步试算与反思重查，从而命中了正确答案并获得了高正向优势；在策略梯度的正反馈累积下，模型迅速学到了“拉长思维链、在草稿中推演与检验能极大提升获赏期望”这一策略，自发展开长文本自我纠错，从而在宏观上呈现出思考长度激增与顿悟自省。
