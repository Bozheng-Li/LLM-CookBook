第 58 章 · 项目四：训练自己的奖励模型

奖励模型（Reward Model, RM）是强化学习对齐（RLHF）体系中的“裁判官”与“指路灯”，也是拒识采样（Rejection Sampling / Best-of-N）提升推理性能的核心标尺。尽管像 DPO 这样的无奖励模型算法日益普及，但在复杂多轮长文本判别、多目标价值权衡及拒识生成搜索中，一个显式、高精度的标量奖励模型依然具有不可替代的工程地位。本章从成对偏好数据建模、单标量 Value Head 架构改造、带 Margin 的 Pairwise 排名损失、RewardBench 基准测评，到工业级 Best-of-N 拒识采样全流程，带你亲手训练一个工业级奖励模型。

1. 奖励模型的定位与核心价值

在人类反馈强化学习（RLHF）的三阶段范式中，奖励模型（Reward Model, RM）扮演着承前启后的中枢角色：它在 SFT 阶段之后接入，专门学习人类的价值喜好，将复杂的主观自然语言文本映射为一个标量分数（Scalar Reward Score）\( r \in \mathbb{R} \)。在随后的 PPO 或在线策略优化中，RM 作为代理环境（Surrogate Environment），为生成模型源源不断地提供奖励信号。

许多开发者产生了一个疑问：既然 DPO 与 GRPO 可以绕过奖励模型直接在偏好或规则上训练，为什么工业界（如 OpenAI、Anthropic、Meta Llama 3 团队）依然高度重视独立奖励模型的研发？主要原因有三：

  • 拒识采样（Rejection Sampling / Best-of-N）的刚需：在推理阶段，让策略模型并发生成 \( N \) 个回答，通过奖励模型打分并挑选得分最高的那个（Best-of-N）。大量实验（如 Llama 2 / Llama 3 技术报告）证明，Best-of-N 往往能在不需要更新策略参数的前提下，显著超越单一贪婪生成的上限；
  • 长程推理过程验证（PRM 演进基石）：标量奖励模型是进一步研发步骤级过程奖励模型（Process Reward Model, PRM）的直系前身，也是测试时搜索（Test-time Compute / MCTS）的关键评估器；
  • 对齐评估与安全守门员：训练好的奖励模型可以直接转化为内容安全审核分类器或自动化 A/B 测试的判别器，成为系统上线前的高精度质量门禁。

2. 奖励模型网络架构与 Pairwise 损失数学推导

如何让一个自回归因果语言模型（Causal LM）输出一个标量评分？标准做法是将模型顶层的自回归输出头（lm_head，映射到词表大小 \( V \)）替换为一个单标量线性回归头（Value Head），即一个权重矩阵 \( W \in \mathbb{R}^{d_{\mathrm{model}} \times 1} \)。

2.1 输入构造与末位 Token 池化

给定一个提示词 \( x \) 以及模型生成的回答 \( y \)，我们将它们按照对话模板拼接为单条序列：

\[ s = [x; y] = (t_1, t_2, \dots, t_L) \]

序列经过 Transformer 骨干网络（如 AutoModelForSequenceClassification）前向传播后，获得最后一层每个 Token 的隐状态向量 \( \mathbf{h}_1, \dots, \mathbf{h}_L \in \mathbb{R}^{d} \)。由于自回归 Transformer 的因果掩码特性，最后一个有效 Token（通常是 <|im_end|> 或句尾 eos_token）的隐状态 \( \mathbf{h}_L \) 已经汇聚了前面所有 Token 的双向与因果注意力上下文。因此，我们提取该末位隐状态，通过单标量权重向量相乘，得到最终的全局标量奖励：

\[ r_\theta(x, y) = W^T \mathbf{h}_L + b \]

2.2 带边缘惩罚的 Pairwise 排名损失（Margin Ranking Loss）

人类在标注偏好时，给出的绝对分数极易受到个人主观打分基准（Calibration Shift）的干扰。因此，奖励模型绝不能按直接回归真实分数的 MSE 损失训练，而必须采用成对比较的对比排序损失（Pairwise Ranking Loss）：

\[ \mathcal{L}_{\mathrm{RM}}(\theta) = -\mathbb{E}_{(x, y_w, y_l) \sim \mathcal{D}} \left[ \log \sigma \left( r_\theta(x, y_w) - r_\theta(x, y_l) \right) \right] \]

当偏好数据集中附带了标注员或 GPT-4 裁判的具体评分差距时，我们可以引入自适应边际惩罚（Margin）\( m(x, y_w, y_l) \ge 0 \)：

\[ \mathcal{L}_{\mathrm{Margin}}(\theta) = -\mathbb{E} \left[ \log \sigma \left( r_\theta(x, y_w) - r_\theta(x, y_l) - m(x, y_w, y_l) \right) \right] \]

引入 Margin 机制的核心收益在于：若 \( y_w \) 仅比 \( y_l \) 略优，模型只需保持微小的奖励差即可收敛；但如果 \( y_w \) 是满分回答而 \( y_l \) 存在严重安全毒害，Margin 强制模型必须将两者的标量奖励拉开极大的绝对安全间距，大幅增强奖励模型在安全边界上的判决鲁棒性。

📘 概念辨析：为什么必须在同一个 Batch 内绑定计算 chosen 和 rejected？

若将 \( (x, y_w) \) 和 \( (x, y_l) \) 分开打散到不同的训练批次中，模型很容易产生打分漂移（Score Drift），例如不同 Step 输出的分数整体向上或向下漂移数百点。只有将同一个 Prompt 的 chosen 与 rejected 绑定在同一个张量批次中，通过相对差值做损失反向传播，模型才能学到稳定不变的相对序关系（Invariant Ranking Relation）。

3. 偏好数据转化为 RM 专用张量格式

训练奖励模型时，数据的格式要求非常特殊。我们需要将每个三元组 (prompt, chosen, rejected) 解构为两条完全拼接好的纯文本：text_chosen = format_chat(prompt, chosen) 和 text_rejected = format_chat(prompt, rejected)。在 DataLoader 组装 Batch 时，必须确保输入张量的偶数索引是 chosen，奇数索引是 rejected。

4. 完整奖励模型训练代码实现

下面给出基于 Hugging Face transformers 和 peft 框架的工业级奖励模型微调脚本。代码基于 Qwen2.5-1.5B，使用 AutoModelForSequenceClassification(num_labels=1) 构建单标量输出头，并编写自定义 Trainer 严格实现带 Margin 的对比排名损失：

train_reward_model.py 
import os
import torch
import torch.nn as nn
from dataclasses import dataclass
from typing import Any, Dict, List, Optional, Union
from datasets import load_dataset
from transformers import (
    AutoTokenizer,
    AutoModelForSequenceClassification,
    Trainer,
    TrainingArguments,
    PreTrainedTokenizerBase
)
from peft import LoraConfig, get_peft_model, TaskType

# 自定义带 Margin 的成对排名损失 Trainer
class RewardModelTrainer(Trainer):
    def compute_loss(self, model, inputs, return_outputs=False, num_items_in_batch=None):
        # inputs 包含成对拼接的 chosen 与 rejected 特征
        rewards_chosen = model(
            input_ids=inputs["input_ids_chosen"],
            attention_mask=inputs["attention_mask_chosen"]
        ).logits.squeeze(-1)
        
        rewards_rejected = model(
            input_ids=inputs["input_ids_rejected"],
            attention_mask=inputs["attention_mask_rejected"]
        ).logits.squeeze(-1)

        margins = inputs.get("margin", torch.zeros_like(rewards_chosen))
        
        # 核心损失：L = - log σ( r_w - r_l - margin )
        diff = rewards_chosen - rewards_rejected - margins
        loss = -torch.mean(nn.functional.logsigmoid(diff))

        if return_outputs:
            return loss, {"chosen_rewards": rewards_chosen, "rejected_rewards": rewards_rejected}
        return loss

@dataclass
class RewardDataCollator:
    tokenizer: PreTrainedTokenizerBase
    max_length: int = 1536

    def __call__(self, features: List[Dict[str, Any]]) -> Dict[str, torch.Tensor]:
        batch_chosen = []
        batch_rejected = []
        margins = []

        for item in features:
            # 格式化组装
            prompt = item["prompt"]
            c_text = item["chosen"]
            r_text = item["rejected"]
            
            # 使用 ChatML 渲染
            text_w = f"<|im_start|>user\n{prompt}<|im_end|>\n<|im_start|>assistant\n{c_text}<|im_end|>"
            text_l = f"<|im_start|>user\n{prompt}<|im_end|>\n<|im_start|>assistant\n{r_text}<|im_end|>"
            
            batch_chosen.append(text_w)
            batch_rejected.append(text_l)
            margins.append(item.get("margin", 0.0))

        tok_chosen = self.tokenizer(
            batch_chosen, max_length=self.max_length, padding="longest", truncation=True, return_tensors="pt"
        )
        tok_rejected = self.tokenizer(
            batch_rejected, max_length=self.max_length, padding="longest", truncation=True, return_tensors="pt"
        )

        return {
            "input_ids_chosen": tok_chosen["input_ids"],
            "attention_mask_chosen": tok_chosen["attention_mask"],
            "input_ids_rejected": tok_rejected["input_ids"],
            "attention_mask_rejected": tok_rejected["attention_mask"],
            "margin": torch.tensor(margins, dtype=torch.float32)
        }

def run_rm_training():
    base_model = "Qwen/Qwen2.5-1.5B"
    output_dir = "output/qwen2.5-1.5b-rm"

    tokenizer = AutoTokenizer.from_pretrained(base_model, trust_remote_code=True)
    if tokenizer.pad_token is None:
        tokenizer.pad_token = tokenizer.eos_token

    print(">>> 加载具有标量 Value Head 的序列分类模型...")
    # num_labels=1 将顶层替换为 Linear(hidden_size, 1) 单标量回归头
    model = AutoModelForSequenceClassification.from_pretrained(
        base_model,
        num_labels=1,
        torch_dtype=torch.bfloat16,
        device_map="auto",
        trust_remote_code=True
    )
    model.config.pad_token_id = tokenizer.pad_token_id

    # 挂载 LoRA，指定同时训练 score.weight (Value Head)
    peft_config = LoraConfig(
        task_type=TaskType.SEQ_CLS,
        r=16,
        lora_alpha=32,
        lora_dropout=0.05,
        target_modules=["q_proj", "k_proj", "v_proj", "o_proj"],
        modules_to_save=["score"] # 关键：必须显式将分类打分头列入可学习参数
    )
    model = get_peft_model(model, peft_config)
    model.print_trainable_parameters()

    # 模拟构建小规模数据集
    sample_data = [
        {
            "prompt": "如何高效提高深度学习模型的训练吞吐？",
            "chosen": "推荐采用混合精度（BF16/FP16）、FlashAttention-2 内核加速，并配合 DataLoader 多进程预读取与梯度累加。",
            "rejected": "多买几张显卡就可以了，越贵越好。",
            "margin": 0.5
        }
    ] * 64

    training_args = TrainingArguments(
        output_dir=output_dir,
        learning_rate=2e-5,
        per_device_train_batch_size=2,
        gradient_accumulation_steps=4,
        num_train_epochs=2,
        weight_decay=0.01,
        bf16=True,
        logging_steps=5,
        save_steps=50,
        save_total_limit=2,
        remove_unused_columns=False,
        report_to="none"
    )

    trainer = RewardModelTrainer(
        model=model,
        args=training_args,
        train_dataset=sample_data,
        data_collator=RewardDataCollator(tokenizer=tokenizer)
    )

    print(">>> 开始奖励模型训练...")
    trainer.train()
    trainer.save_model(output_dir)
    print(f"奖励模型训练完毕，权重已保存至 {output_dir}")

if __name__ == "__main__":
    run_rm_training()

5. RewardBench 体系与对齐评测基准

如何客观评价训练出来的奖励模型是“真懂好坏”还是“仅仅在死记硬背”？AllenAI 提出了权威的 RewardBench 评测基准。RewardBench 从四个维度全面测试奖励模型的判决泛化能力：

  • Chat（日常对话偏好）：评估模型对通用指令遵循、语气诚恳度以及信息完整性的打分敏锐度；
  • Chat Hard（对话硬核困难集）：包含极度相似但存在细微逻辑瑕疵的成对回答，测试 RM 是否会落入“浅层相似度陷阱”；
  • Safety（安全性与越狱检测）：包含针对性红队诱导提示词（Red-teaming Prompts），测试 RM 是否能给充满恶意攻击但文笔华丽的回答赋予最低分；
  • Reasoning（代码与数学分步推理）：测试 RM 是否具备识别推理中间步骤逻辑断裂的能力。

6. 实战应用：基于 RM 的 Best-of-N 拒识采样引擎

训练好奖励模型后，最具性价比的应用就是拒识采样（Rejection Sampling / Best-of-N）。它的运行逻辑极其清晰：针对用户的问题，生成模型在较高采样温度（如 \( T=0.8 \)）下并发采样 \( N \) 个（如 \( N=8 \) 或 \( 16 \)）多样化的候选回答；奖励模型对这 \( N \) 个候选回答逐一打分，并挑选最高分的那一个返回给用户。

以下代码展示了完整的 Best-of-N 推理采样脚本，支持批量前向打分与最佳项选择：

rejection_sampling_engine.py 
from typing import List
import torch
from transformers import AutoTokenizer, AutoModelForCausalLM, AutoModelForSequenceClassification
from peft import PeftModel

class BestOfNEngine:
    def __init__(self, generator_path: str, reward_model_path: str, device: str = "cuda:0"):
        self.device = device
        
        print(">>> 加载生成器模型...")
        self.gen_tokenizer = AutoTokenizer.from_pretrained(generator_path)
        self.generator = AutoModelForCausalLM.from_pretrained(
            generator_path, torch_dtype=torch.bfloat16, device_map=device
        )
        self.generator.eval()

        print(">>> 加载奖励模型...")
        self.rm_tokenizer = AutoTokenizer.from_pretrained(generator_path)
        # 加载分类模型骨干
        rm_base = AutoModelForSequenceClassification.from_pretrained(
            generator_path, num_labels=1, torch_dtype=torch.bfloat16, device_map=device
        )
        self.reward_model = PeftModel.from_pretrained(rm_base, reward_model_path)
        self.reward_model.eval()

    def generate_candidates(self, prompt: str, n: int = 4) -> List[str]:
        """并发采样 N 条候选回答"""
        prompt_text = f"<|im_start|>user\n{prompt}<|im_end|>\n<|im_start|>assistant\n"
        inputs = self.gen_tokenizer(prompt_text, return_tensors="pt").to(self.device)
        prompt_len = inputs.input_ids.shape[1]

        with torch.no_grad():
            outputs = self.generator.generate(
                **inputs,
                max_new_tokens=512,
                num_return_sequences=n,
                do_sample=True,
                temperature=0.85,
                top_p=0.9,
                pad_token_id=self.gen_tokenizer.eos_token_id
            )
            
        candidates = []
        for out in outputs:
            resp = self.gen_tokenizer.decode(out[prompt_len:], skip_special_tokens=True).strip()
            candidates.append(resp)
        return candidates

    def score_candidates(self, prompt: str, candidates: List[str]) -> List[float]:
        """使用奖励模型对所有候选回答进行标量打分"""
        texts = [
            f"<|im_start|>user\n{prompt}<|im_end|>\n<|im_start|>assistant\n{c}<|im_end|>"
            for c in candidates
        ]
        inputs = self.rm_tokenizer(texts, padding=True, truncation=True, return_tensors="pt").to(self.device)
        
        with torch.no_grad():
            logits = self.reward_model(**inputs).logits.squeeze(-1)
            scores = logits.cpu().float().tolist()
        return scores

    def select_best(self, prompt: str, n: int = 4) -> dict:
        """主入口：采样 N 条，打分，返回最高质量结果"""
        candidates = self.generate_candidates(prompt, n=n)
        scores = self.score_candidates(prompt, candidates)
        
        best_idx = int(torch.tensor(scores).argmax().item())
        return {
            "prompt": prompt,
            "best_response": candidates[best_idx],
            "best_score": scores[best_idx],
            "all_scores": scores,
            "all_candidates": candidates
        }

if __name__ == "__main__":
    # 实例化并运行拒识采样测试
    engine = BestOfNEngine(
        generator_path="output/qwen2.5-1.5b-sft",
        reward_model_path="output/qwen2.5-1.5b-rm"
    )
    result = engine.select_best("请解释量子纠缠的基本物理直觉，并用通俗的比喻说明。", n=4)
    print(f"\n最佳回答得分: {result['best_score']:.4f}")
    print(f"最佳回答内容:\n{result['best_response']}")

7. 本章小结

在本章中，我们完整攻克了自主训练工业级奖励模型的全套技术栈。核心要点总结如下：

  • 架构转变：将因果语言模型的顶层解构为单标量 Value Head，通过抽取末位有效 Token 的上下文隐状态计算绝对奖励分数；
  • 成对对比优势：摒弃绝对 MSE 回归，严格采用 Bradley-Terry 成对排名对比损失（Pairwise Ranking Loss），并注入边际动态 Margin 惩罚，赋予模型对不同质量差距的鲁棒区分力；
  • 训练细节至关重要：在挂载 LoRA 训练分类模型时，必须显式将 score（分类层权重）列入 modules_to_save，避免打分层未被更新；
  • 下游释放价值：奖励模型不仅是 PPO 的裁判，更是 Best-of-N 拒识采样与搜索验证的核心基石。低显存的小规模 RM 同样能在推理端展现出强大的性能增益。

8. 自测题

题 1：为什么在微调因果语言模型构建奖励模型时，通常选择提取最后一个 Token 的隐状态向量来计算标量分数，而不是像普通分类任务那样对所有 Token 进行平均池化（Mean Pooling）？
解析：因为标准因果语言模型（Causal LM）采用下三角注意力掩码矩阵，每个 Token 只能看到其自身及之前的词符。靠前的 Token 根本无法获取后面回答的上下文信息。只有序列中最后一个 Token（如 <|im_end|>），其注意力能够单向覆盖前面完整的 Prompt 以及 Assistant 回答的所有词符，汇聚了全局特征表示。若采用平均池化，会导致前期信息严重稀释甚至破坏因果语义。
题 2：在使用 PEFT/LoRA 针对 AutoModelForSequenceClassification 进行奖励模型训练时，为什么必须在 LoraConfig 中设置 modules_to_save=["score"]？
解析：在默认情况下，PEFT 只会将指定的注意力矩阵或全连接层（如 q_proj、v_proj）包裹上 LoRA 增量矩阵，而将其他所有未指定的原生权重完全冻结（requires_grad = False）。在序列分类模型中，score 是新初始化的单标量分类头。如果不将其显式声明在 modules_to_save 中，score.weight 将被冻结为随机初始化的初始权重，导致损失无法反向传播训练分类头，打分输出始终是一团随机噪声。
题 3：在 Best-of-N 拒识采样中，当采样候选数量 \( N \) 从 4 增加到 64 时，模型最终输出质量会无节制地无限提升吗？可能会遭遇什么问题？
解析：不会无限提升。当 \( N \) 过大时，会遭遇严重的“奖励过拟合/黑客攻击（Reward Hacking / Overoptimization）”。由于神经奖励模型并非完美的人类价值代理，它在某些非正常特征（如异常长度、特定重复修饰语）上存在预测盲区。当候选池极大时，极易抽样出刚好命中 RM 漏洞的畸形样本，导致 RM 打出虚高极值，但人类阅读体验反而显著下降。此外，计算推理开销随 \( N \) 线性增长，边际收益急剧递减。
