第 4 部分 · 偏好对齐与 RLHF

第 24 章 · 在线迭代对齐与免奖励模型方法

离线对齐方法（如经典 DPO、SimPO）在训练时完全依赖固定的静态偏好池，极易陷入严重的分布外（Out-of-Distribution, OOD）退化与策略漂移：随着模型权重的更新，模型实际生成的回复分布与离线数据集中的输赢样本分布渐行渐远，导致隐式奖励预测失真。在线迭代对齐（Iterative / Online Alignment）通过“边生成、边评估、边对齐”的动态闭环，让模型持续在自身最新策略边界上展开自博弈或在线评判。本章全面揭示以 SPIN 为代表的自博弈免奖励模型对齐机制、迭代 DPO（Iterative DPO）、在线直接偏好优化（Online DPO）以及在线直接奖励对齐（Direct Alignment from Online AI Feedback, OAIF），打通动态自回归采样与流式偏好更新的高性能工程管线。

1. 静态离线对齐的致命软肋：分布漂移与虚假偏好

自 DPO 问世以来，后训练工业界在享受其免去 PPO 繁复超参调整的同时，也逐步遭遇了其根本性的理论瓶颈。这一瓶颈根源于离线偏好学习的静态分布假设（Static Off-policy Assumption）。在经典的离线直接偏好优化中，偏好对 \((x, y_w, y_l) \sim \mathcal{D}_{\mathrm{offline}}\) 是由历史上的参考模型 \(\pi_{\mathrm{ref}}\) 或其它开源大模型生成的。在训练开始的最初几百个步长内，待优化的策略网络 \(\pi_\theta\) 与 \(\mathcal{D}_{\mathrm{offline}}\) 的分布高度契合，优化器能够快速拉大对数似然差值。

然而，强化学习控制理论与统计学习理论明确指出：策略优化本质上是一个动态的协变量偏移（Covariate Shift）过程。随着梯度步进的累积，当前策略 \(\pi_\theta\) 能够生成的回复分布 \(p_{\pi_\theta}(y \mid x)\) 会显著偏离初始分布 \(\mathcal{D}_{\mathrm{offline}}\)。这导致了两大灾难性的现象：

  • 分布外（OOD）隐式奖励虚高：DPO 损失将隐式奖励定义为 \(r_\theta(x, y) = \beta \log \frac{\pi_\theta(y \mid x)}{\pi_{\mathrm{ref}}(y \mid x)}\)。在 \(\mathcal{D}_{\mathrm{offline}}\) 覆盖之外的高维 Token 空间中，可能存在某些特殊的生成模式，其在参考模型下似然极低但在策略模型下被微小扰动放大，导致隐式奖励飙升。这类似于强化学习中的“盲目乐观”，导致模型在实际推理时生成胡言乱语却自我感觉极佳。
  • 对自身新产生的错误缺乏防御免疫：在静态离线数据中，落败样本 \(y_l\) 往往是旧模型产生的低级错误。当模型进阶变强后，它所面临的新挑战不再是这些低级语法或格式错误，而是诸如复杂的逻辑漏洞、隐蔽的推理偷换概念等高级缺陷。静态离线数据集无法提供模型当前策略下最新缺陷的“靶子”，优化因此迅速陷入瓶颈。

为了解决上述痛点，后训练技术由静态拟合演进为在线迭代对齐（Online / Iterative Alignment）。其核心哲学是：永远用当前模型最新生成的劣质输者作为靶子，或者利用模型自身充当判别器展开对抗博弈，从而使策略在动态更新中始终保持探索与校准的张力。本节小结：闭环是在线算法克服分布偏移的根本出路。

2. 自博弈弱监督对齐范式：SPIN（Self-Play Fine-Tuning）

在所有免奖励模型且追求在线自博弈的算法中，加利福尼亚大学洛杉矶分校（UCLA）Chen 等人提出的 SPIN（Self-Play Fine-Tuning） 是最具革命性的一步。SPIN 的核心立意是：不需要人类偏好数据，不需要外部奖励模型，仅凭高质量 SFT 数据集，让模型自身与先前的自己展开博弈，能否自发实现能力的持续飞跃？

2.1 两常和不完全信息博弈的数学形式化

SPIN 将大语言模型的后训练重新定义为主玩家（Main Player，当前策略 \(\pi_\theta\)）与对手玩家（Opponent Player，上一轮迭代冻结的策略 \(\pi_t\)）之间的两常和博弈。设目标真实数据分布为 \(p_{\mathrm{data}}(y \mid x)\)（由人工精标 SFT 数据集给出）。主玩家的目标是寻找一个策略 \(\pi_\theta\)，使得判别器无法区分其生成的回答与真实人工数据；而对手玩家则试图以历史策略生成伪造样本。

在每一轮迭代 \(t = 0, 1, 2, \dots\) 中：

  1. 对手玩家 Rollout：固定上一轮策略 \(\pi_t\)，输入提示词 \(x \sim \mathcal{D}\)，生成伪造回答 \(y' \sim \pi_t(\cdot \mid x)\)。
  2. 配对构成：将人工真实回复 \(y \sim p_{\mathrm{data}}(\cdot \mid x)\) 视作胜者（Chosen），将本模型上一轮生成的回复 \(y'\) 视作输者（Rejected），构造动态偏好对 \((x, y, y')\)。
  3. 主玩家策略更新：主玩家 \(\pi_{\theta}\) 通过优化下述极小化极大（Minimax）目标完成步进：
\[ \mathcal{L}_{\mathrm{SPIN}}(\theta) = \mathbb{E}_{(x, y) \sim \mathcal{D}, y' \sim \pi_t(\cdot \mid x)} \left[ \ell\left( \lambda \log \frac{\pi_\theta(y \mid x)}{\pi_t(y \mid x)} - \lambda \log \frac{\pi_\theta(y' \mid x)}{\pi_t(y' \mid x)} \right) \right] \]

其中损失函数通常选用二元逻辑斯蒂回归函数 \(\ell(z) = \log(1 + \exp(-z))\)。注意这里的参照物直接换成了上一轮迭代的策略 \(\pi_t\)。

2.2 理论收敛性证明与纳什均衡

Chen 等人在论文中从理论上给出了严格的收敛性保证：当博弈达到纳什均衡（Nash Equilibrium）时，必有：

\[ \pi^* = p_{\mathrm{data}} \]

这意味着，模型在不断打败“过去的自己”的过程中，其概率质量分布在全空间无偏地向真实高质量数据流形靠拢。相较于单遍 SFT 训练（极易对特定表述过拟合），SPIN 每一轮都在寻找当前模型生成分布与真实分布重叠薄弱的边界区域，动态压制模型自发产生的错漏模式。实测表明，在 GSM8K、MATH 及各类自然语言问答基准上，仅使用原始 SFT 数据集，经过 3 轮 SPIN 迭代，模型胜率与推理准确度获得了显著的自发性增长。本节小结：SPIN 将对抗判别转化为自演化对齐动力学。

3. 工业级多轮迭代 DPO（Iterative DPO / Online DPO）

虽然 SPIN 依赖真实 SFT 数据作为天然胜者，但在开放式对话、代码生成、创意写作以及价值观安全对齐等更为广阔的场景中，我们往往拥有更具辨识力的即时反馈机制（例如专用的过程奖励模型 PRM、集成判别器，或是多评测器投票系统）。将 DPO 推向在线化的主流工业路径是迭代 DPO（Iterative DPO）与在线 DPO（Online DPO）。

3.1 Iterative DPO：批式动态外循环

在 Iterative DPO 范式中，训练过程被切分为离散的 \(K\) 个宏观轮次（Epoch / Cycle）。在每个宏观轮次 \(k\) 中：

  • 阶段 A（动态数据合成）：从提示词池 \(\mathcal{X}\) 中采样，使用当前的检查点 \(\pi_{\theta_k}\) 对每个提示词独立采样 \(M\) 个候选输出（例如通过 Nucleus Sampling，\(M = 4 \sim 8\)）： \[ \{y^{(1)}, y^{(2)}, \dots, y^{(M)}\} \sim \pi_{\theta_k}(\cdot \mid x) \]
  • 阶段 B（在线评估与偏好成对化）：利用高精度奖励模型 \(R_\phi\) 或在线仲裁器对这 \(M\) 个候选打分，挑选出得分最高者为 \(y_w\)，得分最低者为 \(y_l\)。若两者分差小于阈值 \(\delta\)，则抛弃该样本以防噪声污染。由此构成当前轮次专属的数据集 \(\mathcal{D}_k\)。
  • 阶段 C（策略微调与参考模型轮转）：将参考模型更新为 \(\pi_{\mathrm{ref}} \leftarrow \pi_{\theta_k}\)，并以 \(\mathcal{D}_k\) 为输入执行标准 DPO 训练，获得下一轮检查点 \(\pi_{\theta_{k+1}}\)。

3.2 Fully Online DPO：单步流式流水线

Iterative DPO 的批式切分在大规模集群调度上容易造成 GPU 利用率波峰波谷（生成阶段访存受限，训练阶段计算密集）。近年来，诸如 HuggingFace TRL 与 DeepSeek 团队采用的是更先进的 Fully Online DPO（流式在线对齐）：每个 Micro-batch 内部，训练引擎直接调用绑定的推理引擎（如 vLLM 或 TensorRT-LLM）对当前 Prompt 实时生成两个采样，经由紧凑型轻量奖励模型即时打分判定胜负，随即直接构造 DPO 梯度进行反向传播！

💡 为什么 Online DPO 能在 AlpacaEval 上击败离线 DPO 10 个百分点以上？

核心原因在于负样本的新鲜度（Freshness）。在离线 DPO 中，负样本是过时模型产生的；而在 Online DPO 中，负样本是当前这一秒模型犯下的“最高概率错误”。优化器对这种在线错误的回击，能够直接削平当前策略在生成几何面上的尖锐虚假奇点，避免了优化方向在错误空间打空拳。

4. 免显式奖励模型的 AI 自主对齐（RLAIF 与 OAIF）

在追求极致自驱动后训练的路径上，不仅可以免去人工标注，甚至可以免去单独训练的数值型奖励模型（Scalar RM）。数值型 RM 存在一个众所周知的痼疾：标量打分难以解释且极易被长度、特殊标点或阿谀奉承（Sycophancy）攻破。

DeepMind 与 Google 研究团队提出了 OAIF（Online AI Feedback） 与直接指令遵从对齐。OAIF 采用一个更强或同等能力但搭载严密指令的语言模型直接作为“自然语言仲裁器”。对于策略模型在线生成的两份候选 \(y_1, y_2 \sim \pi_\theta(x)\)，直接构造如下元提示词送入判别器：

oaif_prompt_template.txt 
你是一位极其严谨的大语言模型回答仲裁专家。请评判针对以下提示词的两个候选回答，哪一个在准确性、无幻觉、格式严谨性上表现更优。
【提示词】：{prompt}
【候选 1】：{y1}
【候选 2】：{y2}

请根据第一性原理进行逻辑分析，并最终在最后一行输出明确的结论：
若候选 1 优于候选 2，输出 [[A]]；
若候选 2 优于候选 1，输出 [[B]]。

通过解析输出的 Token 概率分布：

\[ P(y_1 \succ y_2 \mid x) = \frac{\exp(\mathrm{logit}_{[[A]]})}{\exp(\mathrm{logit}_{[[A]]}) + \exp(\mathrm{logit}_{[[B]]})} \]

不仅完全免去了单独维护复杂价值网络的显存负担，而且可以利用推理模型强大的上下文理解与 Chain-of-Thought（思维链）判别能力，为策略模型提供极其敏锐的高信噪比偏好反馈。本节小结：大模型自身的语义判别能力已成为替代标量奖励模型的最强武器。

5. 在线迭代对齐工程实战：基于 vLLM + PyTorch 的完整在线 DPO 流水线

构建在线对齐系统的难点从来不在损失函数本身，而在于推理生成子进程（Generation Actor）与训练反传引擎（Training Engine）的高吞吐协同。如果在训练卡上直接使用 HuggingFace 默认的 model.generate()，由于缺乏 PagedAttention 与连续批处理（Continuous Batching），GPU 算力利用率通常低于 15%。

在下面的生产级实战中，我们演示如何利用 vLLM 推理引擎 作为高性能并发 Rollout 发生器，结合轻量打分规则与 DPO 反向传播，构建一个自包含、模块化的在线迭代对齐流水线。

online_dpo_pipeline.py 
import os
import torch
import torch.nn.functional as F
from transformers import AutoModelForCausalLM, AutoTokenizer
from vllm import LLM, SamplingParams

class OnlineDPOOrchestrator:
    """
    在线迭代 DPO 协调调度器:
    1. 使用 vLLM 高性能引擎进行在线并发采样本 (Rollout)
    2. 基于规则/打分器确定即时胜负
    3. 同步回传给 PyTorch 策略模型完成梯度步进
    """
    def __init__(self, model_id, beta=0.1, lr=5e-7):
        self.model_id = model_id
        self.beta = beta
        self.device = "cuda:0" if torch.cuda.is_available() else "cpu"

        print(f">>> 正在初始化策略与参考模型: {model_id}")
        self.tokenizer = AutoTokenizer.from_pretrained(model_id)
        if self.tokenizer.pad_token is None:
            self.tokenizer.pad_token = self.tokenizer.eos_token

        # 训练策略模型
        self.policy_model = AutoModelForCausalLM.from_pretrained(
            model_id, torch_dtype=torch.bfloat16
        ).to(self.device)
        self.policy_model.train()

        # 冻结的参考模型
        self.ref_model = AutoModelForCausalLM.from_pretrained(
            model_id, torch_dtype=torch.bfloat16
        ).to(self.device)
        self.ref_model.eval()
        for p in self.ref_model.parameters():
            p.requires_grad = False

        self.optimizer = torch.optim.AdamW(self.policy_model.parameters(), lr=lr)

        # 初始化 vLLM 推理引擎用于高速 Rollout (指定显存利用率)
        print(">>> 正在启动 vLLM 异步采样后端...")
        self.llm_generator = LLM(
            model=model_id,
            tensor_parallel_size=1,
            gpu_memory_utilization=0.35, # 预留显存给策略模型训练
            trust_remote_code=True
        )
        self.sampling_params = SamplingParams(
            n=2,                        # 对每个 Prompt 在线生成 2 个候选回复
            temperature=0.8,
            top_p=0.95,
            max_tokens=256
        )

    def generate_online_pairs(self, prompts):
        """利用 vLLM 并发采样候选对"""
        outputs = self.llm_generator.generate(prompts, self.sampling_params)
        online_data = []
        for out in outputs:
            prompt_text = out.prompt
            resp_a = out.outputs[0].text
            resp_b = out.outputs[1].text
            online_data.append((prompt_text, resp_a, resp_b))
        return online_data

    @staticmethod
    def mock_online_evaluator(prompt, resp_a, resp_b):
        """
        模拟在线判别器（生产环境中可替换为过程奖励模型 PRM、外部 LLM Judge 或语法解析器）
        此处使用简单启发式：优先选择不含代码块错误、字数适中且结构清晰的回答
        """
        score_a = len(resp_a) - (500 if "错误" in resp_a or len(resp_a) > 800 else 0)
        score_b = len(resp_b) - (500 if "错误" in resp_b or len(resp_b) > 800 else 0)
        
        if score_a >= score_b:
            return resp_a, resp_b # winner, loser
        else:
            return resp_b, resp_a

    def compute_logps_for_sequence(self, model, input_ids, attention_mask, labels):
        """计算序列自回归对数似然和"""
        outputs = model(input_ids=input_ids, attention_mask=attention_mask)
        logits = outputs.logits[:, :-1, :] # [B, T-1, V]
        shift_labels = labels[:, 1:]        # [B, T-1]

        # 仅对回答部分的 Token 计算对数概率
        loss_mask = (shift_labels != -100)
        log_probs = F.log_softmax(logits, dim=-1)
        
        # gather 目标 label 的对数似然
        per_token_logps = torch.gather(
            log_probs, dim=2, index=shift_labels.unsqueeze(2).clamp(min=0)
        ).squeeze(2)
        
        seq_logps = (per_token_logps * loss_mask).sum(dim=-1)
        return seq_logps

    def train_step(self, prompt, chosen_text, rejected_text):
        """在线 DPO 单步反向传播"""
        # 构建分词张量
        p_ids = self.tokenizer.encode(prompt, add_special_tokens=False)
        c_ids = self.tokenizer.encode(chosen_text, add_special_tokens=False) + [self.tokenizer.eos_token_id]
        r_ids = self.tokenizer.encode(rejected_text, add_special_tokens=False) + [self.tokenizer.eos_token_id]

        # 胜者输入与掩码
        input_w = torch.tensor([p_ids + c_ids], device=self.device)
        labels_w = torch.tensor([[-100] * len(p_ids) + c_ids], device=self.device)
        mask_w = torch.ones_like(input_w)

        # 输者输入与掩码
        input_l = torch.tensor([p_ids + r_ids], device=self.device)
        labels_l = torch.tensor([[-100] * len(p_ids) + r_ids], device=self.device)
        mask_l = torch.ones_like(input_l)

        # 1. 策略模型前向 (需梯度)
        pi_w_logps = self.compute_logps_for_sequence(self.policy_model, input_w, mask_w, labels_w)
        pi_l_logps = self.compute_logps_for_sequence(self.policy_model, input_l, mask_l, labels_l)

        # 2. 参考模型前向 (无梯度)
        with torch.no_grad():
            ref_w_logps = self.compute_logps_for_sequence(self.ref_model, input_w, mask_w, labels_w)
            ref_l_logps = self.compute_logps_for_sequence(self.ref_model, input_l, mask_l, labels_l)

        # 3. 计算在线 DPO 损失
        pi_ratio = pi_w_logps - pi_l_logps
        ref_ratio = ref_w_logps - ref_l_logps
        loss = -F.logsigmoid(self.beta * (pi_ratio - ref_ratio)).mean()

        # 4. 反向传播与梯度裁剪
        self.optimizer.zero_grad()
        loss.backward()
        torch.nn.utils.clip_grad_norm_(self.policy_model.parameters(), max_norm=1.0)
        self.optimizer.step()

        return loss.item()

    def run_online_cycle(self, prompt_batch):
        print(f"\n>>> 正在为 {len(prompt_batch)} 条 Prompt 在线生成候选并构建偏好...")
        rollouts = self.generate_online_pairs(prompt_batch)
        
        total_loss = 0.0
        for prompt, resp_a, resp_b in rollouts:
            winner, loser = self.mock_online_evaluator(prompt, resp_a, resp_b)
            step_loss = self.train_step(prompt, winner, loser)
            total_loss += step_loss

        avg_loss = total_loss / len(rollouts)
        print(f">>> 在线 DPO 迭代轮完成, 当前批平均损失: {avg_loss:.4f}")
        return avg_loss

在 SPIN 自博弈方案中，每一轮迭代需要将当前策略模型的输出存盘，作为下一轮博弈的输者参考池。以下展示了 SPIN 的数据生成与轮转迭代管理模块：

spin_iteration_runner.py 
import json
import torch
from transformers import AutoModelForCausalLM, AutoTokenizer

def generate_spin_synthetic_negatives(model_path, sft_dataset_path, output_jsonl_path, batch_size=4):
    """
    SPIN 数据生成阶段:
    读取人工真实 SFT 数据集 (含 prompt 和真实人工回答 chosen_response),
    调用上一轮策略模型生成伪造样本作为 negative_response (输者).
    """
    tokenizer = AutoTokenizer.from_pretrained(model_path)
    model = AutoModelForCausalLM.from_pretrained(
        model_path, torch_dtype=torch.bfloat16, device_map="auto"
    )
    model.eval()

    with open(sft_dataset_path, "r", encoding="utf-8") as f:
        sft_data = [json.loads(line) for line in f]

    print(f">>> 正在加载 {len(sft_data)} 条 SFT 数据生成 SPIN 对手负样本...")
    spin_dataset = []

    for i in range(0, len(sft_data), batch_size):
        batch = sft_data[i : i + batch_size]
        prompts = [item["prompt"] for item in batch]
        
        inputs = tokenizer(prompts, return_tensors="pt", padding=True, truncation=True, max_length=1024).to(model.device)
        with torch.no_grad():
            outputs = model.generate(
                **inputs,
                max_new_tokens=256,
                do_sample=True,
                temperature=0.7,
                top_p=0.9,
                pad_token_id=tokenizer.pad_token_id or tokenizer.eos_token_id
            )
        
        for idx, item in enumerate(batch):
            gen_tokens = outputs[idx][inputs["input_ids"][idx].shape[0]:]
            neg_reply = tokenizer.decode(gen_tokens, skip_special_tokens=True)
            spin_dataset.append({
                "prompt": item["prompt"],
                "chosen": item["response"],        # 人工真实回复作为胜者
                "rejected": neg_reply               # 对手策略生成的样本作为输者
            })

    with open(output_jsonl_path, "w", encoding="utf-8") as f:
        for entry in spin_dataset:
            f.write(json.dumps(entry, ensure_ascii=False) + "\n")
    print(f">>> SPIN 对手样本集已成功输出至: {output_jsonl_path}")

6. 在线对齐的稳定性陷阱与工程防护机制

将偏好对齐从静态推向在线虽然大幅提高了能力上限，但同时也成倍放大了系统的不稳定性。如果缺乏严格的工程护栏，在线系统可能在几轮迭代内迅速崩溃。以下是工业落地中最常见的四大故障模式及其解决方案：

6.1 策略自增强崩塌（Self-Reinforcing Delusion）

在自博弈或使用内部模型作为在线判别器时，如果当前模型产生了一种错误的思维模式（例如某种冗长且看似高深的伪学术废话），并且判别器（或启发式规则）误将其判定为优秀回答，这种错误就会在下一轮迭代中被强化。随着轮次累积，模型将彻底蜕变为“废话生成器”。

🚨 防御措施：锚定真实基准分布

绝不要进行纯粹无锚定的封闭自博弈！在每一轮在线生成与 DPO 训练中，必须混入至少 20%~30% 的高保真静态人工精标 SFT 数据，并在损失中施加标准因果语言模型交叉熵正则项（Cross-Entropy Regularization），强制拉拽模型词元先验不偏离自然语言流形。

6.2 在线采样的高熵爆炸与拒绝阈值

在动态生成时，若温度超参 \(T\) 设置过高，模型在线生成的负样本可能充斥着无逻辑乱码或截断文本。这种极其低级的负样本无法提供任何有价值的区分梯度，导致训练步虚耗。

工程法则：引入奖励裕度截断（Margin Filtering）。在在线打分阶段，设定胜负分差门限 \(\delta\)：只有当 \(|R(y_1) - R(y_2)| \ge \delta_{\min}\) 且两者皆不含乱码与重复死循环时，才允许入队反向传播，过滤掉 40% 以上的无效噪声。

8. 本章小结

  • 离线对齐的死穴：静态偏好学习必然导致模型生成分布与固定数据集渐行渐远，诱发严重的分布外（OOD）隐式奖励虚高，且无法有效消解当前策略新暴露的缺陷。
  • SPIN 自博弈的力量：通过将当前模型与历史模型对立，以真实 SFT 数据为靶心展开博弈，SPIN 在完全不依赖外部奖励模型的前提下实现了能力的自举与泛化提升。
  • Iterative/Online DPO 的工业支配地位：通过“实时采样当前策略输出 \(\to\) 动态打分筛选 \(\to\) 偏好步进”的紧密闭环，最新模型错误得以即刻被惩罚，大幅提升了在基准竞技场中的泛化胜率。
  • 基础设施的进化要求：在线对齐的性能天花板不再取决于反向传播算力，而取决于推理引擎（如 vLLM）的 Rollout 并发吞吐与 GPU 显存的精细切分管理。
🧠 自测题（点击展开答案）
问题 1：在 SPIN 自博弈算法中，为什么可以将人工真实 SFT 数据直接作为永恒的胜者（Chosen），而不会导致模型对 SFT 数据过拟合？

答案：在传统 SFT 中，模型只是单纯地以最大似然为目标最小化交叉熵，极易在有限的语料库上对句式、停用词等非本质统计特征过拟合。而在 SPIN 的博弈架构中，主模型不仅要提高真实 SFT 样本的似然，更关键的是要将其与当前对手策略实时生成的伪造样本进行对数概率做差比较（\(\log \pi_\theta(y) - \log \pi_\theta(y')\)）。这意味着损失函数并非单向逼近数据分布，而是在动态调整真实流形与模型错误生成流形之间的相对决策边界。由于对手生成的伪造样本在每一轮迭代中都在动态变化，模型被迫持续探索更鲁棒的语义辨别维度，从而自然获得了正则化效果，克服了单向 SFT 的过拟合。

问题 2：某团队在搭建 Online DPO 系统时，发现 GPU 显存频繁溢出（OOM），且训练吞吐极低，排查发现他们是在同一个训练脚本中交替调用 HuggingFace 的 generate() 和 backward()。应如何从系统架构层面进行重构？

答案：交替在单张训练卡上运行原生 generate() 会导致严重的显存碎片化，且 HuggingFace 原生生成缺乏针对 KV Cache 的显存分页优化（PagedAttention），吞吐极低。工程重构方案通常有两种：
1. 分离集群架构（推荐）：将系统解耦为推理集群（专用节点运行 vLLM / TensorRT-LLM，通过共享存储或高速 RPC 接收 Prompt 并高吞吐返回采样结果）与训练集群（专用节点挂载 DeepSpeed ZeRO-3 / FSDP 专心执行反向传播）；
2. 同节点双卡显存切分：若物理卡数有限，可通过 gpu_memory_utilization 严格划分显存界限，例如给 vLLM 实例分配 35% 显存作为独立常驻进程，训练框架占用剩余 60% 显存并开启梯度检查点（Gradient Checkpointing），通过跨进程队列传递在线生成的张量。

问题 3：在迭代 DPO（Iterative DPO）中，每一轮训练结束后，是否应该将参考模型 \(\pi_{\mathrm{ref}}\) 更新为上一轮新训练出的模型权重？为什么？

答案：应该更新（即执行 \(\pi_{\mathrm{ref}} \leftarrow \pi_{\theta_k}\)）。因为在迭代训练中，如果参考模型始终固定为最初的冷启动 SFT 模型，随着训练轮次 \(k\) 的增加，当前策略 \(\pi_{\theta_k}\) 与最初参考模型之间的 KL 散度会无限制拉大，导致 DPO 损失公式中的对数似然比项出现数值发散或梯度饱和；更重要的是，更新参考模型相当于将当前的生成基准锚定在最新达到的认知水平上，从而使 DPO 能够聚焦于微调当前轮次生成分布的边缘细微偏好，这与近端策略优化（PPO）中定期更新旧策略（Old Policy）以维持信任域约束（Trust Region）的理论逻辑完全一致。
