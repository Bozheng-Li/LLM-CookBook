第 26 章 · 推理后训练范式：从 CoT 到 o1/R1

从 2022 年 Wei 等人提出思维链（Chain of Thought, CoT）提示工程，到 2024 年 OpenAI o1 与 2025 年 DeepSeek-R1 的划时代突破，大语言模型的后训练范式经历了根本性质变。传统 RLHF 主要聚焦于拟合人类审美品味、礼貌风格与事实对齐，而以 DeepSeek-R1 为代表的推理强化学习，则彻底转向通过大规模强化学习诱导模型自主进行长思维链（Long CoT）搜索与试错。本章系统解构这一范式转移背后的认知科学逻辑、可验证奖励强化学习（RLVR）数学机理、反思与回溯的自发涌现、顿悟时刻（Aha Moment）演化轨迹，并深入辨析 SFT 模仿与纯 RL 探索的本质边界。

1. 思维链（CoT）的历史演进：从 Prompt 技巧到内生推理

在大语言模型的发展脉络中，思维链（Chain-of-Thought, CoT）的诞生彻底改变了机器解题的方式。早期以 GPT-3 为代表的自回归模型在接收到复杂数学、逻辑推理或算法编程题时，往往尝试在极短的几个 Token 内直接跳至最终结论，其解题过程本质上等价于单遍前向传播（Single-pass Feedforward）下的模式联想。然而，人类在面对高阶认知挑战时，绝非直接脱口而出答案，而是会在脑海或草稿纸上展开分步推导、假设检验与递进演算。

1.1 提示工程时代的短 CoT：激活潜伏知识

2022 年，Wei 等人发表里程碑式论文 Chain-of-Thought Prompting Elicits Reasoning in Large Language Models，揭示了一个极其简单却威力惊人的事实：仅需在 Few-shot 提示中为范例问题附加逐步思考的过程（如“让我们一步一步思考”或人工撰写的中间推理步骤），参数规模超过千亿的语言模型在 GSM8K、SVAMP、AQuA 等多步数学基准上的正确率就呈现数十个百分点的爆发式跃升。

在随后的两年中，学术界与工业界围绕短 CoT 开展了密集的工程变体探索：

  • 零样本思维链（Zero-shot CoT）：Kojima 等人（2022）发现只需在 Prompt 结尾追加 "Let's think step by step" 这一魔术短语，即可激活基座模型内部未被显式引出的序贯推理概率流。
  • 自一致性采样（Self-Consistency）：Wang 等人（2022）提出在推理时以非零温度（Temperature）对同一个 Prompt 进行 \( K \) 次独立并发采样，利用多数投票机制（Majority Voting）过滤掉偶发计算失误的推理支流，显著压制了随机幻觉。
  • 思维树与思维图（Tree of Thoughts / Graph of Thoughts）：Yao 等人与 Yao 等团队将线性短链推广至多分支搜索空间，利用外部提示词控制模型评估每一步的状态，尝试模拟人类的高级规划机制。

然而，提示工程时代的短 CoT 存在难以逾越的天花板：中间思考过程完全受制于预训练语料中既有的人类知识表征，模型本身并未在训练时建立对“探索失败并推翻重来”的优化机制；面对国际数学奥林匹克（IMO）或复杂算法竞技题，短 CoT 往往在第 3~5 步出现致命幻觉，随后便沿着错误的轨迹一路滑向荒谬的结论。

1.2 从外置提示到模型内生参数重塑

要打破短 CoT 的局限，必须将“思考”从外部 Prompt 技巧转化为模型固有权重中的自发行为。这要求在后训练阶段重构损失函数与数据信号，使模型在生成最终答案前，自发耗费大量 Token 算力展开长程推演。表 26-1 总结了短思维链与长思维链在核心维度的本质分野。

2. 范式裂变：从模仿人类对话到大规模强化学习诱导

在以 InstructGPT、Llama 2-Chat 为代表的经典 RLHF 时代，后训练的核心哲学是人类偏好拟合（Human Preference Alignment）。标注人员根据模型的输出给出胜负打分，训练一个连续标量奖励模型（Reward Model, RM），再通过 PPO 引导模型去取悦人类的审美偏好——结构清晰、语调谦逊、格式严整、富有同理心。然而，这种拟合机制在数理逻辑与确定性推理任务中遭遇了严重的“对齐税（Alignment Tax）”与天花板效应。

2.1 人类偏好拟合的局限性与奖励黑客攻击

经典 RLHF 面向推理任务时面临三大无法调和的矛盾：

  1. 人类标注员的能力上限：面对前沿竞赛数学、底层系统漏洞挖掘或复杂动态规划算法，普通众包标注员甚至无法在数小时内辨别模型推导过程是否存在逻辑跳跃，导致标注信号充满噪声。
  2. 奖励模型的拟合漂移（Reward Hacking）：神经奖励模型容易被“冗长、引经据典、看似头头是道实则包含逻辑谬误”的回答所欺骗。策略模型往往学会了写出极其漂亮的“伪推导”，而非真正解决数学难题。
  3. 风格平庸化：SFT 数据主要采集人类专家的既有解答。由于人类撰写标准答案时偏好精简优雅，省略了试错、涂改、死胡同碰壁与换方向的过程，直接用 SFT 训练的模型只会“模仿成品的优雅表象”，却丧失了在黑暗未知空间中自主试错探索的能力。

2.2 o1 与 DeepSeek-R1 带来的范式转移

2024 年秋季 OpenAI o1 系列模型的发布，以及 2025 年初 DeepSeek-R1 论文与权重的开源，正式宣告了后训练第二曲线的降临。这一范式转移的核心公式可以精辟概括为：

从“让人类教模型如何像人一样说话”，转变为“用可判定的客观真理作为奖励标尺，通过大规模强化学习逼迫模型自发学会深度思考”。

如图 26-1 所示，DeepSeek-R1 验证了一个惊人的科学事实：即使完全不借助人类编写的高质量推理 SFT 数据，仅凭一个预训练完备的基座大模型，在基于确定性规则的强化学习环境下进行大规模探索（DeepSeek-R1-Zero 路径），模型内部的推理能力便会自发发生相变，自主演化出万字长思考链、自我修正与交叉校验机制。

本节小结：推理强化学习彻底摆脱了基于主观偏好的人类奖励模型束缚，转向以客观数学与逻辑真理为唯一锚点的纯粹探索范式。

3. 可验证奖励强化学习（RLVR）原理与数学建模

支持这一波推理革命的核心技术支柱被称为可验证奖励强化学习（Reinforcement Learning with Verifiable Rewards, RLVR）。与必须借助神经网络打分的通用对话不同，在数学、编程、逻辑谜题、形式化证明等确定性领域，答案的对错具有绝对客观的真值判定准则（Ground Truth Verifiability）。

3.1 RLVR 的数学形式化

在 RLVR 设定下，给定训练集中的问题 \( x \in \mathcal{D} \)，策略模型 \( \pi_\theta \) 自回归生成一个完整的输出序列 \( y = (y_{\mathrm{think}}, y_{\mathrm{ans}}) \)，其中 \( y_{\mathrm{think}} \) 为模型内部生成的推导演算过程（通常包裹在特定的标记标签内，如 <think> ... </think>），而 \( y_{\mathrm{ans}} \) 为最终提交的结论。环境由确定性的验证函数（Verifier）构成，其奖励函数 \( R(x, y) \) 定义为：

\[ R(x, y) = R_{\mathrm{acc}}(x, y_{\mathrm{ans}}) + \lambda_{\mathrm{fmt}} R_{\mathrm{format}}(y) \]

其中各项具体含义如下：

  • 准确率奖励 \( R_{\mathrm{acc}}(x, y_{\mathrm{ans}}) \)：由规则解析器或判题沙箱输出的二值奖励： \[ R_{\mathrm{acc}}(x, y_{\mathrm{ans}}) = \begin{cases} 1.0, & \text{若 } \mathrm{Verify}(x, y_{\mathrm{ans}}) = \mathrm{True} \\ 0.0, & \text{若 } \mathrm{Verify}(x, y_{\mathrm{ans}}) = \mathrm{False} \end{cases} \] 在数学问题中，通常将 \( y_{\mathrm{ans}} \) 解析为 LaTeX 数值表达式，利用符号计算库（如 SymPy）与标准答案进行代数等价性校验；在代码问题中，将生成的代码放入单元测试沙箱执行，全部测试用例 Pass 即给 1.0，否则给 0.0。
  • 格式一致性奖励 \( R_{\mathrm{format}}(y) \)：约束模型必须且只能将思考与最终答案按规范排布，防止模型在推理过程中破坏标签闭合或遗漏最终结论。若未包含闭合的 <think> 标签或未在指定格式中输出答案，则施加严厉惩罚（如 \( -1.0 \) 或 \( 0.0 \)）。
  • 权重系数 \( \lambda_{\mathrm{fmt}} \)：平衡格式与准确率的超参数，通常取 0.1 ~ 0.5。

3.2 策略优化目标与无 Critic 优势估计

在 RLVR 中，由于每次采样均生成完整回答，若采用传统的 PPO 架构，需要单独维护一个参数庞大的 Critic（值函数网络）来估计每步的状态价值。然而，Critic 在面对长度超过 16K 的极端长序列时，显存开销会发生爆炸，且对离散答案跳变的值函数拟合极不稳定。

因此，现代推理强化学习普遍采纳群组相对策略优化（Group Relative Policy Optimization, GRPO）或其变体。针对每个问题 \( x \)，策略网络并发采样 \( G \) 个候选轨迹 \( \{y_1, y_2, \dots, y_G\} \sim \pi_{\theta_{\mathrm{old}}}(\cdot \mid x) \)，验证器计算各轨迹的奖励 \( \{r_1, r_2, \dots, r_G\} \)。各轨迹的优势（Advantage）直接由群组内部归一化得出：

\[ A_i = \frac{r_i - \mu_G}{\sigma_G + \epsilon}, \quad \text{其中 } \mu_G = \frac{1}{G}\sum_{j=1}^G r_j, \; \sigma_G = \sqrt{\frac{1}{G}\sum_{j=1}^G (r_j - \mu_G)^2} \]

\[ \mathcal{L}_{\mathrm{RLVR}}(\theta) = -\frac{1}{G}\sum_{i=1}^G \left[ \frac{1}{|y_i|}\sum_{t=1}^{|y_i|} \min\left( \frac{\pi_\theta(y_{i,t} \mid x, y_{i,这一机制确保了如果某一次长探索偶然猜中了正确答案（\( r_i = 1.0 \)），而同一组其他 \( G-1 \) 次探索均告失败（\( r_j = 0.0 \)），该成功轨迹所经历的全部长程思考 Token 将获得极高的正优势 \( A_i > 0 \)，从而在梯度反向传播中被极力强化！

📘 核心启示：稀疏二值奖励为何能诱导万步密集思考？

初学者常疑惑：在 16,000 个 Token 的序列末端仅给一个 0 或 1 的标量，中间每一步甚至没有密集奖励，梯度如何有效分配？答案在于自回归因果概率链与群组对比。当采样群组中大部分样本因走错某一步而导致最终答案为 0 时，唯独走对那关键一步的样本获得了 1。优势归一化后，全序列上的对数似然梯度不仅强化了最终答案，更以连带效应强化了通往成功答案的前置分叉点决策，实现了端到端的自发信用分配（Credit Assignment）。

本节小结：RLVR 以零噪声的客观验证器取代拟合式奖励模型，利用群组采样归一化抹平 Critic 显存开销，构成了长推理链自发演化的底层数学动力。

4. 深度探索中的自主涌现行为：反思、回溯与交叉验证

在纯强化学习环境下持续训练模型时，研究人员观察到了一系列并未在任何 Prompt 中显式要求、也未在 SFT 语料中强制灌输的自主涌现行为（Emergent Reasoning Behaviors）。这些行为在传统的短回答模型中几乎不可见，但在长推理探索树中成为了标准范式。

4.1 反思（Reflection）：元认知视角的自我审视

在推导展开到某个阶段后，模型不再像过去那样盲目下结论，而是自发插入一段形如 "Wait, is this step logically sound?" 或 "Hold on, I assumed that \( n > 0 \), but what if \( n = 0 \)?" 的元语言思考。这种行为的本质是：模型在注意力层级上将过去生成的中间假设作为输入，触发了对先决条件、边界条件及符号代换合法性的再次注意力聚焦（Re-attention）。

4.2 回溯（Backtracking）：死胡同的主动推翻与路径切换

如图 26-2 所示，在传统 LLM 中，一旦前缀中出现错误，自回归误差便会指数级累积。而在长推理强化学习中，当推演走向逻辑死胡同（如导出 \( 0 = 1 \) 或出现代数虚数与题目实数域矛盾）时，策略网络学会了使用否定词句："This leads to a contradiction. So my initial assumption must be false. Let me restart from another perspective..."。模型主动在文本序列中“斩断”此前的无效路径，并将注意力重新引导回分叉点之前，开辟第二条、第三条潜在推导轨迹。

4.3 交叉验证（Cross-checking）：多维度的独立求证

在得出最终结果之前，充分训练的推理模型会自发采用完全不同的方法进行重算。例如：在求定积分时，模型先通过换元法得出结果 \( \frac{\pi}{4} \)，随后立刻自发写出："Let me check this result using numerical substitution or differentiation of the antiderivative..."，通过微分逆运算反向验证原函数，或者代入 \( x = 0, 1 \) 等特值验证边界。只有当两条独立路径得到严格相同的结果时，模型才会信心满满地闭合 </think> 标签并给出最终答案。

本节小结：反思、回溯与交叉检验并非人类工程师硬编码的启发式逻辑，而是强化学习在巨大状态空间中为了获取二值奖励所自发演化出的高阶生存策略。

5. 顿悟时刻（Aha Moment）复盘与动力学机制

在 DeepSeek-R1-Zero 的训练过程中，研究团队记录到了人工智能发展史上极其震撼的一个片段，即被称为顿悟时刻（Aha Moment）的现象。在没有任何人类干预的情况下，模型在思考过程中突然产生了自我怀疑、重新审视并推翻重来的完整心智流。

5.1 原始日志切片重现

以下是 DeepSeek-R1-Zero 在解决一道涉及几何概率与组合积分难题时的原始日志片段节选：

... Thus, the integral evaluates to 3/8. But wait! Let me reconsider the boundary conditions. The problem states that the two points are chosen uniformly on the perimeter, not within the interior! Oh, wow, that completely changes the measure! Let me re-evaluate the measure of the sample space. Aha! If they are on the perimeter, the perimeter length is 4, not area 1. Let me start over with parameter t in [0, 4) ...

在这段文字中，模型不仅表现出极其逼真的拟人化语气助词（"Wait!", "Oh, wow", "Aha!"），更重要的是在认知层面上准确识别出了此前推演中的隐蔽语义漏洞（混淆了周长采样与面积采样），并在瞬间完成了坐标系重构与全套重算。

5.2 顿悟时刻背后的统计物理与动力学机理

从纯数学与统计物理视角审视，为什么自回归模型会产生这种戏剧性的“顿悟”？其底层动力学机理可以归结为以下三个阶段：

  1. 长尾试错积累（Exploration Under Plateau）：在早期训练阶段，绝大多数长思考轨迹都因为错误而得到奖励 0。但在庞大的群组采样（如 \( G = 64 \)）中，偶尔有一条轨迹在第 4,000 个 Token 处碰巧生成了类似于“重新阅读题目”的片段，并侥幸蒙对了答案。
  2. 熵骤降与相变（Phase Transition & Entropy Collapse）：这一成功样本的高优势值迅速将“重新阅读/怀疑假设”这类转换 Token（Shift Tokens）的梯度大幅放大。在几百个优化步内，整个模型在遇到复杂未知模式时的策略熵急剧变化，模型在注意力流中形成了强烈的“自我质疑重定向回路”。
  3. 计算时间的内生扩张（Thinking Length Explosion）：随着反思能力的强化，模型发现只要不断延长思考序列、反复验证，猜中正确答案的期望回报就会持续增加。平均生成长度从初始的几百个 Token 迅速自发膨胀至数万个 Token，进入高阶推理平原。
💡 认知科学视角的双系统理论映射

认知科学家丹尼尔·卡尼曼在《思考，快与慢》中将人类思维分为：直觉快速的系统 1（System 1）与逻辑缓慢、耗费精力的系统 2（System 2）。早期的预训练与标准 SFT 模型本质上是“纯粹的系统 1”，试图仅靠单步自回归直觉回答所有问题；而通过强化学习诱导长思考链，本质上是在单个神经网络内部，通过不断自回归地与自身过去生成的思考 Token 交互，成功模拟并实例化了计算代价高昂却高度精确的系统 2。

本节小结：顿悟时刻是强化学习在探索空间中冲破局部极小值的宏观表现；它标志着模型从死记硬背题解跨越到了自适应的认知重构阶段。

6. 长推理链 SFT 驱动 vs 纯 RL 诱导：机制、泛化与天花板对比

在业界探索推理大模型落地时，存在两种截然不同的技术路线：纯 RL 诱导（Pure RL, 如 DeepSeek-R1-Zero）与高质量长思维链 SFT + RL 混合驱动（Cold-start SFT + RL, 如标准 DeepSeek-R1 与主流商用实践）。二者在工程可行性、性能天花板与行为特征上存在剧烈分野，如表 26-2 所示。

7. RLVR 核心工程组件与环境实战实现

构建一个稳定的可验证奖励强化学习系统，必须具备三个关键软件构件：安全的确定性执行与解析沙箱、推理轨迹中的认知行为监视器、以及基于群组相对优势的策略更新循环。

7.1 数学与规则奖励验证器实现

在数学任务中，模型输出的答案可能带有丰富的排版形式（例如 \( x = \frac{1}{2} \)、0.5、\frac{2}{4} 等）。验证器必须具备符号代数等价性判别能力，同时严格防范恶意注入代码。

math_verifier.py 
import re
from typing import Optional, Tuple
import sympy
from sympy.parsing.sympy_parser import parse_expr, standard_transformations, implicit_multiplication_application

class MathRuleVerifier:
    """可验证奖励数学解析器：负责提取 \\boxed{...} 答案并进行符号代数等价性校验"""
    def __init__(self, timeout_sec: float = 2.0):
        self.timeout_sec = timeout_sec
        self.transformations = standard_transformations + (implicit_multiplication_application,)

    def extract_answer(self, text: str) -> Optional[str]:
        """从模型生成的全文或答案区抽取最终答案"""
        # 优先提取 \\boxed{...} 内的内容
        boxed_matches = re.findall(r'\\boxed\{([^{}]+)\}', text)
        if boxed_matches:
            return boxed_matches[-1].strip()
        
        # 备选：匹配 "The answer is ..."
        answer_pattern = re.findall(r'[Tt]he answer is:?\s*([^\n\.]+)', text)
        if answer_pattern:
            return answer_pattern[-1].strip()
        return None

    def check_equivalence(self, pred: str, target: str) -> bool:
        """基于 SymPy 的代数恒等性判断，兼容分数、根号与符号多项式"""
        pred = pred.replace('$', '').strip()
        target = target.replace('$', '').strip()

        # 快速字符串字面匹配
        if pred == target:
            return True

        # 符号代数判等
        try:
            expr_pred = parse_expr(pred, transformations=self.transformations, evaluate=False)
            expr_target = parse_expr(target, transformations=self.transformations, evaluate=False)
            # 作差检验：若差值为 0，则严格等价
            diff = sympy.simplify(expr_pred - expr_target)
            return bool(diff == 0)
        except Exception:
            # 若无法解析为代数表达式，降级为浮点数近似比对
            try:
                val_pred = float(sympy.N(parse_expr(pred)))
                val_target = float(sympy.N(parse_expr(target)))
                return abs(val_pred - val_target) < 1e-5
            except Exception:
                return False

    def compute_reward(self, model_output: str, ground_truth: str) -> Tuple[float, dict]:
        """计算 RLVR 复合奖励：准确率 (1.0/0.0) + 格式合规性检查"""
        has_think_start = "" in model_output
        has_think_end = "" in model_output
        format_valid = has_think_start and has_think_end

        extracted_pred = self.extract_answer(model_output)
        is_correct = False
        if extracted_pred is not None:
            is_correct = self.check_equivalence(extracted_pred, ground_truth)

        # 奖励计算：正确给 1.0，格式错误扣减 0.2，未提取到或错误给 0.0
        acc_reward = 1.0 if is_correct else 0.0
        fmt_penalty = 0.0 if format_valid else -0.2
        total_reward = max(0.0, acc_reward + fmt_penalty)

        metrics = {
            "is_correct": is_correct,
            "format_valid": format_valid,
            "extracted_pred": extracted_pred
        }
        return total_reward, metrics

7.2 思考轨迹元认知行为监控器

为了在海量采样数据中定量追踪反思、回溯与顿悟时刻的演化频次，我们需要一套高效的模式匹配与注意力语义探测器。

cognition_monitor.py 
from typing import Dict, Any

class ReasoningTrajectoryMonitor:
    """实时监控推理链中的反思（Reflection）、回溯（Backtracking）与顿悟标志"""
    def __init__(self):
        # 典型反思与回溯标记词库
        self.reflection_cues = [
            "wait,", "wait!", "hold on", "let me double check",
            "let me re-read", "reconsidering", "is this correct"
        ]
        self.backtracking_cues = [
            "this leads to a contradiction", "my assumption was wrong",
            "let's start over", "discarding this approach", "scratch that"
        ]
        self.aha_cues = [
            "aha!", "oh, wait", "now i see", "eureka", "wait a second"
        ]

    def analyze_trajectory(self, thinking_content: str) -> Dict[str, Any]:
        text_lower = thinking_content.lower()
        token_count = len(thinking_content.split())  # 粗略词元估计

        reflections = sum(text_lower.count(cue) for cue in self.reflection_cues)
        backtrackings = sum(text_lower.count(cue) for cue in self.backtracking_cues)
        ahas = sum(text_lower.count(cue) for cue in self.aha_cues)

        return {
            "approx_tokens": token_count,
            "reflection_freq": reflections,
            "backtracking_freq": backtrackings,
            "aha_freq": ahas,
            "has_self_correction": (reflections > 0 and backtrackings > 0)
        }

7.3 极简 RLVR 群组优势更新框架

以下代码清晰演示了在一次 Step 中，系统如何对同一 Prompt 进行群组并行采样、执行无 Critic 的优势估计、并对策略网络执行 PPO-Clip 风格梯度优化的核心逻辑。

rlvr_grpo_step.py 
import torch
import torch.nn.functional as F

def compute_group_advantages(rewards: torch.Tensor, eps: float = 1e-4) -> torch.Tensor:
    """针对形如 [Batch_Size, Group_Size] 的奖励矩阵，计算群组内标准化优势"""
    mean = rewards.mean(dim=1, keepdim=True)
    std = rewards.std(dim=1, keepdim=True)
    advantages = (rewards - mean) / (std + eps)
    return advantages

def rlvr_policy_loss(
    logprobs: torch.Tensor,         # [Batch * Group, Seq_Len]
    old_logprobs: torch.Tensor,     # [Batch * Group, Seq_Len]
    advantages: torch.Tensor,       # [Batch * Group]
    mask: torch.Tensor,             # [Batch * Group, Seq_Len]
    clip_eps: float = 0.2
) -> torch.Tensor:
    """计算带重要性采样截断的 RLVR 策略损失"""
    # 计算 Token 级概率比率
    ratio = torch.exp(logprobs - old_logprobs)
    
    # 广播优势至全序列长度
    adv = advantages.unsqueeze(-1)
    
    surr1 = ratio * adv
    surr2 = torch.clamp(ratio, 1.0 - clip_eps, 1.0 + clip_eps) * adv
    
    # 取悲观下界
    policy_loss = -torch.min(surr1, surr2)
    
    # 仅在非 Pad 的有效 Token 处聚合损失
    valid_loss = (policy_loss * mask).sum() / mask.sum().clamp(min=1.0)
    return valid_loss
⚠️ 工程陷阱：长文本下的 NaN 与梯度爆炸

当推理链延伸至 16K 以上时，注意力 Softmax 与全序列求和极易在半精度（FP16）下发生数值下溢或溢出。在进行 RLVR 训练时，强烈建议全管线强制使用 BF16 或 FP32 计算损失，并严格设置梯度范数截断 max_grad_norm = 1.0。同时，对全 0 奖励的群组必须施加方差保底平滑，防止除以零引发整机权重报废。

本节小结：RLVR 核心工程依赖高容错的符号代数判定、轨迹认知监视器以及数值稳定的群组归一化损失实现。

8. 本章小结

本章系统回顾了从外置提示工程（CoT）到内生长推理模型（o1 / DeepSeek-R1）的后训练范式大转移。主要核心结论如下：

  • 范式蜕变：传统 RLHF 止步于模仿人类语言风格与对话礼貌；现代推理强化学习利用确定性环境的客观规则，诱导模型进入自发长程计算。
  • RLVR 机制：通过二值准确率奖励与格式奖励驱动，配合无 Critic 的群组相对优势估计（GRPO），彻底解除了神经奖励模型带来的拟合欺骗难题。
  • 认知涌现：反思、回溯、交叉检验与顿悟时刻并非人为规则编排，而是模型在大规模探索与极限测试时计算下为了最大化正确率的自发优化产物。
  • 技术选型：纯 RL 奠定了探索上限，而冷启动高质量长 CoT 则是商业化模型消除语言混杂、提升工程收敛速度的最佳伴侣。
🧠 自测题（点击展开答案）
问题 1：为什么在长思维链推理强化学习中，通用神经网络奖励模型（RM）会被基于规则的验证器（RLVR）全面取代？

答案：神经网络 RM 存在三大致命缺陷：(1) 奖励黑客攻击（Reward Hacking），模型会学会生成看似严密实则逻辑荒谬的冗长回答来刷分；(2) 面对高阶数理与算法竞赛，人类标注员甚至无法提供无噪声的正确偏好；(3) 连续标量 RM 在离散推理真值面前存在严重的拟合漂移。而规则验证器（如 SymPy 符号代数、代码沙箱）具有确定性、客观性与零偏见，彻底切断了奖励欺骗路径。

问题 2：在没有给中间步骤赋予任何即时奖励的前提下，RLVR 究竟是如何引导模型学会“在第 500 步主动回溯并推翻重来”的？

答案：RLVR 依赖群组采样（Group Sampling）与自回归因果概率流。针对同一个 Prompt，模型采样生成多条轨迹。那些盲目坚持错误假设的轨迹最终得到 0 奖励；而某一条偶然在中间生成了“怀疑假设、重新推导”的轨迹最终验证正确得到 1 奖励。在优势标准化后，这组对比使成功轨迹上的所有 Token（包括中间的回溯转折词）获得极大的正向梯度，在因果链条上强化了“在发现矛盾时主动回溯”的条件概率分布。

问题 3：DeepSeek-R1-Zero 在纯强化学习初期为什么会出现严重的“语言混杂（Language Mixing）”？冷启动 SFT 如何解决这一问题？

答案：R1-Zero 的奖励函数最初仅包含准确率与格式判断，并未对思考链的语言纯净度设置约束。由于预训练基座中蕴含多语言语料，模型在漫长探索中会自发调用最利于压缩表征与符号推导的词汇（如英文数学概念、中文解释词、甚至代码符号碎片），导致中英混杂。冷启动 SFT 通过注入数千条语言规范、段落清晰的人工精选 Long CoT 数据，为模型设定了语言风格与思维骨架的先验，从根源上消除了杂乱无序的混杂现象。
