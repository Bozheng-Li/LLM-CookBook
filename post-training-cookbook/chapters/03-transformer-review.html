1. 为什么要为"后训练"重新复习 Transformer

大多数工程师第一次学 Transformer，是从预训练或者 NLP 课程的视角进入的：关注的是"它为什么能替代 RNN""长距离依赖怎么解决"。但在后训练的语境下，你面对的问题完全不同：你要在冻结或微调一个已经训练好的 7B~70B 模型时，准确说出"我的损失函数作用在哪几个张量上""为什么 PPO 需要同时跑四个模型""为什么把上下文从 4k 扩到 32k 显存会爆"。这些问题的答案，全部埋在架构的细节里。

具体来说，后训练工程师对 Transformer 的依赖集中在四个点上。第一，log 概率是后训练的"通用货币"：SFT 的损失是 Next-Token Prediction 的负对数似然，PPO 的比率 \(r(\theta)\) 是新旧策略的 log 概率差，DPO 的目标里是策略与参考模型的 log 概率比——这些都要求你精确知道"log 概率是怎么算出来的"（第 10 节的前向数据流）。第二，token 是计费与对齐的基本单位：显存、算力、数据量、奖励分配，全部以 token 计（第 3 节与第 9 节）。第三，KV cache 决定推理与 RL rollout 的成本结构：后训练的瓶颈往往不是训练前向，而是采样生成（第 9 节，详见第 45 章）。第四，架构同质化：LLaMA/Qwen/Mistral 系模型几乎是同一套配方（RoPE + RMSNorm + SwiGLU + GQA），记住一张参数表就能覆盖 90% 的开源模型（第 8 节）。

本章不重复教科书式的逐层推导，而是按"后训练视角"重新组织这些知识。先给一张总览图（图 3-1）：一个 token 从整数 ID 一路走到 logits 的完整前向数据流——这是后训练里每一次"取 log 概率"的物理路径，本章后面各节就是沿着这张图逐站展开的。如果你对原始论文已经烂熟，可以快速扫过第 4~6 节，把时间留给第 8~10 节；如果你刚入门，建议按顺序读完，并在读到每个组件时问自己一个问题：它如果我改了，后训练的哪些环节会跟着变？

本节小结：后训练的所有算法都构建在语言模型的前向计算之上，本章的目标是把"会用 API 调模型"升级为"知道每个张量从哪来、到哪里去"。

2. 语言模型的概率定义：链式分解与自回归

一个自回归语言模型（Autoregressive Language Model）对一段长度为 \(T\) 的 token 序列 \(x = (x_1, x_2, \dots, x_T)\) 建模。根据概率的链式分解（chain rule），任意序列的联合概率都可以写成一系列条件概率的乘积：

\[ p_\theta(x) = \prod_{t=1}^{T} p_\theta(x_t \mid x_1, x_2, \dots, x_{t-1}) = \prod_{t=1}^{T} p_\theta(x_t \mid x_{<t}) \]

这个分解在数学上是恒等式，不依赖任何模型假设；语言模型做的唯一一件事，是用一个神经网络 \(p_\theta\) 去逼近其中每一个条件分布。训练目标是极大似然估计（Maximum Likelihood Estimation, MLE），等价于最小化数据分布与模型分布之间的交叉熵：

\[ \mathcal{L}_{\mathrm{LM}}(\theta) = -\sum_{i} \sum_{t=1}^{T_i} \log p_\theta\!\left(x_t^{(i)} \,\middle|\, x_{<t}^{(i)}\right) \]

这里有三件事值得停下来想清楚，因为它们贯穿全书。其一，"生成"就是"采样"：模型在推理时逐 token 地从 \(p_\theta(x_t \mid x_{<t})\) 中采样、拼回前缀、再采下一个——所谓自回归生成，就是把这个条件分布链走完，直到输出终止符。第 6 章会把这个过程精确地建模为一个马尔可夫决策过程。其二，SFT 与预训练的损失函数形式完全相同，区别只在数据分布：预训练最小化互联网文本的负对数似然，SFT 最小化"指令—回答"对中回答部分的负对数似然（只对回答 token 计算 loss，实现细节见第 13 章）。理解了这一点，你就明白 SFT 不是什么新算法，只是换了一个数据分布上的 MLE。其三，后训练的 RL 方法也构建在同一个条件分布之上：策略 \(\pi_\theta(a \mid s)\) 中的"动作概率"，在 LLM 语境下就是 \(p_\theta(y_t \mid x, y_{<t})\)——RLHF 并没有引入新的模型结构，只是换了优化目标（第 5、6 章）。

📘 概念辨析：条件概率 vs 联合概率打分

BERT 类模型学的是双向的、去噪式的表示（第 4 章），它输出的分数不是"给定前缀生成下一个 token"的合法概率，因此不能直接做自回归生成，也不能直接套用策略梯度类方法。这就是为什么本书后训练部分的工作对象几乎全是 decoder-only 的因果语言模型：只有它给出的是规范的、逐 token 条件分布，"采样一条完整回答"与"计算该回答的 log 概率"才是同一个模型的两种用法。第 22 章的 DPO 推导正是同时用到了这两种用法。

本节小结：语言模型 = 条件分布链的参数化；预训练、SFT、RLHF 共用同一个前向计算，差异只在损失函数与数据分布。

3. Tokenization：BPE、SentencePiece 与词表大小的权衡

神经网络不能直接处理字符串，文本必须先切分成 token 并映射为整数 ID。现代 LLM 几乎全部使用子词（subword）分词，主流方案有两种。字节对编码（Byte-Pair Encoding, BPE）从字符级词表出发，反复合并语料中最高频的相邻符号对，直到达到目标词表大小；GPT-2、LLaMA、Mistral 采用它的字节级变体（byte-level BPE），保证任何字节序列都能编码、没有 OOV。SentencePiece（Kudo & Richardson, 2018）是一个把"原始文本→token 序列"整体视为无损耗管线的库，内置 BPE 与 Unigram 两种算法，并把空格当作普通字符处理（用 ▁ 表示），对中日韩等无空格语言和混合语料更友好；Qwen、Gemma 系采用它或等价的实现。

词表大小是Tokenizer 设计中最关键的旋钮，它同时牵动三笔账。算力账：词表越大，同样一段文本被切成的 token 越少，预训练与推理的每字计算量越低——中文在 3.2 万词表下平均 1 个汉字占 1.5~2 token，在 15 万词表下常见词接近 1 token，等价于"同样的模型算力多读了 30%~50% 的中文内容"。显存账：embedding 与输出投影 lm_head 的参数量与词表成正比，128k 词表 × 4096 维的 lm_head 在 bf16 下约 1.0 GB，128k 词表 × 16384 维（405B 模型）则超过 4 GB；此外 lm_head 的 logits 计算与词表softmax在大 batch 下是显著的开销项。效果账：词表过小会过度切碎文本、拉长序列、拖累长距离建模；过大则低频 token 训练不充分（每个 token 需要足够的出现次数才能学到合理的 embedding），并加剧 embedding 层的参数浪费。实践上，多语模型的主流选择在 10 万~25 万之间。

💡 实践建议：为后训练准备特殊 token

后训练阶段你会频繁与特殊 token 打交道：对话模板的轮次分隔符（第 15 章）、填充符、EOS。它们必须在 tokenizer 的词表中预注册（作为 special token，且保证不被 BPE 拆开）。如果你在 SFT 阶段才临时往词表里加 token，新增的 embedding 是随机初始化的，需要额外的训练技巧才能收敛；更稳妥的做法是选型时就确认 base 模型自带的特殊 token 是否够用。另外，统计你业务语料的压缩率（tokens/字符）是估算训练与推理成本的第一步，第 42 章的算力预算全靠它。

下面的代码展示如何用 HuggingFace tokenizers 库从零训练一个 byte-level BPE 分词器，整个过程与 GPT-2/LLaMA 的做法同构：

train_bpe_tokenizer.py 
from tokenizers import Tokenizer, models, trainers, pre_tokenizers, decoders

# 用 byte-level BPE 训练一个 3.2 万词表的分词器（流程与 GPT-2/LLaMA 相同）
tokenizer = Tokenizer(models.BPE(unk_token=None))          # 字节级兜底，无需 unk
tokenizer.pre_tokenizer = pre_tokenizers.ByteLevel(add_prefix_space=False)
tokenizer.decoder = decoders.ByteLevel()
trainer = trainers.BpeTrainer(
    vocab_size=32000,            # 词表上限：权衡算力/显存/低频 token 学习
    min_frequency=2,             # 低于 2 次的合并不采纳
    special_tokens=["<|begin_of_text|>", "<|end_of_text|>", "<|pad|>"],
)
tokenizer.train(["corpus_zh_en.txt"], trainer)
tokenizer.save("bpe_32k.json")

enc = tokenizer.encode("大模型后训练实战：Post-Training Cookbook")
print(enc.tokens)          # 形如 ['大', '模型', '后', '训练', '实战', '：', 'Post', ...]
print(len(enc.ids))        # token 数：压缩率直接决定训练成本与上下文余量
print(tokenizer.encode("鿾").ids)   # 生僻字会退到 UTF-8 字节级表示，保证无损

本节小结：BPE/SentencePiece 用子词在"词表大小、序列长度、无损编码"之间做权衡；对后训练工程师，重点是压缩率决定成本、特殊 token 必须提前注册。

4. 自注意力：QKV 的直觉、公式、多头与因果掩码

自注意力（self-attention）解决的问题是：序列中每个 token 需要从其他 token 处收集信息，且"该看谁"取决于内容本身。它把每个位置的向量 \(x\) 通过三个投影矩阵映射成三种角色：查询（Query）表示"我在找什么"，键（Key）表示"我这里有什么可以被发现"，值（Value）表示"匹配上之后我实际给你的信息"。可以类比为一次软性的哈希检索：用 Q 在所有 K 中做相似度匹配，再按匹配度对 V 加权求和。

缩放点积注意力的公式为：

\[ \mathrm{Attention}(Q, K, V) = \mathrm{softmax}\!\left( \frac{Q K^\top}{\sqrt{d_k}} + M \right) V \]

其中 \(d_k\) 是每个头的键向量维度，\(M\) 是掩码矩阵（下一页详述）。为什么除以 \(\sqrt{d_k}\)？假设 \(q, k\) 的分量是均值 0、方差 1 的独立随机变量，则点积 \(q \cdot k = \sum_{i=1}^{d_k} q_i k_i\) 的方差为 \(d_k\)——维度越高，点积的数值越分散，softmax 会进入饱和区（一个分量接近 1、其余接近 0），梯度消失。除以 \(\sqrt{d_k}\) 把点积方差归一回 1，这是让深栈注意力可训练的关键小技巧。

多头机制（multi-head）把 \(d_{\mathrm{model}}\) 维空间切成 \(h\) 个子空间，每个头在 \(d_k = d_{\mathrm{model}}/h\) 的子空间里独立做注意力，最后拼接并经输出矩阵 \(W_O\) 混合。直觉是：一个头只能表达一种"关注模式"（比如"主语找谓语"或"代词找先行词"），多头让模型在不同子空间并行维护多套模式。顺带一提，现代模型普遍用分组查询注意力（Grouped-Query Attention, GQA）让多个查询头共享一组键值头（LLaMA-2-70B 用 64 个 Q 头配 8 个 KV 头），KV 头数减少直接把 KV cache 压缩数倍（第 9 节），是"几乎不掉点、大幅省推理显存"的免费午餐（Ainslie et al., 2023, arXiv:2305.13245）。

因果掩码（causal mask）是 decoder-only 架构的灵魂。在 softmax 之前，把所有 \(j > i\) 位置（未来 token）的注意力分数置为 \(-\infty\)：

\[ M_{ij} = \begin{cases} 0, & j \le i \\ -\infty, & j > i \end{cases} \]

这样位置 \(i\) 的表示只依赖 \(x_{\le i}\)，整条序列的一次前向就能并行地给出所有 \(T\) 个"预测下一个 token"的条件分布——这正是预训练能在万亿 token 上高效并行的原因：训练时对 \(T\) 个位置的监督信号一次算完，且不需要等真实的"未来"。反过来，推理时的自回归生成无法并行：你必须先算出 \(y_t\) 才能算 \(y_{t+1}\)，这就是 KV cache（第 9 节）要解决的问题。训练并行、生成串行，这个不对称性是理解 LLM 推理成本与 RL rollout 瓶颈的起点。

⚠️ 常见误区：训练与推理的掩码不一致是 SFT 事故高发区

把"指令 + 回答"拼接成一条序列做 SFT 时，回答部分的标签要把输入整体左移一位（loss 只落在回答 token 上），同时因果掩码必须覆盖包括指令在内的整条序列——常见的两个 bug 是：标签没有 shift（模型在学"复制输入"）或回答部分误用了双向注意力（训练-推理不一致，上线后行为诡异）。第 13 章会给出逐行核对清单。

注意力计算本身是 \(O(T^2 d)\) 的显存与算力开销，标准实现要物化 \(T \times T\) 的注意力矩阵。FlashAttention（Dao et al., 2022, arXiv:2205.14135）通过分块计算与在线 softmax 把显存降到 \(O(T)\)、速度提升数倍，且是精确注意力而非近似——如今所有主流训练框架都默认启用它，长上下文工程（第 44 章）建立在这之上。

本节小结：注意力 = 内容寻址的加权检索，\(1/\sqrt{d_k}\) 稳住 softmax，多头并行多套关注模式，因果掩码让训练并行而生成串行。

5. 位置编码：从正弦编码到 RoPE

注意力本身是置换等变的——打乱输入 token 顺序，输出集合不变，位置信息必须显式注入。第一代方案来自原论文的正弦位置编码（sinusoidal encoding）：对位置 \(pos\)、维度对 \(2i\)，用一组不同频率的三角函数生成固定的加性编码：

\[ \mathrm{PE}(pos, 2i) = \sin\!\left(\frac{pos}{10000^{2i/d}}\right), \qquad \mathrm{PE}(pos, 2i+1) = \cos\!\left(\frac{pos}{10000^{2i/d}}\right) \]

低维度用高频率（分辨相邻位置），高维度用低频率（编码远距离），形成类似二进制进尺的多尺度"时钟"。GPT-2 一系改用可学习的绝对位置编码，效果相当，但两者共同的问题是：编码与绝对位置绑定，外推到训练长度之外会急剧失效。

现代开源模型（LLaMA、Qwen、Mistral、DeepSeek 等）几乎统一采用旋转位置编码（Rotary Position Embedding, RoPE）（Su et al., 2021, arXiv:2104.09864）。它的核心思想是：不再给 token 加位置向量，而是在注意力计算内部，把每个头的 \(q, k\) 向量按其所在位置旋转一个与位置成正比的角度。以二维分量对 \((q_1, q_2)\) 为例，位置 \(m\) 处的旋转为：

\[ R(m\theta)\,q = \begin{pmatrix} q_1 \cos m\theta_1 - q_2 \sin m\theta_1 \\ q_1 \sin m\theta_1 + q_2 \cos m\theta_1 \end{pmatrix}, \qquad \theta_i = 10000^{-2i/d} \]

高维情形是把向量切成 \(d/2\) 个二维对、每对用不同频率 \(\theta_i\) 旋转。RoPE 的魔法在于内积的性质：位置 \(m\) 的 \(q\) 与位置 \(n\) 的 \(k\) 旋转后做点积，结果只依赖相对距离 \(m - n\)：

\[ \langle R(m\theta)\,q,\; R(n\theta)\,k \rangle = \langle q, R((m-n)\theta)\,k \rangle \]

证明只需一行：二维旋转矩阵满足 \(R(\alpha)^\top R(\beta) = R(\beta - \alpha)\)，代入即得。这个"注意力分数只看相对位置"的性质让 RoPE 天然适配语言建模，同时旋转不改变向量模长，不引入额外的数值不稳定。理解 RoPE 的第二个理由是工程性的：长上下文扩展的主流方法全是围绕 RoPE 展开的——位置插值（Position Interpolation, arXiv:2309.17074）把位置 \(m\) 压缩到 \(m/L\)，YaRN（arXiv:2309.00071）按频率分组做非均匀插值，LLaMA-3.1 与 Qwen2.5 的 128k 上下文都是"RoPE 插值 + 少量长文本继续预训练"的产物。当你在后训练里做长上下文适配（第 17 章），改的就是这组频率参数。

此外还有一条相对位置的支线：ALiBi（Press et al., 2021, arXiv:2108.12409）不给 token 加编码，而是给注意力分数加一个随距离线性衰减的静态偏置，以外推能力见长，在 BLOOM 等模型中使用。选型时知道它的存在即可，新项目默认跟 RoPE。

本节小结：位置编码解决"注意力不知道顺序"的问题；RoPE 用"按位置旋转 \(q,k\)"实现相对位置感知，且是长上下文扩展技术的主要落点。

6. FFN、残差与归一化：Pre-LN vs Post-LN

一个 Transformer 块 = 注意力子层 + 前馈网络（Feed-Forward Network, FFN）子层，各自包一条残差连接与一个归一化。FFN 是逐位置的 两层 MLP，负责"把注意力汇总来的信息做非线性变换与知识存取"：

\[ \mathrm{FFN}(x) = W_2\, \sigma(W_1 x) \]

中间层维度通常是 \(4d\)。现代模型几乎都把激活函数换成了 SwiGLU（Shazeer, 2020, arXiv:2002.05202）——门控线性单元与 SiLU 激活的组合 \(\mathrm{SwiGLU}(x) = W_2(\mathrm{SiLU}(W_1 x) \odot W_3 x)\)。它多了一个投影矩阵，为了保持参数量不变，中间维度从 \(4d\) 缩到约 \(\frac{8}{3}d\)：LLaMA-7B 的 \(d=4096\)、FFN 中间维 11008，正是这个比例的取整。参数量的经验估算也值得背下来：一个 \(L\) 层、宽度 \(d\) 的 dense 模型（忽略 embedding），总参数约 \(N \approx 12 L d^2\)——看到"70B、80 层、8192 宽"你就能心算验证（\(12 \times 80 \times 8192^2 \approx 6.4 \times 10^{10}\)，加上 embedding 后约 6.9e10，吻合）。

残差连接给梯度提供一条无衰减的恒等通路，使百层网络可训练；归一化稳定各层激活的尺度。这里有一个后训练工程师必须知道的历史转折：归一化放在残差分支的哪里，显著影响训练稳定性。原始 Transformer 是 Post-LN：\(x \leftarrow \mathrm{LN}(x + \mathrm{Sublayer}(x))\)，归一化在残差相加之后；GPT-2 之后的主流是 Pre-LN：\(x \leftarrow x + \mathrm{Sublayer}(\mathrm{LN}(x))\)，归一化在子层输入之前。Xiong et al.（2020, arXiv:2002.04745）从理论上解释了原因：Post-LN 中越深的层梯度越要经过多个 LN 的雅可比，梯度随深度衰减、必须靠小心翼翼的学习率预热；Pre-LN 的残差主路上没有 LN，梯度可以"无阻尼"地直达浅层，深层网络不再需要预热。代价是 Pre-LN 让残差主路的范数随深度膨胀，因此要在栈顶补一个最终 LayerNorm（final LN）——LLaMA 代码里的 norm 层就是它，删掉它模型输出尺度会随深度漂移、SFT 直接训崩。

维度Post-LN（原始 Transformer）Pre-LN（GPT-2/LLaMA/Qwen）
归一化位置残差相加之后：\(x \leftarrow \mathrm{LN}(x + f(x))\)子层输入前：\(x \leftarrow x + f(\mathrm{LN}(x))\)

做继续预训练或架构魔改（换归一化、加层、改 FFN）时，Pre-LN 的 final LN 与残差通路是绝不能破坏的两条"生命线"；全量微调时的学习率应比预训练小 1~2 个数量级（如 1e-5 → 1e-6 量级，第 16 章），一个重要原因就是微调不能扰乱 Pre-LN 体系已经平衡好的激活尺度。

本节小结：FFN（SwiGLU）负责知识变换，残差保梯度通路，Pre-LN + RMSNorm + final LN 是现代模型的稳定标配；估算参数量用 \(N \approx 12Ld^2\)。

7. Decoder-only 架构为何胜出

2018~2020 年，生成式 LLM 存在三条第线：encoder-decoder（T5，arXiv:1910.10683）、decoder-only（GPT 系）、prefix-LM（UL2 等）。到今天，指令与对话模型几乎清一色是 decoder-only。这个胜负不是偶然，而是四个工程约束共同作用的结果。

第一，训练目标与数据利用率。decoder-only 的因果掩码让序列中每个位置都携带监督信号：\(T\) 个 token 产生 \(T\) 个 next-token 损失项，数据效率极高。encoder-decoder 的 span corruption 只在被破坏的片段上有损失，同等算力下"每 token 学到的东西"更少；且它需要"构造输入-目标对"的数据预处理，在万亿级噪声语料上这一步既昂贵又引入人为设计。第二，扩展性（scaling friendliness）。decoder-only 结构最简单：一个栈、一种掩码、一种数据格式，没有 encoder/decoder 的超参切分，几乎不需要调结构就能一路扩到千亿参数——缩放定律（第 4 章）实验全部在这一族模型上完成，形成正反馈。第三，推理与工程效率。自回归生成天然匹配 KV cache（第 9 节）；decoder-only 无需维护两套权重与交叉注意力，部署、量化、投机解码（speculative decoding）的工具链都为它优化。第四，涌现的少样本能力。GPT-3（arXiv:2005.14165）展示了纯因果 LM + 足够规模就能出现上下文学习（in-context learning），而当时的多任务 encoder-decoder 路线（T0、FLAN 早期版本）需要显式的多任务数据混合才能逼近类似能力。ICL 让"同一个 base 模型 + 不同提示词"服务无数任务，这条路径的生态位被 decoder-only 占住了。

需要保留的批判性视角是：encoder-decoder 并没有输在"表达力"上，在小数据、强监督的翻译/摘要任务上它至今仍有优势；prefix-LM 的注意力掩码也已被证明在长上下文上有理论吸引力。decoder-only 的胜出更像是"在互联网规模无监督数据的约束下，最简单、数据利用率最高、最易扩展的那个设计赢了"——是工程选择，不是数学必然。

本节小结：decoder-only 胜出的四根支柱：每 token 监督信号密度最高、结构最简单最易扩展、推理工程效率最高、规模驱动的 ICL 能力。

9. KV cache 与推理成本初步

自回归生成的朴素做法是：每生成一个 token，就把整条前缀重新前向一遍。这意味着生成 \(T\) 个 token 需要 \(O(T^2)\) 次注意力计算和 \(T\) 次完整前向——大量计算浪费在重复计算历史 token 的 K、V 上。观察注意力的因果性可以消除这个浪费：位置 \(i\) 的 K、V 只依赖 \(x_{\le i}\)，历史 token 的 K、V 永远不会变。于是把每一层每个头的 K、V 缓存下来（这就是 KV cache），每步只前向最新的一个 token：

\[ M_{\mathrm{KV}} = 2 \times L \times H_{kv} \times d_{head} \times s \times b \;\; \text{字节} \]

其中因子 2 对应 K 和 V，\(L\) 是层数，\(H_{kv}\) 是 KV 头数（GQA 下远小于查询头数），\(d_{head}\) 头维度，\(s\) 序列长度，\(b\) 批大小（bf16 每元素 2 字节）。拿 LLaMA-3-8B 代入：\(2 \times 32 \times 8 \times 128 = 131072\) 字节/token，即每生成 1 个 token 累积 128 KB 的缓存；8k 上下文就是每条序列 1 GB。对比 LLaMA-2-7B 的 MHA（\(H_{kv}=32\)）：512 KB/token、8k 上下文 4 GB——GQA 用不到 1% 的质量代价把推理显存压到四分之一。

为什么后训练工程师要关心这个？因为 RLHF/RLVR 训练的瓶颈恰恰在生成端。PPO 或 GRPO 的每个训练迭代，都要用当前策略对每个 prompt 采样一条或多条完整回答（rollout），生成几百个 token；采样阶段受制于自回归串行 + KV cache 读写，GPU 利用率远低于训练阶段。当 batch 变大、上下文变长，KV cache 会吃掉本可用于并发的显存——vLLM 的 PagedAttention（Kwon et al., 2023, arXiv:2309.06180）用分页管理把碎片压到最低，已成为 RL rollout 基础设施的标配（第 45 章）。一句话记住推理端的两本账：算力账随生成步数线性增长（每步一次单 token 前向），显存账随上下文线性增长（KV cache 累积）——训练是 6ND 的稠密矩阵乘（第 42 章），推理是访存受限的解码循环，两者的优化逻辑完全不同。

本节小结：KV cache 用空间换时间，把生成从"每步全量重算"变成"每步单 token 前向"；其显存 \( \propto L \times H_{kv} \times d_{head} \times s\)，GQA 与分页管理是控制它的两大手段，也是 RL rollout 成本的核心变量。

10. 动手：极简 attention 与带 cache 的生成循环

理论到此为止，本节用两个"能跑的最小实现"把前面的概念钉死。第一个是从零实现的因果多头注意力，去掉 dropout、bias、flash kernel 等工程件，只保留 QKV、缩放点积、因果掩码、多头四条主线——建议你逐行对着第 4 节的公式读：

minimal_attention.py 
import torch
import torch.nn as nn
import torch.nn.functional as F

class MinimalCausalAttention(nn.Module):
    """极简因果自注意力：省略 dropout/bias，突出 QKV 与因果掩码主线"""
    def __init__(self, d_model: int, n_heads: int):
        super().__init__()
        assert d_model % n_heads == 0
        self.n_heads = n_heads
        self.d_head = d_model // n_heads            # 头维度 d_k，行业惯例取 128
        self.wq = nn.Linear(d_model, d_model, bias=False)
        self.wk = nn.Linear(d_model, d_model, bias=False)
        self.wv = nn.Linear(d_model, d_model, bias=False)
        self.wo = nn.Linear(d_model, d_model, bias=False)

    def forward(self, x: torch.Tensor) -> torch.Tensor:
        B, T, D = x.shape
        # 1) 线性投影出 Q/K/V，并按头拆分：(B, T, D) -> (B, h, T, d_head)
        q = self.wq(x).view(B, T, self.n_heads, self.d_head).transpose(1, 2)
        k = self.wk(x).view(B, T, self.n_heads, self.d_head).transpose(1, 2)
        v = self.wv(x).view(B, T, self.n_heads, self.d_head).transpose(1, 2)
        # 2) 缩放点积：除以 sqrt(d_k) 稳住 softmax，防止高维点积饱和
        att = (q @ k.transpose(-2, -1)) / (self.d_head ** 0.5)
        # 3) 因果掩码：位置 i 只允许关注 j <= i 的键，未来位置置 -inf
        mask = torch.triu(torch.ones(T, T, dtype=torch.bool, device=x.device), diagonal=1)
        att = att.masked_fill(mask, float("-inf"))
        att = F.softmax(att, dim=-1)
        # 4) 按 V 加权求和，合并多头，输出投影
        out = (att @ v).transpose(1, 2).reshape(B, T, D)
        return self.wo(out)

if __name__ == "__main__":
    torch.manual_seed(0)
    x = torch.randn(2, 16, 512)                     # batch=2, 序列长=16, d_model=512
    block = MinimalCausalAttention(d_model=512, n_heads=4)
    out = block(x)
    print(out.shape)                                # torch.Size([2, 16, 512])
    assert torch.isfinite(out).all()

第二个实现是带 KV cache 的生成循环，对应第 9 节的两本账：预填充（prefill）阶段一次性处理完整提示词，解码（decode）阶段每步只喂最后一个 token、复用历史 K/V。真实引擎（vLLM、SGLang）在此基础上叠加分页与连续批处理，但数据流与此一致：

kv_cache_generate.py 
import torch

@torch.no_grad()
def generate_with_kv_cache(model, input_ids, max_new_tokens=64, temperature=0.8):
    """带 KV cache 的自回归生成（简化示意：假设 model.forward 返回 (logits, past_kv)）"""
    past = None
    tokens = input_ids
    for step in range(max_new_tokens):
        if past is None:
            # 预填充：一次性前向整个提示词，产生全部位置的 K/V
            logits, past = model(tokens, past_key_values=None)
        else:
            # 解码：只前向最新 1 个 token，历史 K/V 从 cache 读取并追加
            logits, past = model(tokens[:, -1:], past_key_values=past)
        logits = logits[:, -1, :] / max(temperature, 1e-5)   # 温度控制分布尖锐度
        probs = torch.softmax(logits, dim=-1)
        next_tok = torch.multinomial(probs, num_samples=1)
        tokens = torch.cat([tokens, next_tok], dim=1)
        if next_tok.item() == model.config.eos_token_id:     # 终止符结束本次生成
            break
    return tokens

11. 本章小结

  • 概率定义：语言模型是对条件分布链 \(p_\theta(x_t \mid x_{<t})\) 的参数化；预训练、SFT、RL 共用同一个前向计算，差异只在数据与损失。
  • Tokenization：BPE/SentencePiece 在词表大小、序列长度与低频 token 学习之间权衡；压缩率直接决定算力账，特殊 token 必须预注册。
  • 注意力：QKV 是内容寻址的软检索，\(1/\sqrt{d_k}\) 防饱和，多头并行多套关注模式，因果掩码让训练并行、生成串行——这个不对称性贯穿全书。
  • 位置编码：RoPE 通过按位置旋转 \(q,k\) 实现相对位置感知，是长上下文扩展（PI/YaRN）的支点。
  • 架构标配：decoder-only + Pre-LN RMSNorm + SwiGLU + GQA + 无偏置；参数量心算 \(N \approx 12Ld^2\)，final LN 不能删。
  • KV cache：显存 \(= 2 L H_{kv} d_{head} s b\) 字节（bf16），LLaMA-3-8B 为 128 KB/token；GQA 与 PagedAttention 控制 RL rollout 的最大成本项。

下一章我们沿数据方向继续：这些架构被灌入什么样的预训练数据、遵循什么缩放定律、具备哪些 base 模型能力与缺陷——它们划定了后训练的起点与天花板。

🧠 自测题（点击展开答案）
问题 1：因果掩码为什么能让训练并行、却不能让生成并行？

训练时，整条序列的所有位置都已给定，因果掩码保证位置 \(i\) 的条件分布 \(p(x_i \mid x_{<i})\) 只依赖历史，因此一次前向可以同时算出全部 \(T\) 个位置的 next-token 概率，监督信号并行兑现。生成时，"未来"尚未存在：第 \(t\) 步的输入依赖第 \(t-1\) 步采样出的 token，形成了数据依赖链，只能串行；KV cache 缓解的是每步的重复计算（不必重算历史 K/V），但无法消除步与步之间的串行依赖。

问题 2：把词表从 3.2 万扩到 15 万，分别对算力、显存、模型质量有什么影响？

算力：同样的中文文本被切成更少的 token，前向/反向次数减少，等于同算力多读数据（对中文常见 30%~50% 的压缩收益）。显存：embedding 与 lm_head 参数量与词表成正比，15.2 万词表 × 4096 维的 lm_head 在 bf16 下约 1.2 GB，且 logits 与 softmax 的激活开销同步上涨。质量：低频 token 出现次数变少、embedding 学习不充分，若语料量不足可能损害整体效果；但合理的扩词表能减少过度切碎，改善长距离建模。三笔账一起算，多语模型主流选择在 10 万~25 万词表。

问题 3：Pre-LN 架构为什么必须在栈顶放一个 final LayerNorm？删掉会发生什么？

Pre-LN 中归一化在残差分支内部，残差主路本身不做归一化，因此表示的范数会随深度逐层累加膨胀（大约每层累加一个子层输出）。final LN 在输出前把尺度重新归一，稳定 logits 的量纲。删掉它，模型输出尺度随深度漂移，logits 数值异常，SFT 的损失会剧烈震荡甚至发散；对已预训练好的模型做微调时改动它尤其致命。

问题 4：计算 LLaMA-3-8B 在 32768 上下文、batch=8 时的 KV cache 总显存（bf16，GQA 8 个 KV 头）。

每 token：\(2 \times L \times H_{kv} \times d_{head} = 2 \times 32 \times 8 \times 128 = 131072\) 字节 = 128 KB。32k 上下文单条序列：128 KB × 32768 = 4 GB。batch=8：32 GB。这还只是 KV cache，不含权重（8B 模型 bf16 约 16 GB）与激活——这就是长上下文 RL rollout 必须依赖 GQA、分页与量化的原因。
