第 56 章 · 项目二：DPO 偏好对齐实战

在完成指令微调（SFT）之后，语言模型虽然能够顺畅理解用户指令，但往往伴随着冗长啰嗦、过度谄媚、缺乏事实约束以及道德说教等对齐顽疾。直接偏好优化（Direct Preference Optimization, DPO）抛弃了传统 PPO 复杂的在线采样与独立奖励模型训练，通过对 Bradley-Terry 偏好模型的隐式参数化重构，实现了端到端的高效稳健对齐。本章以项目一训练的 Qwen2.5 模型为基底，从中文 UltraFeedback 偏好对清洗、TRL DPOTrainer 工业级调参、隐式奖励差监控、长度偏置惩罚，到胜率自动化对决评估，展开一次完整的生产级实战。

1. 项目背景与对齐痛点分析

在第 55 章中，我们基于高质量的对话语料与多轮指令完成了小模型的监督微调（SFT）。通过 SFT，模型掌握了遵循指令的基本对话范式并获得了特定的语气风格。然而，当 SFT 模型进入真实开放域交互时，工程师通常会面临一系列经典的“SFT 局限性”表征：

  • 冗长与过度客套（Verbosity and Sycophancy）：模型倾向于生成大量无实际信息增益的礼貌开场白（例如“尊敬的用户，非常荣幸能够为您解答这个深入且具有洞察力的问题……”）并在回答结尾添加冗长且格式化的免责声明。这种行为通常源于 SFT 语料中人类标注员对长文本的无意识偏爱。
  • 事实幻觉与虚假自信（Fact Hallucination）：在面对自身不具备的垂直领域知识或具有陷阱的前提假设时，SFT 模型往往缺乏“坦诚拒绝”或“边界审慎”的动力，而是顺着提问者的诱导生成一本正经的胡说八道。
  • 安全性与有用性的张力失衡（Refusal Over-sensitivity）：传统安全微调若单纯依赖否定样本的监督拟合，极易导致模型对包含敏感关键词的良性提问产生误杀（例如询问“如何防范计算机病毒”被模型生硬拒绝“我不能编写破坏性程序”）。

强化学习来自人类反馈（Reinforcement Learning from Human Feedback, RLHF）正是为了解决这些跨越单纯似然估计的价值取向问题。传统的 PPO 算法需要维护策略模型（Actor）、价值模型（Critic）、参考模型（Reference）与奖励模型（Reward Model）四个网络，且必须在训练循环中实时进行耗时巨大的自回归 Rollout 采样，工程复杂度与显存开销极大。直接偏好优化（Direct Preference Optimization, DPO）由 Rafailov 等人于 2023 年提出，其核心洞察在于：无需显式拟合标量奖励模型，利用数学推导将 Bradley-Terry 偏好目标中的隐式奖励函数直接代换为策略网络与参考网络似然比的对数差。这使得偏好对齐转变为与监督训练形式高度相似的离线二元交叉熵优化，计算效率大幅提升。

本项目旨在以项目一得到的微调模型为起点，通过严格构建的偏好对（Pairwise Data）执行 DPO，彻底纠正啰嗦与谄媚，提升输出的紧凑性、真实性与逻辑辨析力。

2. DPO 核心数学原理与隐式奖励建模

理解 DPO 的数学本质是避免调参盲目性的前提。经典 RLHF 的优化目标是在最大化奖励函数期望的同时，加入策略模型与冻结的参考模型之间的 Kullback-Leibler（KL）散度约束，以防止策略漂移过大：

\[ \max_{\pi_\theta} \mathbb{E}_{x \sim \mathcal{D}, y \sim \pi_\theta(\cdot \mid x)} \left[ r(x, y) \right] - \beta \mathbb{D}_{\mathrm{KL}}\left(\pi_\theta(y \mid x) \,\parallel\, \pi_{\mathrm{ref}}(y \mid x)\right) \]

其中 \( \beta \) 是控制 KL 惩罚力度的核心超参数。通过变分法求解上述带约束优化问题的闭式解，可以推导得到最优策略 \( \pi^*(y \mid x) \) 与真实奖励函数 \( r(x, y) \) 之间的精确解析关系：

\[ \pi^*(y \mid x) = \frac{1}{Z(x)} \pi_{\mathrm{ref}}(y \mid x) \exp\left( \frac{1}{\beta} r(x, y) \right) \]

式中 \( Z(x) = \sum_y \pi_{\mathrm{ref}}(y \mid x) \exp\left(\frac{1}{\beta} r(x, y)\right) \) 为与回答 \( y \) 无关的归一化配分函数。两边取自然对数并重新整理，便可将不可观测的标量奖励 \( r(x, y) \) 用策略似然比完全表达：

\[ r(x, y) = \beta \log \frac{\pi^*(y \mid x)}{\pi_{\mathrm{ref}}(y \mid x)} + \beta \log Z(x) \]

在人类偏好建模中，Bradley-Terry（BT）模型假设人类在给定两个回答 \( y_w \)（获胜项/Chosen）和 \( y_l \)（落选项/Rejected）时，偏好 \( y_w \) 的概率由两者的潜隐奖励差决定：

\[ p(y_w \succ y_l \mid x) = \sigma\left( r(x, y_w) - r(x, y_l) \right) \]

将上式推导出的隐式奖励函数代入 BT 偏好模型中，配分函数 \( Z(x) \) 在做差时奇迹般地完全抵消！由此，我们得到了完全摆脱显式奖励模型与生成采样的 DPO 目标损失函数：

\[ \mathcal{L}_{\mathrm{DPO}}(\pi_\theta; \pi_{\mathrm{ref}}) = -\mathbb{E}_{(x, y_w, y_l) \sim \mathcal{D}} \left[ \log \sigma \left( \beta \log \frac{\pi_\theta(y_w \mid x)}{\pi_{\mathrm{ref}}(y_w \mid x)} - \beta \log \frac{\pi_\theta(y_l \mid x)}{\pi_{\mathrm{ref}}(y_l \mid x)} \right) \right] \]

为了直观展现 DPO 在单批次训练中如何同步前向计算四个序列的似然并构建隐式奖励差反向传播梯度，我们绘制了如下完整的流水线架构图：

📘 概念辨析：为什么说 DPO 具有隐式自适应加权机制？

如果我们对 DPO 损失函数关于策略网络参数 \( \theta \) 求梯度，可以清晰看到其加权项：

\[ \nabla_\theta \mathcal{L}_{\mathrm{DPO}} = -\beta \sigma(\hat{r}_\theta(x, y_l) - \hat{r}_\theta(x, y_w)) \left[ \nabla_\theta \log \pi_\theta(y_w \mid x) - \nabla_\theta \log \pi_\theta(y_l \mid x) \right] \]

系数项 \( \sigma(\hat{r}_\theta(x, y_l) - \hat{r}_\theta(x, y_w)) \) 说明：当当前模型对偏好对的判断错误越大（即模型误以为落选样本 \( y_l \) 的奖励高于获选样本 \( y_w \)）时，该系数趋近于 1，梯度惩罚极大；当模型已经能够轻易区分 \( y_w \) 优于 \( y_l \) 时，该项迅速衰减为 0。这种天然的软间隔（Soft-margin）自适应加权机制，赋予了 DPO 极强的抗噪学习能力。

3. 偏好数据集构建与清洗实战

“Garbage In, Garbage Out”在偏好对齐阶段表现得比 SFT 更加敏感。如果训练对中的 \( y_w \) 仅仅比 \( y_l \) 稍微长一点，或者 \( y_l \) 中包含了大量微弱但合理的替代回答，DPO 会过度压制某些常用词甚至让模型走向退化。我们选用经过行业广泛检验的 UltraFeedback 中文清洗子集，并进行针对性的质量二次过滤。

3.1 构建四维偏好打分矩阵

UltraFeedback 原始数据集使用 GPT-4 从以下四个正交维度对多个候选模型的生成结果进行打分（1~5 分）：

  • 指令遵循度（Instruction Following）：是否完整响应了 Prompt 中的所有硬性约束与负向约束；
  • 真实与客观性（Truthfulness）：是否存在毫无根据的事实编造或逻辑硬伤；
  • 信息深度与诚恳度（Honesty & Helpfulness）：是否废话连篇、是否给出了具体且可落地的可执行步骤；
  • 安全性与道德底线（Safety）：是否存在恶意、有害、偏见或违法内容。

为了构建优质的偏好对，我们制定了严密的清洗过滤流水线，剔除质量模糊和具有长度诱导偏差的脏数据。

3.2 数据集构建中的三大核心清洗工序

在实际操作中，原始的开源偏好语料充斥着各种隐蔽质量问题。为保证 DPO 梯度的纯净度，我们在进入分词器前执行以下三阶段清洗：

  • 阶段一：模式化去伪造与清洗。很多开源回答带有 GPT-4 生成的模式化开头，如“当然！下面是为您准备的……”，“作为一名 AI 助手……”。我们利用正则流水线将这些空洞客套全部剥离，还原核心事实内容。
  • 阶段二：逻辑一致性与事实交叉验证。在针对代码与逻辑题的偏好对中，落选回答往往包含细微但致命的逻辑笔误。我们引入简单的规则测试脚本（如 Python 代码语法解析器 ast.parse），直接剔除落选项带有语法错误但获选项同样报错的“双废样本”。
  • 阶段三：平衡样本正负反馈分布。若某一领域的偏好对完全是一边倒的获选，或者正负样本长度比例严重失衡，模型会学到局部的伪相关性。我们采用分箱采样（Stratified Sampling），确保不同长度差区间的样本均匀分布。

3.2 数据集处理脚本

以下 Python 脚本演示了如何将 Hugging Face 格式的偏好数据转换为符合 ChatML 格式要求的标准化 DPO 输入：

prepare_dpo_dataset.py 
import json
from datasets import load_dataset, Dataset
from transformers import AutoTokenizer

def build_chatml_pair(prompt: str, chosen: str, rejected: str, system_prompt: str = None) -> dict:
    """
    将原始提示词与候选对组装为标准的 ChatML 结构化字典
    """
    system_content = system_prompt or "你是由专业团队训练的严谨、精炼且诚实的中文助手。"
    
    # 组装完整的对话历史
    prompt_messages = [
        {"role": "system", "content": system_content},
        {"role": "user", "content": prompt.strip()}
    ]
    chosen_messages = [{"role": "assistant", "content": chosen.strip()}]
    rejected_messages = [{"role": "assistant", "content": rejected.strip()}]
    
    return {
        "prompt": prompt_messages,
        "chosen": chosen_messages,
        "rejected": rejected_messages
    }

def filter_and_format_preference_data(
    input_path: str, 
    tokenizer_name_or_path: str,
    max_seq_len: int = 1536
) -> Dataset:
    """
    流式读取偏好语料并过滤长度越界与低边际差距样本
    """
    tokenizer = AutoTokenizer.from_pretrained(tokenizer_name_or_path, use_fast=True)
    raw_dataset = load_dataset("json", data_files=input_path, split="train")
    
    valid_samples = []
    dropped_stats = {"length": 0, "margin": 0, "identical": 0}
    
    for item in raw_dataset:
        p = item["instruction"]
        c = item["chosen"]
        r = item["rejected"]
        
        # 1. 过滤实质相同的样本
        if c.strip() == r.strip():
            dropped_stats["identical"] += 1
            continue
            
        # 2. 长度比过滤，防止极端的长度偏差
        len_c, len_r = len(c), len(r)
        if len_r > 0 and (len_c / len_r > 3.0 or len_c / len_r < 0.3):
            dropped_stats["length"] += 1
            continue
            
        # 3. 计算 Token 长度并截断越界样本
        tokenized_prompt = tokenizer.apply_chat_template([{"role": "user", "content": p}], tokenize=True)
        tokenized_chosen = tokenizer.apply_chat_template([{"role": "assistant", "content": c}], tokenize=True)
        if len(tokenized_prompt) + max(len(tokenized_chosen), len(c)) > max_seq_len:
            dropped_stats["length"] += 1
            continue
            
        formatted = build_chatml_pair(p, c, r)
        valid_samples.append(formatted)
        
    print(f"数据清洗完成: 保留有效样本 {len(valid_samples)} 条, 过滤统计: {dropped_stats}")
    return Dataset.from_list(valid_samples)

if __name__ == "__main__":

4. TRL DPOTrainer 深度配置与关键超参数

在 Hugging Face 的 TRL（Transformer Reinforcement Learning）库中，DPOTrainer 已经对隐式奖励差与交叉熵损失进行了高度封装。然而，DPO 的训练动态远比传统监督分类任务更为脆弱敏感。在 SFT 训练中，损失函数单调下降通常对应着模型生成质量的稳定提升；但在 DPO 训练中，损失的单纯下降可能只是因为策略模型找到了某种捷径（如输出特殊的填充 Token 或死循环），导致模型陷入“隐式奖励差居高不下，但实际输出疯狂复读标点或输出乱码”的灾难性模型坍塌（Policy Collapse）。因此，深入理解各个超参数的物理意义并进行精密调校是项目成功的关键。

4.1 超参数 \( \beta \) 的科学调节

\( \beta \) 是 DPO 中最重要的旋钮，它扮演着奖励缩放与 KL 惩罚倒数的双重角色：

  • \( \beta \) 过大（如 \( \beta \ge 0.5 \)）：模型受到强烈的向基准参考模型锚定的约束，策略更新极其保守。模型难以纠正原有的啰嗦和答非所问，对齐收效甚微；
  • \( \beta \) 过小（如 \( \beta \le 0.01 \)）：策略网络会迅速偏离参考网络，隐式奖励极易过饱和。模型在损失快速下降的表象下，极易丧失语言连贯性，甚至出现高频词坍塌（Mode Collapse）；
  • 工业推荐配置：对于 1.5B ~ 7B 级别的小模型，在通用对话偏好对齐中，\( \beta \) 推荐设置在 0.05 ~ 0.10 之间；若偏好对主要是代码与数学等高确定性任务，可微调至 0.02 ~ 0.05。

4.2 损失函数形态选择：Sigmoid、IPO 与 BCO

除了标准的 Bradley-Terry Sigmoid 损失，TRL 还支持多种变体目标：

  • IPO（Identity Preference Optimization）：直接最小化似然比之差与理论边际的均方误差，能够从数学上杜绝 Bradley-Terry 模型在偏好概率趋于 1 时的对数发散，对于避免过拟合具有极强韧性；
  • Robust DPO（带有标签平滑的 DPO）：在数据集中存在不可避免的标注员分歧或裁判失误时，引入 0.05 ~ 0.1 的标签平滑度，避免策略梯度在噪声样本上产生灾难性惩罚；
  • KTO（Kahneman-Tversky Optimization）：若手头没有成对的 chosen/rejected，仅有孤立的点赞/点踩单样本数据，KTO 能够基于前景理论直接针对单条样本进行对齐，也是值得尝试的备选路径。

4.2 训练监控的核心度量指标

在 DPO 训练中，绝不能仅仅依靠 train/loss 曲线来判定训练是否健康。Weight & Biases 或 TensorBoard 日志中必须重点追踪以下三组指标：

  1. rewards/chosen 与 rewards/rejected：隐式奖励的绝对值标量。理想情况下，随着训练推进，rewards/chosen 应该稳步上升，而 rewards/rejected 稳步下降；
  2. rewards/margins（隐式奖励差）：定义为 \( \beta(\log \pi_\theta(y_w)/\pi_{\mathrm{ref}}(y_w) - \log \pi_\theta(y_l)/\pi_{\mathrm{ref}}(y_l)) \)。该差值必须呈现平缓上升并最终收敛在 0.5 ~ 2.5 之间。若差值瞬间飙升至 5 以上，往往预示着模型发生了过拟合或策略崩溃；
  3. rewards/accuracies：当前批次中 \( r_w > r_l \) 的比例。健康训练的准确率应从约 50%（随机猜测）逐渐爬升至 75% ~ 85%。若迅速达到 98% 以上，往往意味着数据集中存在显式的长度作弊特征。
⚠️ 常见误区：为什么不要把 Reference Model 单独放入全量显存？

在使用 PEFT / LoRA 进行 DPO 训练时，很多初学者会分别加载一个 base_model（用于计算策略梯度）和另一个完整的 reference_model，这使得显存开销直接翻倍。最优雅的做法是：策略模型加载为挂载 LoRA 适配器的模型，而参考模型直接使用该基础模型在 adapter.disable_adapter() 上下文下的前向输出！ TRL 的 DPOTrainer 内部原生支持该机制，仅需传入一份基座模型与 LoRA 配置即可，显存节省超过 45%。

下面给出完整的、可在单张 RTX 4090 或 3090（24GB 显存）上稳定运行的 DPO 训练代码。代码中包含了详细的 LoRA 注入、动态隐式奖励回调监控以及早停判定机制。

run_dpo_qwen.py 
import os
import torch
from datasets import load_from_disk
from transformers import (
    AutoModelForCausalLM,
    AutoTokenizer,
    TrainingArguments,
    TrainerCallback
)
from peft import LoraConfig, get_peft_model, TaskType
from trl import DPOTrainer, DPOConfig

# 自定义早停与隐式奖励监控回调
class DPOMetricsEarlyStopCallback(TrainerCallback):
    def __init__(self, target_margin: float = 3.0, patience: int = 3):
        self.target_margin = target_margin
        self.patience = patience
        self.over_margin_counter = 0

    def on_evaluate(self, args, state, control, metrics=None, **kwargs):
        if metrics is not None and "eval_rewards/margins" in metrics:
            eval_margin = metrics["eval_rewards/margins"]
            eval_acc = metrics.get("eval_rewards/accuracies", 0.0)
            print(f"\n[DPO Monitor] Step {state.global_step} | Eval Margin: {eval_margin:.4f} | Accuracy: {eval_acc*100:.2f}%")
            
            # 检测潜在的策略漂移坍塌
            if eval_margin > self.target_margin:
                self.over_margin_counter += 1
                if self.over_margin_counter >= self.patience:
                    print(f"[Warning] Margin 持续超出安全阈值 {self.target_margin}，触发早停保护！")
                    control.should_training_stop = True
            else:
                self.over_margin_counter = 0

def run_dpo_pipeline():
    model_id = "output/qwen2.5-1.5b-sft"  # 指向第 55 章训练导出的 SFT 权重
    output_dir = "output/qwen2.5-1.5b-dpo"
    dataset_path = "./data/dpo_ultrafeedback_zh_clean"

    print(">>> 加载分词器与对话模板...")
    tokenizer = AutoTokenizer.from_pretrained(model_id, trust_remote_code=True)
    if tokenizer.pad_token is None:
        tokenizer.pad_token = tokenizer.eos_token

    print(">>> 加载 SFT 基底模型 (Bfloat16)...")
    model = AutoModelForCausalLM.from_pretrained(
        model_id,
        torch_dtype=torch.bfloat16,
        device_map="auto",
        trust_remote_code=True
    )
    model.enable_input_require_grads()

    # 配置 LoRA 适配器，仅训练微量增量参数
    peft_config = LoraConfig(
        r=16,
        lora_alpha=32,
        lora_dropout=0.05,
        bias="none",
        task_type=TaskType.CAUSAL_LM,
        target_modules=["q_proj", "k_proj", "v_proj", "o_proj", "gate_proj", "up_proj", "down_proj"]
    )

    print(">>> 读取预处理清洗后的偏好数据集...")
    dataset = load_from_disk(dataset_path)
    split_dataset = dataset.train_test_split(test_size=0.05, seed=42)
    train_dataset = split_dataset["train"]
    eval_dataset = split_dataset["test"]

    # 深度配置 DPO 专属训练参数
    training_args = DPOConfig(
        output_dir=output_dir,
        beta=0.08,                          # 核心偏好缩放与 KL 约束超参
        loss_type="sigmoid",
        label_smoothing=0.02,              # 缓解人工排序中的细微标签噪声
        learning_rate=8e-6,                 # DPO 必须使用极低学习率
        per_device_train_batch_size=2,
        per_device_eval_batch_size=2,
        gradient_accumulation_steps=8,     # 等效全局 Batch Size = 16
        num_train_epochs=2,
        max_prompt_length=512,
        max_length=1536,
        warmup_ratio=0.1,
        lr_scheduler_type="cosine",
        logging_steps=10,
        eval_strategy="steps",
        eval_steps=50,
        save_strategy="steps",
        save_steps=100,
        save_total_limit=2,
        bf16=True,
        gradient_checkpointing=True,
        report_to="none"
    )

    print(">>> 实例化 TRL DPOTrainer...")
    # 当 ref_model 传入 None 且启用 peft_config 时，DPOTrainer 会自动复用冻结基座作为 Reference
    dpo_trainer = DPOTrainer(
        model=model,
        ref_model=None,
        args=training_args,
        train_dataset=train_dataset,
        eval_dataset=eval_dataset,
        processing_class=tokenizer,
        peft_config=peft_config,
        callbacks=[DPOMetricsEarlyStopCallback(target_margin=3.5, patience=2)]
    )

    print(">>> 启动直接偏好优化训练...")
    dpo_trainer.train()

    print(f">>> 训练完毕，保存 DPO LoRA 适配器至 {output_dir}")
    dpo_trainer.save_model(output_dir)
    tokenizer.save_pretrained(output_dir)

if __name__ == "__main__":
    run_dpo_pipeline()

6. 应对长度偏置与模型坍塌的防护策略

在实际工业落地中，DPO 面临的最大陷阱就是“长度黑客攻击（Length Hack）”。因为在几乎所有开源偏好数据集中，人类或 GPT-4 标注员天然更偏向于长篇大论的详尽回答。如果不加干预，DPO 模型会迅速捕获这一捷径，产生严重的长度膨胀（Verbosity Bias）。

6.1 长度归一化损失修正

标准 DPO 损失中对数似然序列是直接累加的，这天然赋予了长序列更高的奖励积分潜力。为了消除该偏差，学术界提出了多种长度惩罚与变体：

  • SimPO（Simple Preference Optimization）：将序列对数似然除以其 Token 长度 \( |y| \)，并在间隔中显式引入正边际项 \( \gamma \)： \[ r_{\mathrm{SimPO}}(x, y) = \frac{\beta}{|y|} \log \pi_\theta(y \mid x) \] \[ \mathcal{L}_{\mathrm{SimPO}} = -\log \sigma \left( \frac{\beta}{|y_w|}\log \pi_\theta(y_w \mid x) - \frac{\beta}{|y_l|}\log \pi_\theta(y_l \mid x) - \gamma \right) \]
  • DPO + Length Regularization（长度回归惩罚）：在原始损失外增加一项对回答长度差与奖励差协方差的惩罚项，强制限制模型通过堆砌无用词符来获取虚高隐式奖励。
🚨 重要警告：如何快速排查隐式对齐坍塌？

若在训练过程中观察到：rewards/margins 急剧拉大（例如飙升至 8.0 以上），且 loss 跌入 0.05 以下，但对模型进行即时推理测试时，发现模型开始反复生成“嗯，嗯，对，确实……”或连贯性完全丧失。这属于典型的策略越界坍塌。排查与补救措施：

  1. 立即将 \( \beta \) 从 0.05 调高至 0.10 或 0.15，强化参考模型的锚定阻尼；
  2. 检查学习率是否偏大，建议将学习率从 1e-5 降至 5e-6；
  3. 检查数据集是否存在极其严重的长度失衡（例如 \( y_w \) 平均 800 字而 \( y_l \) 平均仅 50 字）。

7. 对齐前后对决测试与自动化胜率评估

为了科学评测 DPO 对齐给模型带来的真实能力增益，我们构建一套端到端的 LLM-as-a-Judge 自动化胜率评测流水线。我们将基准 SFT 模型（来自第 55 章）与本章完成 DPO 优化的模型在相同的一批测试集上进行成对盲测，交由强大的裁判模型（如 GPT-4o 或开源顶尖的 Qwen2.5-72B-Instruct）进行打分。

以下代码实现了完整的双模型推理、随机位置交换（消除裁判天然倾向于选回答 A 的位置偏差）以及胜率统计：

import random

import torch
from transformers import AutoModelForCausalLM, AutoTokenizer
from peft import PeftModel

JUDGE_PROMPT_TEMPLATE = """你是一名客观、严谨的大语言模型回答质量裁判。请根据用户提问，综合对比模型 A 与模型 B 的回答质量。

【用户提问】
{prompt}

【模型 A 回答】
{response_a}

【模型 B 回答】
{response_b}

【评判标准】
1. 指令遵循：是否完全切中要害，有无遗漏限定条件；
2. 真实有用：逻辑是否连贯，是否存在虚假事实，有无切实操作价值；
3. 精简精炼：是否去除了多余的无意义客套与废话套话。

请在最后一行严格以如下 JSON 格式输出判决结果，不要附带多余文字：
{{"winner": "A" 或 "B" 或 "tie", "reason": "50字以内的裁决理由"}}
"""

def generate_response(model, tokenizer, prompt: str) -> str:
    messages = [
        {"role": "system", "content": "你是由专业团队训练的严谨中文助手。"},
        {"role": "user", "content": prompt}
    ]
    text = tokenizer.apply_chat_template(messages, tokenize=False, add_generation_prompt=True)
    inputs = tokenizer([text], return_tensors="pt").to(model.device)
    
    with torch.no_grad():
        outputs = model.generate(
            **inputs,
            max_new_tokens=512,
            temperature=0.7,
            top_p=0.9,
            repetition_penalty=1.1,
            eos_token_id=tokenizer.eos_token_id
        )
    return tokenizer.decode(outputs[0][inputs.input_ids.shape[1]:], skip_special_tokens=True).strip()

def run_pairwise_eval(test_prompts: List[str], base_model_path: str, dpo_adapter_path: str):
    tokenizer = AutoTokenizer.from_pretrained(base_model_path)
    
    print(">>> 加载 SFT 模型...")
    sft_model = AutoModelForCausalLM.from_pretrained(

    )
    
    print(">>> 加载 DPO 模型...")
    dpo_model = AutoModelForCausalLM.from_pretrained(
        base_model_path, torch_dtype=torch.bfloat16, device_map="cuda:0"
    )
    dpo_model = PeftModel.from_pretrained(dpo_model, dpo_adapter_path)
    
    records = []

    for idx, prompt in enumerate(test_prompts):
        resp_sft = generate_response(sft_model, tokenizer, prompt)

        swap = random.random() > 0.5
        resp_a = resp_dpo if swap else resp_sft
        resp_b = resp_sft if swap else resp_dpo
        
        judge_prompt = JUDGE_PROMPT_TEMPLATE.format(

            response_a=resp_a,
            response_b=resp_b

        # 假设裁判判定 A 胜且 swap=True，则实际是 DPO 获胜

            "prompt": prompt,

8. 本章小结

在本章中，我们完整走通了从 SFT 基底到偏好对齐小模型的端到端 DPO 工业级流水线。总结核心认知如下：

  • 数学优雅性：DPO 通过对 Bradley-Terry 模型的代数重构，将强化学习价值函数替换为当前策略与参考策略的似然比对数差，在避免显式采样和双重训练的同时，达成了等价的偏好约束；
  • 数据质量压倒一切：DPO 极其依赖成对质量分差（Margin）与长度均衡性。必须前置执行 Jaccard 相似度清洗、极端长度比剔除与无意义客套剥离；
  • 监控与调优：必须以 eval_rewards/margins（控制在 0.5 ~ 2.5 之间）和 rewards/accuracies 作为第一健康指标，警惕高隐式奖励诱发的语言连贯性坍塌；
  • 对决与防偏：在下游评估时，采用双盲打乱（Position Swap）的 LLM-as-a-Judge 协议，能够客观量化模型在指令遵循、事实精练性及克服谄媚方面的真实收益。

9. 自测题

题 1：在 DPO 训练中，超参数 \( \beta \) 的作用是什么？如果将 \( \beta \) 设置为接近于 0（如 0.0001），模型最可能出现哪种异常行为？
解析：\( \beta \) 是控制策略网络偏离参考网络（Reference Model）的 KL 惩罚系数。当 \( \beta \to 0 \) 时，对参考模型的锚定约束几乎完全失效，损失函数仅关注拉大当前策略在 chosen 和 rejected 上的输出概率比。这会导致模型迅速发生策略坍塌（Policy Collapse），出现重复胡言乱语、标点符号高频复读或丧失基本自然语言流畅度的严重退化。
题 2：为什么在使用 LoRA 进行 DPO 训练时，无需在显存中真正加载一个独立的参考模型（Reference Model）副本？
解析：因为参考模型的权重正是训练启动前的冻结底座权重。通过 PEFT 库，策略模型是在该底座之上挂载了 LoRA 增量矩阵。在前向计算参考似然 \( \pi_{\mathrm{ref}} \) 时，只需调用 with model.disable_adapter(): 临时关闭 LoRA 分支，即可直接利用同一张卡上的共享底座计算出无梯度的参考对数似然，从而节省整整一个完整底座模型的显存空间。
题 3：什么是 DPO 训练中的“长度黑客攻击（Length Hack）”？在数据预处理与算法设计层面分别应如何防范？
解析：“长度黑客攻击”指模型为了最大化隐式奖励，在生成时盲目堆砌无意义的修饰词和长篇废话。因为未归一化的标准 DPO 损失以词符对数似然累加为目标，长序列天然累积更多分数。防范手段：在数据层面，限制偏好对两者的长度比例（如 \( 0.4 \le \text{len}(y_w)/\text{len}(y_l) \le 2.5 \)），剔除由于虚高长度获胜的脏数据；在算法层面，可采用 SimPO 对序列长度执行 Token 级平均归一化，或在目标函数中加入长度差惩罚正则项。
