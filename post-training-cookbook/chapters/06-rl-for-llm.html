1. 换个视角：生成即决策

SFT 把生成当"模仿"：给定标准答案的每个 token，做加权最大似然。但后训练很快会撞上模仿的天花板：没人能写出"最优回答"。人类标注员只能告诉你哪个回答更好；数学题可以验证对错但没有过程模板；智能体任务里环境会返回成功或失败。这些信号的共同形态是：给定模型的一次完整生成，返回一个（或几个）标量评价——这正是第 5 章 MDP 的"回合 + 奖励"结构。换视角的实质是：不再问"下一个 token 应该是什么"，而是问"在已生成前缀的每一个决策点上，哪种选择会让最终评价更高"。

这个视角迁移不是文字游戏，它带来三个可操作的新能力。第一，优化目标可以直接写成评价函数：奖励模型分数、规则验证器、人类偏好，任何可计算的标量都能成为目标，不需要构造 token 级监督。第二，模型自己的采样成为训练数据：RL 在模型自己生成的分布上优化（on-policy），天然对齐部署时的分布；而 SFT 固定在人类示范分布上，存在"见过的会、没见过的崩"的暴露偏差（exposure bias）。第三，探索成为可能：采样温度让模型尝试多种回答，好的被强化、坏的被打压——这是"超越示范者"的唯一机制，DeepSeek-R1-Zero 展示了它的极限：不靠任何过程示范，纯 RL 把 base 模型的 AIME 2024 pass@1 从 39.7% 推到 71.0%（arXiv:2501.12948）。

当然，代价是继承了第 5 章列出的全部 RL 病灶，且被文本的尺度放大。本章的目标就是把翻译工作做彻底：每个 RL 概念对应 LLM 的什么对象（第 2 节），目标函数长什么样、为什么要加 KL（第 3~4 节），信号怎么给（第 5~7 节），怎么估计（第 8 节），坑在哪里（第 9 节），最后落到代码（第 10 节）。

本节小结：生成即决策的视角把"没有标准答案、只有后果评价"的后训练问题接入 RL 框架，换来可优化任意评价函数、on-policy 数据与探索机制三样新能力。

2. token-level MDP：一张完整的映射表

把一次自回归生成映射为 MDP 的回合（episode）。设提示词为 \(x\)（含对话模板，见第 15 章），回答为 token 序列 \(y = (y_1, \dots, y_T)\)，以 EOS 结束。表 6-1 给出逐项对应——这张表是理解本书所有 RL 算法章节的"字典"，建议打印出来贴在屏幕旁。

这张映射表里藏着一个常被忽略的幸运事实：转移是确定性的。经典 RL 的高方差很大程度来自环境随机性（同样的动作落到不同状态）；文本生成中 \( s_{t+1} = (s_t, a_t) \) 完全确定，随机性只来自策略自己的采样与回合长度的不定。这带来两个简化：其一，"环境模型"就是拼接操作，不需要学世界模型；其二，策略对轨迹分布的控制是全局的——分布偏移的根源纯粹是"策略变了"，这解释了为什么 KL 到参考模型（第 3 节）在 LLM RL 里几乎是唯一需要的"安全带"。

本节小结：状态是前缀、动作是 token、转移是拼接、回合是一次生成；确定性转移让问题比经典 RL 干净，但 15 万维动作空间与数千步回合也带来独特困难。

3. KL 正则化的 RLHF 目标函数：推导与闭式最优解

如果只写"最大化奖励"，优化器会给出灾难性的答案：奖励模型是训练在有限偏好数据上的代理，无约束最大化会找到它的盲区——重复讨好性短语、超长输出、格式套利，语言能力本身崩坏（第 9 节展开）。InstructGPT 以来的标准解法是在目标里加一项"别离参考模型太远"的正则：

\[ \max_{\theta}\; \mathbb{E}_{x \sim \mathcal{D}}\; \mathbb{E}_{y \sim \pi_\theta(\cdot \mid x)}\left[ r(x, y) \right] - \beta\, \mathbb{D}_{\mathrm{KL}}\!\left( \pi_\theta(\cdot \mid x)\, \|\, \pi_{\mathrm{ref}}(\cdot \mid x) \right) \]

其中 \(\pi_{\mathrm{ref}}\) 是冻结的 SFT 模型，\(\beta > 0\) 控制拴绳强度。这个目标有一个精确的闭式解，推导值得完整走一遍（它同时是 DPO 的出发点，第 22 章会复用）。固定 \(x\)，把 \(\pi\) 看作任意分布，用拉格朗日乘子处理归一化约束 \(\sum_y \pi(y) = 1\)：

\[ \mathcal{L}(\pi, \lambda) = \sum_y \pi(y)\left[ r(y) - \beta \log \frac{\pi(y)}{\pi_{\mathrm{ref}}(y)} \right] + \lambda \left( \sum_y \pi(y) - 1 \right) \]

对 \(\pi(y)\) 求导并置零：\( r(y) - \beta\log\pi(y) + \beta\log\pi_{\mathrm{ref}}(y) - \beta + \lambda = 0 \)，解出：

\[ \pi^*(y \mid x) = \frac{1}{Z(x)}\, \pi_{\mathrm{ref}}(y \mid x) \exp\!\left( \frac{r(x, y)}{\beta} \right), \qquad Z(x) = \sum_y \pi_{\mathrm{ref}}(y \mid x) \exp\!\left( \frac{r(x,y)}{\beta} \right) \]

读一下这个解的三层含义。其一，形式是"参考分布 × 奖励指数加权"：KL 约束下的最优策略不是"奖励最大者"，而是把参考模型的分布按奖励做指数级重加权——奖励每高 \(\beta\)，概率质量多 \(e\) 倍。其二，\(\beta\) 的极限行为：\(\beta \to \infty\) 时指数趋平，\(\pi^* \to \pi_{\mathrm{ref}}\)（完全不动）；\(\beta \to 0\) 时退化为 argmax（纯奖励最大化，崩溃）。实战中 \(\beta\) 在 0.02~0.1 之间（第 21 章给调参方法）。其三，重参数化：对最优解取对数、移项，奖励可以反过来用策略比表达：

\[ r(x, y) = \beta \log \frac{\pi^*(y \mid x)}{\pi_{\mathrm{ref}}(y \mid x)} + \beta \log Z(x) \]

这说明"训练后的策略与参考模型的 log 概率比"本身就是奖励的充分统计量——把 \(\pi^*\) 换成可学习的 \(\pi_\theta\)、消掉与 \(y\) 无关的 \(Z(x)\)，就得到 DPO 的损失函数（Rafailov et al., 2023, arXiv:2305.18290）。同一个数学结构，从"RLHF 为什么合理"与"DPO 为什么可行"两个方向被使用，这是理论部分给你的第一份复利。

📘 概念辨析：为什么 KL 用"反向"方向 \( \mathrm{KL}(\pi_\theta \| \pi_{\mathrm{ref}}) \)

KL 不对称。这里约束的是"新策略覆盖不到参考分布"的问题：反向 KL \( \mathrm{KL}(p \| q) = \mathbb{E}_{y \sim p}[\log p - \log q] \) 在 \(p\) 覆盖不到 \(q\) 的高概率区时急剧增大（因为 \(\log p - \log q\) 里 \(\log q\) 很小、\(\log p\) 有概率质量），也就是模式寻求（mode-seeking）——它惩罚"放弃参考模型会说的内容"。反之若用 \( \mathrm{KL}(\pi_{\mathrm{ref}} \| \pi_\theta) \)（正向、均值覆盖），参考分布中低概率的长尾会被新策略"顺手覆盖"，语言可以在奖励方向上漂移得更远。工程上反向 KL 还有决定性优势：样本来自 \(\pi_\theta\)（rollout 本来就要做），期望可直接估计（第 8 节）。

本节小结：RLHF 目标 = 奖励期望 − β·KL(θ‖ref)，其闭式解是"参考分布按奖励指数重加权"；\(\beta\) 是拴绳，重参数化该解即得 DPO——这是全书最重要的一个公式。

4. reward shaping：把 KL 并进奖励

第 3 节的目标里 KL 是序列级的整项；PPO 的算法结构（第 5 章）却要求逐 token 的奖励序列（用于 GAE 与价值回归）。两者能统一起来吗？可以，而且是精确等价，不是近似。关键观察是：序列级 log 概率比按链式法则逐 token 分解：

\[ \log \frac{\pi_\theta(y \mid x)}{\pi_{\mathrm{ref}}(y \mid x)} = \sum_{t=1}^{T} \left[ \log \pi_\theta(y_t \mid x, y_{<t}) - \log \pi_{\mathrm{ref}}(y_t \mid x, y_{<t}) \right] \]

而 KL 正是 log 比在 \(\pi_\theta\) 分布下的期望，所以

\[ \mathbb{D}_{\mathrm{KL}}\!\left( \pi_\theta \| \pi_{\mathrm{ref}} \right) = \mathbb{E}_{y \sim \pi_\theta}\left[ \sum_{t=1}^{T} \log \frac{\pi_\theta(y_t \mid x, y_{<t})}{\pi_{\mathrm{ref}}(y_t \mid x, y_{<t})} \right] \]

于是"期望奖励 − \(\beta\)·KL"完全等价于把每 token 的 shaped reward 定义为：

\[ \tilde{r}_t = \begin{cases} -\beta\, \log \dfrac{\pi_\theta(y_t \mid x, y_{<t})}{\pi_{\mathrm{ref}}(y_t \mid x, y_{<t})}, & t < T \\[6pt] R(x, y) - \beta\, \log \dfrac{\pi_\theta(y_T \mid x, y_{<T})}{\pi_{\mathrm{ref}}(y_T \mid x, y_{<T})}, & t = T \end{cases} \]

即：每个 token 挂一个"离参考模型太远"的负奖励，结果奖励 \(R(x,y)\) 放在末位（InstructGPT 与 Ziegler et al., 2019, arXiv:1909.08593 的原始做法正是如此）。这不只是实现技巧，它改变了学习动力学：KL 惩罚从"回合末的一笔总账"变成即时反馈——策略每漂移一个 token 就被轻轻拉一下，credit assignment 问题凭空多了一条稠密通道（对比第 7 节纯稀疏奖励的困境）。这也是 reward shaping 理论（Ng et al., 1999）在 LLM 上的实例：设计良好的逐项 reward 不改变最优策略，只改变到达它的速度与稳定性。

💡 实践建议：KL 惩罚放每个 token，结果奖励放末位

这是 PPO-for-LLM 的标准姿势，也是第 20 章代码的默认配置。两个细节：其一，KL 惩罚用第 8 节的 k3 估计器（恒非负、数值稳），不要用裸的 log 比（可为负，等效于奖励"向参考模型漂移"，会引入反向的套利空间）；其二，若把结果奖励平摊到每个 token（\(R/|y|\)），会引入"长回答人均摊薄"的长度偏置，不如集中放末位、靠 GAE/优势广播回传。

本节小结：序列级 KL 与逐 token log 比之和精确等价，KL 正则可以无损地改写为每 token 的 shaped reward；"KL 放每个 token、结果奖励放末位"是 RLHF 实现的标准形。

5. per-token 与 sequence-level 奖励：为过程奖励埋下伏笔

第 4 节解决了"奖励放在哪些时间步"的机械问题，但"奖励信号本身在哪一层产生"是另一个正交且更重要的设计决策。按产生粒度分三类：序列级（outcome）——整条回答一个分数，来自奖励模型（第 19 章）或规则验证器（答案对错、单元测试通过）；步级/过程（process）——对推理的每个步骤打分，来自过程奖励模型（PRM）或人工/AI 步骤标注；逐 token——目前只有 KL 惩罚天然逐 token，纯粹的 token 级奖励模型尚不成熟。表 6-2 对比三类信号，第 28 章将展开过程奖励的完整方法论。

一个务实的中庸方案是把序列级奖励"伪稠密化"：把 \(R(x,y)\) 放在末位后，用第 5 章的 GAE 让 Critic 把它逐 token 传播成优势；或用组内基线——同一 prompt 采样 \(k\) 条回答、以组内均值当基线——让每个回答的 token 共享"这组回答好/坏"的信号，这正是 GRPO/RLOO 的思路（第 25 章），它绕开了 Critic，代价是牺牲步级分辨率。什么时候值得升级到真过程奖励？当任务的多步链条长（数学证明、代码多文件修改）、错误步骤需要被单独惩罚而不是"整条连坐"时——可验证奖励 + 过程奖励的混合是第 5 部分反复出现的配方。

本节小结：奖励粒度是正交于放置位置的核心设计：结果奖励便宜但稀疏、过程奖励精准但昂贵、KL 惩罚免费但只约束；组基线与 GAE 是把稀疏信号"传播开"的两大工具。

6. 采样温度与探索

经典 RL 用 ε-greedy 或熵正则探索；LLM 的探索机制是采样温度。对 logits \(z\)，温度 \(T\) 把 softmax 改写为：

\[ p_i = \frac{\exp(z_i / T)}{\sum_j \exp(z_j / T)} \]

\( T \to 0 \) 时分布收缩到 argmax（贪心，无随机性），\( T > 1 \) 时长尾被放大（高熵），\( T \to \infty \) 趋于均匀分布。温度同时控制三件事：生成质量（贪心解码易陷入重复退化，Holtzman et al., 2019, arXiv:1904.09751）、探索广度（rollout 的多样性决定 RL 能发现多少改进方向）、以及与参考模型的 KL 尺度（高温度会系统性抬高逐 token KL 惩罚）。

temperature_demo.py 
import torch

def sample_with_temperature(logits: torch.Tensor, temperature: float = 1.0) -> int:
    """温度采样：T 越小分布越尖（趋近贪心），T 越大越平（探索越强）"""
    if temperature <= 0:                          # 贪心解码：无随机性、无探索
        return int(logits.argmax(dim=-1))
    probs = torch.softmax(logits / temperature, dim=-1)
    return int(torch.multinomial(probs, num_samples=1))

z = torch.tensor([4.0, 3.0, 2.0, 1.0])            # 假想的 4 个候选 token 的 logits
for t in [0.5, 1.0, 2.0]:
    p = torch.softmax(z / t, dim=-1)
    entropy = -(p * p.log()).sum().item()
    print(f"T={t}: 概率 = {[round(x, 3) for x in p.tolist()]}, 熵 = {entropy:.3f}")
# T=0.5: 概率 ≈ [0.866, 0.117, 0.016, 0.002] —— 头部几乎垄断
# T=1.0: 概率 ≈ [0.644, 0.237, 0.087, 0.032] —— 标准 softmax
# T=2.0: 概率 ≈ [0.455, 0.276, 0.167, 0.102] —— 长尾显著放大，熵更高

区分两个容易混淆的旋钮：采样温度作用于数据生成（决定 rollout 的分布与探索量），熵正则（第 5 章）作用于参数化分布本身（防止策略在训练中过早确定化）。实践中温度是主力：RLHF 的 rollout 常用 \( T = 0.7 \sim 1.0 \)；推理强化（RLVR）倾向较高温度以维持推理路径的多样性，DeepSeek-R1-Zero 直接用 \( T = 1.0 \) 采样（arXiv:2501.12948）。调试提示：若训练中发现"每个 prompt 的组内回答几乎相同"，先查温度与 top-p 的设置——组内多样性为 0 的 rollouts 让组基线（GRPO）退化为常数，优势恒为 0，训练静默失效。

本节小结：温度是 LLM 的探索旋钮，同时牵动质量、多样性与 KL 尺度；RL rollout 保持 \( T \approx 0.7 \sim 1.0 \)，并警惕"组内采样同质化"这一静默故障。

7. credit assignment：文本生成的特殊困难

第 5 章把 credit assignment 列为 RL 的本质困难之一，在文本生成里它被放大到极限，特殊性有四。其一，回合极长：一条回答几百到几千个 token，就是一个几千步的决策序列，而评价只有一个标量——第 5 章的策略梯度公式里，几千个 \(\nabla\log\pi\) 共享同一个 \(G_t\)。其二，贡献极不均匀：回答质量常常由少数关键 token 决定（转折处的"但是"、算式里的那个进位、工具调用的参数），大量功能词只是语法填充；均匀广播奖励会把关键信号稀释在噪声里。其三，价值估计先天贫血：Critic 要学的 \(V(x, y_{<t})\) 是"这个前缀的期望最终奖励"，而最终奖励因 prompt、因标注者、因验证器而剧烈波动，信号-噪声比极差——这是 PPO 的 Critic 在 LLM 上又贵又难训的结构性原因（第 25 章 GRPO 的动机）。

其四，方差随长度二次增长：不做任何方差治理时，单标量奖励对 \(T\) 个独立决策的梯度估计方差以 \(O(T^2)\) 增长。实战中的四层缓解，按工程成本从低到高：第一层，基线——批均值、prompt 级均值或移动平均（第 5 章第 5 节的恒等式保证无偏）；第二层，组基线——同一 prompt 采 \(k\) 条互相当基线（GRPO/RLOO），把 prompt 难度从信号中剔除，对奖励尺度跨 prompt 波动的问题尤其有效；第三层，GAE + Critic——用学到的 \(V\) 做每步基线与自举，分辨率最高、成本也最高；第四层，过程奖励——直接给每步打分，从源头缓解（第 28 章）。这四层不是互斥的：R1 式训练常用"组基线 + 规则验证器"，工业 RLHF 常用"组基线或 Critic + KL shaping"。

⚠️ 常见误区：把序列奖励平摊到每个 token 当作 per-token 优势

一种偷懒写法是 \( A_t = R(x,y)/|y| \) 直接当每 token 优势。它无偏性尚可，但把"哪个 token 立功"的信息彻底抹平，且长度偏置会诱导模型学出凑长度或凑段落的策略。正确姿势：奖励放末位，用 GAE/组基线求优势后广播；若确需稠密监督，上 PRM 或步级验证器，而不是算术平摊。

本节小结：长回合 + 稀疏单标量 + 贡献不均 + Critic 贫血，构成文本生成 credit assignment 的四重特殊困难；基线 → 组基线 → GAE → 过程奖励，是按成本递增的四层解法。

8. KL 散度的三种估计器：k1、k2、k3

训练时你无法精确计算 \(\mathrm{KL}(\pi_\theta \| \pi_{\mathrm{ref}})\)（要对全部 \(10^{15}\) 条可能序列求和），只能用 rollout 样本估计。John Schulman 的博客《Approximating KL Divergence》给出了三个估计器及其性质，这组工具在 KL 惩罚、early-stop 监控、DPO 校准里无处不在。目标量是 \( \mathrm{KL}(p \| q) = \mathbb{E}_{y \sim p}[\log p(y) - \log q(y)] \)，样本来自 \(p\)（即当前策略的 rollout），记逐 token 的 log 比 \( \ell = \log p - \log q \)（\(p = \pi_\theta\)，\(q = \pi_{\mathrm{ref}}\)）：

\[ k_1 = \ell, \qquad k_2 = \tfrac{1}{2}\, \ell^2, \qquad k_3 = \frac{q}{p} - \log\frac{q}{p} - 1 \]

三者都是对同一个 KL 的估计，性质却差别很大（表 6-3）。\(k_1\) 是定义本身，无偏，但逐 token 可为负——把它当惩罚会出现"靠近参考模型反而得正奖励"的套利空间，且方差大。\(k_2\) 恒非负、方差小，但有偏：由 \( \mathbb{E}_p[\ell^2] = \mathrm{Var}_p(\ell) + (\mathbb{E}_p[\ell])^2 = \mathrm{Var}_p(\ell) + \mathrm{KL}^2 \) 可得 \( \mathbb{E}[k_2] = \tfrac12 \mathrm{Var}_p(\ell) + \tfrac12 \mathrm{KL}^2 \)——KL 很小时它低估（被方差项主导的符号随机），KL 很大时又高估（平方项爆炸）。\(k_3\) 是兼顾者：利用恒等式 \( \mathbb{E}_p[q/p] = \sum_y p(y) \cdot \frac{q(y)}{p(y)} = 1 \)，有 \( \mathbb{E}_p[k_3] = 1 + \mathrm{KL} - 1 = \mathrm{KL} \)，无偏；又因 \( x - \log x - 1 \ge 0 \) 对一切 \(x > 0\) 成立，逐点非负；在 \(p \approx q\) 附近它关于 \(\ell\) 展开的线性项与 \(k_1\) 相同、方差与 \(k_1\) 同阶但被非负截断压低。这三条性质让 k3 成为 TRL 等主流实现的默认选择。

估计器公式（\(\ell = \log p - \log q\)）无偏逐点非负备注
k1\( \ell \)是否InstructGPT 早期 per-token 惩罚用此形式；可为负、方差大
k2\( \frac{1}{2}\ell^2 \)否是\( \mathbb{E}[k_2] = \frac12 \mathrm{Var}(\ell) + \frac12 \mathrm{KL}^2 \)：小 KL 低估、大 KL 高估
k3\( e^{-\ell} - 1 + \ell \)是是TRL/PPO 实现默认；\(x - \log x - 1\) 结构保证非负

kl_estimators.py 
import torch

def kl_estimators(logp_theta, logp_ref):
    """三种 KL 估计器（输入为逐 token 的 log 概率，样本来自当前策略 p）"""
    log_ratio = logp_theta - logp_ref           # ell = log(p/q)
    k1 = log_ratio                              # 无偏，可为负，方差大
    k2 = 0.5 * log_ratio.pow(2)                 # 恒非负，但有偏
    k3 = torch.exp(-log_ratio) - 1 + log_ratio  # q/p - 1 + log(p/q)：无偏且恒非负
    return k1, k2, k3

# 数值验证：从 p 采样，三个估计器的均值与真实 KL 的关系
torch.manual_seed(0)
p = torch.softmax(torch.randn(8), dim=-1)
q = torch.softmax(torch.randn(8) * 1.3, dim=-1)
true_kl = (p * (p.log() - q.log())).sum().item()
samples = torch.multinomial(p, num_samples=200000, replacement=True)
k1, k2, k3 = kl_estimators(p.log()[samples], q.log()[samples])
print(f"真实 KL      = {true_kl:.5f}")
print(f"k1 估计      = {k1.mean():.5f}（无偏，但单样本可负）")
print(f"k2 估计      = {k2.mean():.5f}（有偏：小 KL 时被压向 0）")
print(f"k3 估计      = {k3.mean():.5f}（无偏，且逐点非负）")
print(f"单样本为负比例(k1) = {(k1 < 0).float().mean():.3f}")

# exp(-log_ratio) 可能在 logp_ref 溢出为 -inf 时爆炸，需 clamp 或跳过极端 token。
🚨 重要警告：KL 估计器的方向与数值边界

两个高频事故。其一，方向装反：估计器假设样本来自 \(p\)、目标是 \(\mathrm{KL}(p\|q)\)。若 rollout 来自当前策略却把 \(p\)、\(q\) 写反，k3 的期望不再等于 KL（恒等式 \(\mathbb{E}_p[q/p]=1\) 不成立），惩罚项系统性失真。其二，数值边界：\(q/p = \exp(\log q - \log p)\)，当参考模型对某 token 的概率下溢（log q ≈ −inf）时 k3 爆炸；实现里要 clamp log 比或用 fp32 计算 log 概率。KL 监控曲线突然出现尖刺，先查这两处（第 46 章）。

本节小结：k1 无偏可为负、k2 稳但有偏、k3 无偏且非负——作为惩罚项选 k3，作为监控指标三条一起看；方向（样本来自 p）与 log 空间数值边界是实现层的两大雷区。

9. 为什么 LLM + RL 这么难：五大结构性困难

把前几节的结论拼起来，就能系统回答"为什么 RLHF/RLVR 的工程难度远超 SFT"。其一，奖励稀疏且延迟：几百上千个决策共享末位一个标量（第 5、7 节），信号-噪声比先天低下；缓解靠 shaping（KL 项）、组基线、GAE 与过程奖励。其二，序列长、方差大：策略梯度方差随长度与动作空间（15 万维）放大，必须依赖方差治理全家桶——基线、优势标准化、梯度裁剪、小学习率；任何一层缺失都可能在某个 batch 上引爆。其三，奖励黑客（reward hacking）：奖励模型是有限数据的代理，强化会让策略精确地最大化代理而非本意（Goodhart 定律），表现为谄媚、冗长、模板化、格式套利；Gao et al.（2022, arXiv:2210.10760）定量刻画了"代理奖励持续上升、真实奖励先升后降"的过优化曲线，KL 系数、RM 集成与人工抽查是三道闸（第 21 章专题）。其四，rollout 成本主导：训练前向是稠密矩阵乘（GPU 友好），生成是访存受限的自回归循环（第 3 章第 9 节），RL 训练的墙钟时间一半以上花在采样；这决定了 rollout 基础设施（vLLM/异步采样，第 45 章）与算法设计的经济约束（GRPO 的组采样正是"一次 rollout 多次复用"的经济学）。其五，超参敏感且失效静默：KL 系数过大=训练无效（策略不动）、过小=崩坏；clip 比例、温度、组大小的失效都不抛异常，只表现为曲线平掉或评测悄然回落——这要求把"监控先于训练"当成纪律（第 46 章的急救手册）。

📘 视角：SFT 与 RL 的适用边界不是"先进/落后"

RL 的三项独特价值（优化任意评价信号、on-policy 分布对齐、超越示范者）与五项结构性困难，共同决定了选型逻辑：有 token 级监督 → SFT；有可验证标量信号且行为可枚举 → RLVR；只有偏好信号 → RM + RLHF 或 DPO 类离线方法；信号昂贵且行为空间小 → 先把 SFT 做满。Ramamurthy et al.（2022, arXiv:2210.01241）对此有系统讨论。第 4 部分会把这条决策树展开成完整方法谱系。

本节小结：稀疏奖励、长序列方差、奖励黑客、rollout 成本、静默失效——五难决定了 LLM+RL 的工程形态；每个困难都已有标准缓解层，关键是组合与监控。

10. 动手：LLM 上的 REINFORCE

把第 5 章的母公式翻译成 LLM 版本，策略梯度有如下的具体形式（组基线版，即 REINFORCEleave-one-out 的核心）：

\[ \nabla_\theta J(\theta) = \mathbb{E}_{x \sim \mathcal{D}}\; \mathbb{E}_{y \sim \pi_\theta(\cdot \mid x)}\left[ \sum_{t=1}^{T} \nabla_\theta \log \pi_\theta(y_t \mid x, y_{<t}) \cdot \left( R(x, y) - b(x) - \beta\, \hat{k}_3(t) \right) \right] \]

其中 \(b(x)\) 是组均值基线（同一 prompt 的 \(k\) 条回答平均奖励），\(\hat{k}_3(t)\) 是第 8 节的逐 token KL 估计（并入奖励，第 4 节）。对应损失就是"优势加权的负对数似然"：\( \mathcal{L} = -\mathbb{E}\left[ \sum_t A_t \log \pi_\theta(y_t \mid x, y_{<t}) \right] \)。下面的最小实现把整章的零件（采样 → 打分 → k3 KL → 组基线 → 加权似然）串成一条流水线，去掉工程件后只有 60 行，GRPO/PPO 的骨架尽在其中：

reinforce_llm_min.py 
import torch
import torch.nn.functional as F

def reinforce_llm_step(policy, ref_model, tokenizer, prompts, reward_fn,
                       group_size=4, beta=0.05, lr=1e-6, temperature=1.0):
    """最小化 REINFORCE-for-LLM：组基线 + 末位结果奖励 + k3 逐 token KL 惩罚
    （教学示意：省略 vLLM 加速、长度截断、多 epoch 等工程件）"""
    optimizer = torch.optim.AdamW(policy.parameters(), lr=lr)
    stats = []
    for x in prompts:
        enc = tokenizer(x, return_tensors="pt").to(policy.device)
        prompt_len = enc["input_ids"].shape[1]

        # 1) 组采样：同一 prompt 采 group_size 条回答（探索来自采样温度）
        rollouts, seq_logps, seq_kl, rewards = [], [], [], []
        for _ in range(group_size):
            out = policy.generate(**enc, do_sample=True, temperature=temperature,
                                  max_new_tokens=256)
            resp = out[0, prompt_len:]                    # 生成的 token（动作序列）
            labels = out                                   # 完整序列（含提示词）

            # 2) 重算当前/参考模型对 response 逐 token 的 log 概率
            logits = policy(labels).logits[:, :-1, :]
            logp = F.log_softmax(logits, dim=-1)
            tok_lp = logp.gather(-1, labels[:, 1:].unsqueeze(-1)).squeeze(-1)[0, prompt_len - 1:]
            with torch.no_grad():
                rlogits = ref_model(labels).logits[:, :-1, :]
                rlogp = F.log_softmax(rlogits, dim=-1)
                ref_lp = rlogp.gather(-1, labels[:, 1:].unsqueeze(-1)).squeeze(-1)[0, prompt_len - 1:]

            # 3) k3 逐 token KL 估计（无偏、非负），并入奖励构成 shaped reward
            log_ratio = tok_lp - ref_lp
            k3 = torch.exp(-log_ratio) - 1 + log_ratio
            r_seq = reward_fn(x, tokenizer.decode(resp, skip_special_tokens=True))

            rollouts.append(resp)
            seq_logps.append(tok_lp)
            seq_kl.append(k3)
            rewards.append(r_seq)

        # 4) 组基线：剔除 prompt 难度，优势 = 回报 - 组均值
        rewards_t = torch.tensor(rewards, device=policy.device)
        advantages = (rewards_t - rewards_t.mean()) / (rewards_t.std() + 1e-8)

        # 5) 优势加权的负对数似然（KL 惩罚经 advantage 折算进权重）
        loss = 0.0
        for i in range(group_size):
            A = advantages[i] - beta * seq_kl[i].mean()   # 简化：KL 以均值并入优势
            loss = loss - A * seq_logps[i].mean()
        loss = loss / group_size

        optimizer.zero_grad()
        loss.backward()
        torch.nn.utils.clip_grad_norm_(policy.parameters(), 1.0)
        optimizer.step()
        stats.append(rewards_t.mean().item())
        print(f"组奖励均值 = {stats[-1]:.3f} | 奖励方差 = {rewards_t.std().item():.3f}")
    return policy

# reward_fn 示例（可验证奖励）：数学题只认最终答案
# def reward_fn(prompt, completion):
#     gold = extract_answer(prompt)
#     return 1.0 if extract_answer(completion) == gold else 0.0

对照第 5 章的伪代码读这段实现：第 1 步是 rollout（成本大头，生产环境换 vLLM），第 2 步对应 PPO 的 logp_old 与参考模型 logp，第 3 步是第 4 节的 reward shaping，第 4 步是第 7 节的组基线，第 5 步就是"优势加权最大似然"。把组基线换成 GAE+Critic、加权似然换成 clip 损失，就得到 PPO；去掉 KL 项换成组内相对排序，就接近 GRPO 的原始形态（第 25 章）。万变不离其宗：LLM 强化方法的全部差异，几乎都在"优势从哪来、KL 怎么算"这两件事上。

本节小结：LLM 版策略梯度 = 优势加权的负对数似然；60 行教学实现已经包含 GRPO/PPO 的全部骨架，方法差异收敛于"优势来源"与"KL 处理"两个自由度。

11. 本章小结

  • MDP 映射：状态 = 前缀，动作 = token，转移 = 拼接（确定性），回合 = 一次生成；随机性全部来自策略采样，\(\gamma = 1\)。
  • 核心目标：\( \max_\theta \mathbb{E}[r] - \beta\,\mathrm{KL}(\pi_\theta \| \pi_{\mathrm{ref}}) \)，闭式最优解 \( \pi^* \propto \pi_{\mathrm{ref}} \exp(r/\beta) \)；重参数化它即得 DPO。
  • KL 并入奖励：序列级 KL 与逐 token log 比之和精确等价；标准姿势是"逐 token KL 惩罚（k3）+ 末位结果奖励"。
  • 奖励粒度：结果（稀疏便宜）、过程（稠密昂贵）、KL（免费但只约束）三种信号各有定位，组基线与 GAE 是稀疏信号的两大传播器。
  • KL 估计器：k1 无偏可为负、k2 有偏、k3 无偏且逐点非负；惩罚用 k3，方向与 log 空间溢出是实现雷区。
  • 五难：稀疏奖励、长序列方差、奖励黑客、rollout 成本、静默失效——各自的缓解层构成第 4、5 部分算法设计的全景图。

理论部分到此收官。你已经具备进入方法主体的全部地基：架构与 log 概率从哪来（第 3 章）、base 模型能干什么（第 4 章）、策略梯度与 PPO 的数学（第 5 章）、以及它们如何落在语言模型上（本章）。接下来进入第 2 部分——后训练的数据工程，那里决定你手里这把"RL 之剑"挥向什么方向。

🧠 自测题（点击展开答案）
问题 1：LLM 的 MDP 转移是确定性的。这个性质带来哪些简化？它是否意味着 RL 的方差问题在 LLM 上不存在？

简化有二：不需要学习或建模环境动力学（"环境"就是字符串拼接），模型和奖励函数是仅有的随机性来源；且回合内未来奖励与当前动作之后的环境随机性无关，回报 \(G_t\) 的条件期望结构更干净。但方差问题依然严重：随机性来自 15 万维动作空间的采样与回合长度不定，单条轨迹的回报方差依旧巨大，策略梯度的方差随序列长度与奖励尺度增长——这正是基线、组基线、GAE、优势标准化在 LLM RL 中不可或缺的原因。确定性转移只是移除了"环境噪声"这一种方差来源。

问题 2：证明 \( k_3 = q/p - \log(q/p) - 1 \) 在样本来自 \(p\) 时是 KL(\(p\|q\)) 的无偏估计，且逐点非负。

无偏性：\( \mathbb{E}_p[q/p] = \sum_y p(y)\, q(y)/p(y) = \sum_y q(y) = 1 \)；\( \mathbb{E}_p[-\log(q/p)] = \mathbb{E}_p[\log(p/q)] = \mathrm{KL}(p\|q) \)；再减常数 1，得 \( \mathbb{E}_p[k_3] = 1 - 1 + \mathrm{KL} = \mathrm{KL} \)。非负性：令 \( x = q/p > 0 \)，由 \( \log x \le x - 1 \)（对数函数的凸性/切线不等式）得 \( x - \log x - 1 \ge 0 \)，等号当且仅当 \(x=1\)（即 \(p=q\)）。两条性质合起来：k3 逐点非负、期望恰为 KL，是三估计器中最适合当惩罚项的。

问题 3：把 RLHF 目标里的 β 从 0.05 调到 0.5，模型行为会发生什么系统性变化？调到 0.001 呢？

\( \beta=0.5 \)：拴绳收紧，最优策略 \( \pi^* \propto \pi_{\mathrm{ref}} e^{r/\beta} \) 中奖励的指数权重被压缩，策略贴近 SFT 参考模型——奖励分数提升有限、回答风格变化小，KL 曲线平直，等于"训练了个寂寞"。\( \beta=0.001 \)：几乎纯奖励最大化，策略迅速漂向奖励模型的盲区——冗长、谄媚、模板化、语言质量退化，评测上代理奖励（RM 分数）持续上升而真实偏好先升后崩（Gao et al. 的过优化曲线）。调参实践：从 0.02~0.1 起步，以"KL 随训练缓慢增长且可控、人工抽查语言质量不退化"为准（第 21 章）。

问题 4：同一个 prompt 用温度 1.0 采样 8 条回答，奖励全都是 1.0。此时组基线（GRPO 式）的优势是多少？训练会发生什么？请给出至少两个可能的原因与排查动作。

优势恒为 0（减去组均值后全为 0），该 prompt 的梯度为 0，训练静默无效。可能原因与排查：其一，任务太简单——模型已能全对，应换更难的 prompt 分桶或提高过滤阈值（RLVR 常按通过率 0.2~0.8 过滤提示词）；其二，探索不足——检查温度/top-p 是否过低、组内回答是否雷同，必要时提高温度或去掉Beam/前缀截断；其三，奖励函数饱和——验证器可能对多种合理输出全给满分，需细化评分。监控指标：组内奖励方差应保持非零，长期为零的 batch 占比是训练健康度的核心仪表（第 46 章）。
