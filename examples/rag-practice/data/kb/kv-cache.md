# KV Cache 与显存

自回归解码时，每生成一个 token 都要对之前所有 token 重新计算 Key 和 Value。KV Cache 把这些张量缓存下来，把每步的注意力计算从 O(n²) 降到 O(n)。

代价是显存。KV Cache 的大小是 `2 × 层数 × 头数 × 头维度 × 序列长度 × 批大小 × 精度字节数`。一个 7B 模型在 fp16、批大小 32、序列长度 4096 下，KV Cache 大约占用 16 GB，已经超过模型权重本身。

减小 KV Cache 有三条主线。第一是减少 KV 头数：MQA 让所有查询头共用一组 KV，GQA 折中为每组查询头共用一组，是目前主流选择。第二是量化：把 KV Cache 存成 int8 甚至 int4，精度损失通常小于权重量化。第三是分页管理：vLLM 的 PagedAttention 把 KV Cache 切成固定大小的块，按需分配，把碎片浪费从 60%~80% 降到 4% 以下。

一个常见的误判是把 OOM 归因于模型太大。批量推理场景下，先算一遍 KV Cache 占用再下结论——多数情况下瓶颈在这里，而不是权重。
