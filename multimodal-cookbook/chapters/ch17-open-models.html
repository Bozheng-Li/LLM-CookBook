💡 本章导读

前三章把 MLLM 拆成了三个零件——视觉编码器、连接器、数据配方——本章把它们重新组装成真实的整机，并沿着开源谱系讲四年的工程演化史。选材标准有三：技术路线有代表性（LLaVA 的极简、Qwen 系的原生动态分辨率、InternVL 的大塔渐进对齐、MiniCPM 的端侧极限）、有公开可复现的技术报告、以及至今仍在活跃迭代。每一系我们都回答同样的四个问题：架构怎么选的？数据怎么配的？训练分几段？下一代改了什么、为什么改？这样读谱系就不是背参数表，而是理解每一步工程决策的因果。最后给出两张硬通货：一张覆盖 2023–2026 主力开源模型的架构对比大表（视觉塔/连接器/分辨率策略/LLM/许可），一张按场景的选型指南与部署起步代码。本章与第 18 章（闭源模型）、第 22 章（高分辨率与文档）、第 31 章（视频理解）互为补集——各家模型在专门任务上的细节会在那里展开。

🕰 开源 MLLM 大事记（2023.04–2025.12）

2023.04：LLaVA 开源，首次给出"从零到对话"的全套配方；2023.08：Qwen-VL 带来交叉注意力解析器与首个系统化的多任务数据配方；2023.10：LLaVA-1.5 用 665K 数据登顶 11 项基准，成为最广泛复用的底座；2023.11–12：CogVLM 视觉专家、MoE 先声、Florence-2 序列到序列统一、Honeybee 连接器科学；2024.02–04：InternVL 1.5（6B 大塔 + 动态分辨率）、DeepSeek-VL（混合签名编码器）发布，Qwen2-VL 蓄势；2024.08–09：MiniCPM-V 2.6 端侧 8B 追平 GPT-4V-1106 口碑，Qwen2-VL 原生动态分辨率 + M-RoPE 重新定义"怎么看大图"；2024.12：InternVL 2.5 与 MoE 化的 DeepSeek-VL2、Qwen2.5 基座就位；2025 上半年：Qwen2.5-VL（Agent 化 + 文档解析）、InternVL 3（原生多模态预训练）把开源旗舰推上 MMMU 70+；2025 下半年：Qwen3-VL、InternVL 3.5（Cascade RL）、GLM-4.5V 等新一代模型把"长思考 + 原生 Agent 能力"变成开源标配。

1.谱系总览：四条架构路线与十年演化

把 2023–2026 年的开源模型摊开，虽然零件各异，但架构决策空间其实只有四个维度：视觉塔怎么选（单塔/双塔/大塔）、连接器怎么连（直连 MLP / 交叉注意力 / 视觉专家）、分辨率怎么管（固定方图 / tile 切块 / 原生动态）、参数怎么省（MoE / 蒸馏 / 端侧量化）。按这四个维度的组合，主流开源模型落进四条路线：

路线 A：极简直连（LLaVA 系）——CLIP 家族塔 + 两层 MLP + 现成指令数据，把复杂性全部留给数据；路线 B：原生动态分辨率（Qwen 系）——从固定 448 方图起步，演进到 NaViT 式任意分辨率、M-RoPE 位置建模，视觉塔内建 token 合并；路线 C：大塔渐进对齐（InternVL 系）——自研 6B 级视觉塔，先对比对齐、再生成、再 SFT 的渐进解冻，动态 tile + pixel shuffle；路线 D：特种路线——端侧（MiniCPM-V、Phi-3.5-Vision）、混合编码器（DeepSeek-VL）、逐层专家（CogVLM）、稀疏化（MoE-LLaVA）、序列到序列统一（Florence-2）。下面的演化树给出时间轴全景，后续各节逐系展开。

2.LLaVA 系：从 1.5 到 OneVision

LLaVA 系的架构在本章几乎不需要新知识：CLIP ViT-L/14-336（或 SigLIP-SO400M）+ 两层 MLP + Qwen2/ Vicuna，Visual token 数 576 起步、AnyRes 可扩展。它的谱系价值在于工程演化路径的示范意义——每个版本解决一个当时最痛的问题：

LLaVA-1.5（2023.10）解决"能力不合格"：MLP 连接器 + 336px + 665K 学术数据混合（第 16 章），7B/13B 两档，一举成为复现底座。它的工程遗产是可复现性文化：训练脚本、数据列表、评测工具全开源，此后几乎所有新模型论文都用"对比 LLaVA-1.5"作为架构消融的默认基线。LLaVA-NeXT（2024.01，博客发布）解决"看不清"：AnyRes 把高分辨率图切成 336 tile + 全局缩略图，分辨率扩展到 672/1344 级，同时发现高分辨率数据顺带提升了 OCR 与推理；另加入四倍视觉 token 的"看图细节能力"与更好的推理数据，但模型仍是 1.5 的骨架。LLaVA-OneVision（arXiv:2408.03326，2024.08）解决"场景割裂"：单图（3.2M 数据）、多图、视频三个场景此前各训各的模型，OneVision 用一套架构（SigLIP + MLP + Qwen2，0.5B/7B/72B）统一支持，并在数据上验证了重要的课程结论——先单图、后多图/视频的顺序产生正迁移，反过来则单图能力受损；其 Higher AnyRes 用双线性插值上采样后再切块，让 token 预算在三类场景间可比（论文 Figure 3 专门设计了各场景的 token 分配上限）。

LLaVA 系的局限同样明显：视觉塔一直是"借来的"CLIP 家族（第 14 章讨论过低分辨率与任务失配问题），官方主线没有自研视觉塔与原生动态分辨率——这恰好为路线 B/C 的崛起留出了空间。生态上，LLaVA 的遗产是无数下游魔改的母版：ShareGPT4V、Cambrian-1、TokenPacker、PruMerge、视频系（Video-LLaVA 等）都在其代码骨架上生长。

3.Qwen-VL → Qwen2-VL → Qwen2.5-VL → Qwen3-VL

Qwen-VL 系是理解"分辨率与位置编码"这条主线最好的教材，因为它三代把三个关键问题各解决了一次：多任务怎么配（2023）→ 任意分辨率怎么进（2024）→ 模型怎么 Agent 化（2025）。

Qwen-VL（arXiv:2308.12966，2023.08）：视觉塔约 1.9B 的 ViT-G（OpenCLIP 风格），语言侧 Qwen-7B。与 LLaVA 最大的架构差异是连接器——不把视觉 token 挤进序列，而是在 LLM 的注意力层间插入带 256 个可学习 query 的交叉注意力层（visual resolver），视觉信息以 256 个定长 token 参与语言建模。输入固定 448×448。数据配方是它的另一大贡献：三阶段训练——（1）大规模图文对齐（约 50 亿对清洗到 14 亿）；（2）多任务预训练，混入 OCR（多语种）、VQA、定位（grounding）、文档与纯文本任务，并把框坐标以文本形式统一表示；（3）155K 多模态指令微调得到 Qwen-VL-Chat。这份"任务全家桶 + 细粒度文本化"的配方直接定义了后续各家数据表的样子。Qwen-VL-Chat 成绩（论文口径）：VQAv2 78.2、TextVQA 61.5、DocVQA 62.6、MME 1449.3——在 2023 年下半年是开源综合第一梯队，且是当时唯一原生支持定位与多图输入的 7B 级开源模型。

Qwen2-VL（arXiv:2409.12191，2024.09）是一次彻底的重构，两项设计成为行业事实标准。其一，原生动态分辨率（NaViT 式）：不再把图像缩放到固定方图，而是按 14×14 patch 原样切分，相邻 2×2 patch 合并（patch merge，本质是第 15 章的 space-to-depth）成一个 token——每个 token 对应 28×28 像素区域，token 数随图像尺寸与长宽比自然伸缩，并用 2D RoPE（行/列两个旋转分量）描述 patch 的绝对位置；视频按帧展开成"时间 × 空间"的 patch 序列，同时可对帧率与总 token 做预算控制。其二，M-RoPE（Multimodal RoPE）：把旋转位置编码的分量拆成时间、高、宽三组——文本 token 三组共享同一位置号（等价普通 RoPE），图像 token 高宽两组按 2D 网格取值、时间组恒定，视频 token 三组各自独立。这让"文本→图像→视频"的位置语义在同一个 LLM 里无缝统一，并显著改善长度外推（论文用 Video-MME 验证了超过训练长度仍稳健）。视觉塔也重设计为约 675M 参数，绝大多数层用窗口注意力、每隔数层做一次全局注意力，兼顾效率与全局建模。模型 2B/5B/7B/72B 四档，72B 的 MMMU 60.6、DocVQA 94.5（论文口径）是 2024 下半年开源标杆。

📐 理论推导：M-RoPE 的分量分解与相对位置性质

回顾第 3 章的 RoPE：对位置 $m$ 的 query 向量 $\mathbf{q}$，按二维子空间逐对旋转 $\theta_j^m = m \cdot \theta_j$（$\theta_j = 10000^{-2j/d}$），使得内积 $\langle R_m \mathbf{q}, R_n \mathbf{k}\rangle$ 只依赖相对位置 $m - n$。M-RoPE 把每个注意力头的维度切成三段，分别用时间 $t$、高度 $h$、宽度 $w$ 三个位置号旋转：

$$R^{\text{M}}_{(t,h,w)} = \big[\, R_t(t) \;\|\; R_h(h) \;\|\; R_w(w) \,\big], \qquad \mathbf{q}' = R^{\text{M}}_{(t,h,w)}\, \mathbf{q}$$

三类模态的取值规则：文本 token $t = h = w = i$（全局序列位置）——三段合起来恰好还原标准 RoPE，保证纯文本能力不退化；图像 token：$h, w$ 按 patch 的二维网格取值，$t$ 取常数（单图时间维退化）；视频 token：$t$ 随帧推进、$h,w$ 为帧内网格。关键性质：由于 RoPE 的相对性，两个 token 的注意力偏置由各分量相对差 $(\Delta t, \Delta h, \Delta w)$ 共同决定——同一行相邻 patch 的 $\Delta w = 1$ 语义被显式编码，不同帧同一位置的 $\Delta t = 1$ 亦然，这是普通 1D RoPE 摊平序列后无法区分的结构。代价是位置分量的"分辨率"变粗（每段维数只有 1/3），对纯文本长序列外推略有影响——Qwen2-VL 用大量文本数据混合训练来补偿。$\blacksquare$

📄 论文精读：Qwen2-VL（arXiv:2409.12191）

一句话贡献：用"原生动态分辨率 + M-RoPE"把 MLLM 从"固定方图时代"带入"任意分辨率时代"。三个值得精读的工程细节：（1）重设计的视觉塔——约 675M 参数，绝大多数层用窗口注意力、每隔数层才做一次全局注意力，窗口内不跨窗混合；这让 2M 像素级输入的视觉塔计算保持近线性，是大分辨率可行性的隐形前提。（2）patch merge 的位置——合并发生在视觉塔输出之后、进入 LLM 之前（2×2 patch 拼接 → MLP），而不是塔的输入端：塔内仍以 14×14 patch 保留计算粒度，只在"给 LLM 看"的接口处压缩，兼顾细节与预算。（3）数据与训练分四阶段——视觉预训练（海量图文 + OCR）→ 多任务联合预训练（含纯文本防遗忘）→ 长分辨率/长视频适应性训练 → 指令微调，"分辨率课程"被显式设计成训练阶段。2B/5B/7B/72B 全档开源（后增 2B），72B 的 MMMU 60.6、DocVQA 94.5。阅读建议：重点看 Figure 3（M-RoPE）、Figure 4（min_pixels 消融）、Figure 5（长度外推）；Qwen2.5-VL 技术报告（arXiv:2502.13923）则补齐了绝对时间对齐与 Agent 数据的细节，两篇连读效果最佳。

Qwen2.5-VL（arXiv:2502.13923，2025.01）在 Qwen2-VL 架构上做增量打磨 + 大幅扩展技能面：视觉塔改为大多数层窗口注意力（不再需要周期性全局层）并保留 patch merge；视频侧引入绝对时间对齐的 MRoPE-Interleave（时间分量用真实秒数编码，模型能回答"第几秒发生了什么"）；训练数据向Agent 化倾斜——原生支持 GUI 截图元素点击坐标输出、手机/电脑操作、长文档解析（输出结构化 HTML/JSON），官方同步发布了文档解析与计算机使用（computer use）的落地方案。72B 版论文口径 MMMU 70.2、DocVQA 95.7、MathVista 68.2，3B/7B 版则是当时部署生态最完善的小尺寸模型。Qwen3-VL（2025，以官方技术博客/报告为准，此处不附 arXiv 号）进一步把三件事变成默认：Interleaved-MRoPE（时间/空间分量在频率维度交错分布，改善长视频位置分辨）、DeepStack（把 ViT 多层中间特征注入 LLM 的多个深度，提升细节保留）、文本-时间戳对齐的视频定位；产品形态上提供 2B–235B（MoE）与 Instruct/Thinking 双版本，长思考（第 44 章）与 Agent 能力内建。

💡 技巧：读懂 Qwen 系的"像素→token"换算

Qwen2/2.5-VL 每个 token 覆盖 28×28 像素（14 patch × 2×2 merge），但有 min_pixels/max_pixels 两个钳位：小图会被放大到 min_pixels 以上（过小的图连 prompt 格式都装不下，第 14 章讨论过"小图上采样涨点"的现象），大图被压到 max_pixels 以下控制预算。实战中：OCR 密集图把 max_pixels 提到 1.5M–2M，自然图像 0.5M–1M 即可；图像长宽比极端（网页长截图）时 token 数会自然膨胀，务必同时检查 max_pixels 与 max_model_len。Qwen2-VL 论文 Figure 4 正是 min_pixels 消融：小图适当放大显著涨点。

代码 1：Qwen2.5-VL 推理起步（transformers 官方用法，注意 qwen_vl_utils 负责把各类输入统一成消息格式并做像素钳位）：

python
import torch
from transformers import Qwen2_5_VLForConditionalGeneration, AutoProcessor
from qwen_vl_utils import process_vision_info      # pip install qwen-vl-utils

model = Qwen2_5_VLForConditionalGeneration.from_pretrained(
    "Qwen/Qwen2.5-VL-7B-Instruct",
    torch_dtype=torch.bfloat16, attn_implementation="flash_attention_2",
    device_map="auto")
processor = AutoProcessor.from_pretrained(
    "Qwen/Qwen2.5-VL-7B-Instruct",
    min_pixels=256 * 28 * 28,        # 最小视觉 token 预算（256 token）
    max_pixels=1280 * 28 * 28)       # 最大视觉 token 预算（约 1280 token）

messages = [{"role": "user", "content": [
    {"type": "image", "image": "file:///data/demo.png", "resized_height": 896,
     "resized_width": 1344},                        # 也可直接传 URL / base64 / PIL
    {"type": "text", "text": "读出图中表格并转成 Markdown。"}]}]

text = processor.apply_chat_template(messages, tokenize=False, add_generation_prompt=True)
image_inputs, video_inputs = process_vision_info(messages)   # 统一处理路径/视频帧
inputs = processor(text=[text], images=image_inputs, videos=video_inputs,
                   padding=True, return_tensors="pt").to(model.device)

out = model.generate(**inputs, max_new_tokens=512, do_sample=False)
print(processor.batch_decode(out[:, inputs.input_ids.shape[1]:],
                             skip_special_tokens=True)[0])

4.InternVL 1.0 → 3.5：大视觉塔与渐进对齐

如果 Qwen 系的主线是"分辨率与位置"，InternVL 系的主线就是"视觉塔本身要大、要对齐得好"。它的起点是一个赌注：CLIP 式 400M 视觉塔是 MLLM 的瓶颈（第 14 章），自研一个 6B 级、用 web 数据对比训练的大塔（InternViT-6B）才配得上 20B 级 LLM。

InternVL 1.0（arXiv:2312.14238，CVPR 2024）验证了这个赌注。它先用 6B 视觉塔 + 4B 语言中间件（QLLaMA）做三段渐进对齐：阶段 1 视觉语言对比训练（把 InternViT-6B 与语言侧用对比目标对齐，稳定大塔训练的关键是"只解冻塔的高层、锁住低层"）；阶段 2 生成式训练（接上生成目标）；阶段 3 SFT。渐进解冻的意义在第 10 章讨论过：6B 大塔如果直接端到端微调，几十亿参数在指令数据上极易被"洗掉"先验。 InternVL 1.0 证明了同一个 InternViT-6B 可以同时服务对比任务（检索/零样本分类）、生成任务与对话任务（论文 Figure 4 展示了灵活组合的多种用法），其大塔在 OCR、文档等细粒度任务上的优势奠定了后续所有版本的基础。

InternVL 1.5（arXiv:2404.16821，2024.04）把架构定型为业内通用的"ViT-MLP-LLM"三明治：InternViT-6B + 两层 MLP + InternLM2-Chat-20B（共约 26B），但配上了两件让 6B 大塔真正发挥的工程：其一，动态高分辨率——把输入图按预定义长宽比集合匹配最优比例，切成若干 448×448 tile（上限 12）+ 一个全局缩略图，每个 tile 独立过塔；其二，pixel shuffle（比例 0.25）——每个 tile 的 1024 个 patch 压到 256 token（第 15 章详解），最坏情况总 token = 12×256 + 256 ≈ 3.3K，完全可预算。这套"动态 tile + 固定 tile token"组合被后续几乎所有高分辨率 MLLM 借用或对标。

InternVL 2.0 → 2.5（2024.07 / arXiv:2412.05271）把路线产品化：2.0 一次性铺开 1B/2B/8B/26B/40B/76B 全尺寸家族（视觉塔同步缩小到 300M–6B 分档），2.5 在架构不变的前提下系统性补课——数据（图像/视频/文本混合与增强策略按数据类型差异化配置）、训练流程（Stage 1 MLP warmup → Stage 1.5 ViT 增量训练 → Stage 2 全参 SFT 的分级流水线，详见下图）、后训练引入 MPO（Mixed Preference Optimization，混合偏好优化）压制幻觉，以及对齐/量化等系统优化。InternVL2.5-78B（InternViT-6B + Qwen2.5-72B）论文口径 MMMU 70.1、DocVQA 94.1，且全家族以 MIT 许可开源——这使它成为 2024 年底至 2025 年商用落地最多的开源 MLLM 之一。

InternVL 3（2025，官方报告，此处不附 arXiv 号）带来范式转换：原生多模态预训练——不再"先训 LLM 再接视觉"，而是把纯文本、图文对、OCR、视频等数据从头混合联合训练，语言与多模态能力在同一损失下共同生长（与第 19 章 Chameleon 的"原生"理念在理解侧的对应物），并采用可变分辨率的视觉位置编码方案；模型覆盖 1B–78B，InternVL3-78B 在 MMMU 上推进到约 72 的水平。InternVL 3.5（2025.08）则聚焦后训练与部署：Cascade RL（先离线偏好优化、后在线强化学习的级联管线，配合 Visual-RFT 让视觉子任务也有可验证奖励）、推理原生（thinking）模式、以及"解耦部署"（视觉塔与 LLM 分开量化/服务）把旗舰 InternVL3.5-241B-A28B（MoE）的推理成本压到可用区间。至此，InternVL 系完成了"自研大塔 → 全尺寸家族 → 原生预训练 → 级联 RL"的完整闭环。

5.端侧路线：MiniCPM-V 与 Phi-3.5-Vision

云端旗舰卷到 70B+ 时，另一条战线的命题完全不同：手机/边缘设备 8GB 内存里跑出接近 GPT-4V 的体验。端侧的约束改写了所有设计决策：显存是硬上限（模型 + KV + 系统占用 < 6GB）、延迟按"单帧首响"计、功耗按"每秒 token"计——所以端侧模型的核心竞争力是每参数的视觉信息密度。

MiniCPM-V 2.6（arXiv:2408.01800，2024.08）是这个路线的代表作：SigLIP-400M（384px）+ Qwen2-7B，总参数 8B，但工程上做到手机级部署（llama.cpp/MLC 量化后约 5–6GB）。它的分辨率策略来自 LLaVA-UHD（arXiv:2403.11703）一脉：自适应分区 + 高压缩——图像先按 384×384 自适应切块（含一张全局块），每块经轻量压缩模块（perceiver 式）降到约 96 个 token，远低于"每块 576"的朴素方案；任意长宽比与最高 1.8M 像素的输入因此只需数百个视觉 token，这对端侧 KV 显存是决定性的。能力上，2.6 版以多轮 OCR、表格转 Markdown、多图与视频对话见长，官方口径在 OpenCompass 多项综合评测上以 8B 达到或超过 GPT-4V（1106 版）水平；其幻觉抑制链路（RLAIF-V：模型自评 → 细粒度偏好数据 → DPO，论文 Figure 4）也值得对齐方向的读者一读。后续 MiniCPM-o 2.6（2025 初）把流式视觉+语音+TTS 装进同一端侧框架，MiniCPM-V 4.x（2025）继续以 8B 推高 OCR 与长视频能力——端侧线至今活跃。

Phi-3.5-Vision（2024.08，微软，技术报告见 arXiv:2404.14219 的 phi-3-small 章节）代表小模型的另一解法：不做小视觉塔，而是把语言底座的"质量密度"做高。结构是 Phi-3.5-mini（3.8B，用教科书级合成数据训练）+ CLIP-L/14-336 动态分块，总参数约 4.2B；长上下文依赖 phi-3-small 引入的 blocksparse attention（每 query 只看局部块 + 少量纵向全局锚点列），把 128K 上下文的 KV 与计算成本压下来——这个注意力稀疏模式与第 4 章的 MQA/GQA 互补，都是"用结构先验省注意力"。Phi 系的启示与 MiniCPM 不同：端侧之外，小模型的另一半出路是数据质量而非架构（ textbooks 式合成数据），这与第 16 章 LIMA/MiniGPT-4 的结论呼应。微软 2025 年的 Phi-4-multimodal 进一步把语音与视觉用 LoRA 式模块挂在同一语言底座上，实现"一次加载、按需挂载模态"。

代码 3：MiniCPM-V 2.6 推理起步（其 model.chat 接口以多模态消息列表为输入，图文交错）：

python
import torch

from transformers import AutoModel, AutoTokenizer

                                  torch_dtype=torch.bfloat16,
                                  attn_implementation="sdpa")

# 注意：MiniCPM 的 chat 接口直接吃 PIL 与文本混排的 content 列表
res = model.chat(image=None, msgs=msgs, tokenizer=tokenizer,
                 temperature=0.1, max_new_tokens=512)
print(res)

6.差异化探索：DeepSeek-VL、CogVLM/CogAgent、MoE-LLaVA、GLM-4V、Florence-2

除了三条主线，一批模型在特定维度上做了值得记录的探索。它们的共同点是：某一项设计做到了"极端"，因此得失都格外清晰。

DeepSeek-VL（arXiv:2403.05525，2024.03）押注"语义与细粒度双签名"：视觉侧并联两个编码器——SigLIP-L（384px，语义对齐特征）与 SAM-B（1024px，高分辨率细粒度特征），后者特征图下采样后与前者网格交错拼接成统一序列再入 LLM；语言侧是 DeepSeek LLM（1.3B/7B 两档）。训练两阶段：先只训 VL 适配器，再进入关键的"VL + 纯文本联合预训练"（混入文本数据保护语言能力，且数据覆盖网页截图、表格、教材、论文等 13 类"真实世界"场景）。它证明了"双编码器互补"（呼应第 15 章 Prismatic 的双塔结论）可以用低成本实现，2024 年底的后继 DeepSeek-VL2 转向 MoE 与动态 tiling，把"细粒度 + 稀疏激活"合流。

CogVLM（arXiv:2311.10782，2023.11）与第 15 章的"视觉专家"呼应：语言主干（Llama2-13B）完全冻结，但 LLM 每层加一组仅作用于图像 token 的可训练"视觉专家"（独立的 QKV 与 FFN 矩阵），加上可训练的视觉塔与 MLP 适配器，可训练参数集中在视觉通路（约 6.5B）。它的成绩（论文口径 VQAv2 82.2、MME 1449、TextVQA 74.3）证明"冻结语言 + 视觉逐层专家"在 2023 年是上限最高的方案之一；代价是工程复杂与"模型内两套通路"的维护成本。CogAgent（arXiv:2312.08914，2023.11）在 CogVLM 之上加第二个高分辨率通路：448 低分辨率走语义、1120 高分辨率经交叉注意力压缩器压到 225 token 汇入，专攻 GUI 截图理解与设备操作（其高分辨率双编码设计是第 43 章 GUI Agent 的直接前身，UI-TARS 等后续工作都引用它作为对比基线）。

MoE-LLaVA（arXiv:2401.15947，2024.01）把稀疏化引入多模态。其 MoE-Tuning 三阶段配方很有参考价值：阶段 1 只训 MLP（防随机初始化的专家噪声破坏对齐）；阶段 2 解冻除视觉塔外全部参数（先把稠密底座练稳）；阶段 3 把 LLM 的 FFN 复制成多份形成专家 + 路由（sparse upcycling），配合路由退火训练。论文结论：Top-2 路由、8 专家以内的配置最稳，更多专家反而出现路由塌缩；MoE-LLaVA-4B×4（激活约 3.9B）在多项基准上与稠密 7B 模型相当，验证了"多模态场景 MoE 的激活预算可大幅低于同性能稠密模型"。这个配方与 DeepSeek-VL2、Qwen3-VL-235B 等后续 MoE 旗舰的"多模态 MoE 化"一脉相承。

GLM-4V（2024.06，随 GLM-4 家族开源，技术报告 arXiv:2406.12793）：GLM-4-9B 语言底座 + 高分辨率视觉塔 + MLP 适配，特点是把"1120 级高分辨率 + 中英双语对话"装进 9B 开源权重；2025 年的 GLM-4.1V-9B-Thinking 用强化学习训练出带思维链的推理模式（回答前先输出推理过程，可关），GLM-4.5V（2025.08）升级为 106B-A12B 的 MoE 旗舰并开源——GLM 系展示了"中型开源模型 + RL 推理"这条后训练路线的性价比。Florence-2（arXiv:2311.06242，2023.11）则干脆放弃"接 LLM"的范式：0.23B/0.77B 的小模型，视觉编码器 + 编码器-解码器，把字幕、检测、定位、OCR、分割全部统一成"prompt → 序列"输出，靠自建的 FLD-5B 数据引擎（5.4B 标注）训练。它证明了一个重要事实：在"感知类任务"上，小而统一的序列到序列模型可以胜过大 LLM 范式——代价是不具备开放对话与推理。Florence-2 因此常被当作 MLLM 的"感知外挂"与轻量基线（第 21 章 grounding 会再次遇到它）。

🍳 实战配方：从云端到端侧的三档部署起点

云端精度优先：旗舰 72B 级（Qwen2.5-VL-72B / InternVL3-78B）用 vLLM 双卡张量并行起服务，bf16 约需 2×80G；多模态请求务必设置 limit-mm-per-prompt 与 max_pixels 上限，防止超长视觉前缀挤占 KV。性价比档：7B/8B（Qwen2.5-VL-7B / InternVL3-8B / MiniCPM-V 2.6 云端部署）单卡 A10/4090 可跑，AWQ/GPTQ 4bit 后 8GB 级显存可用，配合 prefix cache 服务 QPS 翻倍。端侧档：MiniCPM-V 2.6 走 llama.cpp GGUF（4bit 约 5–6GB 内存）或 MLC-LLM（安卓/iOS），Qwen 系 2B 档适合国产芯片 NPU 路线。通用三步验收：① 官方 processor + 官方 chat template（不换预处理）；② 50 条自有数据盲测对比两个候选模型；③ 压测 max_tokens/max_pixels/并发三参数后再放量。

vllm serve Qwen/Qwen2.5-VL-7B-Instruct \
  --max-model-len 32768 --max-num-seqs 32 \
  --limit-mm-per-prompt image=8,video=1        # 单请求最多 8 图 + 1 视频
python
from openai import OpenAI
import base64

client = OpenAI(base_url="http://localhost:8000/v1", api_key="EMPTY")
img_b64 = base64.b64encode(open("demo.png", "rb").read()).decode()
resp = client.chat.completions.create(
    model="Qwen/Qwen2.5-VL-7B-Instruct",
    messages=[{"role": "user", "content": [
        {"type": "image_url",
         "image_url": {"url": f"data:image/png;base64,{img_b64}"}},
        {"type": "text", "text": "总结这张图的要点，控制在 100 字内。"}]}],
    max_tokens=256, temperature=0.1)
print(resp.choices[0].message.content)

⚠️ 选型与迁移的四个高频坑

（1）许可证陷阱：代码 Apache 不代表权重可商用——LLaVA-1.5 的权重条款随 Vicuna（LLaMA2）、Qwen 72B 级多为定制许可，商用前查权重仓库而非代码仓库。（2）预处理不可换：动态分辨率模型的图像预处理（tile 数、插值、归一化）与训练严格绑定，换 resize 逻辑直接掉 10 个点以上；部署时用官方 processor 而非自己写。（3）聊天模板漂移：同一家族不同版本模板都可能变化（系统提示位置、结束符），微调后的模型用错模板等于白训。（4）benchmark ≠ 体验：MMMU 高的模型不一定聊天体验好——各家的后训练（对话风格、拒答策略）差异巨大，选型前务必用自己的真实数据做 50–100 条的盲测。

9.本章小结与自测

本章沿四条路线走完了开源 MLLM 的四年：LLaVA 系证明了"简单架构 + 数据配方"的复利，并在 OneVision 完成多场景统一；Qwen 系用三代模型把"固定方图→原生动态分辨率→M-RoPE→Agent 化"的主干打通，其 patch merge + 动态分辨率成为行业事实标准；InternVL 系押注自研大塔与渐进对齐，从 1.0 的验证走到 3/3.5 的原生预训练与级联 RL；特种路线上，MiniCPM-V 用高压缩自适应编码打进手机、CogVLM/CogAgent 展示了专家化与高分辨率双通路的极致、MoE-LLaVA 确立了多模态稀疏化配方、Florence-2 证明了小模型统一感知的价值。如果只记住一件事，应该是这条主线：2023 年模型之间的差异在架构（连接器、注意力设计），2025 年之后差异收敛到视觉塔质量、数据课程与后训练策略——架构红利已被吃尽，工程红利仍在滚动。下一章我们把视线转向闭源模型，看看不公开权重的头部玩家把天花板抬到了哪里。

✏️ 自测（先作答，再看答案要点）

1. M-RoPE 如何为文本、图像、视频三类 token 分配旋转位置编码的分量？这一设计解决了什么问题？
答案要点：将 RoPE 分量拆成时间/高/宽三组：文本三组取同一位置号（等价普通 RoPE）；图像的时间组恒定、高宽组按 2D 网格取值；视频三组独立（时间随帧推进）。它让同一 LLM 内不同模态的位置语义与物理结构对齐，改善了视频/多图场景的位置建模与长度外推。

2. InternVL 1.5 的"动态 tile + pixel shuffle"组合为什么成为高分辨率标配？给出它的 token 预算计算。
答案要点：tile 数按输入长宽比从预定义集合动态匹配（上限 12），每 tile 448²经 InternViT 输出 32×32=1024 patch，pixel shuffle r=2（比例 0.25）压到 256 token，加全局缩略图 256：最坏 12×256+256≈3.3K token，可精确预算；pixel shuffle 确定性保局部结构，不引入学习成本。

3. CogVLM 的视觉专家与 Qwen-VL 的交叉注意力解析器都属于"旁路"设计，二者在信息流与工程兼容性上有何差异？
答案要点：视觉专家让图像 token 走 LLM 序列但用独立的逐层 QKV/FFN 处理（参数进层、信息在序列内，与主流推理引擎兼容）；交叉注意力解析器以 256 个 query 把视觉信息在 LLM 层间注入（不占序列位置但每层付交叉注意力成本，且与序列式推理生态/prefix cache 不友好）。两者都保护语言能力，但 2024 年后生态选择偏向序列式。

4. MoE-LLaVA 的三阶段训练为什么必须"先稠密后稀疏"？直接随机初始化专家训练会怎样？
答案要点：阶段 I 只训 MLP 是对齐预热（新模块噪声不破坏对齐）；阶段 II 先把稠密底座练稳；阶段 III 才做 FFN 复制 + 路由。若随机初始化专家直接端到端训练，路由面对"尚未分化的专家"随机分配，梯度噪声大，易出现路由塌缩（流量集中到个别专家）与整体性能低于稠密基线。

5. 你要为一个中文票据 OCR + 结构化提取的应用选型（日均 50 万张，需本地部署、可商用）。给出候选、关键校验点与理由。
答案要点：候选：Qwen2.5-VL-7B（Apache-2.0、文档解析原生、动态分辨率适配票据长宽比）、InternVL3-8B（MIT 许可最干净）；备选专用：GOT-OCR2.0。校验点：①权重许可条款逐条核对；②自己票据样本盲测（版面多样性、手写、印章遮挡）；③ max_pixels 与吞吐/显存核算（50 万/日的 batch 吞吐与并发）；④结构化输出的解析稳定性（JSON/HTML 模式约束）；⑤必要时专用 OCR 模型 + VLM 混合管线（第 22 章）成本更低。
