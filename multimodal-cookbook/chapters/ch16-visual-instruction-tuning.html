💡 本章导读

第 15 章结束时我们有了一座"桥"，但桥上还没有车——对齐预训练之后的模型只会"看图说话"，不会听指令：你问"图里有什么危险"，它可能答"一个成熟的牛油果"。把 55 万对齐数据训练出的模型变成能多轮对话、能按格式作答的助手，靠的就是视觉指令微调（Visual Instruction Tuning）：用"图像 + 指令 + 回答"三元组做监督微调（Supervised Fine-Tuning, SFT）。本章的叙事主线是一个反直觉的事实：2023–2026 年 MLLM 的绝大多数能力跃迁来自数据而非架构——LLaVA 用 GPT-4 凭空造出 15.8 万指令数据，LLaVA-1.5 用 66.5 万"小"数据横扫 11 个基准，ShareGPT4V/ALLaVA 证明合成字幕的质量决定模型上限，Cambrian-7M 展示了数据重配平的威力。我们将逐一拆解这些数据是怎么造出来的、训练时 loss 到底算在哪些 token 上（很多教材略过的 loss masking 细节）、并给出一份可以直接跑的 LLaVA 风格 SFT 完整脚本。读完本章，你应当能够：为自己的领域设计指令数据构造管道、看懂任何开源 MLLM 的训练配方、并避开合成数据的五个经典陷阱。

🕰 历史脉络：指令微调如何从 NLP 迁移到视觉

2021：FLAN（arXiv:2109.01652）首次系统地把 NLP 任务改写成指令格式做多任务微调；2022：InstructGPT（arXiv:2203.02155）确立 SFT→RM→PPO 三段式，Self-Instruct（arXiv:2212.10560）证明"模型造数据训自己"可行；2023 年初：LLaMA + Self-Instruct 混合数据的 Alpaca、极小人工数据 LIMA（arXiv:2305.11206）相继出现，指令微调的成本跌到几百美元；2023 年 4 月：LLaVA 把这条流水线搬进多模态——用 GPT-4（纯文本）+ 图像的字幕/框标注合成视觉指令数据，从此"视觉指令微调"成为独立研究方向；2023 下半年起：InstructBLIP（指令感知）、ShareGPT4V（GPT-4V 级字幕）、Cambrian-1（数据配平科学）把重心从"怎么训"彻底转向"训什么"。

1.从对齐到跟随：视觉指令微调的问题设定

第 35 章会系统讲多模态预训练的三阶段配方，这里先明确本章所处的位置。阶段 1（对齐预训练）用几十万"图像→字幕"的弱监督对，把连接器从随机初始化训到"视觉 token 能被 LLM 正常续写"；但这个模型只有一种能力——给图配文。指令微调（阶段 2）要补上的是条件性、多样性、格式性：（1）条件性——同一个图像，不同问题给不同回答（"这是什么"vs"详细描述"vs"图里的文字说了什么"）；（2）多样性——覆盖对话、细节描述、复杂推理、OCR、定位等任务形态；（3）格式性——按指令要求的格式回答（单选字母、单词短语、JSON、坐标框），这是选择题类基准能自动评测的前提。

形式化：SFT 数据是三元组集合 $\{(\mathbf{v}_i, \mathbf{q}_i, \mathbf{a}_i)\}$，其中 $\mathbf{v}$ 是图像（或多图/视频）、$\mathbf{q}$ 是包含系统提示与用户指令的 prompt、$\mathbf{a}$ 是目标回答。训练目标是在只对回答 token 计算的交叉熵（细节在第 7 节）：

$$\mathcal{L}_{\text{SFT}} = -\sum_{t \in \mathcal{A}} \log p_\theta(y_t \mid y_{

其中 $\mathcal{A}$ 是回答 span 的 token 下标集合。与阶段 1 的关键差异有三：数据从"字幕对"变成"指令对话"；可训练参数从"仅连接器"扩大到"连接器 + LLM（可选视觉塔）"；训练时长从 1 epoch 到 1–3 epoch。这些看似只是常规微调，但每个选择都被数据质量放大——这就是为什么本章用三分之二的篇幅讲数据。

最后一个设定问题：指令数据从哪来？三条来路的成本与质量天差地别。（a）学术数据集改造：VQAv2/GQA/OCR-VQA 等现成 VQA 数据加模板 prompt，免费但形态单一、回答偏短；（b）强模型合成：让 GPT-4/GPT-4V 看着（或"听着描述"）图像生成对话与推理，质量上限最高，是 LLaVA 系的正统；（c）人工标注：质量可控但每条数美元，2023 年后基本只用于偏好数据与评测。2023–2026 年的实践是三者按比例混合——比例怎么定，正是各家配方的核心差异。

2.LLaVA：用 GPT-4 造指令数据的全流程

LLaVA（arXiv:2304.08485，2023 年 4 月）是视觉指令微调的开山之作，它最大的贡献不是模型（那只是 CLIP+线性层+Vicuna），而是一条 158K 数据的自动化生产管道。背景约束很关键：当时的 GPT-4 只有纯文本 API，看不了图。LLaVA 的巧思是"用文本替身喂 GPT-4"——图像不能直接给，就把它压缩成两种文字化代理表示：（1）字幕（COCO Captioner 生成的一句话描述）；（2）框序列（检测器输出的物体类别+边界框坐标列表）。把这两种表示连同精心设计的 few-shot 示例与任务模板一起发给 GPT-4，让它"想象"自己在看图，然后生成指令数据。

三类指令数据的分工值得细品，它们对应了对话系统的三种"人格"：① 对话（58K）——模板要求 GPT-4 提出三个"人在看图时自然会问"的问题并回答，训练出多轮、口语化的基本对话能力；② 细节描述（23K）——给出"用一段话详细描述这张图"的 prompt，让 GPT-4 基于框序列尽量还原画面细节，专治模型"懒得说细节"的通病；③ 复杂推理（77K）——要求提出需要逐步逻辑推理的问题（因果、比较、假设），给出详细思维链式回答，这是比例最大的一桶，因为它最难从其他来源获得。三条模板设计原则（论文原话意译）：让 GPT-4 只描述画面内容而非发散联想（防幻觉）；问题以第一视角的观察者口吻提出（避免"图里有什么"式的模板腔）；三类数据分桶构造再混合（保证覆盖）。

代码 1：复刻 LLaVA 式合成数据的调用脚本（今天可以直接换成 GPT-4V/开源 VLM 看图生成，代理表示步骤可跳过）：

python
import json, random
from openai import OpenAI   # pip install openai；也可替换为本地 vLLM 服务

client = OpenAI()

CONV_TEMPLATE = """你是基于图像的 AI 助手。下面是一张图像的描述：
Caption: {caption}
Objects: {boxes}
请模拟一位仔细观察这张图的用户，提出 3 个自然的对话问题并回答。
要求：问题之间有追问关系；回答只基于画面内容，不要脑补画面外的事实。"""

def synthesize(caption: str, boxes: str) -> dict:
    resp = client.chat.completions.create(
        model="gpt-4o-mini",                    # 2023 年原版用 GPT-4 + 文本代理；现在可直接看图
        messages=[{"role": "user", "content": CONV_TEMPLATE.format(caption=caption, boxes=boxes)}],
        temperature=0.7,
    )
    return {"conversations": parse_llava_style(resp.choices[0].message.content)}

def parse_llava_style(text: str) -> list:
    """把生成文本解析成 [human, gpt, human, gpt, ...] 交替结构"""
    turns = []
    for line in text.strip().splitlines():
        line = line.strip()
        if line.startswith(("Q", "问")):
            turns.append({"from": "human", "value": line.split(":", 1)[1].strip()})
        elif line.startswith(("A", "答")):
            turns.append({"from": "gpt", "value": line.split(":", 1)[1].strip()})
    return turns

with open("captions_boxes.jsonl") as f, open("llava_style_sft.jsonl", "w") as out:
    for row in f:                              # 每行 {"image":..., "caption":..., "boxes":...}
        item = json.loads(row)
        item["conversations"] = synthesize(item["caption"], item["boxes"])
        out.write(json.dumps(item, ensure_ascii=False) + "\n")
# 建议加：去重（按问题哈希）、长度过滤、抽检人工评审（抽 1% 看幻觉率）

训练配方（v1）：阶段 1 在 558K 图文对（LAION/CC 子集过滤得到，即 LCS-558K）上只训线性连接器，学习率 2e-5、batch 128、1 epoch；阶段 2 在 158K 指令数据上解冻连接器与 Vicuna（视觉塔仍冻结），学习率 2e-5、batch 32、3 epoch。prompt 模板是 "### Human: ... ### Assistant: ..." 的两段式（V1 模板，之后被各家 chat template 取代）。LLaVA 证明了这条管道可行，但 v1 模型在学术基准上与最强模型仍有明显差距——弥补这个差距的，正是下一段的主角。

3.LLaVA-1.5：学术任务数据混合的魔力

LLaVA-1.5（arXiv:2310.03744，2023 年 10 月）的标题非常诚实："Improved Baselines with Visual Instruction Tuning"——只改了基线。架构上只有三处小改动（336px、两层 MLP、MLP 前加 grid pooling 细节），真正的重头戏是SFT 数据配方：在 158K 指令数据之外，混入约 50 万条学术任务 VQA 数据——把 VQAv2、GQA、OK-VQA、OCR-VQA、TextVQA、ScienceQA、VizWiz、RefCOCO（框坐标转文本）等现成数据集统一改写成对话格式，合计约 665K（加上预训练的 558K 共约 1.2M）。结果是一份令整个领域重新审视数据的成绩单：

这些数字同时超过 InstructBLIP-Vicuna-13B、Qwen-VL-Chat 等当时的强模型，而 1.5 的 SFT 数据量比 InstructBLIP 的 1.2M 还略小。"魔力"到底在哪？论文给出的归因可以提炼成三条数据法则：（1）覆盖即能力——学术数据把 OCR、计数、定位、图表等"硬感知技能"直接灌进 SFT，模型不再只学"说漂亮话"；（2）格式即分数——每条学术数据附带"响应格式提示"（response format prompt），如选择题附加 "Answer with the option's letter from the given choices directly."、开放题附加 "Answer the question using a single word or phrase."。这个看似琐碎的动作同时解决了两个问题：让回答短而准（选择题基准不再被长篇大论拖累）、让评测脚本可解析（答案抽取不再错杀）。后续大量复现证明：同样的模型去掉格式提示，基准分数可以掉好几个点；（3）平衡即鲁棒——对话数据与学术数据约 1:4 的比例既保住聊天能力又不让格式过拟合，配比本身就是超参数。

🍳 实战配方：把 665K 配方迁移到你的领域

第一步，盘点任务形态：领域内的"硬感知技能"是什么（医疗影像的病灶定位、工业图的缺陷计数、文档的表格读数）？每类找一个最接近的公开学术数据集做"格式母版"。第二步，三层配比：通用对话数据（LLaVA-Instruct-158K 直接复用，占 25%–40%，保住基本盘）+ 领域 VQA/定位数据（学术改造或检测器自动标注，占 30%–50%）+ 领域详细描述（用强 VLM 重写字幕，占 20%–30%，参考 ShareGPT4V）。第三步，格式提示照抄：为评测形态逐条写响应格式提示，训练与评测模板逐字符一致。第四步，卫生检查：图像与目标基准去重、按问题哈希去重、抽 1% 人工评审幻觉率。超参起点：7B 模型、lr 2e-5、batch 128、1 epoch 起步；数据少于 20 万条时 2 epoch + 更强正则，并冻结视觉塔。全程预算：7B 单图 SFT 在 8×A100 上约一天，先用 1/10 数据试跑再放量。

后续演进一并提供坐标：LLaVA-NeXT（2024 年 1 月博客，无 arXiv）引入 AnyRes 动态分块把分辨率扩到 672×672、1344 级别，并加入更好的 OCR/推理数据；LLaVA-OneVision（arXiv:2408.03326，2024 年 8 月）把单图（3.2M 数据）、多图与视频（OneVision 1.6M 数据）统一进一个模型，训练分三段：对齐预训练 → 单图中级阶段 → 多图/视频最终阶段，并系统研究了"跨场景迁移"（单图能力会被视频训练冲掉，反过来则增强——先单图后视频的数据课程因此成为定式）。

📄 论文精读：LLaVA-1.5（CVPR 2024，arXiv:2310.03744）

值得精读的三个实验设计：（1）数据混合消融——论文逐项加入学术数据集观察分数变化，结论"VQAv2 数据贡献了通用 VQA 大盘、OCR 类数据带动 TextVQA、RefCOCO 数据带来定位能力且不伤其他任务"，这是"grounding 数据提升整体感知"最早的公开证据之一（第 21 章会再遇到）；（2）响应格式提示对照——同一模型有/无格式提示的分数差被明确报告，促使"格式提示"成为所有后续 SFT 数据的标配字段；（3）与 InstructBLIP 的正面对比——两者都基于 Vicuna 与 CLIP 家族特征，唯一系统性差异是数据构造哲学（学术混合 vs 指令感知重采样），LLaVA-1.5 全面胜出，等于宣判了"纯合成指令数据"的单一食谱不够。复现提醒：LLaVA-1.5 使用了 NEFTune（对词嵌入加均匀噪声的微调技巧，$\alpha=5$），对 MME/MMBench 有约 +1~3 的贡献；复现对不齐时先检查它和 ScienceQA 的 in-house 划分。

4.InstructBLIP：指令感知的 Q-Former

当 LLaVA 在为 Q-Former 钉棺材板时，InstructBLIP（arXiv:2305.06500，Salesforce，2023 年 5 月）为它做了最后一次体面的辩护——并且贡献了一个独立于连接器成败、至今仍被引用的思想：指令感知的视觉特征提取。它的观察是：同一张图，"这张图里有什么幽默之处"和"描述图中的文字"需要关注完全不同的区域，而 LLaVA 式直通连接器把全部 576 个 token 原封不动喂给 LLM，指令相关信息的选择完全留给 LLM 自己。InstructBLIP 的做法是把指令前置到视觉侧：指令文本作为文本输入喂给 Q-Former 的文本分支，32 个 query 在交叉注意力提取视觉特征时"知道"下游任务是什么，从而输出与指令相关的视觉特征。

数据侧，InstructBLIP 把 26 个公开数据集统一改写成指令跟随格式：其中 13 个 held-in 数据集（合计约 1.2M 样本，每个数据集做平衡采样、大集欠采样）用于指令微调，13 个 held-out 用于零样本评测。改写的关键是给每个数据集配了多样化的人工模板（每条数据随机选一个），例如同一道 ScienceQA 题可以有"直接给答案"与"逐步解释"两种指令——这训练出"按指令调整回答风格"的元能力，zero-shot 迁移到没见过的任务格式上。结果：在 held-out 数据集与纯自然图像（NoICE 等）上的零样本能力全面超过 BLIP-2 与当时的 LLaVA。经验与教训：指令感知的思想是对的（后来的任务条件化视觉编码、query 重排都受其影响），但把"指令理解"塞进 188M 的 Q-Former 里委实大材小用——LLaVA-1.5 证明 7B 的 LLM 用更直白的数据就能学会同样的事，而且学得更好。InstructBLIP 留给我们的实用遗产是它的数据改写协议：多模板、平衡采样、held-out 严格隔离，至今仍是构造指令数据集的标准卫生规范。

python
import torch
from PIL import Image
from transformers import InstructBlipProcessor, InstructBlipForConditionalGeneration

# HF 原生支持：指令感知 Q-Former + Vicuna，加载即推理
model = InstructBlipForConditionalGeneration.from_pretrained(
    "Salesforce/instructblip-vicuna-7b", torch_dtype=torch.float16, device_map="auto")
processor = InstructBlipProcessor.from_pretrained("Salesforce/instructblip-vicuna-7b")

image = Image.open("demo.jpg").convert("RGB")
for prompt in ["What is unusual about this image?",
               "Describe the image in detail."]:
    inputs = processor(images=image, text=prompt, return_tensors="pt"
                       ).to(model.device, torch.float16)
    out = model.generate(**inputs, do_sample=False, max_new_tokens=64,
                         min_new_tokens=1, num_beams=5)
    print(prompt, "->", processor.batch_decode(out, skip_special_tokens=True)[0])
# 同一张图、不同指令会得到不同回答——指令同时进入了 Q-Former 与 LLM 两侧

5.MiniGPT-4 与 mPLUG-Owl：两条互补路线

MiniGPT-4（arXiv:2304.10592，2023 年 4 月）与 LLaVA 几乎同期，架构上它选了"最省"组合：直接复用冻结的 BLIP-2（含训好的 Q-Former）+ 一层线性投影 + Vicuna，可训练参数只有一个投影层。它对数据工程的启示比架构更大：作者先用 5M 级图文对（CC/SBU/LAION 混合）把线性层对齐，得到的模型能描述图像但输出不可控（碎句、幻觉、格式混乱）；随后用 ChatGPT 从约 5 万个候选字幕中人工规则 + LLM 筛选出约 3.5K 条高质量图文对（Conceptual Alignment 数据集 CA-3.5K，后续扩到 5K），仅用这几千条做第二轮微调，对话质量发生质变——能写广告文案、看梗图讲笑点、读手写菜谱。结论被后续所有工作反复验证：SFT 数据"几千条高质量"可以胜过"几百万条低质量"。这个"LLM 筛数据"的手法也预演了 2024 年的合成数据革命（第 6 节）。

mPLUG-Owl（arXiv:2304.14178，阿里，2023 年 4 月）则代表了"模块化 + 语言对齐"路线。架构是视觉编码器 + 视觉抽象器（visual abstractor，交叉注意力式连接器）+ LLM；训练分两阶段，但它的独特设计在阶段 2：视觉指令微调的同时混入语言对齐数据（LA，约 7 万条纯文本指令），防止多模态训练冲垮 LLM 原本的对话与知识能力——"多模态训练伤语言"是当时普遍观察到的现象，mPLUG-Owl 用数据配比而非冻结来解。其阶段 1 数据 MIMIC-IT（约 2.8M 图像、3.8M 问答对）由 GPT-4 + 字幕代理合成并人工校验，规模是 LLaVA-158K 的二十多倍，覆盖单图/多图/视频对话。2023 年底的 mPLUG-Owl2 进一步用模态自适应模块（MAM）——共享注意力但按模态分离 K/V 投影——让文本与视觉各自保有自己的表示子空间，缓解模态干扰（它与第 13 章"双流注意力"思想一脉相承）。mPLUG-Owl 系的价值在于把"防遗忘"第一次做成显式的数据与架构机制，这条线后来演化为各家"多模态 SFT 必混纯文本数据"的默认配方。

6.合成数据革命：ShareGPT4V、ALLaVA 与 Cambrian-7M

2023 年的指令数据有一个系统性盲区：字幕太短。LLaVA 系的图文对齐数据沿用 CC3M 式一句话字幕，GPT-4 代理合成的描述受框序列保真度限制——模型见过 55 万张图，但每张图只有"一句话的信息量"。2023 年底 GPT-4V 面世后，"让强 VLM 直接看图写字幕"成为可能，掀起两波浪潮。

第一波：重写字幕（recaption）。ShareGPT4V（arXiv:2311.12793）用 GPT-4V 为 100K 张图生成高信息密度字幕（涵盖物体属性、空间关系、场景氛围、常识知识——典型 5–10 倍于 CC 字幕的 token 量），然后训练一个 ShareGPT4V-Captioner 把高质量字幕扩展到 1.2M，合成约 1.3M 字幕的数据集。用"普通字幕 + GPT4V 字幕"混合重训 LLaVA-1.5，全基准一致提升——证明了模态对齐的上限被字幕的信息密度锁死。这个思想与 DALL-E 3 的重标注革命（arXiv:2310.16825）同源：文生图与多模态理解两条线在 2023 年不约而同地发现"换个字幕器等于换了个模型"（第 34 章从数据工程角度再展开）。ALLaVA（arXiv:2402.11684）把 GPT-4V 合成做到一步到位：直接让 GPT-4V 为图像生成详细字幕与复杂对话（含"无法回答"类样本，专治幻觉），组成 ALLaVA-4V 数据；用它在 3B 规模（ALLaVA-3B）训练的模型在多项基准上与 LLaVA-1.5-13B 打平——"数据质量换模型规模"的代表性证据。

第二波：数据科学化。Cambrian-1（arXiv:2406.16860，NYU，2024）把 SFT 数据当作独立研究对象：从 12 个公开指令数据集汇成 Cambrian-10M，然后按"知识/转录（OCR）/感知/推理/规划/对话"等任务类型重新配平得到 Cambrian-7M（砍掉过采样的对话类、补充感知与知识类）。两个发现值得写进工程手册：其一，配平比规模重要——10M 原始混合不如 7M 配平版；其二，"答题机器现象"（Answer Machine Phenomenon）——全部用"问题→短答案"格式训练会让模型丧失对话能力，用户问"你好"它反问"请提供选项 A/B/C/D"；解法极简单：在指令数据的系统提示里声明"你是一个乐于详细讨论的助手"，并在部分样本中保持长回答（见其论文 Figure 12 的消融）。

⚠️ 合成数据的五个经典陷阱

（1）教师幻觉遗传：GPT-4V 看错的细节会被学生模型加倍自信地复述——用字幕器自产自训（如 ShareGPT4V-Captioner 扩展）时尤其要控制扩展比例，并在 prompt 中强制"只描述可见内容"。（2）格式坍缩：全部数据同一种模板 → 模型只会一种句式（Cambrian 的 Answer Machine 现象是极端形态）；多模板 + 混入多轮对话是基本卫生。（3）短答案偏置：学术 VQA 全是单词答案，过度混合会让模型不会写长文——LLaVA-1.5 的对话桶与响应格式提示就是为此设计的。（4）污染：合成数据的源图与评测基准重叠（COCO 图与 VQAv2 同源）会造成虚高——发布数据集时报告与各基准的图像级重叠是 2024 年后的行规。（5）字幕长度误导：长字幕≠好字幕，GPT-4V 有时用" likely/might be"等模糊词凑长度，训练后模型学会输出不确定性废话——清洗规则里要检查具体性（命名实体、数字、空间词密度）。

代码 2：指令数据入库前的质量诊断脚本——把上面五个陷阱变成可执行的检查项，任何新数据集进训练池前都跑一遍：

python
import json, re, hashlib
from collections import Counter

rows = [json.loads(l) for l in open("sft.jsonl", encoding="utf-8")]

# ① 长度分布：回答过短（<5 词）多为格式坍缩，过长（>512 词）多为注水
ans_len = [len(t["value"].split()) for r in rows for t in r["conversations"]
           if t["from"] == "gpt"]
qs = [round(sum(1 for a in ans_len if a <= p) / len(ans_len), 3)
      for p in (5, 20, 64, 128, 512)]
print("回答长度分位数 [5,20,64,128,512]:", qs)      # 期望：中位数在 20–64 词

# ② 模板多样性：问题首词 Top-3 占比过高说明模板坍缩
first_words = Counter(t["value"].split()[0] for r in rows
                      for t in r["conversations"] if t["from"] == "human")
top3 = sum(c for _, c in first_words.most_common(3)) / sum(first_words.values())
print(f"问题首词 Top-3 占比: {top3:.2f}")             # 期望 < 0.5，过高需加模板

# ③ 精确去重：问题文本哈希 + 图像路径联合去重
seen, keep = set(), []
for r in rows:
    key = hashlib.md5((r["image"] + "|" + r["conversations"][0]["value"]).encode()).hexdigest()
    if key not in seen:
        seen.add(key); keep.append(r)
print(f"去重：{len(rows)} -> {len(keep)}")

# ④ 具体性检查：字幕里数字/命名实体类词密度（专治"长而空"的合成字幕）
def specificity(text):
    tokens = re.findall(r"[A-Za-z\u4e00-\u9fff0-9]+", text)
    info = [w for w in tokens if re.search(r"\d", w) or len(w) > 6]
    return len(info) / max(len(tokens), 1)
spec = [specificity(t["value"]) for r in keep
        for t in r["conversations"] if t["from"] == "gpt"]
print(f"平均具体性: {sum(spec)/len(spec):.3f}")       # 期望 > 0.15，过低过滤重生成

# ⑤ 污染自查：与评测基准共享同一图像 ID 的比例（评测前必须知道）
#    benchmark_ids 为你所用基准的图像清单，此处示意
overlap = sum(1 for r in keep if r.get("source") in ("VQAv2", "TextVQA", "GQA"))
print(f"学术源样本占比: {overlap/len(keep):.2%}")     # 记入数据卡，评测时分层报告

json.dump(keep, open("sft_clean.jsonl", "w"), ensure_ascii=False)

7.SFT 工程细节：loss masking 与训练配方

视觉指令微调的实现细节里，最容易出错也最少被讲清的是 loss masking（损失掩码）。一条多轮多模态样本的 token 序列长这样（以 LLaVA-1.5 的 576 token 单图为例）：

📐 理论推导：掩码交叉熵与 -100 约定的等价性

语言建模的损失是对整个序列求和的交叉熵，但 SFT 只想监督回答 span $\mathcal{A}$。引入指示函数 $m_t = \mathbb{1}[t \in \mathcal{A}]$，目标写作：

$$\mathcal{L} = -\frac{1}{|\mathcal{A}|}\sum_{t} m_t \cdot \log p_\theta(y_t \mid y_{

HF 实现里没有显式的 $m_t$，而是用 labels 张量携带掩码信息：不参与 loss 的位置填 $-100$，参与的位置填"下一个真实 token"的词表 id。原因在 nn.functional.cross_entropy(ignore_index=-100)：设填充位置的目标类为 $-100$，则

$$\mathcal{L} = -\sum_{t=1}^{T-1} \mathbb{1}[y_t \neq -100] \cdot \log p_\theta(y_t \mid y_{

与掩码目标逐项相同。两个对齐细节：（1）因果语言模型的 labels 需要右移一位——模型在位置 $t$ 的输出分布预测的是位置 $t+1$ 的 token，因此回答 span 的掩码在 labels 中要落在"回答的第一个 token 前一位到回答最后一个 token"的区间（实现上通常先给整段 prompt 区间置 -100，再让回答区间保持原 token id）；（2）视觉 token 的处理——LLaVA 类实现把 <image> 占位符在词嵌入层"原位展开"成 576 个连续视觉特征，输入序列变长 576，labels 必须同步插入 576 个 -100，否则会产生 576 个"预测占位符"的垃圾监督项。有个流行的反面实验：不做 masking 直接全序列训练，模型会学出"自动续写新问题"的行为（因为它学了问题的分布 $p(\mathbf{q})$），且视觉位置上模型被迫拟合一个 576 次重复的伪分布——两者都在消耗模型容量。$\blacksquare$

训练配方清单（LLaVA-1.5 公开配方为基准）：优化器 AdamW（$\beta_2=0.999$，权重衰减 0），学习率 2e-5 + 余弦退火，warmup 约 3%，全局 batch 128（7B 单机多卡梯度累积），bf16，梯度裁剪 1.0，SFT 1 epoch；阶段 1 仅训连接器时学习率 1e-3（全新参数）。视觉塔默认冻结——除非目标是提升 OCR/细粒度（Qwen-VL、InternVL 后期都解冻视觉塔并用更小学习率如 2e-6 级）。显存技巧：视觉 token 占序列 70%+ 时激活显存可观，gradient checkpointing 与 Flash Attention-2（第 4 章）是标配；576 token 的视觉前缀在多轮对话中重复出现，服务端可用 prefix caching 复用其 KV（第 39 章）。

8.SFT 完整脚本实战

下面给出一个结构完整的 LLaVA 风格 SFT 脚本（HF transformers 生态，可直接适配到自家数据）。核心三件事：占位符展开、labels 掩码、冻结策略。

python
import torch, json
from torch.utils.data import Dataset
from transformers import (LlavaForConditionalGeneration, AutoProcessor,
                          Trainer, TrainingArguments)

MODEL_ID = "llava-hf/llava-1.5-7b-hf"
processor = AutoProcessor.from_pretrained(MODEL_ID)
IGNORE = -100

class InstructDataset(Dataset):
    """每行：{"image": path, "conversations": [{"from": "human"|"gpt", "value": str}, ...]}"""
    def __init__(self, path):
        self.rows = [json.loads(l) for l in open(path, encoding="utf-8")]
    def __len__(self): return len(self.rows)
    def __getitem__(self, i):
        row, conv = self.rows[i], self.rows[i]["conversations"]
        text = "USER: " + conv[0]["value"].replace("<image>\n", "") \
               + " ASSISTANT: " + "".join(t["value"] for t in conv[1:])
        # 真实多轮请按轮次拼接并分段掩码；此处以单轮为例
        enc = processor(images=row["image"], text=text, return_tensors="pt")
        return enc

def build_labels(input_ids, n_img_tokens=576, answer_start_char=None):
    labels = input_ids.clone()
    # 1) 视觉占位符区间（<image> 展开后 576 个位置）全部 mask
    img_pos = (input_ids == processor.tokenizer.convert_tokens_to_ids("<image>"))
    # llava-hf 在 forward 内展开占位符，labels 需与展开后序列对齐——
    # 简化起见这里按"prompt 段全 mask、回答段保留"的原则处理：
    labels[:] = IGNORE                       # 先全 mask
    # 2) 回答段恢复（示意：最后一个 ASSISTANT: 之后的 token 参与 loss）
    aid = processor.tokenizer.encode("ASSISTANT:", add_special_tokens=False)[-1]
    # 生产实现请用字符级 offset_mapping 定位回答起点，这里用简化标记位
    return labels

def collate(batch):
    item = batch[0]
    pixel_values = item["pixel_values"]
    input_ids = item["input_ids"].squeeze(0)
    labels = build_labels(input_ids)
    return {"pixel_values": pixel_values, "input_ids": input_ids.unsqueeze(0),
            "labels": labels.unsqueeze(0)}

model = LlavaForConditionalGeneration.from_pretrained(
    MODEL_ID, torch_dtype=torch.bfloat16, attn_implementation="flash_attention_2")
model.config.use_cache = False
for p in model.vision_tower.parameters():          # 冻结视觉塔（LLaVA-1.5 默认）
    p.requires_grad_(False)

args = TrainingArguments(
    output_dir="llava-sft-out", per_device_train_batch_size=4,
    gradient_accumulation_steps=32,                # 全局 batch 128
    learning_rate=2e-5, lr_scheduler_type="cosine", warmup_ratio=0.03,
    num_train_epochs=1, bf16=True, gradient_checkpointing=True,
    logging_steps=10, save_strategy="epoch", remove_unused_columns=False)

trainer = Trainer(model=model, args=args, train_dataset=InstructDataset("sft.jsonl"),
                  data_collator=collate)
trainer.train()
trainer.save_model("llava-sft-final")
# 生产级替代：LLaMA-Factory / ms-swift 已内置多轮掩码、packing、DeepSpeed 与多卡分条，
# 用它们跑 LLaVA/Qwen-VL 的 SFT 是 2024–2026 的默认实践；本脚本用于理解内部机制。

💡 技巧：SFT 排查三板斧

（1）先训 200 步看 loss：健康曲线从约 2–3 降到 1.3–1.6 区间；若不降，八成是 labels 掩码错位（全 -100 会让 loss 恒为 0，忘了 mask 会高得离谱）。（2）抽 20 条做贪心解码：训练初期模型就该复读式跟随格式；若回答与图像无关，检查视觉特征是否真的进了序列（打印 inputs_embeds 长度 = 文本 token 数 + 576）。（3）分数突然崩查模板：训练与评测的 chat 模板（</s>、角色标记）必须逐字符一致——2024 年大量"复现失败"最终都是模板差异。

✏️ 自测（先作答，再看答案要点）

1. 为什么视觉 token 必须从 loss 中 mask 掉？如果忘了 mask，会出现哪两类具体问题？
答案要点：视觉 token 是输入而非生成目标，没有真实的"下一个 token"标签。忘 mask 的后果：①模型被迫在 576 个连续位置拟合一个重复伪分布，浪费容量且污染输出分布（可能输出乱码或重复占位）；②交叉熵被大量无意义项主导，回答 span 的有效梯度被稀释，训练不收敛或格式崩坏。

2. LLaVA-1.5 的数据"魔力"由哪三条法则构成？各举一个具体做法。
答案要点：覆盖即能力——混入 VQAv2/GQA/OCR-VQA/TextVQA/RefCOCO 等学术数据；格式即分数——每条数据附响应格式提示（"用一个词回答"/"直接给选项字母"），答案短且可解析；平衡即鲁棒——对话数据与学术数据按比例混合（约 1:4），防格式过拟合、保聊天能力。

3. InstructBLIP 的"指令感知 Q-Former"机制是什么？为什么说它思想超前但载体选错了？
答案要点：指令文本进入 Q-Former 文本分支，32 个 query 在交叉注意力时以指令为条件提取视觉特征，同一图像随指令产出不同视觉表示。思想超前（任务条件化感知），但把指令理解放在 188M 的 Q-Former 里，而同样的条件化由 7B LLM + 更好数据即可学到且更好；其多模板改写协议反而是最持久的遗产。

4. 推导：为什么 HF 用 labels=-100 就能实现掩码交叉熵？多轮对话时掩码区间如何界定？
答案要点：cross_entropy(ignore_index=-100) 自动跳过目标为 -100 的位置，等价于乘指示函数 $m_t$。多轮对话时：所有用户 turn 与系统提示置 -100，每个 assistant turn 的 token（含结束符）保留；注意 labels 相对 logits 右移一位，掩码要对齐到"被预测的 token"而非"预测它的位置"。

5. ShareGPT4V、ALLaVA、Cambrian-7M 各自解决了合成数据的哪个痛点？
答案要点：ShareGPT4V——字幕信息密度不足（用 GPT-4V 重写 + 自训 captioner 扩展）；ALLaVA——合成数据的多样性与诚实性（直接看图合成、含拒答样本，小模型逼近大模型）；Cambrian-7M——任务类型配比失衡（10M→7M 重配平）与格式坍缩（系统提示缓解 Answer Machine 现象）。
