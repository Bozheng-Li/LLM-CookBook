1.预训练：数据、目标与 Scaling Laws

1.1 目标函数与数据管道

现代开源 LLM 的预训练目标极其朴素：因果语言建模（CLM），即对序列 $\mathbf{w}=(w_1,\dots,w_T)$ 最小化负对数似然

$$\mathcal{L}_{\mathrm{CLM}}(\theta) = -\sum_{t=1}^{T} \log P_\theta(w_t \mid w_{

真正的功力全在数据管道。以 LLaMA（arXiv:2302.13971）与 Qwen 的公开配方为例，一条万亿 token 的数据管道通常包含：①多源采集（CommonCrawl 快照、代码 GitHub、书籍、百科、论文、对话）；②语言识别与启发式过滤（CCNet 规则：标点占比、停用词、困惑度过滤——用一个小模型给"高质量"语料打分）；③去重（精确去重用哈希；模糊去重用 MinHash + LSH，能显著降低记忆与提升下游性能）；④毒性/隐私过滤（分类器 + PII 检测）；⑤配比与课程（代码占比提升推理能力，多语言占比决定语言能力，数学数据决定 GSM8K 级别的基础）。数据工程的细节决定了一个模型 80% 的最终素质——这也是第 34 章"多模态数据工程"的方法论源头。

1.2 Scaling Laws：算力该怎么花

Scaling Laws 回答的问题是：给定算力预算 $C\approx 6ND$（$N$ 参数量、$D$ 数据量、6 为前反向传播的每参数每 token FLOPs 近似），$N$ 与 $D$ 应如何分配使 loss 最低？

📐 理论推导：Chinchilla 的算力最优配比

Kaplan 等人（arXiv:2001.08361）发现 loss 服从幂律 $\mathcal{L}(N,D)=E + A N^{-\alpha} + B D^{-\beta}$（$E$ 为不可约熵）。Hoffmann 等人（Chinchilla，arXiv:2203.15556）在其参数化下求解约束优化：在 $C=6ND$ 约束下最小化 $\mathcal{L}$，对 $N$、$D$ 分别取偏导并令其相等，可得最优解满足 $N \propto C^{a}$、$D\propto C^{b}$，且拟合给出 $a\approx 0.50,\ b\approx 0.50$——即参数与数据应等比例扩张。代入具体近似后得到经验法则：$D^\ast \approx 20N$，即每个参数配 20 个 token。据此，70B 模型的"计算最优"训练量约 1.4T token（Chinchilla 70B 用 1.4T token 超过了同期 280B 的 Gopher）。但要注意：Chinchilla 最优化的是"给定算力下的 loss"，而非"给定推理成本下的最优模型"——推理成本与 $N$ 成正比且长期摊销，因此 Llama 2/3、Qwen 系列普遍过训练（Llama 3 8B 用了 15T token，约 $1900N$），用更高的训练算力换取更小的推理成本，这是 2023 年后工业界的普遍转向。

1.3 训练配方要点

现代开源预训练的"共识配方"（以 Llama 3、Qwen2.5 技术报告与开源复现如 TinyLlama 为参照）：优化器 AdamW（$\beta_1{=}0.9,\beta_2{=}0.95$）、峰值学习率随规模递减（7B 级约 $3\times10^{-4}$）、cosine 衰减至峰值的 10%、warmup 约 2000 步、全局 batch 4M–16M token、梯度裁剪 1.0、混合精度 BF16、序列长度分阶段扩展（4K→32K→128K，长上下文阶段调整 RoPE 基频）。数据"退火"（annealing）技巧：训练末期用最高质量数据并以线性小学习率收尾，可再榨出 1–3% 的下游提升。

1.4 训练监控与 loss 曲线诊断

长周期预训练的核心日常是"看曲线"。三条判读规则：①平滑度——BF16 + AdamW 下，正常曲线是带小锯齿的光滑下降；出现 loss spike（突然跳升数倍）优先查数据（脏批次）与数值（梯度爆炸/NaN），对策是跳过坏批、梯度裁剪收紧、必要时回滚到 spike 前的 checkpoint 并跳过对应数据窗口（LLaMA 系与 Qwen 系的技术报告都记录过此类处理）。②斜率——双对数坐标下应近似直线（幂律）；提前"弯折"意味着学习率衰减过快或数据耗尽进入重复。③下游对齐——每 1000 亿 token 在固定小评测集（MMLU 子集、GSM8K 子集）上打点，下游分应随 loss 单调改善；若 loss 降而下游不涨，优先怀疑数据分布过偏（例如清洗把知识性内容洗掉了）。

2.监督微调（SFT）：从基座到助手

基座模型只会"续写"：问它"法国的首都是哪里？"它可能接着输出"这是地理课的第三道题"。SFT（Supervised Fine-Tuning）用指令-回答对数据继续做 CLM，但有两个关键差异：① loss masking——只对回答（assistant 部分）计算损失，提示词部分置 $-100$ 忽略；②对话模板——用特殊 token 划分轮次与角色（如 ChatML 的 <|im_start|>/<|im_end|>），让模型学会"在何时停下"。SFT 数据的质量法则是 LIMA 原则（Zhou et al., arXiv:2305.11206）：《Less Is More for Alignment》用仅 1000 条精选数据就调出了高质量助手，结论是"对齐几乎全是学到的能力，微调主要是激活与风格塑造"——数据质量与多样性 ≫ 数量。这条原则对第 16 章的视觉指令微调同样成立。

⚠️ 陷阱：SFT 的三个常见翻车点

①模板不一致——训练与推理使用不同的 chat template，是 API 行为异常的第一大原因（务必用 tokenizer 自带模板序列化样本并逐 token 检查）；②打包（packing）破坏语义——把多样本拼到定长提高效率时若不做注意力隔离，样本间会互相"串戏"，正确做法是位置 ID 重置或文档掩码（FlashAttention varlen，第 4 章）；③灾难性遗忘——纯指令数据小学习率多轮训练会侵蚀基座能力，对策是混入 5–20% 预训练数据回放、控制 epoch（通常 1–3）。

2.1 数据混合与多轮对话的工程细节

SFT 数据的构成远比"指令→回答"复杂，主流开源配方（Tülu 3、OpenHermes、SmolTalk 等）通常混七类源：通用指令（人工/GPT 合成）、数学（GSM8K/MATH 风格 + CoT 轨迹）、代码（补全、调试、解释）、多轮对话、角色扮演/写作、安全拒绝样本、工具调用（function calling 格式）。比例是隐秘的艺术：数学与代码占比过高会让日常对话"学究气"，过少则推理能力不达标。多轮对话的训练细节有三处易错：①只对助手段算 loss（含用户段会把"模仿用户"学进去）；②上下文依赖——第 3 轮的回答的输入包含前 2 轮，loss 应只在第 3 轮的回答上计算（而非整段拼接后全算）；③轮间一致性——多轮样本打包时不能拆散对话边界。这三点在多模态数据上同样成立，且第 16 章还会多一条：视觉 token 不参与 loss。

💡 技巧：用"生成配置文件"统一团队行为

把 temperature/top_p/repetition_penalty/max_new_tokens/stop 序列写成随模型分发的 generation_config.json，而不是散落在业务代码里。排查"线上和测试行为不一致"时，90% 的元凶是：测试走 greedy、线上走采样；或一处用 raw 模型、一处用 chat 模型。把配置资产化后，这类事故率趋近于零。

3.RLHF 三阶段：对齐的完整数学

InstructGPT（Ouyang et al., arXiv:2203.02155）确立了 LLM 对齐的标准三阶段：SFT → 奖励模型训练 → PPO 强化学习。这里给出完整数学，第 37 章的多模态对齐将直接在此基础上加一个视觉维度。

3.1 奖励模型：Bradley-Terry 参数化

收集人类对同一提示下两个回答的偏好标注 $(y_w \succ y_l \mid x)$，用 Bradley-Terry 模型把偏好概率参数化为奖励差：

$$P(y_w \succ y_l \mid x) = \sigma\big(r_\phi(x, y_w) - r_\phi(x, y_l)\big)$$

损失为该似然的负对数 $\mathcal{L}_{\mathrm{RM}}=-\log\sigma\big(r_\phi(x,y_w)-r_\phi(x,y_l)\big)$。实践中 $r_\phi$ 通常是把语言模型最后一层换成标量头的版本——语言模型本体就是最好的文本特征提取器。

3.2 PPO 阶段：带 KL 约束的策略优化

把"生成回答"视为策略 $\pi_\theta(y\mid x)$，奖励为 $r_\phi$，但纯最大化奖励会导致奖励黑客（reward hacking）——模型学到刷分而非真正变好。标准解法是在奖励中加入与参考策略（SFT 模型 $\pi_{\mathrm{ref}}$）的 KL 惩罚，构成"RLHF 目标"：

$$\max_\theta\ \mathbb{E}_{x\sim\mathcal{D},\,y\sim\pi_\theta(\cdot\mid x)}\Big[r_\phi(x,y) - \beta\,\mathrm{KL}\big(\pi_\theta(y\mid x)\,\|\,\pi_{\mathrm{ref}}(y\mid x)\big)\Big]$$

$\beta$ 控制偏离 SFT 行为的容忍度（典型 $0.01\text{–}0.1$）。PPO 用裁剪代理目标近似求解（完整推导与 TRL 实现见第 37 章与参考书第二部分）。工程上这套流程要同时驻留 4 个模型（actor、critic、reward、reference），显存与系统复杂度极高——这正是 DPO（arXiv:2305.18290）走红的原因：把奖励差重参数化为策略对数概率差，直接在偏好数据上做闭式监督训练，跳过 RM 与采样环节；其数学推导与多模态应用见第 37 章。

🍳 实战配方：小团队的对齐路线选择

算力紧张/数据少：直接 SFT + 高质量数据（LIMA 式），再叠 DPO；跳过 PPO。有可验证信号（数学、代码）：用 RLVR/GRPO 思路——规则奖励 + 组内相对基线（DeepSeekMath，arXiv:2402.03300），比训练 RM 更稳。追求极致对话质量：迭代式偏好收集（在线 DPO / 迭代 RM）。多模态场景：优先在文本侧做对齐，再用多模态偏好数据（图像条件下的拒绝-偏好对）做轻量 DPO——第 37 章给完整代码。

3.3 PPO 机制速览：四个模型如何协作

完整的 RLHF-PPO 训练循环同时驻留四个模型，理解它们的数据流是把理论落到工程的关键：①Actor（被训练的策略，即当前 SFT 模型副本）负责生成；②Reference（冻结的 SFT 模型）与 Actor 对同一序列各算一次对数概率，其差构成 KL 惩罚；③Reward Model 给整段回答打标量分；④Critic（价值头）估计每个 token 位置的预期回报，用于计算优势函数（GAE）以降低梯度方差。一个 batch 的生命周期：Actor 采样回答 → 四模型并行前向得到 logprob/ref_logprob/reward/value → 计算优势与 PPO 裁剪目标 → 多个小批量梯度更新 Actor 与 Critic → 下一批重新采样。显存压力直观可算：四个 7B 模型仅权重就要 4×14GB（FP16）——这也是为什么学术界迅速转向 DPO 及其变体，以及为什么第 38 章的并行与卸载技术在对齐训练里是刚需。

train = ds.map(fmt, remove_columns=ds.column_names)

DPOTrainer(model=model, ref_model=ref, args=cfg,

⚠️ 陷阱：DPO 的三大翻车模式

①学习率过大 → 两个策略概率同时塌缩、输出退化成模板，务必从 5e-7 起步；②参考模型没冻结/没传对 → 隐式奖励失真，确认 ref_model 权重与 requires_grad=False；③偏好数据本身偏短或偏格式 → 模型学会"喜欢短回答/喜欢列表体"而非真正偏好，构建数据时对长度做配对控制（第 37 章多模态偏好数据同理）。

4.解码策略全家桶

训练决定分布，解码决定样本。同一个模型，解码策略选错能让回答质量天差地别。设第 $t$ 步词表上的 logits 为 $\mathbf{z}\in\mathbb{R}^{|V|}$，逐一分析主流策略。

温度缩放（temperature）：$P(w_i)=\mathrm{softmax}(\mathbf{z}/T)_i$。$T<1$ 使分布更尖锐（更确定），$T>1$ 更平缓（更多样）。温度并非"创造性"旋钮——它只是对 logits 的全局缩放，过高会放大长尾噪声导致胡言乱语。

Top-k 采样：只保留概率最高的 $k$ 个词再归一化采样。问题是 $k$ 固定不合身：分布尖锐时 $k{=}50$ 仍会引入垃圾词，分布平缓时又截断多样性。

Top-p（nucleus）采样（Holtzman et al., arXiv:1904.09751）：保留累计概率达到 $p$ 的最小词集，词集大小随分布形状自适应。经验上 $p\in[0.9,0.95]$ 配合 $T\in[0.6,0.8]$ 是多数对话模型的甜点区。理解 top-p 的关键在于它与 top-k 的差别：当模型"很有把握"（分布尖锐，如事实问答）时 top-p 自动缩到极小的词集——几乎等价贪心；当模型"在犹豫"（分布平缓，如创意写作）时词集自动扩大——保留多样性。这正是与 top-k 的本质区别：top-k 的 $k$ 是静态超参，top-p 的词集大小是由模型自身置信度决定的动态量。也因此，top-p 对温度更鲁棒：调温度改变分布形状时，top-p 能自适应补偿，而 top-k 的截断边界不动。

Min-p 采样（Nguyen et al., arXiv:2407.01082）：设词表最大概率为 $p_{\max}$，仅保留 $P(w_i)\ge \alpha\, p_{\max}$ 的词（$\alpha$ 常取 0.05–0.2）。相对 top-p，它在高温度下的稳定性更好——截断阈值随分布尖锐度自适应缩放，2024 年后在开源社区快速流行。

贪心与束搜索：贪心每步取 argmax；束搜索维护 $B$ 条最优部分序列。对翻译/摘要等有明确目标的任务有效，但对开放生成会导致"高似然陷阱"——重复、乏味（Holtzman 的《The Curious Case of Neural Text Degeneration》正是用这个现象推动了采样研究）。

重复惩罚与频率惩罚：对已出现 token 的 logits 减去惩罚项 $\delta$ 或除以因子 $\gamma^{\mathrm{count}}$，缓解循环；过强会伤害专有名词与代码缩进这类"合法重复"。

4.1 受控生成：让输出严格合法

生产系统里模型输出经常要"必须是合法 JSON / 必须匹配正则 / 必须是词表内的类别"。受控生成（constrained/guided decoding）的做法是在每步解码前用自动机掩码：根据目标文法（正则 NFA、JSON Schema 编译出的下推自动机）计算当前前缀下"哪些 token 合法"，把非法 token 的 logits 置 $-\infty$ 后再采样。outlines、xgrammar、llguidance 等库与 vLLM/SGLang 的 guided_json 参数都是这套原理。两个工程要点：①掩码与采样顺序——先掩码后温度/采样，否则非法 token 会"漏"回来；②性能——编译一次文法、按状态缓存掩码，否则每步重算的开销会吃掉吞吐。受控生成在多模态下的典型用例：让 VLM 输出严格的结构化检测结果（bbox + 类别 + 置信度的 JSON），第 43 章的 GUI Agent 大量依赖它。

5.模型压缩：量化、蒸馏与剪枝

5.1 量化：把 FP16 压到 INT4 的艺术

量化把权重（与/或激活）从 16 位浮点映射到低位整数。朴素均匀量化：$x_q=\mathrm{round}(x/s)+z$，反量化 $\hat{x}=s(x_q-z)$；尺度 $s$ 与零点 $z$ 按 per-tensor / per-channel / per-group（group size 128 是主流）粒度计算。低位量化的两大难点与对应名作：①离群值问题——LLM 激活中存在少数巨大离群通道，直接 INT8 即崩溃；SmoothQuant（arXiv:2212.08143）把激活的尺度"平滑"转移到权重上（$W'=W/s,\ X'=X\odot s$），两端都好量化。②误差累积——逐层量化误差在残差流中放大；GPTQ（arXiv:2210.17323）基于二阶信息（Hessian 逆）逐列更新补偿，实现 4-bit 近无损；AWQ（arXiv:2306.00978）观察到约 1% 的"显著权重"由激活幅度决定，对其缩放保护即可保住精度。多模态模型量化还有一个特有坑：视觉编码器输出的激活分布与文本侧差异大，混合精度策略（视觉塔保持 FP16、LLM 侧 INT4）常是更稳的起点——第 39 章展开。

5.2 蒸馏与剪枝

知识蒸馏让学生模型拟合教师的软标签分布：$\mathcal{L}=\alpha\,\mathrm{KL}(p_T^\tau\|p_S^\tau)+(1-\alpha)\mathcal{L}_{\mathrm{CE}}$，温度 $\tau$ 软化分布暴露"暗知识"（类间相似度）。LLM 时代的代表是 R1-Distill 系列：用大模型的推理轨迹对小模型做 SFT 蒸馏（第 37 章前沿部分详述）。剪枝分非结构化（One-Shot 剪枝如 Wanda，按 $|w|\cdot\|x\|$ 打分）与结构化（剪头/剪层，如 ShortGPT 用"层贡献度"删除冗余层）；LLM 层间冗余度高，24 层剪到 20 层常见可保 95% 性能，是多模态端侧部署（第 39 章）的常用组合拳。

💡 技巧：压缩组合拳的推荐顺序

单卡部署 7B–14B 模型的实用组合：第一步 GQA 检查（结构红利，零成本）；第二步 AWQ/GPTQ INT4 权重量化（4× 显存节省，几乎无感损失）；第三步按需 KV 量化（长上下文场景）；第四步才考虑剪层/蒸馏（收益大但需重校准，风险最高）。多模态叠加一条：视觉编码器在 INT4 下对 OCR/细粒度任务损伤明显，优先保持视觉塔高精度、先压 LLM 部分。压缩后务必在同一评测集上做前后对比（POPE/MMBench 子集即可），"看起来能跑"和"质量可接受"是两回事。

5.3 长上下文工程：位置外推与 KV Cache 压缩

把 4K 训练的模型用到 128K 上下文，核心障碍是位置编码的外推性。以 RoPE 为例（完整推导在第 3 章），三种主流方案：①线性插值（PI）（arXiv:2306.15595）——把位置索引整体缩放 $m/L_{\mathrm{train}}$，代价是高频分辨率损失；②NTK-aware 缩放——不均匀地拉伸各频率分量（低频多拉、高频少拉），相当于修改 RoPE 基频 $b$（$b'=b\cdot s^{L/(L-2)}$），无需训练即可外推一段；③YaRN（arXiv:2309.00071）——NTK 分频插值 + 注意力温度随上下文缩放 + 少量微调，是当前开源长上下文的事实标准。选型建议：只差 2–4× 且能接受少量微调 → YaRN；不能动训练 → 动态 NTK（推理时按实际长度缩放基频）；从头训练 → 直接上长序列课程（文档级数据 + 分阶段扩长），并为注意力算子选 varlen 支持（第 4 章）。多模态场景里"长"来得更快：一张 2K 图像动辄上千视觉 token，128K 文本上下文在多图输入下只需几十张图就能耗尽——这就是第 22 章（动态分辨率）与第 31 章（视觉 token 压缩）存在的根本原因。

KV Cache 是长上下文的显存大头：$2\times L\times H\times d_{\mathrm{head}}\times \mathrm{seq}\times \mathrm{dtype}$ 字节（$L$ 层、$H$ KV 头数）。压缩三板斧：①结构压缩——MQA/GQA 让所有查询头共享少量 KV 头（Llama 2 70B 用 GQA，KV 显存降 8×）；②量化——KV Cache FP16→INT8/INT4（per-token/per-head 尺度），对生成质量影响很小；③淘汰与合并——H2O 等注意力分数驱动的 token 淘汰、流式对话的滑窗 + 系统提示缓存。vLLM 的 PagedAttention（第 8 章）解决的是 KV 显存的碎片与复用，与上述正交，共同构成推理服务的基础设施。

📐 理论视角：位置插值为什么"温和"

RoPE 把位置 $m$ 编码为对 $\{q,k\}$ 的旋转变换，其注意力 logits 只依赖相对位置 $m-n$ 且由频率 $\omega_i=b^{-2i/d}$ 调制。直接外推时，训练中未见过的低频相位（$m\omega_i$ 超出训练范围）导致注意力矩阵出现"尖刺"。线性插值把位置缩到训练范围内，本质是牺牲"相邻 token 的旋转分辨差"换取"全部相对位置落在已见域"——高频分量受影响最大。NTK-aware 方案的洞察是：高频（局部）信息不能动（它负责近距离语法），低频（全局）信息可以压缩（它负责远距离主题，语义上有冗余），于是按频率分层插值。这个"频谱分层"思想后来也被多模态借鉴：视频模型的 M-RoPE（Qwen2-VL）对时间/空间频率做不同处理，本质同源。

6.推测解码：用小模型给大模型"代驾"

自回归解码每步只产出一个 token，却要完整过一遍大模型——访存受限（第 8 章），GPU 算力大量闲置。推测解码（Speculative Decoding）（Leviathan et al., arXiv:2211.17192；Chen et al., arXiv:2302.01318）用小草稿模型（draft）快速草拟 $\gamma$ 个 token，再让大模型（target）并行验证：一次前向同时算出这 $\gamma$ 个位置上大模型的分布，从前往后逐 token 接受或拒绝。关键设计是拒绝采样修正：接受概率 $\min(1, p_t(x)/p_d(x))$ 保证最终输出分布与 target 模型严格一致——加速不降质是硬保证。经验加速比 2–3×（草稿接受率决定）。变体：Medusa（arXiv:2401.10774）让 target 自带多头并行预测多 token；Eagle（arXiv:2401.15077）用特征级草稿进一步提接受率；vLLM/SGLang 均已内建 n-gram 与 draft 模型方案。对多模态服务，视觉 token 的 prefill 占比高，speculative 解码主要加速 decode 阶段——图文长回答场景收益显著。落地清单：①草稿模型与 target 必须共享 tokenizer（或做 token 映射）；②接受率低（<0.6）时先怀疑草稿模型太小或领域偏移；③n-gram 草稿（无模型，从提示/历史里匹配连续片段）对代码、模板化文本的加速出乎意料地好，且零额外显存。

📐 理论推导：拒绝采样为何能保分布一致

草稿分布 $p_d(x)$，目标分布 $p_t(x)$。以概率 $\min(1,p_t/p_d)$ 接受草稿样本 $x$；被拒时从残差分布 $\mathrm{norm}(\max(0, p_t-p_d))$ 重新采样。对任意 $x$，最终命中概率为：

$$P(x)=p_d(x)\min\!\Big(1,\frac{p_t(x)}{p_d(x)}\Big)+\max(0,p_t(x)-p_d(x))=\min(p_d(x),p_t(x))+\max(0,p_t(x)-p_d(x))=p_t(x)$$

分类讨论即得等式：当 $p_t\le p_d$ 时两项和为 $p_t$；当 $p_t>p_d$ 时第一项为 $p_t$。这就是"无损加速"的数学根基——同样的技巧在 RLHF 的 KL 修正采样与多模态 token 压缩的无损校验中也常出现。

7.幻觉：定义、成因与检测

幻觉（hallucination）指模型生成与输入或世界知识不符、却以流利语气呈现的内容。文本侧的经典二分：事实性幻觉（与可验证事实冲突）与忠实性幻觉（与给定文档冲突，RAG 场景常见）。成因画像：①预训练的"合理续写"目标不区分真假（只追求似然）；②采样随机性放大低概率事实错误；③知识边界缺失——模型不会说"不知道"；④SFT 数据的风格偏差（宁可编也要答完）。多模态侧的对应物是对象幻觉（图里没有的说成有，源自语言先验）——POPE（arXiv:2305.10355）用"是/否"探针量化它，第 37、41 章专门展开。检测方法谱系：自一致性（多次采样投票）、不确定性（token 熵/语义熵）、检索验证（把声明逐条与外部知识比对）、基于内部状态的探针（真假陈述的隐状态可分性）。缓解则在三个层面同时下手：数据（承认无知的样本）、训练（RLHF 惩罚编造 / R-Tuning 式拒答训练）、推理（检索增强、解码层干预如 DoLa）。

7.1 一个最小的"防幻觉"系统设计

把本节方法组装成生产可用的三道防线：第一道（生成前）——检索增强：把与问题相关的文档放进上下文，并在系统提示中明确"仅依据给定资料回答，资料不足时明确说明"；第二道（生成中）——降低采样随机性 + 受控生成约束输出结构，关键数值类答案可要求模型先给出依据再给结论；第三道（生成后）——声明级校验：用 NLI 模型或 LLM 把回答拆成原子声明逐条与资料比对，不一致则触发重写或标注"未经验证"。多模态版本把第一道换成"图像证据"（先让模型引用图中区域再作答，即第 44 章的 visual CoT），第三道换成"视觉声明校验"（VLM 自查 + 检测器交叉验证）。三道防线的设计哲学是：不指望模型不说谎，而指望说谎时能被发现。

# 自一致性（Self-Consistency）幻觉粗检：多次采样投票
import torch
from collections import Counter
from transformers import AutoModelForCausalLM, AutoTokenizer

def self_check(model, tok, question, n=8, temperature=0.9):
    answers = []
    for _ in range(n):
        prompt = tok.apply_chat_template(
            [{"role": "user", "content": question}],
            tokenize=False, add_generation_prompt=True)
        ids = tok(prompt, return_tensors="pt").to(model.device)
        out = model.generate(**ids, do_sample=True, temperature=temperature,
                             max_new_tokens=256, top_p=0.95,
                             pad_token_id=tok.eos_token_id)
        answers.append(tok.decode(out[0][ids.input_ids.shape[1]:],
                                  skip_special_tokens=True).strip())
    # 归一化后取多数派：多数一致 → 可信；高度分裂 → 疑似幻觉/模糊
    norm = Counter(a[:50] for a in answers)   # 简化：前缀归并（生产中用语义聚类）
    top, cnt = norm.most_common(1)[0]
    return top, cnt / n

# 用 TRL 对 1.5B 模型做一次完整 SFT（loss masking 自动处理）
from datasets import load_dataset
from trl import SFTConfig, SFTTrainer
from transformers import AutoModelForCausalLM, AutoTokenizer
import torch

model_id = "Qwen/Qwen2.5-1.5B"
model = AutoModelForCausalLM.from_pretrained(model_id, torch_dtype=torch.bfloat16)
tok = AutoTokenizer.from_pretrained(model_id)

# 示例数据集：指令-回答对（生产中替换为你自己的高质量数据）
ds = load_dataset("HuggingFaceTB/smoltalk", split="train[:1%]")

def to_text(example):
    # 套用官方 chat template；SFTTrainer 会自动识别 assistant 段做 masking
    return {"text": tok.apply_chat_template(example["messages"],
                                            tokenize=False)}

train_ds = ds.map(to_text, remove_columns=ds.column_names)

cfg = SFTConfig(
    output_dir="out_sft", per_device_train_batch_size=4,
    gradient_accumulation_steps=4, learning_rate=2e-5,
    num_train_epochs=1, bf16=True, logging_steps=10,
    lr_scheduler_type="cosine", warmup_ratio=0.03,
    gradient_checkpointing=True, max_length=2048)
trainer = SFTTrainer(model=model, args=cfg, train_dataset=train_ds,
                     processing_class=tok)
trainer.train()
trainer.save_model("out_sft/final")

学习率 1e-5～2e-5（全参）/ 1e-4～2e-4（LoRA）；epoch 1–3（>3 几乎必过拟合风格）；warmup 3%；cosine 衰减；有效 batch 64–128 样本；BF16 + 梯度检查点 + packing（带隔离）。判断 SFT 是否到位：看三个信号——训练 loss 平稳下降到 0.8–1.2 区间、停不下来（学会 EOS）、 held-out 指令集的人工盲评胜率。loss 过低（<0.6）通常是背诵数据而非泛化风格，应减少 epoch 或增数据。

9.本章小结

本章完成了 LLM 技术栈的巡礼：预训练的算力经济学（Chinchilla 配比 → 推理感知过训练）、数据管道与 loss 曲线诊断、SFT 的质量法则（LIMA + 模板纪律 + packing 陷阱）、RLHF 的完整数学（Bradley-Terry 奖励 + KL 约束 PPO → DPO 的简化路线）、解码策略的工程甜点区与受控生成、压缩三件套（量化/蒸馏/剪枝）与长上下文工程（位置外推 + KV 压缩）、推测解码的无损加速证明，以及幻觉的成因-检测-缓解矩阵。所有这些在多模态语境下逐一对应：第 35 章 = 预训练 + SFT 的多模态版，第 37 章 = RLHF/DPO 的多模态版，第 39 章 = 压缩与推测解码在 VLM 服务上的落地，第 43 章 = 受控生成在 Agent 动作输出上的应用。语言侧的基本功到此完备，第 8 章补最后一块系统基石（GPU 与并行），随后正式进入多模态核心。

如果你只有时间做一件事，就做第 8 节的两次训练：跑通一次 SFT、再跑一次 DPO，观察 loss 曲线与生成行为的差异——这两个实验会把本章的抽象概念全部"钉"进肌肉记忆，也是后面所有多模态训练实验的心理模板。

✏️ 自测

1. Chinchilla 的 $D^\ast\approx 20N$ 最优化的是什么？为什么 Llama 3 8B 却用了 15T token？
答案要点：给定训练算力下 loss 最优；产品更在意推理成本，过训练用一次性训练算力换小模型的长期推理开销。

2. 写出 RLHF 目标函数并解释 $\beta$ 的作用；DPO 如何绕开奖励模型？
答案要点：$\max_\theta \mathbb{E}[r_\phi-\beta\,\mathrm{KL}(\pi_\theta\|\pi_{\mathrm{ref}})]$；$\beta$ 控制偏离 SFT 的幅度；DPO 用 $\log\frac{\pi_\theta(y_w)}{\pi_{\mathrm{ref}}(y_w)}-\log\frac{\pi_\theta(y_l)}{\pi_{\mathrm{ref}}(y_l)}$ 重参数化奖励差，闭式监督训练。

3. 为什么 top-p 比 top-k 更自适应？min-p 又改进了什么？
答案要点：top-p 按累计概率动态定词集大小；min-p 以最大概率的比例为阈值，在高温度（分布极平）时仍能稳定截断。

4. 推测解码为什么能保证输出分布与大模型严格一致？加速比受什么限制？
答案要点：拒绝采样修正（推导见 box-theory）；受草稿接受率与验证开销之比限制，接受率越高加速越大。

5. SmoothQuant 与 AWQ 分别解决量化的哪个问题？
答案要点：SmoothQuant 把激活离群尺度转移到权重，解决激活难量化；AWQ 保护少量"显著权重"（由激活幅度判定），解决 4-bit 下关键通道的精度损失。

6. SFT 中 packing 若不做注意力隔离会造成什么后果？正确做法？
答案要点：不同样本间互相注意，"串戏"污染训练信号；用位置 ID 重置/文档掩码配合 FlashAttention varlen。
