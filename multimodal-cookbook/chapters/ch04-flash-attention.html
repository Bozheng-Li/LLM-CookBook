第 3 章末尾我们留了一个引子：视觉 token 数量动辄数千到数万，注意力的平方复杂度会把多模态模型压垮。本章的主角 FlashAttention（Dao et al., arXiv:2205.14135，NeurIPS 2022）给出了 2022–2026 年最重要的工程答案：它不改变注意力的数学（精确注意力，不是近似），而是改变注意力的读写方式——把中间的 $T\times T$ 矩阵彻底"藏进片上内存"，用 tiling（分块）与 online softmax（在线归一化）让显存从 $O(T^2)$ 降到 $O(T)$、速度提升 2–4 倍。没有 FlashAttention，就没有 16k 上下文 BERT、没有 Qwen2-VL 的原生任意分辨率、也没有 vLLM 的高吞吐服务。本章按"瓶颈分析 → 数学推导 → 前向/反向 → 硬件演进（FA2/FA3）→ KV 瘦身（MQA/GQA）→ varlen 与多模态打包"的顺序展开，online softmax 的推导与数值算例一步不跳。

1.注意力的两本账：计算量与访存量

分析任何 GPU 算子要同时记两本账。计算账：注意力每层的前向 FLOPs 约为 $4T^2 d$（$\mathbf{Q}\mathbf{K}^{\top}$ 与 $\tilde{\mathbf{P}}\mathbf{V}$ 两次 $T\times T\times d$ 矩阵乘，每次 $2T^2d$ FLOPs，忽略 softmax 的指数开销）。访存账：朴素实现需要把 $\mathbf{Q}\mathbf{K}^{\top}$（未归一化分数 $\tilde{\mathbf{S}}$，$T\times T$）与 softmax 结果 $\mathbf{P}$（又是 $T\times T$）写进显存（HBM）再读回来，每份 $T^2\times p$ 字节（$p$=2 为 FP16）。

两本账的比值叫算术强度（Arithmetic Intensity，FLOPs/字节），它决定算子处于 Roofline 模型的哪一段：以 A100 SXM 为例，BF16 Tensor Core 峰值约 312 TFLOPs/s、HBM 带宽约 2 TB/s——要让计算单元吃满，算子的算术强度必须超过约 $312\times10^{12} / 2\times10^{12} \approx 156$ FLOP/字节。大矩阵乘（batch × 大尺寸）轻松超过这个门槛，是计算受限（compute-bound）；而标准注意力实现每完成 275 GFLOPs 的计算（$T=4096, d=4096$ 例），却要为 $T\times T$ 中间矩阵支付约 4–8 GB 的 HBM 往返流量，算术强度不足 50 FLOP/字节——访存受限（memory-bound）：GPU 的 SM 大量时间在等数据，而不是在算。

2.标准实现的真相：为什么慢

先用最朴素的 PyTorch 代码复现标准实现（不是生产代码，但每一行都对应一次真实的显存读写）：

python
import torch, time
import torch.nn.functional as F

torch.manual_seed(0)
device = "cuda" if torch.cuda.is_available() else "cpu"
B, h, T, d_head = 1, 32, 8192, 128          # 8k 序列、32 头
Q = torch.randn(B, h, T, d_head, device=device)
K = torch.randn(B, h, T, d_head, device=device)
V = torch.randn(B, h, T, d_head, device=device)

def naive_attention(Q, K, V):
    scores = Q @ K.transpose(-2, -1) / Q.size(-1) ** 0.5   # 写出 T×T（8k²×2B×32头=4 GiB）
    P = F.softmax(scores, dim=-1)                          # 读 S、写 P（再 8 GiB 流量）
    del scores                                              # 即使 del，峰值也已经发生
    return P @ V                                            # 读 P、写输出

if device == "cuda":
    torch.cuda.reset_peak_memory_stats()
    t0 = time.perf_counter()
    out = naive_attention(Q, K, V)
    torch.cuda.synchronize()
    print(f"朴素: {time.perf_counter()-t0:.3f}s, "
          f"峰值显存 {torch.cuda.max_memory_allocated()/2**30:.2f} GiB")

    torch.cuda.reset_peak_memory_stats()
    t0 = time.perf_counter()
    out2 = F.scaled_dot_product_attention(Q, K, V, is_causal=False)  # 自动分派 Flash/高效后端
    torch.cuda.synchronize()
    print(f"SDPA: {time.perf_counter()-t0:.3f}s, "
          f"峰值显存 {torch.cuda.max_memory_allocated()/2**30:.2f} GiB")
    print("数值一致:", (out - out2).abs().max().item())     # ≈1e-6：Flash 是精确注意力

在 A100 上运行（8k 序列）：朴素版峰值显存约为 SDPA 版的 6–8 倍，耗时长 3–5 倍——差距全部来自中间矩阵的 HBM 流量，而不是"算得不够快"。还有一个更深的问题让"优化 softmax 本身"看似不可能：softmax 的归一化分母要整行求和，似乎必须先看到整行。Tile 级计算与"必须全行"的矛盾，正是 online softmax 要解决的。

3.Tiling 与 Online Softmax 完整推导

📐 理论推导：从 Safe Softmax 到 Online Softmax，再到分块重标定

第一步：Safe Softmax（数值稳定版）。直接按定义算 softmax 会因指数溢出出错（第 1 章的陷阱），标准做法先减去行最大值 $m$：

$$\mathrm{softmax}(\mathbf{x})_i = \frac{e^{x_i - m}}{\sum_{j} e^{x_j - m}}, \qquad m = \max_j x_j$$

分子分母同乘 $e^{m}$ 不改变结果，且所有指数的输入 $\le 0$，绝不上溢。问题依旧：$m$ 需要看完一整行才知道。

第二步：Online 重标定（流式更新 max 与分母）。关键洞察：分母 $l = \sum_j e^{x_j - m}$ 可以在 $m$ 变化时廉价修正。设已处理前 $k$ 个元素，记录 $m^{(k)}$（当前最大）与 $l^{(k)} = \sum_{j\le k} e^{x_j - m^{(k)}}$。来了新元素 $x_{k+1}$：

$$m^{(k+1)} = \max\big(m^{(k)}, x_{k+1}\big), \qquad l^{(k+1)} = e^{\,m^{(k)} - m^{(k+1)}}\, l^{(k)} + e^{\,x_{k+1} - m^{(k+1)}}$$

证明只需一行：旧项 $e^{x_j - m^{(k)}} = e^{x_j - m^{(k+1)}}\cdot e^{m^{(k)} - m^{(k+1)}}$——每个旧贡献乘上同一个"降权因子" $e^{m^{(k)}-m^{(k+1)}}$ 即对齐到新基准。这就是 online softmax（Milakov & Gimelshein, arXiv:1805.02867）：一遍流式扫描，同时维护 $\max$ 与分母，不需要回头。

第三步：带值的分块（attention 版 online softmax）。注意力输出 $\mathbf{o}_i = \frac{1}{l}\sum_j e^{s_{ij}-m}\mathbf{v}_j$，把"分子"也做成流式状态。对第 $i$ 个 query 行，已见分块 $[1..j]$ 的状态是三元组 $(m^{(j)},\, l^{(j)},\, \mathbf{o}^{(j)})$（$\mathbf{o}^{(j)}$ 为未归一化的加权和）。新到分块 $\mathbf{K}_j, \mathbf{V}_j$，算出局部分数 $\tilde{\mathbf{s}} = \mathbf{q}_i\mathbf{K}_j^{\top}/\sqrt{d_k}$ 与局部统计 $m_j = \max \tilde{\mathbf{s}}$、$l_j = \sum e^{\tilde s - m_j}$、$\mathbf{p}_j = e^{\tilde{\mathbf{s}} - m_j}$：

$$m^{\text{new}} = \max\big(m^{(j)},\, m_j\big), \qquad l^{\text{new}} = e^{\,m^{(j)}-m^{\text{new}}}\,l^{(j)} + l_j$$
$$\mathbf{o}^{\text{new}} = \underbrace{e^{\,m^{(j)}-m^{\text{new}}}\,\mathbf{o}^{(j)}}_{\text{旧块整体降权}} + \underbrace{\mathbf{p}_j\,\mathbf{V}_j}_{\text{新块未归一化累加}}$$

扫描完所有块后，归一化一次：$\mathbf{o}_i = \mathbf{o}^{\text{final}} / l^{\text{final}}$。用归纳法可证最终结果与整行 softmax 完全一致：每一步只是把"以旧 max 为基准的未归一化和"换算成"以新 max 为基准"，与第二步的单元素情形逐项相同。$\blacksquare$

为什么这解决了 tiling 矛盾：每个分块内部只需要块内的 max 与求和（片上完成），跨块只传递两个标量 $m, l$ 和一个 $T\times d$ 向量 $\mathbf{o}$——$T\times T$ 矩阵从未成形。

数值算例（手算一遍，彻底安心）：取一行分数 $\mathbf{s} = [1, 2, 3, 4]$，对应标量值 $\mathbf{v}=[v_1,v_2,v_3,v_4]$，分两块计算。第一块 $[1,2]$：块内 $m^{(1)}=2$，$l^{(1)}=e^{-1}+e^{0}\approx 1.3679$，$\mathbf{o}^{(1)} = 0.3679\,v_1 + 1\cdot v_2$。第二块 $[3,4]$：$m_2=4$，$l_2 \approx 1.3679$，$\mathbf{p}_2 = [e^{-1}, 1] = [0.3679, 1]$。合并：$m^{\text{new}}=4$；旧块降权 $e^{2-4}\approx0.1353$；于是 $l^{\text{new}} = 0.1353\times1.3679 + 1.3679 \approx 1.5530$；$\mathbf{o}^{\text{new}} = 0.1353\times(0.3679 v_1 + v_2) + (0.3679 v_3 + v_4) = 0.0498 v_1 + 0.1353 v_2 + 0.3679 v_3 + v_4$。归一化后权重 $\approx [0.0321, 0.0871, 0.2369, 0.6439]$——与直接整行 softmax（$e^{-3},e^{-2},e^{-1},1$ 除以 1.5530）逐项一致。下面用代码复现这个算例：

python
import torch
import torch.nn.functional as F

torch.manual_seed(0)
T, d = 8, 4
X = torch.randn(1, T, d)                       # 一条"序列"同时充当 K 和 V 的来源
S = X @ X.T / d ** 0.5                          # 8×8 分数矩阵（演示用）
V = X

def online_softmax_blockwise(S, V, block=2):
    """按 K 维分块的 online softmax 注意力：只维护每行 (m, l, o) 三个状态"""
    rows = []
    for i in range(S.size(0)):                  # 逐 query 行（真实 kernel 是逐块、并行的）
        m, l, o = torch.tensor(float("-inf")), torch.zeros(1), torch.zeros(d)
        for j0 in range(0, S.size(1), block):   # 外层：K/V 分块，一次一块进 SRAM
            s_blk = S[i, j0:j0+block]                       # 块内分数
            m_j = s_blk.max()
            p_blk = torch.exp(s_blk - m_j)                  # 块内未归一化权重
            l_j = p_blk.sum()
            m_new = torch.maximum(m, m_j)                   # 合并 max
            scale = torch.exp(m - m_new) if m != float("-inf") else torch.tensor(0.0)
            l = scale * l + l_j                             # 分母重标定
            o = scale * o + p_blk @ V[j0:j0+block]          # 输出重标定累加
            m = m_new
        rows.append(o / l)                       # 最后统一归一化
    return torch.stack(rows)

out_block = online_softmax_blockwise(S, V, block=2)
out_full = F.softmax(S, dim=-1) @ V
print("分块 vs 全行的最大误差:", (out_block - out_full).abs().max().item())  # ~1e-6
print("精确一致 ⇒ FlashAttention 不是近似，是换了一种读写顺序的精确注意力")

4.FlashAttention 前向：SRAM 里的分块流水

有了 online softmax，算法层面"分块计算精确注意力"已经成立；但要把性能吃满，还差最后一环：让分块大小与硬件内存层级匹配。GPU 的内存层级（第 8 章详解）：每个 SM 有约 192 KB 的 SRAM（A100，Hopper 约 228 KB），读写速度接近寄存器；HBM 容量大（40–80 GB）但带宽慢一个量级。FlashAttention 的 kernel 设计原则是：每个线程块（thread block）领取一个 Q 行块，把对应 K/V 块分批搬进 SRAM，重复"算分数 → softmax 重标定 → 累加"，SRAM 里没有任何东西回流 HBM。

分块大小怎么定：设行块大小 $B_r$、列块大小 $B_c$，SRAM 需要容纳 $\mathbf{Q}_i$（$B_r\times d$）、$\mathbf{K}_j,\mathbf{V}_j$（各 $B_c\times d$）与中间分数块（$B_r\times B_c$），即 $(B_r + 2B_c)\,d + B_r B_c \le \mathrm{SRAM}$。以 $d=128$、A100 约 100 KB 可用为例，$B_r=B_c\approx 100$–128 是典型取值——每个块都是几百到几千 KB 的"工作集"，恰好 tensor core 也喜欢这种方形 tile。循环顺序：FA1 是外层扫 K/V 块、内层扫 Q 行块（每个 Q 行块自己维护 $(m, l, \mathbf{o})$ 状态，互不干扰，天然并行）；FA2 会交换内外循环（第 6 节讲为什么）。

正确性与精度：整个计算只有两类数值偏离"教科书"：分块 exp 的顺序不同（浮点加法不结合，误差在 $10^{-6}$ 量级），以及统计量 $m,l$ 的重标定乘法。在 BF16 下与朴素实现的端到端差异通常小于 $10^{-3}$，所有主流模型（LLaMA/Qwen 系列）都是直接用 FlashAttention 训练的，不存在"精度切换"问题。

💡 技巧：为什么 softmax 每行还要存 m 和 l

前向把输出 $O$ 归一化后写回，但反向传播还需要未归一化的信息重算 $\mathbf{P}$。与其存下 $T\times T$ 的 $\mathbf{P}$，不如只存每行的 $m_i, l_i$（$2T$ 个标量）——反向时用 $\mathbf{S} - m_i$ 重算指数、除以 $l_i$ 即可精确恢复 $\mathbf{P}$。这是"显存 O(T)"的另一半：前向丢弃 $T^2$ 中间量、只留统计量，反向重新算一遍。下一节展开。

5.反向传播：用重计算换显存

标准实现的反向传播需要保存 $\mathbf{P}$（$T\times T$）来计算 $\partial \mathbf{S} = \mathbf{P}\odot(\partial\mathbf{P} - \mathrm{rowsum}(\partial\mathbf{P}\odot\mathbf{P}))$。FlashAttention 的做法：前向只保存 $O_i$ 与 $(m_i, l_i)$；反向重新执行一遍分块前向（同样的 tiling）重建 $\mathbf{P}$ 的每个小块，边重建边算梯度。代价是额外约 1.5–2 倍的注意力 FLOPs；收益是反向显存也从 $O(T^2)$ 降到 $O(T)$，而且由于算子本来就访存受限，多算的那部分 FLOPs 大部分被带宽等待"吸收"了——端到端训练时间仍比标准实现快 2–4 倍。

把反向公式的推导写完整（这是很多博客"直接引用"的部分）。设 $\mathbf{O} = \mathrm{softmax}(\mathbf{S})\mathbf{V} = \mathbf{P}\mathbf{V}$，$\mathbf{S} = \mathbf{Q}\mathbf{K}^{\top}/\sqrt{d_k}$，上游梯度为 $\partial\mathbf{O}$：

$$\partial\mathbf{V} = \mathbf{P}^{\top}\partial\mathbf{O}, \qquad \partial\mathbf{P} = \partial\mathbf{O}\,\mathbf{V}^{\top}$$

softmax 的反向：对行向量 $\mathbf{p} = \mathrm{softmax}(\mathbf{s})$，雅可比 $\partial\mathbf{s} = \mathbf{p}\odot(\partial\mathbf{p} - \langle \mathbf{p}, \partial\mathbf{p}\rangle)$（利用 $\sum_j p_j = 1$ 与 $\frac{\partial p_i}{\partial s_j} = p_i(\delta_{ij} - p_j)$，逐分量展开即可验证）。逐行写成矩阵形式时，$\langle \mathbf{p}, \partial\mathbf{p}\rangle$ 是逐行点积，故：

$$\mathbf{D} = \mathrm{rowsum}\big(\partial\mathbf{P}\odot\mathbf{P}\big)\in\mathbb{R}^{T}, \qquad \partial\mathbf{S} = \mathbf{P}\odot\big(\partial\mathbf{P} - \mathbf{D}\big)$$

FlashAttention 反向里 $\mathbf{D}$ 的计算有个巧妙事实：不需要单独跑一遍。由链式法则 $\langle \mathbf{p}_i, \partial\mathbf{p}_i\rangle = \langle \mathbf{o}_i, \partial\mathbf{o}_i\rangle$（因为 $\partial\mathbf{o}_i = \partial\mathbf{p}_i\mathbf{V}$、$\mathbf{o}_i = \mathbf{p}_i\mathbf{V}$，代入即得 $\partial\mathbf{o}_i\cdot\mathbf{o}_i = \partial\mathbf{p}_i\mathbf{V}\mathbf{V}^{\top}\mathbf{p}_i^{\top}$，而 $\partial\mathbf{p}_i\cdot\mathbf{p}_i$ 经同样展开与 $\mathbf{V}\mathbf{V}^{\top}$ 的二次型相等——精确等式 $\mathrm{rowsum}(\partial\mathbf{P}\odot\mathbf{P}) = \mathrm{rowsum}(\partial\mathbf{O}\odot\mathbf{O})$），于是 $\mathbf{D}$ 可以在 kernel 启动前用一次便宜的逐元素乘求和得到。最后：

$$\partial\mathbf{Q} = \partial\mathbf{S}\,\mathbf{K}/\sqrt{d_k}, \qquad \partial\mathbf{K} = \partial\mathbf{S}^{\top}\mathbf{Q}/\sqrt{d_k}$$

所有这些计算都在与前向相同的 tiling 结构里分块完成——$\partial\mathbf{V}$ 用重算的 $\mathbf{P}$ 块，$\partial\mathbf{S}$ 在 SRAM 里逐块算完即用。

6.FA2 与 FA3：并行度、Hopper 特性与 FP8

6.1 FlashAttention-2（arXiv:2307.08691）：把 SM 喂饱

FA1 证明了"tiling + online softmax"的可行性，但只利用了 A100 理论 FLOPs 峰值的 25–40%。诊断出的问题有三个，FA2 逐一修复：（1）并行度不足：FA1 沿 K/V 块做外层循环，不同线程块处理的 Q 行块数量受限于 batch×头数——4k 序列、单 batch 单头时只有极少数 SM 有活干（A100 有 108 个 SM）。FA2 把外层循环换成 Q 行块，并行度变成"Q 块数 × batch × 头数"，长序列下 SM 几乎满载。（2）非 matmul 操作太多：softmax 的 max/exp/乘加无法用 tensor core，FA1 的内核里这类操作占比可观；FA2 重新组织了线程间的数据划分（每个 warp 处理 d 维的不同切片），把非 matmul FLOPs 与寄存器往返砍掉约一半。（3）块尺寸：调整 $B_r/B_c$ 更贴近 128×128 的 tensor core 甜点。结果：前向达到 A100 BF16 理论峰值（312 TFLOPs/s）的约 73%（反向约 63%），GPT-2 级端到端训练约 225 TFLOPs/s，整体比 FA1 快约 2 倍。

6.2 FlashAttention-3（arXiv:2407.08608）：拥抱 Hopper 的异步

H100 引入了两组新硬件能力，FA3 的设计围绕它们展开：WGMMA（warpgroup matrix multiply-accumulate，矩阵乘可跨 warp 组异步执行）与 TMA（Tensor Memory Accelerator，异步搬运数据、支持 barriers）。Ampere 时代"边搬边算"的同步开销在 Hopper 上成了新瓶颈。FA3 的三板斧：（1）生产者-消费者异步流水——专门的 warp 组用 TMA 预取下一块 K/V（生产者），另一组 warp 并行做矩阵乘与 softmax（消费者），数据一到位立即计算；（2）pingpong 调度——两组消费者错峰执行 GEMM 与 softmax，让 tensor core 与 SFU（算 exp 的单元）交替满载；（3）FP8 支持——用 8 位精度做矩阵乘（吞吐翻倍），配 in-kernel 的逐块缩放与（可选）非一致性量化（incoherent processing，用随机正交变换消除激活离群值），把 FP8 的精度损失压到可控。结果：BF16 下达 540–740 TFLOPs/s（约为 H100 理论峰值 989 的 55–75%），比 FA2 快 1.5–2 倍；FP8 下接近 1.2 PFLOPs/s。FP8 注意力对多模态还有一层特殊价值：视觉 token 的激活分布差异大，FA3 的逐块缩放是"kernel 内治理离群值"的示范，与第 39 章的多模态量化难点相呼应。

问题：注意力是访存受限算子，$T\times T$ 中间矩阵造成显存与带宽的双重浪费；已有"稀疏/低秩近似"路线牺牲精度且加速不稳定。方法：IO-aware 的精确注意力——分析 GPU 内存层级后设计 tiling（前向）与重计算（反向），用 online softmax 让分块结果可精确合并。关键结果：BERT-large（512）端到端快 15%、GPT-2（1k）快 3 倍、Long-Range Arena（4k）快 2.4 倍；注意力显存从 $O(T^2)$ 降到 $O(T)$，首次使 16k 上下文 BERT 的训练成为可能。为什么重要：它确立了"系统瓶颈决定算法设计"的思路（IO-aware algorithm design），此后 FA2/FA3、PagedAttention、第 39 章的整个推理优化栈都沿用"先算算术强度、再设计 kernel"的方法论。重读建议：第 2 节的 IO 复杂度分析（为什么分块次数 $\Theta(T^2 d^2 / M)$）与 Algorithm 1/2 值得逐行对照本章第 3–5 节。

7.MQA 与 GQA：给 KV Cache 瘦身

FlashAttention 解决"计算与中间显存"，而推理服务的另一半瓶颈是第 3 章的 KV Cache。多查询注意力（Multi-Query Attention, MQA，Shazeer, arXiv:1911.02150）给出激进方案：所有头共享一组 K/V——KV Cache 直接缩小 $H$ 倍，但质量有明显损失。分组查询注意力（Grouped-Query Attention, GQA，Ainslie et al., arXiv:2305.13245，EMNLP 2023）取中庸：把 $H$ 个 Q 头分成 $g$ 组，每组共享一组 K/V（$g=H$ 退化为 MHA，$g=1$ 退化为 MQA）。LLaMA-2-70B、Llama-3 全系、Qwen2/3 全系、Mistral 均采用 $g=8$ 量级的 GQA。

顺带一提更新的 MLA（Multi-head Latent Attention，DeepSeek-V2/V3 采用）：把 KV 压缩进一个低秩潜在向量再展开，显存进一步下降，代价是 kernel 实现更复杂（需要吸收矩阵运算以保持速度）。它与 GQA 的取舍在 2026 年仍是活跃话题，但工程生态（FlashAttention/vLLM/TensorRT 原生支持）仍是 GQA 最成熟。

8.Varlen 注意力与多模态序列打包

训练数据里的序列长短悬殊：一段对话 300 token、一份图文文档 8000 token。把它们 pad 到同一长度再过注意力，既浪费计算（pad 部分照样过 kernel）也浪费显存。varlen（变长）注意力的做法是把多条序列首尾相接拼成一条，用偏移数组 cu_seqlens 记录每条的边界，kernel 内保证"注意力只在自己的序列内部进行"——零 padding、零跨序列泄漏。flash-attn 库为此提供专门接口：

python
# pip install flash-attn --no-build-isolation   （需要与 PyTorch/CUDA 匹配的编译环境）
import torch
from flash_attn import flash_attn_func, flash_attn_varlen_func

B, T, H, D = 2, 4096, 32, 128
q = torch.randn(B, T, H, D, device="cuda", dtype=torch.bfloat16)   # 注意：flash-attn 用 (B,T,H,D) 布局
k, v = q.clone(), q.clone()

# —— 场景 1：稠密等长批 ——
out = flash_attn_func(q, k, v, causal=True, window_size=(-1, -1))   # 滑窗给 (左,右)，(-1,-1)=全局
print(out.shape)                                                    # [2, 4096, 32, 128]

# —— 场景 2：变长打包（多条序列拼成一条，比如图文样本打包）——
# 总 token 8192 = 4 条序列：[2048, 1024, 3072, 2048]
cu = torch.tensor([0, 2048, 3072, 6144, 8192], device="cuda", dtype=torch.int32)
q_flat = q.transpose(1, 2).reshape(-1, H, D)      # [total_tokens, H, D]
k_flat, v_flat = k.transpose(1, 2).reshape(-1, H, D), v.transpose(1, 2).reshape(-1, H, D)
out_flat = flash_attn_varlen_func(
    q_flat, k_flat, v_flat,
    cu_seqlens_q=cu, cu_seqlens_k=cu,             # 各序列的起止偏移（长度可互不相同）
    max_seqlen_q=3072, max_seqlen_k=3072,         # 仅用于 kernel 选 tile，给最大值即可
    causal=True)                                  # 掩码在各序列内部独立生效，不跨序列
print(out_flat.shape)                              # [8192, 32, 128]
# 多模态意义：一条"样本"= 图像 token + 文本 token，注意力必须跨模态贯通；
# 而"不同样本之间"必须隔离 —— varlen 恰好把这两件事一次做对（第 9 节展开）。

多模态打包的完整故事是：样本内（视觉+文本 token）注意力全局连通；样本间用 varlen 或位置重置（position ids 重置 + 文档掩码）隔离。HuggingFace 的 FlashAttentionKwargs（cu_seq_lens_q / cu_seq_lens_k）与 packing 数据加载器（如 DataCollatorWithFlattening）已经把这条路径工程化。另一个多模态特有的注意点：视觉 token 常常是"双向感知"的——若视觉编码器输出后再被因果掩码切一刀，部分实践（如 InternVL 系对 tile 的处理）会让每个 tile 内部的视觉 token 保持可学习的位置关系，具体掩码策略因模型而异，读源码时留意 _update_causal_mask 类函数对图像段的处理。

9.对多模态的意义：高分辨率的平方税

现在把第 3 章与本章的账本合并，回答一个问题：为什么多模态模型比纯文本模型更依赖 FlashAttention？算一笔账。纯文本典型输入 2k token；而一个多模态样本：

表格最后一列解释了两个工程事实。其一：2022 年前的 VLM 全部把图像压到 224/336 分辨率——不是不想看清，而是 $T^2$ 的账付不起；FlashAttention 普及后（2023 下半年起），LLaVA-NeXT、InternVL、Qwen2-VL 才敢把视觉 token 推到数千乃至数万。其二：即便 FA 解决了显存，计算量仍是平方的——3 万 token 的 prefill 单层就要约 5.7 TFLOPs（$4T^2d$），几十层叠加后高分辨率首 token 延迟显著，这直接催生了视觉 token 剪枝/压缩方向（FastV 等，第 39 章）与连接器压缩设计（第 15 章）。可以说：多模态的"分辨率军备竞赛"是被 FlashAttention 解锁、又被平方复杂度封顶的。

⚠️ 陷阱：多模态训练里的注意力相关高频错误

（1）位置 id 忘记重置：多条样本打包后 RoPE 的位置必须按样本重置，否则第 2 条样本的 token 带着巨大的绝对位置参与旋转，注意力分布错乱（表现为 loss 收敛后突然升高）。（2）varlen 边界算错：cu_seqlens 是"前缀和"（首元素 0、末元素为总长），写成了"长度数组"会让注意力跨样本泄漏——数据泄漏的静默版本。（3）SDPA 的布尔掩码语义：传 attn_mask 布尔张量时 True 表示参与计算，与加性掩码（0/−inf）的直觉相反，且布尔掩码常使 kernel 退回慢速数学后端。（4）fp16 训练配 FlashAttention：FA 对 fp16 的分数会做内部缩放，但整个模型仍建议 bf16，避免 attention logit 溢出（第 1 章 FP16 位宽问题）。（5）GQA 与 flash-attn 的头序：flash-attn 要求 K/V 的头数能整除 Q 头数，且布局是 (B, T, H, D)——从 transformers 的 (B, H, T, D) 转换时忘记 transpose(1,2) 是最常见 bug。

python
import torch
import torch.nn.functional as F

def kv_cache_bytes(n_layers, n_kv_heads, head_dim, seq_len, batch, bytes_per=2):
    """KV Cache 显存公式（第 3 章式）的代码版：训练前先算账"""
    per_token = 2 * n_layers * n_kv_heads * head_dim * bytes_per
    return per_token * seq_len * batch

# 例：Qwen2.5-VL-7B 形态（28 层、28 Q 头、4 KV 头、head_dim=128）做 32k 上下文视频理解
gb = kv_cache_bytes(28, 4, 128, 32768, batch=1) / 2**30
print(f"单请求 KV Cache: {gb:.2f} GiB")       # ≈ 1.75 GiB —— 长视频理解可行

# —— SDPA 的三个后端与 GQA（PyTorch ≥ 2.5 支持 enable_gqa）——
q = torch.randn(1, 28, 32768, 128, device="cuda", dtype=torch.bfloat16)  # [B, H_q, T, D]
k = torch.randn(1, 4, 32768, 128, device="cuda", dtype=torch.bfloat16)   # [B, H_kv, T, D]：仅 4 头
v = torch.randn(1, 4, 32768, 128, device="cuda", dtype=torch.bfloat16)
from torch.nn.attention import sdpa_kernel, SDPBackend
with sdpa_kernel(SDPBackend.FLASH_ATTENTION):         # 显式锁定 Flash 后端（可用的前提是形状合规）
    out = F.scaled_dot_product_attention(q, k, v, is_causal=True, enable_gqa=True)
print(out.shape)                                       # [1, 28, 32768, 128]，K/V 自动按组广播
# 提示：SDPA 会依据 dtype/形状/掩码自动挑后端（FLASH > EFFICIENT > MATH）；
# 布尔掩码、任意 attn_mask、fp32 都可能让它退回慢速 MATH 后端 —— 生产代码要显式检查。

🍳 实战配方：注意力实现的选型决策树

（1）默认起点：训练与推理都直接用 F.scaled_dot_product_attention(is_causal=True)——PyTorch 自动分派，代码零维护。（2）追求极限吞吐 / 需要滑窗、varlen、MLA 特性：装 flash-attn 包，用 flash_attn_func / flash_attn_varlen_func；H100 + FP8 场景等 FA3 类 kernel（2026 年 PyTorch/transformers 已在逐步内置 Hopper 路径）。（3）长上下文服务：选 GQA 模型 + vLLM（PagedAttention 管理分页 KV，见第 8、39 章）；上下文扩展用 YaRN 配置而不是重训。（4）多模态高分辨率：先估视觉 token 数（表 4-4），超过 8k 就要配 token 压缩或分辨率分桶；训练用 varlen 打包 + 位置 id 重置。（5）极端显存：KV 量化（FP8/INT8）或 MLA 系模型；但先确认推理引擎支持。（6）永远做对的两件事：位置重置 + 序列边界隔离——这两个 bug 都是静默的。

10.本章自测

✏️ 自测（先独立作答，再看答案要点）

1. 为什么标准注意力实现是访存受限而不是计算受限？用算术强度说明。
答案要点：A100 上计算峰值的门槛约 156 FLOP/字节（312 TFLOPs ÷ 2 TB/s）；标准实现为 $T\times T$ 的 S/P 矩阵付出约 4–8 GB HBM 流量，而总 FLOPs 仅约 $4T^2d$，强度不足 50 FLOP/字节 → SM 等数据。大矩阵乘强度高（计算受限），注意力慢在"搬运"而非"计算"。

2. 写出 online softmax 的合并公式，并解释为什么它能保证与整行 softmax 一致。
答案要点：$m^{new}=\max(m^{old},m_j)$，$l^{new}=e^{m^{old}-m^{new}}l^{old}+l_j$，$\mathbf{o}^{new}=e^{m^{old}-m^{new}}\mathbf{o}^{old}+\mathbf{p}_j\mathbf{V}_j$（$\mathbf{p}_j$ 为块内未归一化权重），最后除以 $l^{new}$。一致性源于 $e^{x_j-m^{old}} = e^{x_j-m^{new}}\cdot e^{m^{old}-m^{new}}$：所有历史贡献按同一比例换基到新 max，归纳可得与全局 softmax 逐项相等。

3. FlashAttention 反向传播为什么要重计算？重算什么？多花了多少？
答案要点：为省掉 $T\times T$ 的 P 矩阵存储，前向只留输出 O 与每行统计量 $(m,l)$；反向重跑一遍分块前向重建 P（用 $m,l$ 归一），同时算 $\partial V=P^{\top}\partial O$、$\partial S=P\odot(\partial P-D)$（$D=\mathrm{rowsum}(\partial O\odot O)$）与 $\partial Q,\partial K$。额外约 1.5–2 倍注意力 FLOPs，但反向显存从 $O(T^2)$ 降到 $O(T)$，端到端仍更快（访存受限）。

4. FA2 相对 FA1 的两个主要改进是什么？FA3 靠什么在 H100 上再快 1.5–2 倍？
答案要点：FA2：外层循环改为 Q 行块提升并行度（SM 占满）、重排线程分工减少非 matmul FLOPs（前向达峰值约 73%）。FA3：利用 Hopper 的 WGMMA/TMA 做生产者-消费者异步流水、pingpong 调度让 GEMM 与 softmax 互补占用、FP8 支持吞吐翻倍（BF16 540–740 TFLOPs/s，FP8 近 1.2 PFLOPs/s）。

5. 一个 MHA 7B 模型（32 层、32 头、128 维）转 GQA-8 后，KV Cache 缩小多少？质量如何保住？
答案要点：KV 头从 32 → 8，KV Cache 缩小 4 倍（每 token 512 KiB → 128 KiB）。质量靠 uptraining：把 MHA 的 K/V 投影按组平均池化成 8 组，再用约 5% 原始算力继续预训练（GQA 论文的转换流程），质量接近原 MHA 且优于同规模 MQA。

6. 为什么说"FlashAttention 解锁了多模态的高分辨率"？请用视觉 token 数与显存量说明。
答案要点：高分辨率→视觉 token 千到万级（如 448×448×16 帧 ≈ 16k），标准实现单层 S 矩阵 32 头约 18 GiB、根本无法物化；FA 额外显存 O(T)，使数千-数万视觉 token 可训可推。但计算仍为 O(T²)（prefill 压力），因此高分辨率上限还受 token 压缩/剪枝制约（第 15、39 章）。

7. varlen 打包多模态样本时，哪两个 bug 是"静默"的？如何自查？
答案要点：（1）位置 id 未按样本重置（RoPE 位置串样本）；（2）cu_seqlens 写成长度数组导致注意力跨样本泄漏。自查：构造两条短样本打包，检查任一 token 的注意力是否对另一条样本的 token 权重为 0；并对比"打包 batch loss"与"逐样本单跑 loss"是否一致。
