💡 本章导读

第 15–17 章的主流架构（编码器 + 连接器 + LLM）在工程上大获全胜，但它们都是"嫁接"出来的：视觉与语言在各自的预训练里长大，相遇时已经定型。本章讨论更激进的问题：能不能让模型从出生（预训练第一天）就同时看图和读文？这就是原生多模态（natively multimodal）与早期融合（early fusion）。2024 年是这个方向的爆发年——Chameleon、Fuyu、Transfusion、Emu3 几乎同时出现，各自给出了不同的技术答案；GPT-4o 与 Gemini 的"原生"叙事也在此背景下获得技术注脚。本章逐一解剖这些方案，并用表示效率的理论视角回答：早期融合是未来，还是昂贵的弯路？

"为什么是 2024 年"也值得问。三个条件的成熟使原生路线从论文概念变成可执行工程：①tokenizer 达标——VQGAN 系的重建质量跨过"生成图像可用"的门槛；②数据管道成熟——图文对、交错网页、视频-文本的大规模清洗管线（第 34 章）被 CLIP/LAION 时代打磨完毕；③稳定性知识积累——大模型训练的 spike 治理、norm 设计（第 7、8 章）已有 playbook。三者齐备后，原生路线的"难"从原理性困难降级为工程性困难——这是所有技术路线成熟的标志。

1."原生"的定义：适配器路线的三重天花板

先厘清术语。适配器路线（adapter-based）：独立视觉编码器（常已对齐，如 CLIP）+ 连接器 + 语言模型，视觉是"外挂"。它在 2023–2024 横扫开源社区，但有三个结构性天花板：①信息瓶颈前置——视觉信息被压缩进几百个 token 后不再有"反悔"的机会，编码器看不见的细节 LLM 永远看不见（第 14 章已论证）；②目标函数割裂——视觉编码器的目标（对比/重建）与 LLM 的目标（下一词预测）不同，连接器只能在两个已定型的表示空间之间"和稀泥"；③任务形态受限——理解容易、生成难：适配器路线的模型几乎都不能输出图像，因为语言模型的输出空间里没有图像的容身之处。

原生多模态的三种理解层次（从弱到强）：弱原生——预训练早期就混合多模态数据（多数旗舰已做到，如 Qwen-VL 的三阶段）；中原生——单一模型统一处理多模态输入与输出（理解+生成一体）；强原生——所有模态在同一 tokenizer/序列空间中无差别处理（Chameleon 式）。本章的主角覆盖后两个层次。判断一个模型"多原生"的最快方法：看它的损失函数——只有文本 loss？还是图文共用一个生成目标？

三重天花板还可以用数字来感受。瓶颈之痛：CLIP-ViT-L 的 576 token 相当于把一张图压到"一句话"的预算——适配器路线的"看到"从定义上就是"摘要式地看到"。目标割裂之痛：CLIP 的对比目标只需要保留"足以与文本区分"的信息，"图里有几把椅子"这类细节如果在 caption 里不可辨，编码器就没动力编码——而 MLLM 的下游恰恰要问这类问题。任务形态之痛：2023 年用户问得最多的问题是"它能画图吗？"，适配器架构的答案永远是"不能"——这不是工程偷懒，而是输出空间的结构性缺失。原生路线的动机不是学术洁癖，而是这三个痛点的真实存在。

把"原生能多好"说得更具体，有三个可验证的优势形态：①交错理解——多图多轮中跨图的指代与推理（"第一张图的风格画第二张图的内容"），适配器路线因为每图独立编码而天然薄弱；②生成式感知——用"生成"验证"理解"（让模型画出它理解的几何题，画错即理解错），这是纯理解架构无法自检的盲区；③统一的表示经济性——同一组参数同时服务两种模态，理论容量利用率更高（在数据充足时）。这三点也是评测原生模型时最该看的"原生特有"指标——通用基准的分数差异只是故事的次要部分。

🕰 历史一刻：2024 年 5 月，两条新闻的交汇

2024 年 5 月，OpenAI 发布 GPT-4o（"o" = omni），主打端到端的原生全模态（文本/音频/视觉实时交互）；同月 Meta 放出 Chameleon 论文，公开了离散 token 早期融合的完整训练配方。一闭一开，都在回答同一个问题：适配器路线的成熟，是否恰恰意味着它已经是"上一代技术"？GPT-4o 用产品行为投票，Chameleon 用工程细节投票——本章讨论的正是这场投票背后的技术逻辑。值得注意的是结果的微妙：到 2026 年，开源社区的主流仍是适配器路线（或其强化版），原生路线的全面胜利尚未到来——为什么？本章末尾给出解释。

💡 技巧：判断论文里"原生"成色的三个检查点

读任何宣称"原生多模态"的论文，先查三件事：①预训练目标是否统一——找损失函数定义，图文是否共享同一个目标（或至少同参数联合训练）；②预训练数据是否从头混合——看训练配置表的数据课程，"后训练才见图"的不算；③输出空间是否含视觉——能不能画图/出语音，不能则为"原生理解"。三问之后，"原生"的营销水分基本挤干——这不是抠字眼，而是三个检查点分别对应本章三个技术方案的根本差异。

2.Chameleon：离散 token 早期融合的工程实录

Chameleon（Meta，arXiv:2405.09818）是强原生路线最完整的公开技术报告。核心设计：用同一个 token 流处理文本与图像。文本用 BPE（128K 词表），图像用 VQ tokenizer（基于第 2 章的 VQ-GAN 谱系，8192 码本，1024 token/图，8192 图像 token 不与文本共享）——两种 token 拼进统一序列，从头预训练。理解与生成对称：读图是"图像→token 序列"，生图是"token 序列→图像"，同一个下一 token 预测目标覆盖两种模态。架构本身几乎不变（Transformer 解码器），所有革命都在数据、tokenizer 与训练稳定性上。

数据侧的设计同样关键。Chameleon 的预训练混合以"文本打底、图文逐步加码"为原则：语言数据（约一半）保持原有的去重与课程，图像-文本对经过 CLIP 分数过滤与重新标注（利用其自家的 captioner 提升文本质量），交错序列（网页式图文混排）则负责教会模型"图文轮流说话"的节奏。一个反直觉的细节：交错数据的比例并不高（个位数百分比），但对"看图说话的对话感"影响巨大——这暗示交错"格式"本身是重要的学习信号，而不只是数据量的堆叠。

数据侧的设计同样关键。Chameleon 的预训练混合以"文本打底、图文逐步加码"为原则：语言数据保持原有的去重与课程，图像-文本对经过 CLIP 分数过滤与重新标注，交错序列（网页式图文混排）负责教会模型"图文轮流说话"的节奏。一个反直觉的细节：交错数据的比例并不高（个位数百分比），但对"看图说话的对话感"影响巨大——这暗示交错"格式"本身是重要的学习信号，而不只是数据量的堆叠。

论文最有价值的部分是它对训练不稳定的坦白：早期融合的训练在纯文本阶段后引入图像，出现 loss spike 与发散。两大修复：①QK-Norm——对注意力的 Q、K 做 RMSNorm（替换 logit 缩放），抑制注意力 logits 的爆炸——图像 token 的激活分布比文本更重尾（VQ 码字的稀疏跳变），未约束的 QK 点积容易把 softmax 推入饱和区、梯度消失进而发散；②Z-loss 正则——惩罚 logits 的 $\log\sum\exp(z)$ 幅度，约束 softmax 分母的稳定性。加上"前 15% 训练无图像数据"的课程设计，7B/34B 两档模型才稳定跑完 4.4T–6.9T token 的多模态混合。这段"踩坑实录"是全章最值得精读的部分——它把早期融合的真实工程代价摆上了台面。

成绩方面，Chameleon-34B 在多项基准上表现强劲（COCO caption 微调后 SOTA、TextVQA 45.4），更重要的演示是"生成式交错输出"：回答里可以自由穿插图像与文本（如"这里有你需要的零件图<图>"），这是适配器路线结构性做不到的产品形态。局限也很诚实：34B 版本的图像生成质量仍低于同期的专用文生图模型（SDXL/Imagen），若干知识基准暴露了多模态训练对语言能力的稀释（alignment tax）——"两头都要强"在 2024 年仍是未完成的目标。

📄 论文精读：Chameleon（Team Chameleon, arXiv:2405.09818）

问题：能否用统一的离散 token 空间与下一 token 预测目标，从零预训练一个"理解+生成"的原生多模态模型，并保持文本能力不倒退？方法：图像 VQ tokenizer（8192 码本、1024 token/图）+ BPE 文本统一序列；QK-Norm + Z-loss；"先文本后多模态"的课程；7B（4.4T token）与 34B（6.9T token）两档。关键结果：34B 在理解与生成双侧进入当时第一梯队，首次公开演示高质量的图文交错输出；附录的稳定性与超参数披露是开源社区的公共财富。为什么重要：它是"强原生路线可行"的最完整公开证明；踩坑记录把"原生比适配器难多少"变成可量化的工程知识。延伸阅读：对照 Emu3（纯 AR 独立复现）与 Transfusion（双目标改进），三条路线合读才能拼出完整地图。

3.Fuyu：最激进的无编码器路线

Adept 的 Fuyu-8B（2023 年 11 月，博客发布）把原生路线推到逻辑极端：不要视觉编码器。图像的 patch 经一个线性层直接映射进解码器——没有 ViT、没有 CLIP 预训练、没有连接器，"编码"被完全交还给 LLM 本体。设计动机：①支持任意分辨率与架构最简（图表/GUI 截图等"非自然图像"不需要 ImageNet 式先验）；②训练管线统一（只有一条 LM 损失）。代价同样极端：8B 的 LLM 要同时学"语言"与"从零开始的视觉感知"，图像理解的上限显著受限于模型规模与视觉数据量——Fuyu 在通用基准上落后同期适配器路线约一档，但在 UI 截图理解等目标场景表现出人意料。

从架构细节看，Fuyu 的极简是一条完整的推理链：图像直接 resize 到任意偶数尺寸 → 切 patch → 线性投影 → 与文本 token 拼接进因果 Transformer → 下一词预测一路到底。没有独立的视觉位置编码，没有模态类型嵌入（模型"自己学"哪些 token 是图的）。这种激进设计在多模态 Agent 场景（UI 截图/图表）获得了意外契合——但也正是这些场景的数据规模不足以让 LLM 从零学好感知，最终 Fuyu 线的迭代停在 2023 年底。它的遗产被后来的"线性视觉投影"研究继承。

Fuyu 的价值不在分数而在思想实验价值：它测出了"LLM 自学视觉"的下限。结论是——用 10B 级模型 + 万亿 token 级数据，自学视觉是"能用但浪费"的；视觉感知有其内在的统计结构（局部性、层级性），ViT 式的专用预训练等于"先修完视觉的通识课再上大学"。这个结论与第 6 节的理论分析（早融合的表示效率优势需要更大规模才能兑现）互相印证——事实上 Fuyu 可以看作"把原生路线的门槛条件（大数据）当作默认前提"的设计，前提不满足时它的短板就全部暴露。工程上真正存活下来的是 Fuyu 的"无编码器思想"的高分辨率变体：Qwen2.5-VL 的原生动态分辨率在形式上就是"Fuyu 式直进 + ViT 式预训练"的折中——保留专用视觉塔，但让它吃任意分辨率的 patch 而非固定网格。

💡 技巧：一张表看懂"谁的视觉先验在哪一层"

判断任何架构的"视觉先验位置"：适配器路线——先验在编码器（CLIP 的 4 亿对）、LLM 零视觉先验；Chameleon 式——先验在 tokenizer 与统一预训练（图像作为"外语"学进去）；Fuyu 式——先验全在 LLM 预训练数据里；混合式（Qwen2.5-VL）——先验在编码器（预训练 ViT）+ LLM 的多模态联训。先验位置决定了"换任务时该微调什么"：适配器路线换重感知任务要动编码器，Chameleon 式只需要数据，Fuyu 式要重训本体。

4.Transfusion：一个 Transformer 内的两种生成范式

Transfusion 的推理侧设计同样精巧：文本照常逐 token 生成；当模型输出"开始图像"的标记时，切换到扩散模式——初始化一段纯噪声的图像潜变量块，执行 $T$ 步去噪（每步是完整的双向注意力前向，文本部分 KV 缓存复用），完成后回到文本生成。两种模式共享同一套权重，切换由内容决定——这是"上下文驱动的多模态执行流"，比"一个理解模型+一个生成模型的级联"优雅得多。消融显示：双向注意力的图像段比"强行因果"的图像段生成质量高一个档次；λ 从 0.01 到 1 的扫描中，0.1 附近是理解/生成的帕累托平衡点——这个"损失配比"超参数的敏感性，是混合目标路线的额外调参负担。

Chameleon 的统一自回归有个隐性代价：图像 token 的 AR 生成质量低于扩散模型——逐 token 生成图像在全局一致性（纹理、对称、细粒度结构）上不如扩散的全局去噪。Transfusion（Meta，arXiv:2408.11039）给出第三条路：文本走 LM 损失、图像走扩散损失，共享同一个 Transformer。

📐 理论推导：Transfusion 的双目标与双向注意力设计

设序列中文本 token $t_{1..L}$、图像潜变量块 $x_{1..N}$（经 VAE 编码，每块是一个 patch 的连续向量）。总损失是两个目标之和：

$$\mathcal{L} = \underbrace{\mathcal{L}_{\mathrm{LM}}(\text{文本段，下一词预测})}_{\text{因果注意力}} \;+\; \lambda\, \underbrace{\mathcal{L}_{\mathrm{Diffusion}}(\text{图像段，加噪去噪})}_{\text{双向注意力}}$$

关键的架构决策在注意力掩码：文本段之间因果（语言生成需要单向）；图像块之间双向（扩散去噪需要全图信息）；文本对先前图像块可见（理解需要）。训练时对图像块独立加噪（每块独立采样时间步 $t$），模型用 DiT 式的 adaLN/上下文条件输出噪声预测。两个精妙细节：①模态间不需要重算——图像去噪的迭代在推理时只重复图像段的前向，文本 KV 可缓存；②λ 的平衡（原文 0.1 量级）决定"理解 vs 生成"的资源分配。效果：在同等算力下，Transfusion 的图像生成质量超过同规模 AR 模型（Chameleon 式），文本能力不受损——"扩散管生成质量，LM 管语义理解"的分工被证明可行。它与第 20 章 Janus 的"解耦视觉编码器"形成互补：Janus 解耦在"表示层"，Transfusion 解耦在"目标函数层"。

与 Chameleon 式离散路线的对比还有一层信息论含义：VAE 潜变量是连续的，每块携带的信息量由 VAE 的瓶颈决定，不存在"码本塌缩到少数码字"的表示浪费；但代价是生成时的采样迭代（多步去噪）与序列化困难（图像潜变量难以像 token 那样自然地承载"语义推理"）。Transfusion 的工程答案是把扩散目标"装进" LM 的训练循环里，让两个空间的表示由同一组参数协调——2025 年后的后续工作（Janus-Flow、BAGEL 等统一模型）基本都沿这条"混合目标"主线迭代，说明它已成为统一路线的主流工程形态。

5.Emu 系：从上下文学习到自回归统一

BAAI 的 Emu 系（Emu/Emu2 arXiv:2312.13289、Emu3 arXiv:2409.18869）走的是"渐进式原生"路线。Emu2：把连续视觉特征（EVA 编码）作为"视觉 token"放进 LLM 序列（回归式生成走扩散解码器），用 1.4 万亿多模态 token 训练出 37B 模型，演示了"生成式多模态上下文学习"——把示例图放进上下文，模型能完成"图生图"式的 few-shot 任务。Emu3 则彻底离散化：文本、图像、视频全部用下一个 token 预测（图像用 SBER-MoVQGAN tokenizer，视频是时间维度的图像序列），5B 模型 + 8.7 万亿 token 的纯 AR 训练，同时做到理解、图像生成与视频生成——它是"AR 统一论"的最有力证据：只要 tokenizer 与数据规模到位，扩散并非必需。

Emu3 的关键消融给了社区两个重要结论：①"vision tokenizer 的码本质量"是 AR 统一路线的第一瓶颈（重建质量直接封顶生成质量——第 2 章的 VQ 谱系因此重新变热）；②视频 AR 生成的时序一致性来自"时间维度的位置编码设计"而非模型结构。它也与 Chameleon 一起定义了原生路线的两大分支：离散 AR 统一（Chameleon/Emu3/LlamaGen）与连续+扩散混合（Transfusion/Janus-Flow）——第 20 章的统一模型章节将在此分类上展开。

在应用侧，Emu3 展示了一个特别有启发性的能力：用 AR 生成做"视觉思维链"——模型可以先生成一张中间草图再基于它继续推理/生成，这预示了"原生模型的推理可以包含生成动作"的范式（与 o3 的缩放查看形成有趣对照：一个是"生成中间表示辅助推理"，一个是"主动调用感知工具辅助推理"，殊途同归）。这类能力在纯理解架构上无法实现，因为它的输出空间里没有"图"。

Emu 系还有一处容易被忽视的设计演进：Emu2 的"回归式"视觉特征——图像以连续特征（而非离散 token）进入序列，需要生成时回归出扩散模型的条件。这条"连续特征 + 外接生成器"的中间路线，实际上是适配器路线与强原生路线的杂交：理解侧继承 EVA 编码器的质量，生成侧外包给专用扩散模型。Emu3 转向全离散则是"押注 tokenizer 进步"的战略决策——只要 tokenizer 的重建与语义质量持续提升，纯 AR 的简洁性红利就会持续放大。

🕰 历史一刻：2024 年，VQ tokenizer 的"文艺复兴"

VQ-VAE（2017）与 VQGAN（2021）本是图像生成的"老技术"，在扩散模型崛起后一度边缘化——Stable Diffusion 选择了连续 VAE + UNet 去噪的路线。2024 年 Chameleon/Emu3 的原生浪潮让 VQ tokenizer 戏剧性回归：它不再只是"压缩器"，而是多模态统一语言的"字母表"。这个角色转变把老技术问题重新变成前沿问题：码本规模、重建感知质量、语义与外观的兼顾（SEED 系的语义码本，第 20 章）。到 2026 年，"为多模态 LLM 设计 tokenizer"已经成为独立的研究方向——历史在这里完成了一个循环：老技术因为新的系统语境而重新年轻。这个循环也给研究者一个提醒：判断一项技术的价值，要放在"系统语境"里而非绝对性能里——VQ 在纯生成竞赛里输给扩散，在统一架构里却找到了不可替代的位置。

6.理论分析：早期融合与晚期融合的表示效率

把三条路线放进一个理论框架里比较。设模态 $m$ 的"原始信息量"为 $H_m$、模型的容量为 $C$，核心问题是：容量怎么分配给"各模态的感知"与"跨模态的对齐"？

适配器路线把对齐压缩在连接器的少量参数里——容量利用率高（感知与语言各用现成的），但对齐上限低（接口处是信息瓶颈，且两个预训练空间的"语义坐标系"不同）。原生路线让对齐渗透在全部参数里——上限高（无接口瓶颈，语义坐标系从头统一），但容量利用率低：在多模态数据占比不足时，大量容量仍在重复学习文本结构；且视觉 token 的序列长度（1024+/图）使注意力成本显著高于纯文本。定量含义：原生路线的优势需要一个"数据规模门槛"——多模态 token 占比足够大后，统一表示的复利才开始兑现。这解释了经验观察：小规模上适配器路线几乎总是赢，超大规模上原生路线开始反超（GPT-4o/Gemini 的"原生"选择本质上是"它们的数据与算力已经越过了门槛"）。

📐 理论视角：为什么图像 token 是"贵"的

语言 token 的信息密度高（一个词往往对应一个概念），图像 patch 的信息密度低（16×16 像素大部分是冗余的纹理）。信息论地看，若图像的信息熵集中在低频结构，VQ tokenizer 的 1024 token 中有效熵可能只占几百 token——AR 统一路线的序列成本是"按冗余付费"。三种缓解：①更好的 tokenizer（把熵压缩进更少 token，如更高压缩率的 VQ/扩散式 tokenizer）；②token 合成（Janus 的理解/生成分离编码器，各自用最经济的表示）；③混合目标（Transfusion 让图像留在连续空间，绕开离散化熵损失）。这也回答了"为什么 2026 年主流仍是适配器"：在 tokenizer 便宜下来之前，按冗余付费的路线只有在算力过剩时才划算。

实证侧也有交叉证据。MM1（arXiv:2403.09611）的消融显示：同等算力下，"CLIP 编码器 + 适配器"的混合预训练在多数理解基准上胜过完全从零的多模态预训练——因为对比预训练以极低的算力成本"预付"了对齐的大部分工作。而原生阵营的反例是 Gemini 系的持续强势：当预训练数据中多模态占比足够高且质量高，从头统一的优势开始显现。结论不是谁对谁错，而是"对齐预训练"与"统一预训练"是同一条效率曲线上的不同区段——你的预算落在哪个区段，决定哪条路线更优。

🍳 实战配方：原生路线的"最小可行入门"（两周计划）

第一周：tokenizer——用预训练 VQGAN（Emu3 开源的 MoVQGAN 或 taming-transformers）把 1 万张图转成 token 序列，计算码本利用率（目标 >30%）；用现成 1B LM 在"图像 token+文本"混合序列上做 10 亿 token 续训，观察 loss 稳定性与文本 PPL 是否退化。第二周：复现 QK-Norm/Z-loss 效果——同一设置下去掉两者，记录 spike 频率；对比"先文本后图像"vs"全程混合"两种课程。产出：《小规模原生训练观察报告》。这个实验建立"原生路线的体感"——它到底比适配器难在哪，做过一次就不会再迷信任何一方的宣传。

📐 理论推导：双向图像段的注意力成本账

Transfusion 式混合的一个隐藏优势在注意力成本。设文本长 $L$、图像块 $N$（$N\gg L$ 是常态）。纯 AR（Chameleon 式）：注意力成本 $ rac{1}{2}(L+N)^2 d$（因果三角），且每生成一个图像 token 都要重新 attend 全部前文；扩散式（Transfusion 式）：文本部分 $ rac{1}{2}L^2 d$ + 图像双向 $N^2 d$ + 跨模态 $LN d$，但去噪的 $T$ 步之间图像表示独立重算、文本 KV 只算一次。在 $N=1024$、$L=200$ 的典型配比下，两者的理论量级接近，但扩散式的并行度高（$T$ 步可并发、无序列依赖），在 Hopper 级硬件上的实际吞吐显著优于 AR 逐 token 的访存受限解码（第 8 章 roofline）。这个"理论成本相近、硬件效率占优"的账，是混合目标路线在工程上的隐性加分项。

7.训练稳定性与数据配比：原生的真实代价

综合 Chameleon/Emu3/Transfusion 的披露，原生路线的工程代价集中在四件事：①损失尖峰治理——图像 token 引入重尾 logits，QK-Norm + Z-loss + 梯度裁剪的组合拳是标配（第 7 章的 spike 处置在此全面升级）；②数据配比课程——先用纯文本稳住语言底座，再渐进引入图像（Chameleon 前 15% 无图），配比失衡会让语言能力"倒退"（alignment tax 的多模态版）；经验区间是文本：多模态 ≈ 1:1 起步、语言不低于 40%，且交错数据虽占比小但不可缺；③tokenizer 是新的一等公民——码本规模、重建质量、码本利用率（codebook usage）的监控成为日常，tokenizer 升级等于模型重训；④评测双线——理解与生成分开打分，防止"生成拉垮理解"或反之的隐性退化。给实践者的现实建议：7B 以下规模、以理解为主的场景，适配器路线仍是首选；原生路线的入门实验建议从"Emu3 式小规模复现"（第 49 章 L3 缩比）或直接使用 Chameleon/Emu3 的开源权重开始，而不是从零训。

训练中的监控面板建议分四格：①文本 loss（held-out 文本 PPL——语言税的哨兵）；②图像重建/生成 loss（分 tokenizer 与模型两段看）；③注意力熵（按模态分组统计——饱和与坍缩的哨兵）；④梯度范数与 spike 计数（稳定性哨兵）。四格中任何一格异常都对应第 7A 节的一类失败模式——这个"仪表盘到诊断"的映射，让原生训练的日常运维有章可循。

把三份报告的训练配置并排读，还有一个有趣的对比：Chameleon（6.9T token/34B）与 Emu3（8.7T/5B）的"数据规模/参数规模"比都在 200–1700 区间的极端过训练带——远超 Chinchilla 的 20 倍标准。原因与第 7 章的推理感知过训练一致：统一模型的多模态任务（尤其生成）对模型"内化程度"的要求更高，且生成质量对欠训练极其敏感。原生路线因此天然是"重数据"路线——这不是缺点而是结构属性：它用数据代替了结构先验（编码器）与对齐捷径（连接器）。

三份技术报告之外，开源社区对原生路线的独立检验也值得一读：OpenEmu/Chameleon 复现项目普遍报告"复现分数低于原论文 5–15%"，主要缺口在数据管线而非模型（原论文的数据质量与课程顺序难以完整复原）。这再次呼应第 34 章的主题：数据工程是原生路线真正的护城河——模型结构都是公开的，"怎么喂"才是秘密。

7A.原生路线的评测与失败模式

原生模型需要双线评测，且两线会互相"抢算力"。理解线沿用第 40 章基准（MMMU/MMBench/DocVQA）；生成线用 GenEval/VBench 类；交叉线才是原生独有的——图文交错任务（先描述再画示意图）、"指着自己生成的内容回答"的自指一致性、"用图修正文字"的多模态自我修正。交叉任务缺少标准化基准，社区常用人工评估，这也是原生路线进展难以精确比较的原因之一。

五类典型失败模式：①模态退化——多模态数据占比过低，模型"忘记"怎么生图；诊断：分模态 loss 分开监控。②tokenizer 玻璃化——生成图像出现规则性纹理伪影（码本塌缩或重建上限）；诊断：先单独测 tokenizer 重建质量再怪模型。③注意力饱和——长图 token 稀释文本注意力；诊断：注意力熵监控（按模态分组的熵统计）。④语言税——混合训练后文本基准下降；诊断：held-out 文本 PPL 双跟踪。⑤交错错乱——图文时序错位、图不对应文；诊断：交错一致性探针。出问题时先对号，再开药；若多条同时命中，优先处理数据侧（配比/质量），再动结构侧（norm/位置编码）——数据问题的修复收益总是更大。

⚠️ 陷阱：把 tokenizer 的锅甩给模型

AR 统一路线的生成质量"卡在重建上限"是最常见的误诊：tokenizer 的重建质量决定生成质量的理论天花板，模型再大也变不出来。排障的正确顺序：先用 tokenizer 走一遍"图→token→重建图"的闭环，重建不满意先升级 tokenizer（更高压缩、更大码本、感知损失加权），再调模型。Emu3 与 Chameleon 都把 tokenizer 作为独立工程章节对待——这不是巧合，而是依赖结构使然。

🍳 实战配方：原生 vs 适配器的"五问决策卡"

拿这五个问题给你的项目打分，三问以上答"是"才考虑原生：①产品需要模型生成图像/视频/语音吗？②需要跨模态的交错连贯性（指着自己画的图继续说）吗？③有多模态占比 ≥30% 的训练数据与万亿级 token 预算吗？④能承受 tokenizer 迭代带来的重训成本吗？⑤理解类指标已接近适配器路线的天花板（需要新增长点）吗？评分低不代表原生不好，只代表"现在还轮不到它"——把这张卡存档，每半年重新打一次分。

7B.2025–2026 的产品化观察：原生走到哪了

把这一年的产品信号汇总，可以看到原生路线的真实渗透节奏：①语音先行——GPT-4o 与 Gemini Live 的实时语音是最先兑现的"原生"能力，因为音频的 token 化（RVQ，第 30 章）比图像成熟且序列短；②图像生成 API 化——GPT-4o 原生生图（2025 年 3 月的吉卜力风潮）证明"理解模型内生高质量生成"在产品上可行，其技术路线（自回归+扩散混合或改进 tokenizer）虽未公开，但市场反馈证明用户在意的是"同一个模型理解并生成"的连贯体验；③开源侧的折中——Qwen3-VL、InternVL3.5 等旗舰在理解侧持续逼近闭源，但生成侧仍以"外接生成模型"的管道方案为主——适配器路线的产品惯性可见一斑。④Agent 场景的隐性原生需求——GUI 操作要求"看到什么就操作什么"的闭环，生成侧需求弱但感知侧要求极高，这解释了为什么 Agent 旗舰（UI-TARS 系）多为"适配器强化感知"而非全面原生。

给"要不要现在转向原生"的团队一个决策框架：你的产品需要模型生成交互资产（图/视频）吗？不需要 → 适配器路线的性价比仍是碾压性的。需要，且质量要求中等 → 混合管道（理解模型+生成模型，第 45 章工作流）成熟可靠。需要，且"理解-生成连贯性"是核心体验（创作工具、教育产品）→ 原生路线开始值得投入，从开源 Chameleon/Emu3 权重微调起步。需要，且要求端到端语音/实时 → 这是原生路线的核心腹地，目前闭源领先最多，开源需评估自研成本。

把观察收敛成一张"成熟度表"：语音原生——产品级成熟（4o/Gemini Live）；图像原生生图——产品级可用（4o 生图、Chameleon 演示）；视频原生生成——技术演示期（Sora 类）；文档/Agent 场景原生——无需原生，适配器足够。这个成熟度分层解释了一个看似矛盾的现象：为什么"原生多模态"喊了两年，多数开发者的日常仍是适配器模型？因为多数开发者的任务集中在"理解类"，而理解类的原生优势尚未跨过性价比门槛。判断转折点的信号：当开源原生模型在理解基准上稳定追平同尺寸适配器模型时——按 2026 年的趋势，这个信号可能出现在未来一两年内。

8.本章小结

本章解剖了原生多模态的三个技术方案与一个理论框架：Chameleon 证明离散 token 早期融合可行并公开了稳定性配方（QK-Norm/Z-loss/数据课程）；Fuyu 探测了"无编码器"的下限——视觉先验不能省，只能换位置；Transfusion 用双目标掩码设计让"LM 管理解、扩散管生成"在同一 Transformer 内共存；Emu3 用纯 AR 补齐了统一路线的最后一环。理论层面，"对齐容量的分配"视角解释了三条路线的适用域：小规模适配器赢，超规模原生赢，而分水岭由数据规模与 tokenizer 效率决定。到 2026 年，原生路线已经从"激进实验"演化为"旗舰预训练的默认选项之一"，但开源社区的主流实践仍以适配器为性价比之选——这个"落后半步"的格局，正是当前多模态工程生态的真实形态——也是机会所在：原生路线的工程知识与开源工具链仍然稀缺，早期投入者将在 2027 年的格局里占据身位。下一章把"统一"推到极致：理解与生成的完全统一、以及任何模态到任何模态的 any-to-any。

✏️ 自测

1. Chameleon 的两大训练稳定性修复是什么？各自的机理？
答案要点：QK-Norm——对 Q/K 做 RMSNorm 抑制注意力 logits 爆炸（图像 token 分布重尾）；Z-loss——惩罚 softmax 分母的幅度，防数值发散。配合纯文本先行的数据课程。

2. Fuyu 实验的"思想实验价值"是什么？
答案要点：测出 LLM 自学视觉的下限——10B 级+万亿数据可用但浪费，说明视觉先验不可省只能换位置；其无编码器思想以"原生动态分辨率"形式活在后续模型里。

3. 写出 Transfusion 的总损失与掩码设计要点。
答案要点：$\mathcal{L}=\mathcal{L}_{\mathrm{LM}}+\lambda\mathcal{L}_{\mathrm{Diff}}$；文本段因果、图像段双向、文本可见先前图像；图像块独立加噪、adaLN 条件。

4. "对齐容量的分配"框架如何解释"小规模适配器赢、超规模原生赢"？
答案要点：适配器把对齐压缩在连接器（容量利用率高、上限低）；原生把对齐分散到全参数（上限高、利用率低），多模态数据占比过门槛后统一表示的复利才兑现。

5. 为什么说 AR 统一路线是"按冗余付费"？三种缓解？
答案要点：图像 patch 信息密度低、VQ 序列含大量冗余 token；缓解：更好 tokenizer（熵压缩）、理解/生成分离编码器（Janus）、混合目标留连续空间（Transfusion）。

6. 原生路线的四件工程代价是什么？
答案要点：损失尖峰治理（QK-Norm/Z-loss/裁剪）、数据配比课程（语言先稳）、tokenizer 成为一等公民（升级=重训）、理解/生成双线评测防隐性退化。

7. 交叉评测为什么对原生模型是刚需？举一个例子。
答案要点：单侧评测无法暴露"模态间协作"的退化；如"先文字描述再生成示意图"要同时考核文本准确性、生成质量与图文一致性——单侧分数好可能是另一侧崩坏的掩护。

8. 为什么说"对齐预训练与统一预训练是同一条效率曲线上的不同区段"？
答案要点：对比预训练以低成本"预付"对齐（适配器路线受益）；数据与算力越过分水岭后，从头统一的上限优势开始兑现（原生受益）；MM1 消融与 Gemini 强势分别是两端的经验证据。

9. 你的产品是儿童教育应用（需要"讲一个故事并画出插图"，图文必须连贯），三条路线怎么选？
答案要点：核心体验是理解-生成连贯性 → 原生路线开始值得投入；务实路径是先用"强理解模型+强生成模型+连贯性工程（角色卡、风格锚定，第 28/45 章）"上线，同时小规模试点原生模型（Chameleon/Emu3 系微调），一旦连贯性体验明显更优再迁移。

10. Chameleon 用"前 15% 训练不含图像"的课程，而 Emu3 用全程混合也成功。如何理解这种差异？
答案要点：稳定性问题与数据分布、tokenizer 设计、模型规格强相关，不是原生的必然属性；Chameleon 34B+大码本更易失稳，Emu3 5B+改进 tokenizer 分布更温和。结论：课程是手段不是教条，判断依据是前期 spike 监控。
